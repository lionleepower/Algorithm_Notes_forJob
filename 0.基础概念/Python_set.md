# Python 集合 set：不重复 + O(1) 查找的哈希容器

`set` 是 Python 的集合类型，两个核心特性：**元素不重复**、**查找是 $O(1)$**。算法题里凡是要「记录见过的元素」「判断某个东西在不在」「一步去重」，几乎都用它而不用 `list`。

---

## 思路

程序经常要回答「这个东西之前出现过吗」。用 `list` 存，`x in my_list` 要逐个扫，$O(n)$；数据一多就成瓶颈。`set` 底层是哈希表，`x in my_set` 对 `x` 算一次 hash 直接定位，$O(1)$。

> [!tip]- 核心思路
> 
> 需要「快速判断存在性」或「去重」就用 `set`。
> 
> ```python
> seen = set()
> if x in seen:      # O(1)，hash 定位，不是逐个比较
>     ...
> seen.add(x)
> ```
> 
> 判断依据：只关心「在不在 / 有没有重复」、不关心顺序和出现次数，就是 `set`。

---

## 1. 导入与创建

`set` 是内置类型，不需导入。注意最大的坑：`{}` 是**空字典**不是空集合。也就是相当于dict()去掉了value

> [!success]- 基础语法
> 
> ```python
> s = set()              # 空集合（{} 是空字典！）
> s = {1, 2, 3}          # 非空可以用花括号
> s = set([1, 2, 2, 3])  # 从 list 建集合 => {1, 2, 3}，顺便去重
> s = set(range(n))      # 从可迭代对象建集合
> ```

---

## 2. 核心操作

| 操作 | 作用 | 时间复杂度或注意事项 |
| --- | --- | --- |
| `s.add(x)` | 加入元素 | $O(1)$；重复加入集合不变 |
| `x in s` | 判断存在性 | $O(1)$，hash 定位 |
| `s.remove(x)` | 删除 | $O(1)$；元素不存在会报错 |
| `s.discard(x)` | 删除 | $O(1)$；元素不存在也不报错 |
| `len(s)` | 元素个数 | $O(1)$ |
| `s - {x}` | 差集，返回**新集合** | $O(\text{len}(s))$；不修改 `s` |

> [!example]- 最小示例
> 
> ```python
> s = set()
> s.add(3)
> s.add(3)           # 重复加入，集合不变
> print(3 in s)      # True，O(1)
> s.discard(5)       # 不存在也不报错（remove 会 KeyError）
> print(len(s))      # 1
> ```

---

## 3. 关键行为与边界

> [!tip]- 为什么快：底层是 Hash
> 
> `set` 和 `dict` 底层都是哈希表。`x in s` 不是逐个遍历比较，而是对 `x` 算一次 hash 直接跳到对应桶。
> 
> ```python
> x in my_list   # O(n)，逐个扫
> x in my_set    # O(1)，hash 定位
> ```
> 
> 这就是算法题里「记录见过的元素」几乎总用 `set` 的原因。

> [!warning]- 边界条件
> 
> - `{}` 是空字典，空集合只能写 `set()`。
> - `set` 里只能放**可哈希（不可变）**的东西：数字、字符串、`tuple` 可以，`list` 不行。
> - 去重会**丢失原顺序**；要保序去重用 `dict.fromkeys(nums)`。
> - `remove` 删不存在的元素抛 `KeyError`，不确定存不存在用 `discard`。

---

## 4. 实例一：差集 `s - {x}` —— 不可变副本传递

排列型回溯 [[6.3 排列型回溯]] 的 `set` 版靠差集实现「免恢复现场」：`s - {x}` **新建**一个集合，不动原来的 `s`。

> [!success]- 差集不修改原集合
> 
> ```python
> s = {1, 2, 3}
> t = s - {2}    # t 是新集合 {1, 3}
> print(s)       # {1, 2, 3}，s 完好无损
>
> s.remove(2)    # 对比：就地修改，s 变成 {1, 3}，原来的没了
> ```

每层递归拿到的是自己的一份副本，从没动过上一层的候选池——**复印一份名单，在复印件上划掉一个名字再交给下一层，原件永远干净**。这是不同于 `pop` 的另一种状态管理，见 [[状态恢复]]。

## 5. 实例二：用 set 记录见过的元素

> [!success]- 环形链表（哈希解法）
> 
> ```python
> def hasCycle(head):
>     visited = set()
>     while head:
>         if head in visited:    # 再次遇到 → 有环
>             return True
>         visited.add(head)
>         head = head.next
>     return False
> ```

> [!summary]- 当前实例复杂度
> 
> - 时间复杂度：$O(n)$，每个节点最多访问一次，`in`/`add` 都是 $O(1)$。
> - 空间复杂度：$O(n)$，最坏存下全部节点——这是相对快慢指针（$O(1)$ 空间）的代价，见 [[4.1 快慢指针，环形链表]]。

---

## 6. 与相近写法怎么选

| 需求 | 推荐写法 | 原因 |
| --- | --- | --- |
| 判断存在性 / 去重 | `set` | $O(1)$ 查找，一步去重 |
| 需要计数 / 键值映射 | `dict` | `set` 只有键没有值，见 [[Python_dict]] |
| 需要保序、可索引 | `list` | `set` 无序、不能下标访问，见 [[pythonList、Tuple、Dict容器创建与操作选择]] |
| 保序去重 | `dict.fromkeys` | `set` 去重会丢顺序 |

---

## 7. 常见易错点

> [!warning]- 易错点
> 
> - **`{}` 当空集合**：它是空字典，空集合必须 `set()`。
> - **往 set 里放 list**：`s.add([1, 2])` 抛 `TypeError: unhashable type`；改用 `tuple`：`s.add((1, 2))`。
> - **以为 set 有序**：迭代顺序不保证，不能靠它排序或按下标取值。
> - **`remove` 删不存在元素**：抛 `KeyError`；不确定就用 `discard`。

---

## 复杂度

> [!summary]- 复杂度
> 
> - 核心操作：`add` / `in` / `remove` / `discard` 均摊 $O(1)$，因为哈希表按 hash 直接定位。
> - 差集 `s - t`：$O(\text{len}(s))$，要遍历 `s` 逐个判断是否在 `t` 里。
> - 额外空间：$O(n)$，$n$ 个元素各占一个哈希桶。

---

## 一句话总结

`set` = 哈希表支撑的「不重复 + $O(1)$ 存在性判断」容器；要去重或记录见过的东西就用它，代价是无序、只能装可哈希对象、`{}` 是字典这个坑。

---

## 模板归纳

看到以下信号时，优先想到 `set`：

- 「判断有没有出现过 / 是否重复」→ `if x in seen`
- 「一步去重」→ `set(nums)`（不在乎顺序）
- 「维护窗口内是否存在某元素」→ 滑动窗口配 `set`
- 「候选池，用一个删一个且不想改原池」→ `s - {x}` 传副本

```python
# 最常用：记录见过的元素
seen = set()
for x in data:
    if x in seen:
        ...          # 命中重复的处理
    seen.add(x)
```
