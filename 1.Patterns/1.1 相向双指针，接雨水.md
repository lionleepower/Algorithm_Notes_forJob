# 相向双指针：盛最多水的容器与接雨水

## 解决什么问题

两道题都围绕高度数组 `height`，都由「左右边界」共同决定答案，但**问的东西不同**——这是不能混的第一件事：

| 题目 | 核心问题 | 关键公式 |
| --- | --- | --- |
| 11. 盛最多水的容器 | 选**两根**柱子，围成的面积最大 | $(right - left) \times \min(h[left],\ h[right])$ |
| 42. 接雨水 | **每个位置**上方能存多少水 | $\min(preMax[i],\ sufMax[i]) - h[i]$ |

一个是**选两根柱子**，一个是**逐个位置累加**。公式记混是本篇最高频的错。

## 变体一：11. 盛最多水的容器

![](assets/1.1%20移动短板.svg)

> [!tip]- 核心思路：为什么一定移动短板
> 
> 容器宽度是 $right - left$，高度由**较短**的那根决定：
> 
> $$area = (right - left) \times \min(h[left],\ h[right])$$
> 
> ![](../attachments/Exported%20image%2020260514133539-0.png)
> 
> 设 `h[left] < h[right]`，左边是短板。此时若移动**右**指针：
> 
> - 宽度**一定变小**
> - 高度仍被左边这块短板卡住，**不可能变大**
> - ⇒ 面积严格不增，白走一步
> 
> 所以只能移动**短板**——只有换掉短板，高度才有机会抬上去。
> 
> 这和 [[1.0 相向双指针-多数之和]] 是同一个**排除法**：移动短板 = 断定「以这块短板为边界的所有组合都不可能更优」，一次划掉一整行/列，指针永不回头 ⇒ $O(n)$。
> 
> 区别只在排除的依据：1.0 靠**排序后的单调性**，本题靠**「短板决定高度」+ 宽度必减**——所以**本题不需要排序**，它的单调性来自面积公式本身。

> [!success]- Python 实现
> 
> ```python
> class Solution(object):
>     def maxArea(self, height):
>         ans = 0
>         left = 0
>         right = len(height) - 1
>
>         while left < right:
>             area = (right - left) * min(height[left], height[right])
>             ans = max(ans, area)                  # 先更新，再移动
>
>             if height[left] < height[right]:
>                 left += 1                         # 左边是短板
>             else:
>                 right -= 1                        # 右边是短板（或等高）
>         return ans
> ```
> 
> - **关键变量**：`ans` 维护历史最大面积；`area` 是当前这一对柱子的面积。
> - **易错位置**：**先更新 `ans` 再移动指针**——当前这对边界只会出现一次，错过就没了。

> [!example]- 示例推演
> 
> ```python
> height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
> ```
> 
> ```text
> left=0, right=8   area = 8 × min(1, 7) = 8    左边短 → left 右移
> left=1, right=8   area = 7 × min(8, 7) = 49   右边短 → right 左移
> 后续继续移动短板，最大面积始终没被超过
>
> 答案 49
> ```

## 变体二：42. 接雨水（前后缀分解）

> [!tip]- 核心思路：水位由「左右最高」的较小值决定
> 
> 对每个位置 `i`，它上方能存的水由两件事决定：
> 
> - 左边最高柱子 `pre_max[i]`
> - 右边最高柱子 `suf_max[i]`
> 
> 水位取**两者的较小值**，再减去自己的高度：
> 
> $$water_i = \min(preMax[i],\ sufMax[i]) - h[i]$$
> 
> **为什么取较小值？** 因为水必须被**两边同时挡住**。左边最高 3、右边最高 5，水最多到 3——超过 3 的部分会从左边流走。
> 
> **为什么不是看相邻柱子？** 相邻柱子矮不代表水会流走，只要更远处有更高的墙挡着，水照样存得住。**决定权在左右两侧的最高值，不在邻居。**
> 
> ![](../attachments/Pasted%20image%2020260702145608.png)

> [!success]- Python 实现
> 
> ```python
> class Solution(object):
>     def trap(self, height):
>         n = len(height)
>
>         pre_max = [0] * n
>         pre_max[0] = height[0]
>         for i in range(1, n):
>             pre_max[i] = max(pre_max[i - 1], height[i])      # 前缀最大值
>
>         suf_max = [0] * n
>         suf_max[-1] = height[-1]
>         for i in range(n - 2, -1, -1):                       # 必须从右往左
>             suf_max[i] = max(suf_max[i + 1], height[i])      # 后缀最大值
>
>         ans = 0
>         for h, pre, suf in zip(height, pre_max, suf_max):
>             ans += min(pre, suf) - h
>         return ans
> ```
> 
> - **关键变量**：`pre_max[i]` 是从左到 `i` 的最高柱子（**含自己**），`suf_max[i]` 同理。因为含自己，所以 `min(pre, suf) - h` 至少是 0，不会算出负数。
> - **易错位置**：两个数组的初值 `pre_max[0] = height[0]` / `suf_max[-1] = height[-1]`；后缀数组**必须从右往左**遍历。

> [!example]- 示例推演
> 
> ```python
> height = [0, 1, 0, 2]
> ```
> 
> 看位置 `2`：
> 
> ```text
> height[2] = 0
> 左边最高 pre_max[2] = 1
> 右边最高 suf_max[2] = 2
> 水位 = min(1, 2) = 1
> 接水 = 1 - 0 = 1
> ```

> [!tip]- 这题还有第二种视角：横向分层
> 
> 前后缀分解是**纵向**的——枚举每一**列**，问「这一列能接多少」。
> 
> 还可以**横向**做——枚举每一**层**，遇到「上一个更大元素」时把中间那个坑一次填平。那是[[2.1 单调栈 每日温度 接雨水]]的解法，也是能迁移到 84 柱状图最大矩形的那一套。
> 
> 两者都是 $O(n)$，答案当然一致。**纵向更直观、还能优化到 $O(1)$ 空间；横向更通用。**

## 易错点

> [!warning]- 易错点
> 
> - **盛最多水移动了高板**：面积高度由短板决定，移动高板只会让宽度变小而短板没变，面积不可能更优。**必须移动短板。**
> - **接雨水只看相邻柱子**：能接多少水由**左右两侧的最高柱子**决定，不由邻居决定。
> - **混淆两题的公式**：`(right-left) × min(h[left], h[right])` 是选两根柱子围面积；`min(pre_max[i], suf_max[i]) - h[i]` 是逐个位置累加。一个选两根，一个遍历全部。
> - **忘记先更新答案**：盛最多水里，每次移动指针**前**要先 `ans = max(ans, area)`——当前这对边界只出现一次。
> - **接雨水没处理空数组**：`pre_max[0] = height[0]` 会在 `height` 为空时 `IndexError`（实测确实会抛）。LeetCode 原题保证长度合法，但面试手写时最好补一句 `if not height: return 0`。
> - **后缀数组遍历方向写反**：`suf_max` 必须从 `n-2` 倒着推到 `0`，正着写就变成前缀了。

## 复杂度

> [!summary]- 复杂度
> 
> **11. 盛最多水的容器**
> 
> - 时间 $O(n)$ —— 左右指针合计最多移动 $n$ 次且永不回头。
> - 空间 $O(1)$ —— 只用常数个变量。
> 
> **42. 接雨水（前后缀分解）**
> 
> - 时间 $O(n)$ —— 三次线性遍历：算 `pre_max`、算 `suf_max`、累加答案。
> - 空间 $O(n)$ —— 两个长度为 $n$ 的辅助数组。
> - **可以优化到 $O(1)$ 空间**：改用相向双指针，一边走一边维护两侧的最大值，谁小就结算谁——那一版和 11 的骨架完全一样。
> - 对比 [[2.1 单调栈 每日温度 接雨水]] 的单调栈解法：同为 $O(n)$ 时间、$O(n)$ 空间，但那套能迁移到 84 柱状图最大矩形，这套不能。

## 一句话总结

**盛最多水**的本质是移动短板寻找最大面积，**接雨水**的本质是用左右最高边界计算每个位置的存水量——前者选两根柱子，后者逐列累加，两者共享的只有「左右边界共同决定答案」这个形状。

## 模板归纳

**相向双指针**适合：左右边界共同决定答案、每一步能根据某种规则排除一整侧、两端向中间收缩、要把 $O(n^2)$ 压成 $O(n)$。

```text
看到：两根柱子 + 最大面积
想到：左右指针 + 每次移动短板（先更新答案，再移动）

看到：每个位置能接多少水
想到：当前位置水量 = 左侧最高与右侧最高的较小值 − 当前高度
```

**前后缀分解**是一个独立的通用套路，别只当成接雨水的专用解法：

```python
# 凡是「答案依赖 i 左边的某个聚合值 和 右边的某个聚合值」，都可以这样拆
pre[i] = f(pre[i - 1], a[i])        # 从左往右
suf[i] = f(suf[i + 1], a[i])        # 从右往左
ans    = combine(pre[i], suf[i], a[i])
```
