# 滑动窗口：最短子数组与合法子数组计数

## 解决什么问题

**连续区间**上的最长 / 最短 / 计数问题。识别信号：

```text
连续子数组 subarray / 连续子串 substring + 最长最短 / 满足条件的数量
```

能用滑动窗口的前提是**单调性**：以 209 的正整数数组为例，`right` 右移窗口和只会**变大**，`left` 右移只会**变小**。有了这个方向感，就不必枚举所有 $O(n^2)$ 个子数组，只需让两个指针各走一遍。

> [!tip]- 和相向双指针的分野
> 
> | | [[1.0 相向双指针-多数之和]] | **本篇 滑动窗口** |
> | --- | --- | --- |
> | 指针方向 | 两端**相向**收缩 | 两个都**同向**右移 |
> | 单调性来自 | 数组**有序**（要先排序） | 元素**恒正**等题目性质（不排序，排序会破坏「连续」） |
> | 每步排除 | 一整行 / 一整列 | 一批以当前 `right` 结尾的非法区间 |
> 
> **千万别对滑动窗口的输入排序**——「连续」是题目给的结构，排完就没了。

## 三种问法只差一件事：答案在哪一步更新

![](assets/2.0%20滑动窗口%20三种问法.svg)

> [!tip]- 最长 / 最短 / 计数 的骨架差异
> 
> 骨架都是「右指针扩张 → `while` 收缩左边界 → 更新答案」，区别只在 **`while` 的条件**和 **`update` 的位置**：
> 
> | 问法 | `while` 的条件 | 答案在哪更新 |
> | --- | --- | --- |
> | 求**最长** | 窗口**不合法**时收缩 | `while` **之后**：`ans = max(ans, right-left+1)` |
> | 求**最短** | 窗口**合法**时收缩 | `while` **之内**：`ans = min(ans, right-left+1)` |
> | 求**数量** | 窗口**不合法**时收缩 | `while` **之后**：`ans += right-left+1` |
> 
> **最短为什么在 `while` 里面量？** 因为一旦合法就要立刻记下长度，然后继续缩看能不能更短；缩到不合法再量就晚了。
> 
> **最长为什么在 `while` 外面量？** 因为要缩到**刚好合法**才算数，`while` 里的中间态是非法的。
> 
> 记混这三者是本篇最高频的错——**先问自己「合法时该继续缩，还是该停下」**。

## 变体一：209. 长度最小的子数组（求最短）

找出和 $\ge target$ 的**最短**连续子数组长度，不存在返回 0。数组元素均为正整数。

> [!success]- Python 实现
> 
> ```python
> class Solution:
>     def minSubArrayLen(self, target: int, nums: list[int]) -> int:
>         n = len(nums)
>         left = 0
>         window_sum = 0
>         ans = n + 1                              # 哨兵：比任何合法长度都大
>
>         for right, x in enumerate(nums):
>             window_sum += x                      # 扩张
>             while window_sum >= target:          # 合法就一直缩
>                 ans = min(ans, right - left + 1) # 先量长度
>                 window_sum -= nums[left]         # 再移出左端元素
>                 left += 1                        # 最后才移动指针
>             
>         return ans if ans <= n else 0            # 哨兵没被改动 = 无解
> ```
> 
> - **主流程**：`right` 负责扩张，窗口一旦合法就用 `while` 持续收缩，边缩边记录更短的答案。
> - **关键变量**：`ans = n + 1` 是哨兵，表示「还没找到合法窗口」；最后靠 `ans <= n` 判断有没有解。
> - **易错位置**：收缩的三步顺序是**量长度 → 移出元素 → 移动指针**，`window_sum -= nums[left]` 必须写在 `left += 1` **之前**。

> [!example]- 示例推演：`target = 7`，`nums = [2,3,1,2,4,3]`
> 
> ```text
> right=0  加 2   sum=2    不合法
> right=1  加 3   sum=5    不合法
> right=2  加 1   sum=6    不合法
> right=3  加 2   sum=8    合法 → 长度 4，缩：移出 2，sum=6 不合法
> right=4  加 4   sum=10   合法 → 长度 4，继续缩…
> right=5  加 3            最终找到 [4, 3]
>
> 最短长度 2
> ```

## 变体二：713. 乘积小于 K 的子数组（求数量）

统计乘积**严格小于** `k` 的连续子数组数量。

> [!tip]- 核心思路：`ans += right - left + 1` 而不是 `ans += 1`
> 
> 这题不求最长最短，而是**统计所有以 `right` 结尾的合法子数组**。
> 
> 当窗口 `[left, right]` 已经收缩到合法时，所有**以 `right` 结尾、起点落在 `[left, right]` 内**的子数组都合法：
> 
> ```text
> nums[right : right+1]
> nums[right-1 : right+1]
> ...
> nums[left : right+1]
> ```
> 
> 数量正好是 `right - left + 1`。所以每轮加的是**一整批**，不是 1。
> 
> **为什么它们必然都合法？** 因为元素都 $\ge 1$，乘积随区间缩短只会不增——`[left, right]` 合法，那么它的任何后缀也合法。
> 
> **`k <= 1` 必须特判**：`nums[i] >= 1` 意味着任何子数组的乘积都 $\ge 1$，不可能严格小于 1。不特判的话 `while product >= k` 会把 `left` 推过 `right`，逻辑崩掉。

> [!success]- Python 实现
> 
> ```python
> class Solution:
>     def numSubarrayProductLessThanK(self, nums: list[int], k: int) -> int:
>         if k <= 1:
>             return 0                             # 必须特判
>
>         left = 0
>         product = 1
>         ans = 0
>
>         for right, x in enumerate(nums):
>             product *= x                         # 扩张
>             while product >= k:                  # 不合法就缩
>                 product //= nums[left]
>                 left += 1
>             ans += right - left + 1              # 一次加一整批
>         return ans
> ```
> 
> - **关键变量**：`product` 维护窗口乘积；`product //= nums[left]` 是精确整除（除掉的正是当初乘进来的那个数）。
> - **易错位置**：`ans += right - left + 1` 是本题核心；写成 `ans += 1` 会严重少算。

> [!example]- 示例推演：`nums = [10,5,2,6]`，`k = 100`
> 
> ```text
> right=0  窗口 [10]        新增 1 个
> right=1  窗口 [10,5]      新增 2 个
> right=2  乘积 100 不合法 → 移出 10，窗口 [5,2]，新增 2 个
> right=3  窗口 [5,2,6]     新增 3 个
>
> 合计 1 + 2 + 2 + 3 = 8
> ```

## 易错点

> [!warning]- 易错点
> 
> - **把「连续子数组」当成「任意选元素」**：滑动窗口只能处理连续区间，题目关键词是 `subarray` / `substring` / `continuous`。不连续就得换 DP 或别的思路。
> - **最短窗口用 `if` 代替 `while`**：209 一旦合法必须**持续**收缩，用 `if` 只缩一次，会错过更短答案。
> - **移动 `left` 前忘了移出元素**：必须先 `window_sum -= nums[left]` 再 `left += 1`，反过来会减错元素。
> - **713 忘了特判 `k <= 1`**：不特判会让 `left` 越过 `right`。
> - **计数题写成 `ans += 1`**：应该是 `ans += right - left + 1`——以 `right` 结尾的合法子数组是一整批。
> - **混淆最长 / 最短 / 计数三种骨架**：见上方对照表，关键是「合法时该继续缩还是该停」。
> - **对输入排序**：会破坏「连续」这个前提，滑动窗口直接失效。
> - **窗口内要求极值时硬套**：和、计数、种类数都可以「加进来、减出去」，而**极值减不掉**——那种情况要换 [[2.2 单调队列 滑动窗口的最大值]]。

## 复杂度

> [!summary]- 复杂度
> 
> 两题同阶：
> 
> - **时间 $O(n)$** —— 每个元素最多被 `right` 加入窗口一次、被 `left` 移出一次；`left` **只增不减、永不回退**，所以内层 `while` 的总执行次数被 $n$ 卡死。这与 [[2.0 单调栈与单调队列]] 的摊还分析是同一套论证——看到「循环套循环」不要直接判成 $O(n^2)$。
> - **空间 $O(1)$** —— 只维护 `left`、`window_sum` / `product` 等常数个变量。若窗口状态需要 `Counter` / `set`（如字符计数类题目），则是 $O(|\Sigma|)$。

## 一句话总结

滑动窗口的本质是**维护一个连续区间**，靠左右指针的单调移动把 $O(n^2)$ 的子数组枚举降到 $O(n)$；三种问法（最长 / 最短 / 计数）只差「`while` 的条件」和「答案在哪一步更新」这两个位置。

## 模板归纳

看到「**连续区间 + 最长 / 最短 / 数量**」，两步落笔：

1. **确认窗口状态可增量维护**：加入 `nums[right]` 和移出 `nums[left]` 都能 $O(1)$ 更新吗？和、计数、字符种类数都可以；**极值不行**（减不掉），那是 [[2.2 单调队列 滑动窗口的最大值]] 的活。
2. **按问法选骨架**：合法时该继续缩（求最短）还是该停下（求最长 / 计数）。

```python
# 通用骨架
left = 0
for right in range(len(nums)):
    add(nums[right])                       # ① 扩张
    while window_invalid:                  # ② 收缩到合法
        remove(nums[left]); left += 1
    update_result()                        # ③ 更新答案

# 求最短：while 的条件反过来，答案在循环里量
for right in range(n):
    add(nums[right])
    while window_valid:
        ans = min(ans, right - left + 1)
        remove(nums[left]); left += 1

# 求数量：收缩到合法后，一次加一整批
for right in range(n):
    add(nums[right])
    while window_invalid:
        remove(nums[left]); left += 1
    ans += right - left + 1

# 定长窗口：不需要 while，够长就吐掉最老的一个
for right in range(n):
    window_sum += nums[right]
    if right >= k:
        window_sum -= nums[right - k]      # 维持长度恰好为 k
    if right >= k - 1:
        update_answer()
```

窗口状态需要 `Hash Map` 的常见情形：维护字符出现次数用 `Counter`，维护字符最后出现位置用 `dict`，只判断存在性用 `set`。

```text

=> 优先想 Sliding Window
```
