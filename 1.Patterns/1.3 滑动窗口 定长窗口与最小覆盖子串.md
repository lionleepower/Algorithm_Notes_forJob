# 滑动窗口进阶：定长窗口与最小覆盖子串

## 解决什么问题

[[1.2 滑动窗口]] 用「和」「乘积」做窗口状态，本篇换成**字符计数**：窗口里装的不再是一个数，而是一张 26 格（或哈希表）的计数表。

三道代表题分处光谱两端：

- **438. 找到字符串中所有字母异位词**——窗口**定长**，问「哪些位置合法」。
- **567. 字符串的排列**——同样定长，只问「**存不存在**合法位置」。
- **76. 最小覆盖子串**——窗口**变长**，问「最短的合法窗口有多长」。

识别信号：`子串 substring` + `字符组成 / 覆盖 / 异位词`。

## 先看一个反例：为什么「每窗重排」必然超时

思路对、复杂度错，是这类题最典型的失败方式。

> [!warning]- 反例代码（438，逻辑正确但 TLE）
> 
> ```python
> class Solution:
>     def findAnagrams(self, s: str, p: str) -> List[int]:
>         sorted_p = ''.join(sorted(p))
>         m = len(s)
>         n = len(p)
>         ans = []
>         left = 0
> 
>         for right in range(n, m + 1):
>             if ''.join(sorted(s[left:right])) == sorted_p:   # ← 病灶
>                 ans.append(left)
>             left += 1
> 
>         return ans
> ```
> 
> **判定依据没错**：两串互为异位词，当且仅当排序后相等。窗口的滑法也没错——定长、左右同步右移。
> 
> 错的只有一处：**判定方式不可增量**。第 $k$ 个窗口和第 $k+1$ 个窗口只差一个字符，但排序结果没法从上一次 $O(1)$ 推出来，只能推倒重排。于是每个窗口都付三笔全额账单：
> 
> | 操作 | 代价 | 为什么躲不掉 |
> | --- | --- | --- |
> | `s[left:right]` | $O(n)$ | 切片是**复制**，不是视图 |
> | `sorted(...)` | $O(n\log n)$ | 排序结果无法继承 |
> | `''.join(...)` | $O(n)$ | 又造一个新字符串 |
> 
> 窗口共 $m-n+1$ 个，总时间 $O\big((m-n)\cdot n\log n\big)$。$m = n = 3\times 10^4$ 时约 $10^{10}$ 量级，必挂。

> [!tip]- 诊断信号：循环体里出现「从头扫一遍窗口」
> 
> 滑动窗口能做到 $O(n)$，靠的是**继承**：右指针加一个、左指针减一个，两次 $O(1)$ 更新就把上一个窗口的答案改成这一个窗口的答案。
> 
> 一旦在循环体里对窗口内部做了 `sorted` / `sum` / `max` / `in` 这类**从头扫一遍**的操作，继承链就断了——外层滑窗 + 内层全扫 $= O(n^2)$ 起步，等于回到暴力枚举，滑窗白滑。
> 
> 所以落笔前必须先过 [[1.2 滑动窗口]] 那条前提：**窗口状态能不能 $O(1)$ 地加进来、减出去**？
> 
> - 和、乘积、字符计数：**可以**，加减是逆运算。
> - 排序后的串：**不行**，改判定方式（排序相等 → 计数相等）。
> - 窗口内最大值：**不行**，减不掉，换 [[2.2 单调队列 滑动窗口的最大值]]。
> 
> 本篇三道题走的都是第一条路：把「排序相等」换成等价的「**计数相等**」，判定就变成可增量维护的了。

## 统一模板

> [!tip]- 核心思路：计数表 + 一个「还差几种」的标量
> 
> 直接比较两张计数表是 $O(|\Sigma|)$，虽然够用，但更通用的写法是把「窗口计数」和「目标计数」**合并成一张差值表**，再额外维护一个标量：
> 
> - 差值表的一格表示「窗口与目标在这个字符上差多少」，零就是持平。**符号取哪个方向是随意的**——本篇 438 取「目标 $-$ 窗口」（正数是缺），76 取「窗口 $-$ 目标」（负数是缺），两者互为镜像，对照表见变体二的「符号约定」。
> - 标量记录**配平 / 达标的种数**（438 记 `diff`——还有几种没配平；76 记 `ge_cnt`——已有几种达标）。
> 
> 有了这个标量，「窗口是否合法」就从 $O(|\Sigma|)$ 的表比较降成 $O(1)$ 的判零。指针每移动一步只改一格计数，顺带看这一格是否**跨过零点**来增减标量——这是本篇所有代码的公共骨架。

> [!success]- 骨架一：定长窗口的「入 → 更新 → 出」
> 
> ```python
> # 窗口长度固定为 n
> for right in range(m):
>     add(s[right])                       # ① 入：右端进一个
>     if right < n - 1:                   # ② 窗口还没填满，跳过
>         continue
>     left = right - n + 1
>     update(left)                        # ③ 更新：此时窗口恰好定长
>     remove(s[left])                     # ④ 出：左端吐一个，为下一轮腾位
> ```
> 
> - **三步顺序不能乱**：先入后出，中间那一刻窗口才是满的。
> - `if right < n - 1: continue` 是定长窗口的标志性一行——省了它，前 $n-1$ 个不满的窗口会被误判。
> 
> ```python
> # 骨架二：变长窗口求最短（对照 1.2 的最短型）
> left = 0
> for right in range(m):
>     add(s[right])                       # ① 扩张
>     while window_valid:                 # ② 合法就继续缩
>         update(left, right)             # ③ 答案在 while 内部量
>         remove(s[left]); left += 1
> ```
> 
> 求最短的答案必须在 `while` **里面**更新：一旦合法就立刻记长度，再试着缩得更短；缩到不合法才量就晚了一步。

## 典型变体

### 变体一：438. 找到字符串中所有字母异位词（定长窗口）

找出 `s` 中所有是 `p` 的字母异位词的子串，返回起始下标。

相对模板：**什么都不变**，`add` / `remove` 就是计数加一减一，`update` 就是判「计数表是否相等」。

> [!success]- 写法 A：定长窗口 + Counter 比较（首选，逐字对应骨架一）
> 
> ```python
> from collections import Counter
> 
> class Solution:
>     def findAnagrams(self, s: str, p: str) -> List[int]:
>         cnt_p = Counter(p)                       # 目标计数
>         cnt_s = Counter()                        # 窗口计数，空表起步
>         ans = []
> 
>         for right, c in enumerate(s):
>             cnt_s[c] += 1                        # ① 入
> 
>             left = right - len(p) + 1
>             if left < 0:                         # ② 窗口还没填满
>                 continue
> 
>             if cnt_s == cnt_p:                   # ③ 更新
>                 ans.append(left)
> 
>             cnt_s[s[left]] -= 1                  # ④ 出
> 
>         return ans
> ```
> 
> - 主流程：严格就是骨架一的四步，一行不多。**不要手工构造第一个窗口**——空 `Counter` 起步，前 `len(p)-1` 轮被 `continue` 挡住，窗口自己就填满了，连 `m < n` 的特判都省了。
> - 关键变量：`left = right - len(p) + 1` 是**当前窗口的起点**（不是被移出的下标），所以答案直接 `append(left)`。把「入 → 更新 → 出」写成「入 → 出 → 更新」也能对，但那时比较的是 `[left+1, right]`，答案要写成 `left + 1`，凭空多一个偏移量要记。
> - 与反例的唯一差别：判定从「重排整串」换成「两张表比较」，每轮从 $O(n\log n)$ 降到 $O(|\Sigma|)$。
> 
> `Counter` 的基本行为见 [[Python_dict]]（它是 `dict` 子类，缺键读作 0）。零值键的比较问题见易错点——**在 LeetCode 的 Python 3.10+ 上不必 `del`**。

> [!success]- 写法 B：不定长窗口 + 「无超额」不变量（$O(m)$，最短）
> 
> ```python
> from collections import Counter
> 
> class Solution:
>     def findAnagrams(self, s: str, p: str) -> List[int]:
>         cnt = Counter(p)                         # cnt[x]：还能再放几个 x
>         ans = []
> 
>         left = 0
>         for right, c in enumerate(s):
>             cnt[c] -= 1                          # ① 扩张
>             while cnt[c] < 0:                    # c 超额了，缩到不超额为止
>                 cnt[s[left]] += 1
>                 left += 1
>             if right - left + 1 == len(p):       # ② 长度够了 ⇒ 必然完全相等
>                 ans.append(left)
>         return ans
> ```
> 
> **为什么「不超额 + 长度相等」就等价于「完全相等」**：`while` 维持的不变量是**每种字母都不超过 `p` 里的数量**，即恒有 $c_x \le t_x$。若某个 $c_x < t_x$，由 $\sum c_x = \sum t_x = |p|$（长度相等）可知必存在另一个 $c_y > t_y$，与不变量矛盾。所以全部取等——这一步论证就是本写法的全部含金量。
> 
> - **判定被压成一次长度比较**，省掉了写法 A 每步 $O(|\Sigma|)$ 的表比较——**三种写法里最短的一版**，也最好背。但「最短」不等于「最快」：实测它比写法 C 慢约 2.7 倍，因为 `Counter` 的每次读写都要过一遍哈希，而写法 C 走的是数组下标。
> - 内层 `while` 不代表 $O(n^2)$：`left` 只增不减，总移动次数被 $m$ 卡死（摊还，同 [[1.2 滑动窗口]]）。
> - 这套「**超额就缩**」的骨架能原样迁到 3. 无重复字符的最长子串、424. 替换后的最长重复字符——只换「超额」的定义。

> [!success]- 写法 C：差值表 + diff 标量（纯数组版，通向 76）
> 
> ```python
> class Solution:
>     def findAnagrams(self, s: str, p: str) -> List[int]:
>         m, n = len(s), len(p)
>         if m < n:
>             return []
> 
>         cnt = [0] * 26                           # cnt[i] > 0 表示还缺 i
>         for c in p:
>             cnt[ord(c) - 97] += 1
>         diff = sum(1 for x in cnt if x)          # 未配平的字母种数
> 
>         ans = []
>         for right, ch in enumerate(s):
>             i = ord(ch) - 97
>             cnt[i] -= 1                          # ① 入
>             if cnt[i] == 0:
>                 diff -= 1                        # 刚好配平
>             elif cnt[i] == -1:
>                 diff += 1                        # 从配平变成多了一个
> 
>             left = right - n
>             if left >= 0:                        # ④ 出
>                 j = ord(s[left]) - 97
>                 cnt[j] += 1
>                 if cnt[j] == 0:
>                     diff -= 1
>                 elif cnt[j] == 1:
>                     diff += 1
> 
>             if diff == 0:                        # ③ 更新
>                 ans.append(left + 1)
>         return ans
> ```
> 
> - **为什么不用判窗口是否填满**：窗口未满时 `sum(cnt) > 0`，必有非零格，`diff` 不可能为 0——定长窗口那句 `continue` 被计数本身的性质替代了。
> - **跨零点才动标量**：只有 `cnt[i]` 变成 0（配平）或离开 0（失衡）时 `diff` 才变，其余情况标量不动。这是把 $O(|\Sigma|)$ 的比较压成 $O(1)$ 的全部秘密。
> - **最啰嗦，却也最快**：$\lvert s \rvert = 10^5$ 实测本写法 0.024 s、写法 B 0.066 s、写法 A 0.235 s——26 格数组下标完全绕开了哈希。所以选型是「白板上写 A / B，数据大或要卡常时换 C」，而不是「C 没用」。
> - 另一个留着它的理由：「**标量 + 跨零点维护**」正是变体二 76 唯一可行的路子——**写法 B 的「不超额」不变量迁不到 76**，因为 76 允许富余，`while` 收缩的触发条件不再是「超额」。先在 438 上见过这个标量，读 76 时就不用现学。

### 变体二：76. 最小覆盖子串（变长窗口，求最短）

在 `s` 中找出**包含 `t` 全部字符**（含重复次数）的最短子串。

相对变体一改了三处：

| | 438 | 76 |
| --- | --- | --- |
| 窗口长度 | 固定 `len(p)` | 可变 |
| 合法条件 | 计数**恰好相等** | 计数**够用即可**（多了不算错） |
| 答案更新 | 定长窗口的 ③ | `while` 合法时在**循环内部**量 |

「多了不算错」是 76 唯一的新意：窗口里某个字符**有富余**并不影响合法性。所以 438 那套「恰好配平」的判据在这里失效，得换成「**每种字符都已达标**」。

> [!success]- 写法 A：Counter 多重集比较（最短，但只适合讲思路）
> 
> ```python
> from collections import Counter
> 
> class Solution:
>     def minWindow(self, s: str, t: str) -> str:
>         cnt_s = Counter()                        # 窗口内各字母的出现次数
>         cnt_t = Counter(t)
> 
>         ans_left, ans_right = -1, len(s)         # 哨兵：区间长度大于任何合法解
>         left = 0
> 
>         for right, c in enumerate(s):
>             cnt_s[c] += 1                        # ① 扩张
>             while cnt_s >= cnt_t:                # ② 涵盖了，尝试缩短
>                 if right - left < ans_right - ans_left:
>                     ans_left, ans_right = left, right    # ③ 只记下标，不切片
>                 cnt_s[s[left]] -= 1
>                 left += 1
> 
>         return "" if ans_left < 0 else s[ans_left: ans_right + 1]
> ```
> 
> `cnt_s >= cnt_t` 把「涵盖」直接写成了一个**多重集包含**判断，可读性无可挑剔——但有两个代价，都不小：
> 
> - **Python 3.10 才有**。`Counter` 的 `<` `<=` `>` `>=` 是 3.10 加的多重集比较；3.9 及以前会抛 `TypeError: '>=' not supported between instances of 'Counter' and 'Counter'`。LeetCode 选 Python3 能过，本地用旧解释器验证会直接报错。
> - **每次判定都是 $O(\lvert\Sigma\rvert)$**，整体退回 $O(m\cdot\lvert\Sigma\rvert)$。实测 $\lvert s\rvert = 10^5$、`t` 含 26 种字母时，本写法 1.12 s，下面的写法 B 只要 0.025 s——**差 45 倍**，规模再大一点就是 TLE。
> 
> 结论：面试口述时拿它讲清楚「什么叫涵盖」很好，真要提交请写写法 B。

> [!success]- 写法 B：差值表 + `ge_cnt` 标量（主推，$O(m)$）
> 
> ```python
> from collections import defaultdict
> 
> class Solution:
>     def minWindow(self, s: str, t: str) -> str:
>         # defaultdict(int) 比 Counter 快：Counter.__missing__ 是 Python 层的方法
>         diff = defaultdict(int)                  # 窗口内个数 - t 内个数
>         for c in t:
>             diff[c] -= 1
>         kinds = len(diff)                        # t 中不同字母的种数（先快照！）
> 
>         ans_left, ans_right = -1, len(s)
>         ge_cnt = 0                               # 已达标（出现次数 >= t）的种数
>         left = 0
> 
>         for right, c in enumerate(s):
>             diff[c] += 1                         # ① 扩张
>             if diff[c] == 0:                     # 从「不够」变成「刚好够」
>                 ge_cnt += 1
> 
>             while ge_cnt == kinds:               # ② 每种都达标 ⇒ 合法，尝试缩短
>                 if right - left < ans_right - ans_left:
>                     ans_left, ans_right = left, right    # ③ 只记下标
> 
>                 x = s[left]
>                 if diff[x] == 0:                 # 移出前恰好持平 ⇒ 移出后就不够了
>                     ge_cnt -= 1
>                 diff[x] -= 1                     # 顺序：先判断，后减
>                 left += 1
> 
>         return "" if ans_left < 0 else s[ans_left: ans_right + 1]
> ```
> 
> - 主流程：右指针一路扩张，每当窗口合法就用左指针尽力压缩，压到不合法再放右指针走。
> - **`kinds = len(diff)` 必须在这个位置取**。`diff` 是 `defaultdict`，后面 `diff[c] += 1` 会为 `t` 之外的字符**插入新键**；`kinds` 早已快照成 `t` 的种数，所以不受影响。把这一行挪到循环之后，`kinds` 会被撑大，`ge_cnt == kinds` 永远不成立。
> - `t` 之外的字符：`diff[c]` 从 0 加到 1，跳过了 0，永远不触发 `ge_cnt` 的增减，天然被忽略。
> - 为什么用 `defaultdict` 不用 `Counter`：两者缺键都读作 0，但 `Counter.__missing__` 是 Python 层函数，`defaultdict` 的默认工厂在 C 层。实测同一份逻辑，`Counter` 版 0.066 s、`defaultdict` 版 0.025 s。

> [!tip]- 符号约定：`ge_cnt` 向上数，`less` 向下数，是同一个东西的镜像
> 
> 本篇出现了两套相反的符号，换题时最容易记岔，对照一下就不会乱：
> 
> | | 变体一 写法 C（438） | 变体二 写法 B（76） |
> | --- | --- | --- |
> | 差值表的含义 | `cnt` $=$ 目标 $-$ 窗口 | `diff` $=$ 窗口 $-$ 目标 |
> | 「还缺」表现为 | 正数 | 负数 |
> | 标量 | `diff`：还有几种没**配平** | `ge_cnt`：已有几种**达标** |
> | 合法 | `diff == 0`（数到 0） | `ge_cnt == kinds`（数到满） |
> 
> 也可以把 76 写成向下数的 `less`（初值 `len(need)`，凑够一种就减一，`less == 0` 即合法），与上面完全等价——只是 `ge_cnt == kinds` 把「所有种类都达标」这个不变量写在了脸上，读起来更直白。
> 
> 真正的分界是**判据本身**：438 要「恰好配平」，所以标量盯着 0；76 要「够用即可」，所以标量只盯「达标 / 未达标」这个二值状态，富余多少一概不管。

### 变体三：567. 字符串的排列（定长窗口，只问存在性）

判断 `s2` 是否包含 `s1` 的**某个排列**作为子串，返回布尔值。

「包含 `s1` 的排列」就是「存在一个长为 `len(s1)` 的窗口与 `s1` 互为异位词」——判定与变体一**逐字相同**。所以本题不带来任何新东西：**变体一的三种写法原样搬过来，把「记录答案」那一行换成 `return True`、末尾补 `return False`**，就是三份 567 的解。

| 变体一的写法 | 改这一行 |
| --- | --- |
| 写法 A（Counter 比较） | `ans.append(left)` → `return True` |
| 写法 B（不超额不变量） | `ans.append(left)` → `return True` |
| 写法 C（差值数组 + `diff`） | `ans.append(left + 1)` → `return True` |

只问存在性带来的唯一收益是**提前返回**。这是剪枝：最坏情况（压根不存在合法窗口）仍要扫完全串，渐进复杂度和 438 完全一样。

> [!success]- Python 实现（取写法 B，本题最短）
> 
> ```python
> from collections import Counter
> 
> class Solution:
>     def checkInclusion(self, s1: str, s2: str) -> bool:
>         cnt = Counter(s1)                    # 注意：s1 才是模式串
>         left = 0
>         for right, c in enumerate(s2):
>             cnt[c] -= 1                      # ① 扩张
>             while cnt[c] < 0:                # c 超额了，缩到不超额为止
>                 cnt[s2[left]] += 1
>                 left += 1
>             if right - left + 1 == len(s1):  # ② 长度够了 ⇒ 必然完全相等
>                 return True
>         return False
> ```
> 
> - 九行写完，白板上最好背的一版；正确性论证见变体一写法 B（不超额 + 长度相等 $\Rightarrow$ 完全相等）。
> - **要快就换写法 C**：最坏情况（$\lvert s_2 \rvert = 10^5$、无解、全程扫完）实测写法 C 0.024 s、本写法 0.062 s、写法 A 0.229 s。26 格数组下标不走哈希，这个差距和 438 上量到的完全一致。
> - **参数顺序是本题最大的坑**：签名 `checkInclusion(s1, s2)` 把短的模式串放在**第一个**，与 438 的 `findAnagrams(s, p)` 正好相反。窗口长度写成 `len(s2)`，整题语义就反了。
> - 「排列」这个词容易把人引到 [[6.3 排列型回溯]] 去——枚举 `s1` 的全排列再逐个匹配是 $O(n! \cdot m)$，必挂。看到「排列 / 异位词」要条件反射成**计数相等**，而不是真的去生成排列。

## 易错点

> [!warning]- 易错点
> 
> - **在循环里对窗口重新排序 / 求和 / 求最大值**：本篇头号错误，见开头的反例。判定必须能从上一个窗口 $O(1)$ 推出来，否则滑窗退化成暴力。
> - **`Counter` 的零值键，是否要 `del` 取决于 Python 版本**：**3.10 起** `Counter.__eq__` 被重写为「缺失计数按 0 处理」，`Counter({'a': 0}) == Counter()` 为**真**，零值键无害；**3.10 以前**它继承 `dict.__eq__`，两者**不相等**，计数减到 0 必须 `del`，否则窗口一滑过某个字符，之后所有比较全部失败。LeetCode 跑的是 3.10+，写法 A 不用 `del`；本地拿旧解释器对拍才会踩到——现象是「样例过、随机测试大面积漏答案」。
> - **定长窗口漏掉「未满不更新」**：骨架里的 `if right < n - 1: continue` 或差值写法里的 `left >= 0` 判断，少一个就会在窗口还没填满时误报答案。
> - **`left` 的含义搞混**：定长写法里 `left = right - n` 是**将被移出**的下标，新窗口起点是 `left + 1`；写成 `left` 会整体偏移一位。
> - **76 用 `if` 代替 `while` 收缩**：合法后必须**持续**缩到刚好不合法，只缩一次会漏掉更短的答案。这与 [[1.2 滑动窗口]] 里 209 的坑是同一个。
> - **76 里判断与改计数的顺序颠倒**：`diff[x] -= 1` 必须在 `if diff[x] == 0` **之后**。先减再判，那一格已经变成 -1，`ge_cnt` 永远不减，窗口会一路缩穿。
> - **`kinds` 取快照的时机**：`kinds = len(diff)` 必须紧跟在填入 `t` 之后。`defaultdict` 会为 `t` 之外的字符插入新键，晚取一步 `kinds` 就被撑大，`ge_cnt == kinds` 再也不成立。
> - **记录答案时直接切片**：`ans = s[left:right+1]` 每次复制 $O(n)$，把 $O(m)$ 的算法拖回 $O(m \cdot n)$。只存下标，最后切一次。
> - **忘了 `m < n` 的特判**：438 里 `s` 比 `p` 短时应直接返回空列表，否则第一个窗口就越界。
> - **567 把 `s1` 和 `s2` 认反**：LeetCode 的签名把**模式串放在第一个参数**，与 438 相反。窗口长度取错，整题的语义就反了。

## 复杂度

> [!summary]- 复杂度
> 
> 记 $m = |s|$、$n = |p|$ 或 $|t|$、$|\Sigma|$ 为字符集大小（小写字母为 26）。
> 
> | 解法 | 时间 | 来源 |
> | --- | --- | --- |
> | 反例（每窗重排） | $O\big((m-n)\cdot n\log n\big)$ | 每个窗口独立付「切片 + 排序 + join」全款 |
> | 438 写法 A（Counter 比较） | $O(m\cdot\lvert\Sigma\rvert)$ | 每步 $O(1)$ 增删，但每步做一次 $O(\lvert\Sigma\rvert)$ 的表比较；实测 0.235 s |
> | 438 写法 B（不超额不变量） | $O(m + \lvert\Sigma\rvert)$ | 判定退化成一次长度比较；`left` 只增不减，`while` 摊还；实测 0.066 s |
> | 438 写法 C（差值数组 + `diff`） | $O(m + \lvert\Sigma\rvert)$ | 每步只改一格计数并 $O(1)$ 维护 `diff`；数组下标不走哈希，实测 0.024 s |
> | 567 | 同 438 对应写法 | 只把记录答案换成 `return True`；提前返回是剪枝，不改渐进阶 |
> | 76 写法 A（Counter 比较） | $O(m\cdot\lvert\Sigma\rvert)$ | 每步一次多重集比较；$\lvert s\rvert = 10^5$ 实测 1.12 s，有 TLE 风险 |
> | 76 写法 B（diff + `ge_cnt`） | $O(m + n + \lvert\Sigma\rvert)$ | `left` 与 `right` 各单调走完一遍，内层 `while` 总次数被 $m$ 卡死（摊还）；同规模实测 0.025 s |
> 
> 表中「实测」为本机 CPython 3.12、$\lvert s \rvert = 10^5$ 下三轮的最好成绩，**只用来看相对量级**，绝对值随机器和数据分布浮动。同阶的写法之间差 2～3 倍，跨阶的（写法 A）差一个数量级——这正是「渐进复杂度相同也要挑写法」的理由。
> 
> 空间一律 $O(\lvert\Sigma\rvert)$ —— 只有一张计数表；返回结果（438 的下标列表、76 的子串）另计。
> 
> 内层 `while` 不代表 $O(n^2)$：`left` **只增不减、永不回退**，这与 [[1.2 滑动窗口]] 和 [[2.0 单调栈与单调队列]] 的摊还论证是同一套。

## 一句话总结

字符串滑窗的胜负手不在「怎么滑」，而在「**怎么判**」——先把不可增量的「排序后相等」换成可增量的「计数相等」，再把逐格比较换成 $O(1)$ 判据：定长题用「不超额 + 长度相等」，覆盖题用「已达标几种」的标量。

## 模板归纳

看到「**子串 + 字符组成**」，四步落笔：

1. **先问判定能不能增量**。异位词想到「排序相等」很自然，但排序不可继承——立刻换成等价的「计数相等」。这一步不做，后面写得再漂亮也是 $O(n^2\log n)$。
2. **再看窗口定长还是变长**。题目给定了另一个串的长度（438、567）就是定长，套「入 → 更新 → 出」；只说「包含 / 覆盖」而长度自由（76）就是变长，套 [[1.2 滑动窗口]] 的最短型骨架，答案在 `while` 内部量。
3. **最后看要「全部」还是「存在」**。要全部合法位置就记录后继续滑（438），只问存不存在就命中即返回（567）——这一步只影响剪枝，不影响骨架。
4. **决定合法性怎么表示**。定长题最省事的是「**不超额 + 长度相等**」（438 写法 B）；要写成标量就是恰好相等用 `diff`（还没配平的种数，数到 0），够用即可用 `ge_cnt`（已达标的种数，数到 `kinds`）——两者都只在某一格计数**跨过零点**时才改动。76 只能走标量这条路。

```python
# 定长：438 / 567（567 把 record 换成 return True）
for right in range(m):
    add(s[right])
    if right < n - 1:
        continue
    if valid():
        record(right - n + 1)
    remove(s[right - n + 1])

# 变长求最短：76
left = 0
for right in range(m):
    add(s[right])
    while valid():
        record(left, right)
        remove(s[left]); left += 1
```
