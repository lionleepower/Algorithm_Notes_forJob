# 堆：Top K、频率前 K 与对顶堆

## 解决什么问题

一句话：**要在一堆不断变化的候选里反复取极值。**

堆（优先队列）的性价比来自一个不对称性——它**只保证堆顶最小**，不保证整体有序。放弃「全序」这个用不上的信息，换来 $O(\log n)$ 的插入与弹出。

识别信号：

```text
「第 K 大 / 前 K 个 / 最小的 K 个」、「数据流中的中位数」、「每次都要拿当前最小的那个」
```

三道 Hot100 题正好对应三种用法：

| 题 | 用法 | 堆里装什么 |
| --- | --- | --- |
| 215. 第 K 个最大元素 | **定长小顶堆**筛 Top K | 目前最大的 K 个 |
| 347. 前 K 个高频元素 | 哈希计数 + 定长堆 | `(次数, 值)` |
| 295. 数据流的中位数 | **对顶堆** | 一半小的、一半大的 |

## 变体一：215. 数组中第 K 个最大元素

> [!tip]- 核心思路：求「第 K 大」用**小顶堆**——反直觉但正确
>
> 直觉会说「求最大就用大顶堆」，但那样要弹 K 次、堆要装 $n$ 个元素。正解反过来：
>
> **维护一个大小恰好为 K 的小顶堆，里面装「目前见过的最大的 K 个」。堆顶就是这 K 个里最小的，也就是当前的第 K 大。**
>
> 新元素来了，只和**堆顶**比：
> - 比堆顶大 $\to$ 它有资格进 Top K，弹掉堆顶换它进来
> - 不比堆顶大 $\to$ 它连当前第 K 大都不如，**永远不可能是答案**，直接丢
>
> 最后一句是关键——和 [[2.0 单调栈与单调队列]] 的「永久淘汰」是同一种论证：**先证明某些候选此后再无翻身机会，再把它们扔掉。**
>
> **复杂度对比**
>
> | 做法 | 时间 | 空间 | 什么时候选 |
> | --- | --- | --- | --- |
> | 排序 | $O(n\log n)$ | $O(1)$ | 兜底，能说但别只说这个 |
> | 定长小顶堆 | $O(n\log k)$ | $O(k)$ | **数据流 / $k \ll n$，面试主答** |
> | 快速选择 | 平均 $O(n)$，最坏 $O(n^2)$ | $O(1)$ | 本题最优，但要会随机选 pivot |
>
> **快速选择 Quickselect**：快排的分区只递归**答案所在的那一半**，于是 $n + n/2 + n/4 + \ldots = O(n)$。必须**随机化 pivot**，否则全相同元素或有序数组会退化到 $O(n^2)$。

> [!success]- 代码实现
>
> ```python
> import heapq
> class Solution:
>     def findKthLargest(self, nums: List[int], k: int) -> int:
>         h = []                          # 小顶堆，最多装 k 个
>         for x in nums:
>             if len(h) < k:
>                 heapq.heappush(h, x)
>             elif x > h[0]:              # 只和堆顶比，够格才换
>                 heapq.heapreplace(h, x) # = 先 pop 再 push，但只调整一次
>         return h[0]
>
>     # 一行版（面试可以先给这个再解释原理）
>     # return heapq.nlargest(k, nums)[-1]
> ```
> 当然还有一个极简的版本，直接利用sorted的性质，可以快速解决：
> ```python
> class Solution: 
> def findKthLargest(self, nums: List[int], k: int) -> int: 
> 	return sorted(nums)[len(nums) - k]
> ```
>
> **主流程**：维持堆的大小恰为 K $\to$ 与堆顶比较决定去留 $\to$ 堆顶即答案。
> **关键不变量**：任何时刻，堆里正是「已扫描元素中最大的 $\min(k, i)$ 个」。
> **易错位置**：`heappushpop` 与 `heapreplace` 顺序相反——`heapreplace` 先弹后压（要求堆非空），`heappushpop` 先压后弹。用错在 `x < h[0]` 时结果不同。

## 变体二：347. 前 K 个高频元素

> [!tip]- 核心思路：先把「频率」算出来，问题就退化成 215
>
> 两步：
> 1. `Counter(nums)` 得到 `值 -> 次数`（$O(n)$）。
> 2. 在这些 `(次数, 值)` 对上求 Top K —— 完全是 215，只是比较的键从「值本身」换成「次数」。
>
> **面试加分：桶排序做到 $O(n)$。** 次数的取值范围是 $[1, n]$，开 $n+1$ 个桶，`buckets[c]` 存所有出现 `c` 次的元素，然后从后往前收集 K 个。这是「**值域受限就别用比较排序**」的又一例，与 [[8.1 哈希实战 分组、连续序列与原地哈希]] 里的原地哈希同源。

> [!success]- 代码实现（堆 + 桶排序两版）
>
> ```python
> from collections import Counter
> import heapq
>
> class Solution:
>     def topKFrequent(self, nums: List[int], k: int) -> List[int]:
>         cnt = Counter(nums)
>         h = []                                   # (次数, 值) 的小顶堆
>         for val, c in cnt.items():
>             if len(h) < k:
>                 heapq.heappush(h, (c, val))
>             elif c > h[0][0]:
>                 heapq.heapreplace(h, (c, val))
>         return [val for c, val in h]
>
>         # 等价一行：return [v for v, _ in cnt.most_common(k)]
> ```
>
> 桶排序版（$O(n)$）：
>
> ```python
> def topKFrequent(self, nums: List[int], k: int) -> List[int]:
>     cnt = Counter(nums)
>     buckets = [[] for _ in range(len(nums) + 1)]  # 下标 = 出现次数
>     for val, c in cnt.items():
>         buckets[c].append(val)
>     ans = []
>     for c in range(len(nums), 0, -1):             # 从高频往低频收
>         ans += buckets[c]
>         if len(ans) >= k:
>             return ans[:k]
>     return ans
> ```
>
> **易错位置**：元组入堆时 Python 按**字典序**比较，`(c, val)` 在 `c` 相同时会去比 `val`——本题无所谓，但若 `val` 是不可比较对象（如自定义类）会抛 `TypeError`，见 [[c++python 堆与栈]] 的 `ListNode` 坑。

## 变体三：295. 数据流的中位数（对顶堆）

> [!tip]- 核心思路：把有序序列从中间劈开，两半各用一个堆盯住切口
>
> 中位数只关心「中间那一两个数」，两端的极值毫无用处。于是：
>
> - **`small`：大顶堆**，装较小的一半，堆顶是这一半的**最大值**
> - **`large`：小顶堆**，装较大的一半，堆顶是这一半的**最小值**
>
> 两个堆顶正好夹住中位数。
>
> **两条不变量**（每次插入后必须同时成立）
> 1. `max(small) <= min(large)`——两半没有交叉
> 2. `0 <= len(small) - len(large) <= 1`——大小差不超过 1，且规定多的那个放 `small`
>
> 于是取中位数：奇数个 $\to$ `small` 堆顶；偶数个 $\to$ 两个堆顶的平均。
>
> **怎么同时维持两条**：先把新数**无条件推进 `small`**，再把 `small` 的堆顶**倒一个给 `large`**（这一步保证不变量 1），最后如果 `large` 比 `small` 还多就倒回来一个（保证不变量 2）。
> 「**推进去、倒一次、必要时倒回来**」这三步固定不变，不要写成一堆 `if` 分类讨论——那正是本题最常见的 bug 源。
>
> **Python 没有大顶堆**：靠**存相反数**模拟。`heappush(small, -x)`，读堆顶时再取一次负号。这是 Python 写堆题的固定操作，写的时候要在心里默念「small 里全是负数」。

> [!example]- 示例推演：依次加入 `1, 2, 3`
>
> ```text
> add(1): small=[-1]  ->  倒 1 给 large: small=[]   large=[1]
>         large 更多 -> 倒回来:          small=[-1]  large=[]
>         中位数 = 1
>
> add(2): small=[-2,-1] -> 倒 2 给 large: small=[-1] large=[2]
>         大小相等，不用倒回
>         中位数 = (1 + 2) / 2 = 1.5
>
> add(3): small=[-3,-1] -> 倒 3 给 large: small=[-1] large=[2,3]
>         large 更多 -> 倒回 2:            small=[-2,-1] large=[3]
>         中位数 = 2
> ```

> [!success]- 代码实现
>
> ```python
> import heapq
>
> class MedianFinder:
>     def __init__(self):
>         self.small = []      # 大顶堆（存负数），较小的一半
>         self.large = []      # 小顶堆，较大的一半
>
>     def addNum(self, num: int) -> None:
>         heapq.heappush(self.small, -num)                      # 1. 先无条件进 small
>         heapq.heappush(self.large, -heapq.heappop(self.small)) # 2. 把 small 最大的倒给 large
>         if len(self.large) > len(self.small):                  # 3. 必要时倒回来
>             heapq.heappush(self.small, -heapq.heappop(self.large))
>
>     def findMedian(self) -> float:
>         if len(self.small) > len(self.large):
>             return -self.small[0]
>         return (-self.small[0] + self.large[0]) / 2
> ```
>
> **关键不变量**：`len(small) - len(large) ∈ {0, 1}` 且 `-small[0] <= large[0]`。
> **易错位置**：负号一共出现 5 次，漏任何一个都会得到「看起来接近但偶尔不对」的答案——写完务必用 `1,2,3,4` 手验一遍。

## 易错点

> [!warning]- 易错点
>
> **1. 求第 K 大用了大顶堆**
> 能做对（弹 K 次），但空间 $O(n)$、时间 $O(n + k\log n)$，且在数据流场景下完全不可行。面试要主动说「**求第 K 大用小顶堆，求第 K 小用大顶堆**」这句反直觉的结论。
>
> **2. Python 大顶堆忘了取负**
> 只在 `push` 时取负、`pop` 后忘了取回，是最高频的低级错误。
>
> **3. `heappushpop` 和 `heapreplace` 混用**
> `heapreplace(h, x)`：**先弹后压**，弹出的一定是旧堆顶，即使 `x` 比它小。
> `heappushpop(h, x)`：**先压后弹**，若 `x` 最小则原样返回 `x`，堆不变。
> 在「够格才换」的写法里两者都对（因为已经判过 `x > h[0]`），但省掉判断直接用时必须选 `heappushpop`。
>
> **4. 元组入堆时第二个元素不可比较**
> `(c, val)` 中 `c` 相同就会去比 `val`。`val` 是 `ListNode` 之类会抛 `TypeError`，解法是加一个唯一的序号做「防撞键」：`(c, idx, obj)`。
>
> **5. 对顶堆写成一堆分支**
> 「新数比中位数小就进 small，否则进 large，再调平衡」的分支写法会漏边界（尤其第一个数、两堆之一为空）。**用固定三步写法**。
>
> **6. `heapify` 的复杂度**
> `heapq.heapify(nums)` 是 $O(n)$ 不是 $O(n\log n)$。要一次性建堆就别写循环 `heappush`，理由见 [[c++python 堆与栈]]。
>
> **7. 忘记堆不是有序表**
> `h[0]` 是最小值，但 `h[1]` 不是第二小；想遍历有序结果必须反复 `heappop`。

## 复杂度

> [!summary]- 复杂度
>
> - **215（定长堆）**：时间 $O(n\log k)$ —— $n$ 个元素各做一次 $O(\log k)$ 的堆操作；空间 $O(k)$。快速选择平均 $O(n)$ / 空间 $O(1)$，但最坏 $O(n^2)$。
> - **347**：计数 $O(n)$ + 堆筛 $O(m\log k)$（$m$ 为不同值个数）；桶排序版 $O(n)$ 时间 $O(n)$ 空间。
> - **295**：`addNum` $O(\log n)$ —— 最多三次堆操作；`findMedian` $O(1)$ —— 只读两个堆顶；空间 $O(n)$。
>
> 对比全排序的 $O(n\log n)$：堆省下的是「给用不上的那 $n-k$ 个元素排序」这部分工作。

## 一句话总结

堆用「只保证堆顶」换来 $O(\log n)$ 的动态极值；**求第 K 大要用大小为 K 的小顶堆**，因为堆顶恰是「Top K 里的门槛」，进不来的候选此后永远进不来；而中位数问题把序列从中间劈开，让两个堆的堆顶隔着切口互相盯住。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 「第 K 大 / 前 K 个」$\to$ 大小为 K 的**反向堆**（求大用小顶，求小用大顶）
- 「数据流 / 在线，还要随时查」$\to$ 堆（排序做不到增量）
- 「中位数 / 把集合分成两半」$\to$ 对顶堆
- 「每次取当前最小的那个继续处理」$\to$ 堆（合并 K 路、任务调度）
- 「窗口定长 + 极值」$\to$ **不是堆**，去看 [[2.2 单调队列 滑动窗口的最大值]]

**落笔三步**

1. **定方向**：写下「我要的是最大，所以堆顶要放门槛，所以用小顶堆」这句话再动手。
2. **定容量**：堆里最多几个？超了弹谁？
3. **定内容**：只放值，还是放 `(键, 值)`？后者要检查第二元素**可不可比较**。
