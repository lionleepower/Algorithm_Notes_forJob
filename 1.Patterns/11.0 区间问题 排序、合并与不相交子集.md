# 区间问题：排序、合并与不相交子集

## 解决什么问题

输入是一组 `[start, end]`，问「合并后剩几段」「最少删几个才能互不重叠」「最少几支箭能扎穿全部」。

识别信号只有一条：**输入是一堆区间，答案取决于区间之间的相对位置**。

朴素做法是两两比较，$O(n^2)$。排序之后，「任意两个」的关系被压成「只和邻居的关系」，一趟扫描就够——所以这类题的骨架永远是**先排序，再线性扫**。唯一要想清楚的是：**排序键取左端点还是右端点**。

![](assets/11.0%20排序键决定题型.svg)

| 排序键 | 题型 | 扫描时维护什么 | 代表题 |
| --- | --- | --- | --- |
| **左端点**升序 | 合并 / 覆盖 | 当前正在延伸的区间 `[s, e]` | 56、57、1288 |
| **右端点**升序 | 选最多不相交 / 最少打点 | 上一个被选中区间的右端点 `end` | 435、452、会议室 |

## 统一模板

> [!tip]- 核心思路：排序把「两两比较」降成「只和一个邻居比较」
>
> **按左端点排序后的不变量**：左端点单调不减，所以新区间 `[a, b]` 若还能碰到某个已经收进答案的旧区间，那个旧区间的右端点就必然 $\ge a$，也必然 $\ge$ 它后面所有区间的左端点——那它当初就该被合并掉，不可能以独立形态留在答案里。
>
> 于是「和所有区间比」被合法地砍成「**只和最后一个比**」。
>
> **按右端点排序后的不变量**：在所有还能选的区间里，右端点最小的那个「最不挡路」。把最优解里的第一个区间换成它，剩下的选择一个都不会失效（因为它结束得更早，留给后面的空间只多不少）——这就是**交换论证 exchange argument**，贪心正确性的标准证法。

> [!success]- 模板代码：两个骨架
>
> ```python
> # 骨架 A：按左端点排序，合并
> intervals.sort(key=lambda p: p[0])
> ans = []
> for a, b in intervals:
>     if ans and a <= ans[-1][1]:          # 与最后一段相交
>         ans[-1][1] = max(ans[-1][1], b)  # 必须 max，不能直接 = b
>     else:
>         ans.append([a, b])               # 断开，开新的一段
>
> # 骨架 B：按右端点排序，贪心选不相交
> intervals.sort(key=lambda p: p[1])
> keep, end = 0, -inf
> for a, b in intervals:
>     if a >= end:                         # 与已选的不冲突 ⇒ 收下
>         keep += 1
>         end = b
> ```
>
> - 关键变量：A 里的 `ans[-1][1]` 是「当前正在延伸的右端点」，B 里的 `end` 是「已选集合中最靠右的右端点」。
> - 两个骨架都只扫一遍，代价全在排序。

## 典型变体

### 变体一：56. 合并区间

把所有重叠的区间合并，返回不重叠的区间列表。

排序之后只剩三种相对位置，而**第三种（被包含）正是必须写 `max` 的原因**：

![](assets/11.0%20合并只需比较最后一个.svg)

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def merge(self, intervals: List[List[int]]) -> List[List[int]]:
>         intervals.sort(key=lambda p: p[0])
>         ans = []
>         for a, b in intervals:
>             if ans and a <= ans[-1][1]:
>                 ans[-1][1] = max(ans[-1][1], b)
>             else:
>                 ans.append([a, b])
>         return ans
> ```
>
> - 主流程：排序 → 扫描 → 要么延长最后一段，要么另起一段。
> - 易错位置：`a <= ans[-1][1]` 的等号——`[1,4]` 与 `[4,5]` 端点接触，本题要求合并成 `[1,5]`，所以带等号。等号方向必须看题目对「接触算不算重叠」的定义。

### 变体二：57. 插入区间

给定**已排好序且互不重叠**的区间列表，插入一个新区间并保持性质。

「什么不变」：仍然是按左端点扫。「什么改变」：**输入已经有序，不需要再排序**，$O(n\log n)$ 降到 $O(n)$；扫描退化成清晰的三段。

> [!tip]- 核心思路：三段扫，不要走通用合并
>
> 以新区间 `[s, e]` 为参照，原列表天然被切成三块：
>
> 1. **完全在左边**（`intervals[i][1] < s`）：原样搬走，不可能相交。
> 2. **与新区间相交**（`intervals[i][0] <= e`）：全部吞进新区间，边吞边把 `s` 往小拉、`e` 往大推。
> 3. **完全在右边**：剩下的整段 `extend` 过去。
>
> 判断第 2 段的条件用的是**吞掉后不断更新的 `e`**，不是原始的 `e`——因为吞掉一个区间后新区间会变长，可能又够到了下一个。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
>         s, e = newInterval
>         ans, i, n = [], 0, len(intervals)
>         while i < n and intervals[i][1] < s:       # ① 左段：整段在前
>             ans.append(intervals[i])
>             i += 1
>         while i < n and intervals[i][0] <= e:      # ② 中段：相交就吞
>             s = min(s, intervals[i][0])
>             e = max(e, intervals[i][1])
>             i += 1
>         ans.append([s, e])
>         ans.extend(intervals[i:])                  # ③ 右段：整段在后
>         return ans
> ```
>
> - 易错位置：三个 `while` 的下标 `i` 全程只往前走，绝不能重置；`ans.append([s, e])` 必须在两段之间，写到最后就乱序了。

### 变体三：435. 无重叠区间 · 452. 引爆气球

两题是同一道题的两种问法，都必须**按右端点排序**。

- **435**：至少删掉几个区间，使剩下的互不重叠 $\Rightarrow$ 先算「最多能留几个」，答案是 $n -$ 留下的个数。
- **452**：最少几支箭扎穿所有气球 $\Rightarrow$ 一支箭能扎穿的正是一组两两相交的气球，箭数 $=$ 不相交组的个数。

> [!warning]- 两题唯一的差别：等号
>
> ```python
> # 435：[1,2] 与 [2,3] 不算重叠，可以都留
> if a >= end: ...
>
> # 452：气球 [1,2] 与 [2,3] 在 x = 2 处可以被同一支箭扎穿
> if a > end: ...
> ```
>
> 等号写反在这两题上都能过一半用例再挂掉。判据只有一个：**问自己「端点刚好接触时，算冲突吗」**，题面通常明说（452 原文写了「弓箭沿边界射出也可引爆」）。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
>         intervals.sort(key=lambda p: p[1])          # 按右端点
>         keep, end = 0, -inf
>         for a, b in intervals:
>             if a >= end:
>                 keep += 1
>                 end = b
>         return len(intervals) - keep
>
> class Solution2:
>     def findMinArrowShots(self, points: List[List[int]]) -> int:
>         points.sort(key=lambda p: p[1])
>         ans, end = 0, -inf
>         for a, b in points:
>             if a > end:                              # 接触也能一箭穿
>                 ans += 1
>                 end = b
>         return ans
> ```

### 变体四：扫描线 / 差分（会议室 II、1094 拼车）

问「同一时刻最多有几个区间同时活着」时，区间的**成对结构反而是累赘**——把每个区间拆成两个事件更方便：

- `(start, +1)`、`(end, -1)`，按时间排序后扫一遍，维护当前活跃数的最大值；
- 或者值域不大时直接开差分数组 `diff[start] += 1; diff[end] -= 1`，前缀和一遍取最大值。

这是区间题的第三条路：**不排区间，排端点**。完整写法与二维推广见 [[8.2 差分数组与二维前缀和]]——差分是前缀和的逆运算，扫描线则是差分在值域巨大时的稀疏版。

## 易错点

> [!warning]- 易错点
>
> **1. 排序键选错**
> 用左端点排去做 435，会先收下最长的 `[1,14]`，把后面所有区间都挡掉，得到明显偏小的答案。选键的判据：要**合并**就排左端点（保证不漏相交），要**留最多**就排右端点（保证给后面留最多空间）。
>
> **2. 合并时写成 `ans[-1][1] = b`**
> 遇到「新区间被旧区间完全包含」（如 `[1,10]` 后面来 `[2,3]`）会把已合并的区间截短。必须 `max`。
>
> **3. 等号方向**
> 「端点接触算不算重叠」由题目定义，56 和 452 算，435 不算。写之前先在草稿上试 `[1,2]` 与 `[2,3]`。
>
> **4. `end` 初值用 0**
> 题目允许负坐标（452 的 `xstart` 可以到 $-2^{31}$），初值必须是 $-\infty$（Python 写 `-inf`，需 `from math import inf`），用 0 会漏掉所有负区间。
>
> **5. `sort` 的返回值是 `None`**
> `intervals = intervals.sort(...)` 会把变量变成 `None`。列表原地排序用 `list.sort()`，需要新列表才用 `sorted()`，见 [[Python_常用内置函数]]。
>
> **6. 452 用 `b - a` 之类的表达式当排序键**
> 有人想「先扎最小的气球」，但区间大小和贪心正确性无关，只有右端点有交换论证支撑。

## 复杂度

> [!summary]- 复杂度
>
> - 时间：$O(n\log n)$ —— 排序主导，之后的扫描是 $O(n)$。57 因为输入已有序，是 $O(n)$。
> - 空间：$O(\log n)$ 辅助空间（Timsort 的栈开销）$+\ O(n)$ 返回结果；435 / 452 只返回一个整数，辅助空间 $O(\log n)$。
> - 扫描线 / 差分：排序端点同样 $O(n\log n)$；值域受限时用差分数组可以降到 $O(n + V)$。

## 一句话总结

区间题的全部智慧都在排序键上：**要合并就按左端点排（保证不漏相交），要留得多就按右端点排（保证给后面留最多空间）**；排完之后永远只需要和一个邻居比较。

## 模板归纳

**触发信号**：输入是 `List[List[int]]` 且每个元素是 `[start, end]`；问「合并 / 重叠 / 覆盖 / 最少几个 / 最多几个」。

**三步落笔**：

1. **定排序键**——问自己要的是「合并」还是「留最多」。合并 $\to$ 左端点；留最多 / 打点 $\to$ 右端点。
2. **定维护量**——合并维护 `ans[-1]`（可变的最后一段），贪心维护 `end`（上一个被选中的右端点，初值 $-\infty$）。
3. **定等号**——拿 `[1,2]` 和 `[2,3]` 试一遍题意，决定用 `<=` 还是 `<`。

**如果问的是「同一时刻的重叠数量」**，立刻改道扫描线 / 差分：拆成 `(+1, -1)` 事件，不要在区间层面纠缠。
