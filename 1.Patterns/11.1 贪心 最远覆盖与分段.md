# 贪心：最远覆盖与分段

## 解决什么问题

55 跳跃游戏、45 跳跃游戏 II、763 划分字母区间——三道题看起来毫不相干（两道跳格子、一道切字符串），但它们共用同一个骨架：

> **一边从左往右扫，一边维护「当前这一段还必须覆盖到哪里」；走到这个边界时结算一次。**

和 [[11.0 区间问题 排序、合并与不相交子集]] 的区别在于**区间不是给定的，而是边扫边算出来的**：55 / 45 的区间是 `[i, i + nums[i]]`，763 的区间是「某个字母首次到末次出现」。所以这里连排序都不需要——下标本身就是有序的。

识别信号：

```text
从左往右一趟扫 + 维护一个「最远右边界」+ 到达边界时做一件事（计数 / 切段）
```

## 统一模板

> [!tip]- 核心思路：两个变量，`far` 探路，`end` 结算
>
> | 变量 | 含义 | 什么时候变 |
> | --- | --- | --- |
> | `far` | 扫到目前为止**能摸到的最远下标** | 每一步都更新 |
> | `end` | **当前这一段的右边界** | 只在 `i == end` 时跳到 `far` |
>
> 关键是理解 `end` 的语义：它把数组切成了若干段，**第 `k` 段 = 「恰好走 k 步能到达的下标集合」**。这正是 BFS 的分层（见 [[5.4 层序遍历]]），只不过图的结构太规整，不需要真的建队列。
>
> **为什么贪心在这里一定最优**：在同一段内，你可以从任意位置起跳，而 `far` 已经取了这一段所有位置的最大值。既然「多走几步再跳」不可能跳得比 `far` 更远，那么提前跳就没有任何损失——**没有选择余地的贪心，必然最优**。

> [!success]- 模板代码
>
> ```python
> far = end = ans = 0
> for i in range(len(a) - 1):        # 注意 -1，见下方易错点
>     far = max(far, reach(i))       # reach(i) 由题目定义
>     if i == end:                   # 走到本段边界，必须开新的一段
>         ans += 1
>         end = far
> ```
>
> - `reach(i)` 是全部差异所在：45 是 `i + nums[i]`，763 是 `last[s[i]]`。
> - 结算动作也因题而异：45 是「跳跃次数 +1」，763 是「切一刀并记录长度」。

## 典型变体

### 变体一：55. 跳跃游戏（只问能否到达）

`nums[i]` 表示在下标 `i` 最多能向右跳几步，判断能否到达最后一个下标。

这是模板的**退化版**——不需要分段，只需要 `far`。

> [!tip]- 核心思路：把「能否到达」翻译成「覆盖会不会断」
>
> 从左往右扫，`far` 是当前能覆盖到的最右端。**一旦 `i > far`，说明下标 `i` 根本走不到**，它右边的更走不到，直接返回 `False`。
>
> 换个说法：这是一条不断向右生长的覆盖带，题目问的是这条带子中途会不会断。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def canJump(self, nums: List[int]) -> bool:
>         far = 0
>         for i, x in enumerate(nums):
>             if i > far:                 # 覆盖断了
>                 return False
>             far = max(far, i + x)
>         return True
> ```
>
> - 易错位置：`if i > far` 必须写在更新 `far` **之前**。写在后面就变成「用 `nums[i]` 自己的跳跃能力证明能走到 `i`」，循环论证，永远返回 `True`。
> - 另一种写法：判断 `far >= n - 1` 时提前 `return True`，效果相同。

### 变体二：45. 跳跃游戏 II（最少跳几次）

保证一定能到达终点，求最少跳跃次数。

![](assets/11.1%20最远覆盖与分层.svg)

> [!tip]- 核心思路：一次跳跃 = BFS 的一层，答案就是层数
>
> 第 0 层是 `{0}`；第 1 层是「一步能到的所有下标」，即 `[1, nums[0]]`；第 2 层是「从第 1 层任意位置再跳一步能到的、且还没被覆盖的下标」……
>
> 每一层是一段**连续区间**（因为跳跃可以少跳，所以能到 `far` 就能到 `far` 之前的一切），于是不需要队列，只要记住每层的右边界 `end`。
>
> 走到 `end` 说明本层已经扫完，`far` 也已经收集了本层所有位置的最大射程——此时 `ans += 1` 并把 `end` 推到 `far`，就完成了一次「层的切换」。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def jump(self, nums: List[int]) -> int:
>         ans = end = far = 0
>         for i in range(len(nums) - 1):     # 不遍历最后一个下标
>             far = max(far, i + nums[i])
>             if i == end:                   # 本层扫完，必须再跳一次
>                 ans += 1
>                 end = far
>         return ans
> ```
>
> - **`range(len(nums) - 1)` 是本题唯一的坑**：到达终点就不用再跳了。若写成 `range(n)`，当 `n-1` 恰好是某层右边界时会多触发一次结算，答案凭空 +1。用 `[2,3,1,1,4]` 验证：正确答案 2，写成 `range(n)` 会得到 3。
> - 关键变量：`end` 是「本层右边界」，`far` 是「下一层右边界」。两个变量各司其职，别合并。

### 变体三：763. 划分字母区间

把字符串划分成尽可能多的片段，要求**同一个字母只出现在一个片段里**，返回各片段长度。

![](assets/11.1%20划分字母区间.svg)

> [!tip]- 核心思路：`far` 换成「本段字母最后一次出现的位置」
>
> 预处理 `last[c]` = 字母 `c` 最后出现的下标。扫描时：
>
> - 每读到一个字母，本段就**被迫**延伸到 `last[c]`——因为这个字母的所有出现必须待在同一段。
> - 当 `i == end` 时，说明本段内**所有出现过的字母都已经把最后一次出现交代完了**，可以安全地切一刀。
>
> 正确性同样来自「没有选择余地」：`end` 只能被动往右推，一旦能切就必须立刻切（切晚了片段数只会更少），所以贪心必然给出最多的片段数。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def partitionLabels(self, s: str) -> List[int]:
>         last = {c: i for i, c in enumerate(s)}   # 后写覆盖先写，天然是「最后一次」
>         ans, start, end = [], 0, 0
>         for i, c in enumerate(s):
>             end = max(end, last[c])
>             if i == end:
>                 ans.append(end - start + 1)
>                 start = i + 1
>         return ans
> ```
>
> - 主流程：一遍预处理 `last`，一遍扫描切段。
> - 关键写法：`{c: i for i, c in enumerate(s)}` 中后出现的 `i` 会覆盖先出现的，正好就是「最后一次出现」，不必额外判断。
> - 与 45 的对照：`end = max(end, last[c])` 与 `far = max(far, i + nums[i])` 是同一行代码，只是「射程」的来源不同。

### 变体四：区间已经给定时（1024 视频拼接 / 1326 灌溉花园）

如果题目直接给出一堆区间 `[start, end]`，问「最少选几个能覆盖 `[0, T]`」，骨架仍然是最远覆盖，只是 `far` 要先按左端点归拢：

```python
# 先把每个左端点能到达的最远右端点存进 reach[]
reach = [0] * (T + 1)
for s, e in clips:
    if s <= T:
        reach[s] = max(reach[s], e)
# 之后完全就是 45 的模板
```

这一步「把区间转成 `reach` 数组」是本类题唯一的额外动作，转完之后代码和 45 一字不差。这也说明 [[11.0 区间问题 排序、合并与不相交子集]] 与本篇本来就是一件事：**11.0 排序后处理显式区间，本篇边扫边生成隐式区间**。

## 易错点

> [!warning]- 易错点
>
> **1. 45 的循环写成 `range(n)`**
> 多算一次跳跃。到了终点就不用跳了，必须 `range(n - 1)`。
>
> **2. 55 的 `if i > far` 写在更新 `far` 之后**
> 变成循环论证，任何输入都返回 `True`。判断必须在更新之前。
>
> **3. 把 `far` 和 `end` 合并成一个变量**
> 写成 `if i == far: ans += 1` 会在长跳跃时提前结算。两个变量的语义不同：`far` 属于下一层，`end` 属于当前层，混用必错。
>
> **4. 763 的 `last` 记成「首次出现」**
> `{c: i for i, c in enumerate(s)}` 是后覆盖前，得到的是最后一次；若写成 `setdefault` 就变成首次，答案完全错。
>
> **5. 763 忘记更新 `start`**
> 长度算成 `end + 1` 而不是 `end - start + 1`，第一段对、后面全错。
>
> **6. 试图给 55 / 45 写 DP**
> $O(n^2)$ 的 DP 能过 55 但会让 45 超时。看到「最少步数 + 每步能到一段连续区间」，第一反应就该是分层贪心而不是 DP。

## 复杂度

> [!summary]- 复杂度
>
> | 题 | 时间 | 空间 | 来源 |
> | --- | --- | --- | --- |
> | 55 | $O(n)$ | $O(1)$ | 一遍扫描，只有 `far` |
> | 45 | $O(n)$ | $O(1)$ | 一遍扫描，`far` / `end` / `ans` 三个变量 |
> | 763 | $O(n)$ | $O(\Sigma)$ | 一遍预处理 + 一遍扫描；`last` 至多 26 项，视作 $O(1)$ |
>
> 对照 DP 解法：45 的朴素 DP 是 $O(n^2)$（每个位置枚举跳多远），贪心把这一层枚举整个省掉了——省下的正是「同一层内部谁跳的其实无所谓」这个观察。

## 一句话总结

三道题只有一行代码不同：**维护「本段必须覆盖到哪里」，走到边界就结算一次**——45 结算的是跳跃次数，763 结算的是一刀切下的片段，55 连结算都不需要，只问覆盖会不会断。

## 模板归纳

**触发信号**：从左往右一趟能扫完 + 每个位置能影响到「右边一段连续区间」+ 问「最少几次 / 最多切几段 / 能不能到」。

**三步落笔**：

1. **定 `reach(i)`**——问自己「站在 `i`，本段被迫延伸到哪里」。跳跃题是 `i + nums[i]`，分段题是 `last[s[i]]`，区间题是预处理好的 `reach[i]`。
2. **定结算动作**——`i == end` 时要做什么：计数（45）、切段并记录长度（763）、什么都不做（55）。
3. **定循环右界**——目标是「到达终点」就写 `range(n - 1)`（45）；目标是「扫完整个序列」就写 `range(n)`（763、55）。

**先自问一句「有没有选择余地」**：如果每一步的最优选择是被逼出来的（`far` 已经是最大值），贪心就是对的；如果存在「现在拿了以后就拿不了」的取舍，回到 [[7.1 DP 打家劫舍]]。
