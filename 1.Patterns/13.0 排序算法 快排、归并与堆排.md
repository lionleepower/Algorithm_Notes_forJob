# 排序算法：快排、归并与堆排

## 解决什么问题

平时刷题都是 `nums.sort()` 一行带过，但秋招有两个场景绕不开手写：

1. **笔试白板**：直接要求实现快排 / 归并，或 912 排序数组这种「不许调库」的题。
2. **面试追问**：「快排最坏情况多少？」「哪个是稳定的？」「为什么 Python 用 Timsort 而 C++ 用 introsort？」——**这些问题的答案全部可以从算法结构里推出来，不需要背。**

三种 $O(n\log n)$ 比较排序其实只有两种骨架：

| 算法 | 骨架 | 干活的时机 | 稳定 | 最坏时间 | 额外空间 |
| --- | --- | --- | --- | --- | --- |
| **快速排序** | 分治 | **下行**：划分时干活，回来什么都不做 | ✗ | $O(n^2)$ | $O(\log n)$ 递归栈 |
| **归并排序** | 分治 | **上行**：下沉只算 `mid`，合并时干活 | ✓ | $O(n\log n)$ | $O(n)$ 临时数组 |
| **堆排序** | 选择 | 反复取堆顶 | ✗ | $O(n\log n)$ | $O(1)$ |

![](assets/13.0%20分治时机%20快排与归并.svg)

> [!tip]- 三条结论都是从「活在哪一层干」直接推出来的
>
> **最坏情况**：快排的递归树形状由 pivot 决定，选到最值就退化成 $n$ 层的链；归并每次都对半砍，树高恒为 $\log n$。
>
> **额外空间**：快排在原数组上交换，只花递归栈；归并的 `merge` 无法原地（两个有序段交错着往外吐，必须有落脚点），要借等长临时数组。
>
> **稳定性**：`merge` 里「相等取左边」就保住了相对顺序；快排的 `partition` 会把远处元素长距离换过来，相等元素的先后关系被打乱。
>
> 堆排序不在这张图里——它不分治，是把「选择排序每轮 $O(n)$ 找最大值」加速成 $O(\log n)$ 的结果。

## 典型变体

### 变体一：快速排序（912 排序数组）

![](assets/13.0%20快排划分与随机化.svg)

> [!tip]- 核心思路：partition 的循环不变量，以及两个不能省的优化
>
> `partition` 做的事：选一个 `pivot`，把数组重排成「左边都 $<$ pivot、右边都 $>$ pivot」，返回分界点。**pivot 一旦归位就永远不动**，这是快排不需要「合并」的原因。
>
> **优化一：随机化 pivot（必须）**
> 固定取首元素时，有序数组每次只切掉 1 个元素，递归深度变成 $n$，$O(n^2)$ 且可能爆栈。随机化把「最坏输入」变成「最坏运气」，期望仍是 $O(n\log n)$。
>
> **优化二：三路划分（处理大量重复元素）**
> 把数组分成 `x < pivot` / `x == pivot` / `x > pivot` 三段，中间那段整体跳过。全等数组从 $O(n^2)$ 降到 $O(n)$。这就是荷兰国旗问题（75 颜色分类）的推广。
>
> LeetCode 912 的测试数据里同时有**有序数组**和**全等数组**，两个优化都不做会直接超时——面试官问「你的快排怎么防卡」时，答案就是这两条。

> [!success]- 代码实现（三路划分 + 随机 pivot）
>
> ```python
> import random
>
> class Solution:
>     def sortArray(self, nums: List[int]) -> List[int]:
>         def quick_sort(l: int, r: int) -> None:
>             if l >= r:
>                 return
>             pivot = nums[random.randint(l, r)]      # 随机化，防有序数据
>             lt, i, gt = l, l, r                     # [l,lt) < pivot, [lt,i) == pivot, (gt,r] > pivot
>             while i <= gt:
>                 if nums[i] < pivot:
>                     nums[i], nums[lt] = nums[lt], nums[i]
>                     lt += 1
>                     i += 1
>                 elif nums[i] > pivot:
>                     nums[i], nums[gt] = nums[gt], nums[i]
>                     gt -= 1                          # i 不前进！换过来的元素还没看过
>                 else:
>                     i += 1
>             quick_sort(l, lt - 1)
>             quick_sort(gt + 1, r)                    # == pivot 的整段跳过
>
>         quick_sort(0, len(nums) - 1)
>         return nums
> ```
>
> - 关键不变量：`[l, lt)` 小于、`[lt, i)` 等于、`(gt, r]` 大于，`[i, gt]` 未处理。
> - **最易写错**：`nums[i] > pivot` 分支里 `i` 不能前进。从右边换过来的元素还没被检查过，`i += 1` 等于直接跳过它。
> - `pivot` 存的是**值**不是下标，因为随机位置的元素在交换中会移动。

> [!example]- 快速选择：215 数组中的第 K 个最大元素
>
> 排序是 $O(n\log n)$，但只要第 K 大的话，**每次 partition 后只递归有答案的那一半**，期望降到 $O(n)$：
>
> ```python
> def quick_select(l: int, r: int, k: int) -> int:      # k 是目标下标（0-indexed）
>     pivot = nums[random.randint(l, r)]
>     lt, i, gt = l, l, r
>     while i <= gt:
>         ...                                          # 同上三路划分
>     if k < lt:
>         return quick_select(l, lt - 1, k)
>     if k > gt:
>         return quick_select(gt + 1, r, k)
>     return pivot                                     # 落在等于区，直接就是答案
> ```
>
> 期望复杂度的直觉：每轮问题规模期望减半，$n + n/2 + n/4 + \cdots = 2n$。
>
> 面试对照：215 的三种解法——**排序** $O(n\log n)$、**小顶堆** $O(n\log k)$（见 [[10.0 堆 TopK与对顶堆]]）、**快速选择** 期望 $O(n)$。数据流场景只能用堆，一次性静态数组用快速选择最快。

### 变体二：归并排序（+ 逆序对）

![](assets/13.0%20归并统计逆序对.svg)

> [!tip]- 核心思路：merge 是原子操作，稳定性和计数都藏在一个等号里
>
> `merge` 的前提是**两半各自已经有序**。此时两个指针各扫一遍，谁小谁出队。
>
> **稳定性来自 `a[i] <= a[j]` 的等号**：相等时让左半（原数组里靠前的）先出队。写成 `<` 就不稳定了。
>
> **逆序对是免费赠品**：当右半的 `a[j]` 抢先出队时，左半剩下的 `a[i..mid]` 全都排在它前面且全都比它大，一次性贡献 `mid - i + 1` 个逆序对——**因为左半有序，所以能整段计数而不是逐个数**，这正是省掉一层循环的地方。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def sortArray(self, nums: List[int]) -> List[int]:
>         tmp = [0] * len(nums)                        # 复用同一个临时数组，别在递归里反复开
>
>         def merge_sort(l: int, r: int) -> None:
>             if l >= r:
>                 return
>             mid = (l + r) // 2
>             merge_sort(l, mid)
>             merge_sort(mid + 1, r)
>             i, j, k = l, mid + 1, l
>             while i <= mid and j <= r:
>                 if nums[i] <= nums[j]:               # 等号 = 稳定
>                     tmp[k] = nums[i]; i += 1
>                 else:
>                     tmp[k] = nums[j]; j += 1
>                     # cnt += mid - i + 1             # 统计逆序对就加这一行
>                 k += 1
>             while i <= mid:
>                 tmp[k] = nums[i]; i += 1; k += 1
>             while j <= r:
>                 tmp[k] = nums[j]; j += 1; k += 1
>             nums[l:r + 1] = tmp[l:r + 1]             # 写回原数组
>
>         merge_sort(0, len(nums) - 1)
>         return nums
> ```
>
> - 易错位置：`tmp` 必须在外层开一次并复用；每层递归里 `tmp = [0]*n` 会让空间和常数都爆掉。
> - 两个收尾 `while` 不能省：跳出主循环时必有一半还剩东西。
> - 与 [[4.4 链表归并 排序链表与合并K个]] 对照：链表版的 `merge` 靠哨兵 + 尾插，**不需要临时数组**——这是归并排序在链表上空间 $O(1)$ 而在数组上 $O(n)$ 的原因，面试常问。

### 变体三：堆排序

> [!tip]- 核心思路：选择排序的加速版
>
> 选择排序每轮扫一遍找最大值，$O(n)$ × $n$ 轮 $= O(n^2)$。把「找最大值」交给大顶堆，每轮 $O(\log n)$，总共 $O(n\log n)$。
>
> 两个阶段：
>
> 1. **建堆**：从最后一个非叶节点 `n//2 - 1` 倒着 `sift_down`。**建堆是 $O(n)$ 不是 $O(n\log n)$**——因为绝大多数节点在底层，下沉距离很短，$\sum_{h} \frac{n}{2^{h+1}} \cdot h$ 收敛到 $O(n)$。这是面试爱问的一个「反直觉复杂度」。
> 2. **排序**：反复把堆顶（最大值）与末尾交换，堆大小减一，再 `sift_down` 修复。
>
> **升序排序要用大顶堆**：堆顶最大，换到数组末尾，天然从后往前填。

> [!success]- 代码实现
>
> ```python
> def heap_sort(nums: List[int]) -> None:
>     n = len(nums)
>
>     def sift_down(i: int, size: int) -> None:
>         while True:
>             largest = i
>             l, r = 2 * i + 1, 2 * i + 2
>             if l < size and nums[l] > nums[largest]:
>                 largest = l
>             if r < size and nums[r] > nums[largest]:
>                 largest = r
>             if largest == i:
>                 break
>             nums[i], nums[largest] = nums[largest], nums[i]
>             i = largest
>
>     for i in range(n // 2 - 1, -1, -1):      # 建堆 O(n)
>         sift_down(i, n)
>     for end in range(n - 1, 0, -1):          # 排序 O(n log n)
>         nums[0], nums[end] = nums[end], nums[0]
>         sift_down(0, end)
> ```
>
> - 关键：`sift_down` 多带一个 `size` 参数，排序阶段用它把已排好的尾部排除在堆外。
> - 下标关系：父 `i` 的左右孩子是 `2i+1` / `2i+2`，孩子 `j` 的父是 `(j-1)//2`。配套见 [[c++python 堆与栈]] 与 [[10.0 堆 TopK与对顶堆]]。

### 变体四：非比较排序与 $\Omega(n\log n)$ 下界

> [!tip]- 为什么 $O(n)$ 排序不违反下界
>
> **比较排序的下界**：$n$ 个元素有 $n!$ 种排列，每次比较最多把候选集砍一半，所以至少需要 $\log_2(n!) = \Theta(n\log n)$ 次比较。这是**信息论下界**，任何基于比较的算法都逃不掉。
>
> 计数排序 / 基数排序 / 桶排序**不做元素之间的比较**，而是直接用值当下标，所以不受这个下界约束：
>
> | 算法 | 复杂度 | 适用 | 稳定 |
> | --- | --- | --- | --- |
> | 计数排序 | $O(n + k)$ | 整数且值域 $k$ 不大 | 可以（倒序填回时） |
> | 基数排序 | $O(d(n+k))$ | 定长整数 / 字符串，按位分轮 | 是（必须，否则前几轮白做） |
> | 桶排序 | 平均 $O(n)$ | 数据均匀分布 | 取决于桶内排序 |
>
> 这条思路在刷题里其实见过——[[8.1 哈希实战 分组、连续序列与原地哈希]] 里 41 的**原地哈希**（值域与下标一一对应）本质就是计数排序的思想。

## 易错点

> [!warning]- 易错点
>
> **1. 快排不随机化**
> 有序数组直接 $O(n^2)$ 超时。912 的数据专门卡这个。
>
> **2. 三路划分里 `> pivot` 分支让 `i` 前进**
> 从右边换过来的元素还没检查过，跳过它会漏排。
>
> **3. `pivot` 存下标而不是值**
> 随机选中的元素在交换中会移动，存下标会指向错误元素。存值。
>
> **4. 归并在每层递归里新开临时数组**
> 空间从 $O(n)$ 变成 $O(n\log n)$，常数也爆炸。外层开一次复用。
>
> **5. 归并的比较写成 `<` 而不是 `<=`**
> 排序结果仍然正确，但**失去稳定性**；如果题目要统计逆序对，`cnt` 也会算错（相等元素不构成逆序对）。
>
> **6. 堆排序用小顶堆做升序**
> 会得到降序。升序要大顶堆，因为交换到末尾的是当前最大值。
>
> **7. 建堆时正序 `sift_down`**
> 必须从 `n//2 - 1` **倒序**，保证处理某个节点时它的两棵子树已经是合法堆。正序做需要 `sift_up`，复杂度退化到 $O(n\log n)$。
>
> **8. Python 递归深度**
> 快排最坏 $n$ 层会触发 `RecursionError`（默认上限 1000）。这也是必须随机化的实际理由之一。

## 复杂度

> [!summary]- 复杂度与稳定性总表（面试直接背这张）
>
> | 算法 | 平均 | 最坏 | 最好 | 空间 | 稳定 | 备注 |
> | --- | --- | --- | --- | --- | --- | --- |
> | 快速排序 | $O(n\log n)$ | $O(n^2)$ | $O(n\log n)$ | $O(\log n)$ | ✗ | 常数最小，实战最快 |
> | 归并排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✓ | 链表上空间 $O(1)$ |
> | 堆排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ✗ | 唯一的原地 $O(n\log n)$ |
> | 插入排序 | $O(n^2)$ | $O(n^2)$ | $O(n)$ | $O(1)$ | ✓ | 近乎有序时极快 |
> | 计数排序 | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | $O(k)$ | ✓ | 非比较，值域受限 |
>
> **快速选择**（215）：期望 $O(n)$，最坏 $O(n^2)$（同样靠随机化规避）。

> [!tip]- 面试追问：各语言的标准库用了什么
>
> | 语言 | 实现 | 为什么 |
> | --- | --- | --- |
> | **Python** `list.sort` / `sorted` | **Timsort**（归并 + 二分插入） | 语言保证**稳定**；对真实世界里「部分有序」的数据识别 run 后合并，接近 $O(n)$ |
> | **Java** `Arrays.sort(int[])` | 双轴快排 Dual-Pivot Quicksort | 基本类型无所谓稳定性，追求速度和原地 |
> | **Java** `Arrays.sort(Object[])` | TimSort | 对象排序**必须稳定**（多关键字排序依赖它） |
> | **C++** `std::sort` | introsort（快排 + 递归过深转堆排 + 小段插入排序） | 平均快，且用堆排兜底把最坏拉回 $O(n\log n)$ |
>
> 一句话答法：**要稳定就归并系（Timsort），不要稳定就快排系，怕最坏就混入堆排（introsort）。**

## 一句话总结

快排和归并是同一棵递归树，**快排在下行时干活（先分后治）、归并在上行时干活（先治后分）**；稳定性、空间、最坏情况这三个面试必问项，全部是这个差别的直接推论。

## 模板归纳

**触发信号**：题目禁用内置排序；或者要求「$O(n)$ 找第 K 大」；或者要统计「有多少对 $(i, j)$ 满足 $i < j$ 且 $a_i > a_j$」这类**跨越左右两半才产生的量**。

**选型三问**：

1. **要稳定吗？** 要 $\to$ 归并；不要 $\to$ 快排（更快、空间更省）。
2. **有额外空间吗？** 没有 $\to$ 堆排（唯一原地的 $O(n\log n)$）。
3. **只要第 K 个吗？** 是 $\to$ 快速选择（期望 $O(n)$），别整个排完。

**看到「跨两半的统计量」就想归并**：逆序对、翻转对、右侧更小元素个数——这类题的通用套路是「归并排序 + 在 merge 的分支里累加」，因为 merge 那一刻两边都已有序，可以整段计数。

**手写时的固定动作**：快排先写 `random.randint` 那一行，归并先在外层开好 `tmp`。这两行是防超时和防爆空间的保险，写在最前面就不会忘。
