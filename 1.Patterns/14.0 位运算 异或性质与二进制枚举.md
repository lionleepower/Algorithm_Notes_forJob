# 位运算：异或性质与二进制枚举

## 解决什么问题

位运算在秋招里有两个固定出场位置：

1. **把 $O(n)$ 空间的哈希表压成 $O(1)$**——「只出现一次的数字」系列（136 / 137 / 260）。
2. **把「选或不选」的集合压成一个整数**——子集枚举、状压 DP。

识别信号：

```text
「恰好出现一次 / 成对出现 / 出现三次」+ 要求 O(1) 空间   →  异或或按位计数
「枚举所有子集」+ n ≤ 20 左右                            →  二进制枚举
「判断 2 的幂 / 统计 1 的个数 / 取最低位」                →  恒等式工具箱
```

## 工具箱

![](assets/14.0%20位运算工具箱.svg)

> [!tip]- 三条异或性质，是「只出现一次」系列的全部理论
>
> $$a \oplus a = 0, \qquad a \oplus 0 = a, \qquad \text{可交换、可结合}$$
>
> 推论：**一堆数全部异或起来，成对出现的自动抵消，与顺序无关**。所以不需要排序、不需要哈希表，扫一遍即可。
>
> 另一个视角：异或就是**不进位的二进制加法**（按位模 2 加）。看到「模 2」就该想到它。

> [!success]- 高频写法速查
>
> ```python
> x & 1                       # 最低位（判奇偶）
> x >> 1                      # 除以 2（对负数是算术右移）
> x >> i & 1                  # 取第 i 位
> x |  (1 << i)               # 第 i 位置 1
> x & ~(1 << i)               # 第 i 位清 0
> x ^  (1 << i)               # 第 i 位翻转
> x & (x - 1)                 # 去掉最低位的 1  → Brian Kernighan 数 1 的个数
> x & (-x)                    # 只留最低位的 1  → lowbit
> n > 0 and n & (n - 1) == 0  # 判断是不是 2 的幂
> ```
>
> **优先级是最大的坑**：Python 里 `&` `|` `^` 的优先级**比比较运算符还低**。
> `if x >> i & 1 == 1` 会被解析成 `x >> i & (1 == 1)`，静默给出错误结果。
> 保险写法：**任何位运算表达式参与比较时，一律加括号** —— `if (x >> i & 1) == 1`。

## 典型变体

### 变体一：只出现一次的数字（136 → 260 → 137）

三题是同一条主线上的三级台阶。136 已在 [[8.1 哈希实战 分组、连续序列与原地哈希]] 出现过，这里接着往下走。

**136**（其余出现两次）：全部异或即答案，一行。
```python
class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        return reduce(xor, nums)
```
或者是：
```python
class Solution:
    def singleNumber(self, nums: List[int]) -> List[int]:
        x = 0
        for num in nums:  # 1. 遍历 nums 执行异或运算
            x ^= num      
        return x;         # 2. 返回出现一次的数字 x
```

**260**（有两个只出现一次，其余两次）：全部异或只剩 `a ^ b`，难点是怎么把两个数拆开。

![](assets/14.0%20异或分组%20136到260.svg)

> [!tip]- 核心思路：异或值里的任何一个 1，都是「a 和 b 在这一位不同」的证据
>
> 既然 `a ^ b != 0`，它至少有一个 1。取出其中任意一位（用 `lowbit` 只是因为一行能写完），按这一位把所有数分成两组：
>
> - **`a` 和 `b` 必然被分到不同组**——它们在这一位不同。
> - **成对的数必然进同一组**——两个相同的数每一位都相同，继续互相抵消。
>
> 于是每组都退化成 136，各自异或即可。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def singleNumber(self, nums: List[int]) -> List[int]:
>         xor_all = reduce(xor, nums)          # from functools import reduce; from operator import xor
>         low = xor_all & -xor_all             # 取任意一个不同位
>         a = 0
>         for x in nums:
>             if x & low:                      # 只异或该位为 1 的那一组
>                 a ^= x
>         return [a, xor_all ^ a]              # 另一个由整体异或反解
> ```
>
> - 关键：第二个数不用再扫一遍，`xor_all ^ a` 直接得到。
> - 时间 $O(n)$，空间 $O(1)$，两遍遍历。

**137**（其余出现**三次**）：异或失效了——三个相同的数异或起来还剩一个。

> [!tip]- 核心思路：模 2 换成模 3，就得逐位统计
>
> 异或本质是「按位模 2 加」。出现三次时要的是**按位模 3**，没有现成运算符，只能手动统计：
>
> 对每一位 `i`，把所有数的第 `i` 位加起来，`% 3` 的结果就是答案在这一位的值——因为出现三次的数贡献 0 或 3，模 3 后消失。

> [!success]- 代码实现（逐位统计，最好懂）
>
> ```python
> class Solution:
>     def singleNumber(self, nums: List[int]) -> int:
>         ans = 0
>         for i in range(32):
>             cnt = sum(x >> i & 1 for x in nums) % 3
>             if cnt:
>                 ans |= 1 << i
>         # Python 整数没有位宽，负数要手动还原补码
>         return ans - (1 << 32) if ans >= (1 << 31) else ans
> ```
>
> - **Python 特有的坑**：整数是无限位宽的，`-3` 的二进制不是 32 位补码而是「无穷多个 1」。所以固定扫 32 位之后，若最高位（第 31 位）是 1，说明原数是负数，要减去 $2^{32}$ 还原。C++ / Java 里没这个问题。
> - 进阶写法是两个状态变量 `ones` / `twos` 的数字电路解法，面试可以提一句「用两个变量模拟三进制状态机」，但**逐位统计更好讲清楚**，优先写这个。

### 变体二：数 1 的个数（191 / 338）

**191** 位1的个数：`while x: x &= x - 1; cnt += 1`。循环次数等于 1 的个数，比逐位扫 32 次更快。

**338** 比特位计数：要求 $O(n)$ 求出 `0..n` 每个数的 1 的个数——**这是一道披着位运算皮的 DP**：

> [!success]- 两种递推，任选其一
>
> ```python
> # 写法 A：最低位分解，f[i] = f[i >> 1] + (i & 1)
> f = [0] * (n + 1)
> for i in range(1, n + 1):
>     f[i] = f[i >> 1] + (i & 1)
>
> # 写法 B：最高位分解，f[i] = f[i & (i - 1)] + 1
> f = [0] * (n + 1)
> for i in range(1, n + 1):
>     f[i] = f[i & (i - 1)] + 1
> ```
>
> 两种写法的共同点：**子问题的值一定比 `i` 小，所以正序递推时已经算好**。这正是 [[7.0 DP]] 里「无后效性」的要求在位运算上的体现。

### 变体三：二进制枚举子集（78 的迭代解法）

> [!tip]- 核心思路：一个 n 位整数就是一个「选或不选」的向量
>
> 集合 `{0, 1, ..., n-1}` 的子集与 `[0, 2^n)` 的整数一一对应：**第 `i` 位为 1 表示选了第 `i` 个元素**。于是「枚举所有子集」变成「从 0 数到 $2^n-1$」。
>
> ```python
> for mask in range(1 << n):
>     sub = [nums[i] for i in range(n) if mask >> i & 1]
>     ans.append(sub)
> ```
>
> 和 [[6.1 子集型回溯]] 的对照：回溯是**显式递归 + 状态恢复**，二进制枚举是**把递归的选择路径直接编码成整数**。前者更通用（能剪枝、能处理去重），后者更短且没有递归开销，但只适用于 $n \le 20$ 左右（$2^{20} \approx 10^6$）。

> [!example]- 进阶：枚举一个 mask 的所有子集
>
> 状压 DP 的入场券，必须会背：
>
> ```python
> s = mask
> while s:
>     ...            # 处理子集 s
>     s = (s - 1) & mask
> # 循环结束后还要单独处理 s = 0（空集）
> ```
>
> 为什么 `(s - 1) & mask` 能不重不漏地走遍所有子集：`s - 1` 借位后，`& mask` 把 mask 之外的位清掉，效果等价于「在 mask 的那些位上做减一」，于是按降序枚举了 mask 的全部子集。
>
> 所有 mask 的所有子集总数是 $3^n$ 而不是 $4^n$——每一位有「都不选 / 只在 mask 里 / 都在」三种状态。这是状压 DP 复杂度分析的常见考点。

## 易错点

> [!warning]- 易错点
>
> **1. 运算符优先级**
> Python 里 `&` `^` `|` 的优先级**低于比较运算符**（`x == y`、`x < y`）。`x & 1 == 1` 等价于 `x & (1 == 1)`。**位运算参与比较时一律加括号。**
>
> **2. Python 整数没有位宽**
> 137 这类需要「固定 32 位」的题，负数必须手动还原补码：`ans - (1 << 32) if ans >= (1 << 31) else ans`。`~x` 在 Python 里等于 `-x - 1`，不是「32 位取反」。
>
> **3. 负数右移**
> Python 的 `>>` 是算术右移，`-1 >> 1` 仍是 `-1`，会死循环。处理负数前先转成无符号表示。
>
> **4. 260 只取一个 1 就够**
> 有人想「把所有不同位都用上」，没必要——任取一位就能把 a、b 分开，多取反而错。
>
> **5. 二进制枚举越界**
> `1 << n` 在 $n > 30$ 左右会让循环次数爆炸。先看数据范围，$n \le 20$ 才能用。
>
> **6. 枚举子集漏掉空集**
> `while s: ... ; s = (s - 1) & mask` 的出口条件是 `s == 0`，空集不会进循环体，需要单独处理。

## 复杂度

> [!summary]- 复杂度
>
> | 题 | 时间 | 空间 | 来源 |
> | --- | --- | --- | --- |
> | 136 / 268 | $O(n)$ | $O(1)$ | 一遍异或 |
> | 260 | $O(n)$ | $O(1)$ | 两遍遍历 |
> | 137 | $O(32n)$ 即 $O(n)$ | $O(1)$ | 32 位 × 每位扫一遍 |
> | 191 | $O(\text{popcount})$ | $O(1)$ | `x &= x-1` 循环次数 = 1 的个数 |
> | 338 | $O(n)$ | $O(n)$ | 每个数 $O(1)$ 递推 |
> | 78 二进制枚举 | $O(2^n \cdot n)$ | $O(1)$ 辅助 | $2^n$ 个 mask，每个拆 $n$ 位 |
> | 枚举所有 mask 的子集 | $O(3^n)$ | — | 每位三种状态 |
>
> 位运算的价值几乎总是在**空间**上：把 $O(n)$ 的哈希表压成 $O(1)$，把 $O(2^n)$ 的集合压成一个整数。

## 一句话总结

异或是**不进位加法**，所以「成对出现」自动消失；`x & (x-1)` 清最低位的 1、`x & (-x)` 取最低位的 1，这两条恒等式加上「整数即集合」的视角，覆盖了秋招里九成的位运算题。

## 模板归纳

**触发信号**：

- 「其余元素出现两次 / 三次」+ 要求 $O(1)$ 空间 $\to$ 异或（两次）或按位模 3（三次）
- 「枚举所有子集」+ $n \le 20$ $\to$ 二进制枚举
- 「统计 1 的个数 / 判 2 的幂 / 取最低位」$\to$ 恒等式工具箱

**三步落笔**：

1. **先判断能不能用异或**——只有「成对抵消」才行。出现三次、四次都要改成按位计数。
2. **需要区分两个答案时，找一个「它们不同的位」**——`lowbit(xor_all)` 是最省事的取法，分组后各自退化成 136。
3. **写完检查括号**——凡是位运算参与比较，把整个表达式括起来。这一条能省掉最难查的一类 bug。

**Python 专属检查**：涉及负数或固定位宽时，先想清楚「Python 整数是无限位」这件事会不会咬人；需要 32 位语义就显式截断和还原。
