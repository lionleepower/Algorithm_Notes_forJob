# 字符串：KMP 匹配与回文中心扩展

## 解决什么问题

字符串题在秋招里分两大类，这两类恰好共用一个思想内核：

| 类型 | 代表题 | 手法 |
| --- | --- | --- |
| **匹配**：在文本里找模式串 | 28 找出字符串中第一个匹配项、459 重复的子字符串 | **KMP**：失配时利用「已经比过的部分」跳过无效对齐 |
| **回文**：找最长 / 计数回文子串 | 5 最长回文子串、647 回文子串 | **中心扩展**：以每个中心为起点向两边扩 |

内核是同一句话：**别把已经获得的信息扔掉再重算**。暴力匹配失配后把文本指针退回去重来，暴力找回文对每个区间重新验证——两者浪费的是同一样东西。

> [!warning]- 先澄清一个容易走错的岔路口
>
> [[7.6 区间DP 最长回文子序列]] 讲的是 **516 最长回文子序列**（可以不连续）。本篇的 **5 最长回文子串**要求**连续**，是完全不同的题：
>
> - **子序列**（516）：区间 DP，`dfs(i, j)` 表示 `s[i..j]` 内的最长回文子序列长度，$O(n^2)$ 时间 + $O(n^2)$ 空间。
> - **子串**（5 / 647）：中心扩展，$O(n^2)$ 时间 + $O(1)$ 空间，代码短得多。
>
> 看到「回文」先分清子串还是子序列，这是选错解法的头号原因。

## 典型变体

### 变体一：5. 最长回文子串 · 647. 回文子串（中心扩展）

![](assets/15.0%20回文中心扩展%202n-1个中心.svg)

> [!tip]- 核心思路：枚举中心，而不是枚举区间
>
> 暴力是枚举所有 $O(n^2)$ 个区间，再花 $O(n)$ 验证，总共 $O(n^3)$。
>
> 换个角度：**每个回文串都由它的中心唯一决定**。所以枚举中心（只有 $2n-1$ 个），从中心往两边同时扩，一路相等就继续——扩不动为止就是以该中心为轴的最长回文。总共 $O(n^2)$，而且**空间是 $O(1)$**。
>
> **为什么是 $2n-1$ 个中心而不是 $n$ 个**：偶数长度回文的对称轴落在两个字符**之间**。`"cbbd"` 的答案 `"bb"` 的中心就在两个 `b` 的缝隙里；只枚举字符中心会漏掉全部偶数长度的回文。

> [!success]- 代码实现（一个循环覆盖两类中心）
>
> ```python
> class Solution:
>     def longestPalindrome(self, s: str) -> str:
>         n = len(s)
>         start, length = 0, 1
>         for i in range(2 * n - 1):
>             l, r = i // 2, i // 2 + i % 2     # i 偶数 → l==r；i 奇数 → r==l+1
>             while l >= 0 and r < n and s[l] == s[r]:
>                 l -= 1
>                 r += 1
>             if r - l - 1 > length:            # 退出时两端各多走一步
>                 start, length = l + 1, r - l - 1
>         return s[start:start + length]
> ```
>
> - 关键变量：`l, r = i // 2, i // 2 + i % 2` 用一个整数同时表示两类中心，省掉写两遍循环。
> - **最易写错**：退出 `while` 时 `l` 和 `r` 已经各自越过边界，真正的回文是 `s[l+1 : r]`，长度是 `r - l - 1`。写成 `r - l + 1` 是本题第一高频错误。
> - **647 回文子串**（统计个数）：把 `if` 换成「每成功扩一次就 `ans += 1`」，因为每扩一次就多确认一个回文子串。

> [!example]- 面试可以提一句：Manacher 算法
>
> 在字符间插入分隔符 `#` 把所有回文统一成奇数长度，再用「已知的最长回文右边界」复用对称位置的信息，把 $O(n^2)$ 降到 $O(n)$。
>
> **秋招不需要手写**——面试里能说清「插 `#` 统一奇偶 + 借助对称性复用」这两点即可。真要写代码，中心扩展的 $O(n^2)$ 在 $n \le 1000$ 的题目里完全够用。

### 变体二：28. 找出字符串中第一个匹配项的下标（KMP）

![](assets/15.0%20KMP%20next数组与跳转.svg)

> [!tip]- 核心思路：失配时不回退文本指针，让模式串滑到自己的最长相等前后缀
>
> **暴力错在哪**：失配后把文本指针 `i` 退回起点 +1 重来，前面比过的全白费，最坏 $O(nm)$。
>
> **KMP 的观察**：失配时，模式串已匹配的那一段是**已知的**。如果这一段的「后缀」和模式串的「前缀」有一部分相同，那么把模式串直接滑到让这段前缀对齐这段后缀的位置，**前面那几个字符保证已经匹配**，不必重比。
>
> 于是定义 `nxt[i]` = `p[0..i]` 的**最长相等真前后缀**长度（真 = 不能是整个串自己）。失配在 `j` 时，令 `j = nxt[j-1]` 继续比，`i` 全程只前进。
>
> **中间被跳过的对齐位置为什么一定失败**：它们要求一个比 `nxt[j-1]` 更长的相等前后缀，而 `nxt` 取的已经是最长值，不存在更长的。
>
> **求 `nxt` 数组本身就是「模式串和自己做一次 KMP 匹配」**——这是全篇最妙的一步，也是最难第一次想到的一步。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def strStr(self, haystack: str, needle: str) -> int:
>         n, m = len(haystack), len(needle)
>         if m == 0:
>             return 0
>
>         # ① 构建 nxt：模式串自己和自己匹配
>         nxt = [0] * m
>         j = 0
>         for i in range(1, m):                     # 注意 i 从 1 开始
>             while j and needle[i] != needle[j]:
>                 j = nxt[j - 1]                    # 回退到更短的相等前后缀
>             if needle[i] == needle[j]:
>                 j += 1
>             nxt[i] = j
>
>         # ② 匹配：i 永不回退
>         j = 0
>         for i in range(n):
>             while j and haystack[i] != needle[j]:
>                 j = nxt[j - 1]
>             if haystack[i] == needle[j]:
>                 j += 1
>             if j == m:
>                 return i - m + 1
>         return -1
> ```
>
> - **两段结构完全一样**，只有「和谁比」不同。记住这一点就不用分别背两段代码。
> - 易错位置：构建 `nxt` 时 `i` 必须从 1 开始（`nxt[0]` 恒为 0，真前后缀不能是自己）；回退写 `j = nxt[j-1]` 而不是 `nxt[j]`。
> - `while` 不能写成 `if`：一次回退后可能还是不匹配，要一直退到 0 或匹配为止。

> [!example]- 459. 重复的子字符串：next 数组的免费推论
>
> 问 `s` 能不能由某个子串重复多次拼成。设 `n = len(s)`，`k = nxt[n-1]`（整个串的最长相等前后缀长度），则：
>
> $$s \text{ 由重复子串构成} \iff k > 0 \ \text{且}\ n \bmod (n - k) = 0$$
>
> 直觉：`n - k` 就是最小循环节的长度。前后缀重叠得越多，说明周期越短。
>
> 还有一个不需要 KMP 的技巧解法，面试当彩蛋讲很好用：
>
> ```python
> return s in (s + s)[1:-1]
> ```
>
> `s + s` 里去掉首尾各一个字符，如果 `s` 还能找到，说明 `s` 平移某个非零距离后能盖回自己 —— 等价于有周期。

> [!example]- 替代方案：字符串哈希 Rabin-Karp
>
> 给每个长度为 `m` 的窗口算一个多项式哈希，滑动窗口 $O(1)$ 更新，$O(n+m)$ 完成匹配。
>
> 优点是好写、能扩展到「多模式串」「二维匹配」；缺点是有哈希冲突（需要双模数降低概率），且面试官问「最坏情况」时不好答。**28 这种单模式匹配还是首选 KMP**，哈希留作备选口述。

## 易错点

> [!warning]- 易错点
>
> **1. 把 5 当成 516 来做**
> 「子串」要连续，「子序列」可以跳，两者的最优解法完全不同。看到「回文」先确认这一点。
>
> **2. 中心扩展只枚举 n 个中心**
> 漏掉全部偶数长度回文。必须是 $2n-1$ 个。
>
> **3. 中心扩展的长度算成 `r - l + 1`**
> 退出循环时两端各多走一步，正确长度是 `r - l - 1`，子串是 `s[l+1 : r]`。
>
> **4. 构建 nxt 时 `i` 从 0 开始**
> `nxt[0]` 必须是 0（真前后缀不能取整个串），从 0 开始会得到全 1 的错误数组。
>
> **5. 回退写成 `j = nxt[j]`**
> 应该是 `j = nxt[j - 1]`——`j` 是「已匹配的长度」，对应的下标是 `j - 1`。这两个下标的错位是 KMP 最容易记混的地方。
>
> **6. 回退用 `if` 而不是 `while`**
> 退一次后可能仍不匹配，要循环退到底。
>
> **7. Python 里直接用 `haystack.find(needle)` 交卷**
> 能过，但面试官问的就是手写。CPython 的 `str.find` 实际用的是 Crochemore-Perrin（two-way）算法，不是朴素也不是 KMP——这个冷知识答出来是加分项。

## 复杂度

> [!summary]- 复杂度
>
> | 题 | 时间 | 空间 | 来源 |
> | --- | --- | --- | --- |
> | 5 / 647 中心扩展 | $O(n^2)$ | $O(1)$ | $2n-1$ 个中心 × 每个最多扩 $O(n)$ |
> | 5 区间 DP | $O(n^2)$ | $O(n^2)$ | 同样的时间但多花一张表，不如中心扩展 |
> | 5 Manacher | $O(n)$ | $O(n)$ | 复用对称信息，秋招不必手写 |
> | 28 暴力 | $O(nm)$ | $O(1)$ | 每次失配退回重来 |
> | 28 KMP | $O(n + m)$ | $O(m)$ | 构建 `nxt` $O(m)$ + 匹配 $O(n)$，`i` 不回退 |
>
> KMP 的 $O(n)$ 匹配用**摊还分析**说明：`j` 每轮最多 +1，总共加了 $n$ 次；`while` 里每次回退都让 `j` 严格减小，而 `j` 非负，所以总回退次数不超过总增加次数 $n$。这是面试里「证明一下你的复杂度」的标准答法。

## 一句话总结

两类字符串题共用一句话：**别扔掉已经比过的信息**——KMP 用 `nxt` 数组把「已匹配的后缀」翻译成「可以直接跳到哪」，中心扩展用「回文由中心唯一决定」把区间枚举降成中心枚举。

## 模板归纳

**触发信号**：

- 「在 A 中找 B 第一次出现的位置」「判断周期性」$\to$ KMP
- 「最长回文**子串**」「回文子串的个数」$\to$ 中心扩展
- 「最长回文**子序列**」$\to$ 回 [[7.6 区间DP 最长回文子序列]]

**中心扩展三步**：

1. 循环 `range(2 * n - 1)`，`l, r = i // 2, i // 2 + i % 2`。
2. `while` 两端相等就外扩。
3. 退出后长度写 `r - l - 1`，子串写 `s[l+1 : r]`。

**KMP 三步**：

1. 先写 `nxt`：`i` 从 1 开始，`while j and p[i] != p[j]: j = nxt[j-1]`，相等则 `j += 1`，最后 `nxt[i] = j`。
2. 匹配段照抄同一结构，只把 `p[i]` 换成 `s[i]`。
3. `j == m` 时命中，返回 `i - m + 1`。

**记忆锚点**：KMP 的两段代码长得一模一样，因为**构建 next 数组就是模式串和自己做一次匹配**。记住这一句，两段代码只需要记一段。
