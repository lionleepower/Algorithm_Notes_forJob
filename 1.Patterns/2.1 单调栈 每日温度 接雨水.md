# 单调栈：每日温度与接雨水

## 解决什么问题

一句话识别信号：

```text
要算的东西涉及「上一个 / 下一个 更大 / 更小的元素」 → 优先考虑单调栈
```

单调栈说白了就是：**及时去掉无用数据，保证栈中数据有序**。它把「对每个 `i` 都往右扫一遍找答案」的 $O(n^2)$ 压到 $O(n)$，靠的不是技巧，而是一条很硬的性质——**被遮蔽的元素永远不会再有用**（见下方核心论证）。

四种问法只是「方向」和「比较符」的排列组合，模板同一套：

| 要找的 | 遍历方向（候选池视角） | 弹出条件 |
| --- | --- | --- |
| 下一个更大 | 从右往左 | 栈顶 $\le$ 当前 → pop |
| 下一个更小 | 从右往左 | 栈顶 $\ge$ 当前 → pop |
| 上一个更大 | 从左往右 | 栈顶 $\le$ 当前 → pop |
| 上一个更小 | 从左往右 | 栈顶 $\ge$ 当前 → pop |

## 核心：为什么敢 pop，而不是 peek

![](assets/8.1%20单调栈%20永久淘汰.svg)

> [!tip]- 永久淘汰论证（全篇地基）
> 
> 以 739 从右往左的写法为例。设栈顶为下标 $j$（$j > i$），且 $t[i] \ge t[j]$。
> 
> 对任意 $k < i$，问一句「$j$ 还可能是 $k$ 的答案吗？」——**不可能**。因为 $i$ 比 $j$ **更近**，且 $t[i] \ge t[j]$：只要 $j$ 能满足 $k$（即 $t[j] > t[k]$），$i$ 必然也满足，而且会**更早被遇到**。
> 
> **$j$ 被 $i$ 永久遮蔽了**，此后再无翻身机会。
> 
> 这就是单调栈的全部秘密：**一个元素一旦被「更近且不更小」的元素遮蔽，就永远无用**。不是「暂时不用」，是「永远不用」——所以敢 `pop` 而不是 `peek`。每个下标最多进栈一次、出栈一次，$O(n)$ 由此而来。

## 变体一：739. 每日温度

给温度数组，对每一天求「要等几天才能遇到更高的温度」，没有则填 0。

### 视角 A：从右往左（栈 = 候选答案池）

> [!tip]- 先把语义契约钉死，其他一切都是推论
> 
> ```text
> 遍历到 i 时，栈里存的是：i 右边所有「还有可能成为某个左侧元素答案」的下标
> ```
> 
> 由这个契约立刻推出两条**不变量**（每轮循环结束时都成立）：
> 
> - **下标**：从栈顶到栈底**递增**（从右往左走，越早入栈的下标越大）
> - **温度**：从栈顶到栈底**严格递增**（栈顶最小）
> 
> 这两条合在一起就是全部：**栈顶是离 `i` 最近的候选，而且它是候选里最小的那个。**
> 
> **pop 完为什么栈顶就是答案？** 循环退出时有 `temperatures[st[-1]] > t`（严格大于），而被 pop 掉的恰好是 `i` 与 `st[-1]` 之间的**全部**候选，它们无一严格大于 `t`。所以 `st[-1]` 就是 `i` 右边第一个严格更大者。栈空则说明右边没有更大的，`ans[i]` 保持初值 0。

> [!success]- 代码实现
> 
> ```python
> class Solution:
>     def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
>         n = len(temperatures)
>         ans = [0] * n
>         st = []                                        # 存下标，不存温度值
>         for i in range(n - 1, -1, -1):
>             t = temperatures[i]
>             while st and t >= temperatures[st[-1]]:    # 等号必须有，见下
>                 st.pop()                               # 清理无效候选
>             if st:
>                 ans[i] = st[-1] - i                    # 自己写自己
>             st.append(i)
>         return ans
> ```
> 
> - **关键变量**：`st` 存的是**下标**——存温度值就算不出天数差了，这是所有单调栈题的通用约定。
> - **主流程**：先清理，再查询，最后自己入栈当候选。

> [!warning]- `>=` 里的等号为什么必须要
> 
> 题目要的是**严格更高**的温度。若 `temperatures[i] == temperatures[j]`：
> 
> - `j` 对 `i` 本身无用（不严格大于）
> - `j` 对 `i` **左边**任何人也无用（被 `i` 遮蔽，理由同永久淘汰论证）
> 
> 两头都没用，所以等号情况**必须 pop**。
> 
> 手推一遍「对于相同的数字，保留左边的就好」就很清楚——从右往左扫时，右边那个相同值会被左边这个顶掉。
> 
> **实测**：把这里的 `>=` 写成 `>`，3000 组随机数据里错了 **1913 组**；把视角 B 的 `>` 写成 `>=`，同样错 1913 组。这不是偶发边界，是必错。

### 视角 B：从左往右（栈 = 还没拿到答案的欠债人）

![](assets/8.1%20单调栈%20两种视角.svg)

> [!success]- 代码实现
> 
> ```python
> class Solution:
>     def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
>         n = len(temperatures)
>         ans = [0] * n
>         st = []
>         for i, t in enumerate(temperatures):
>             while st and t > temperatures[st[-1]]:     # 注意：这里不含等号
>                 j = st.pop()
>                 ans[j] = i - j                         # 给别人结算
>             st.append(i)                               # 自己也去排队欠债
>         return ans
> ```
> 
> 这一版更能体现单调栈「**延迟结算**」的特点：栈里全是还欠着答案的人，来一个更大的就一次性还掉一批。

> [!warning]- 等号方向为什么恰好相反
> 
> 因为两边判断的**不是同一件事**：
> 
> - **视角 A** 问的是「栈顶这个候选**还有没有用**」——相等也没用，所以连等号一起 pop（`>=`）。
> - **视角 B** 问的是「当前元素**够不够格给栈顶结算**」——相等不够格（要严格更大），所以只在严格大于时 pop（`>`）。
> 
> **建议只精熟一种，另一种能读懂即可**，否则等号方向必串。个人推荐：视角 A 更符合「我要找我的答案」的直觉，视角 B 更贴近大多数题解和 84 那类「结算矩形」的题。

## 变体二：42. 接雨水（横向分层）

[[1.1 相向双指针，接雨水]] 已经讲过**前后缀分解**的算法，这里是**完全不同的第二种视角**——注意对比。

![](assets/8.1%20单调栈%20接雨水横向分层.svg)

> [!tip]- 核心思路：找「上一个更大元素」，在找的过程中填坑
> 
> **纵向 vs 横向**是这两种解法的根本分歧：
> 
> | | [[1.1 相向双指针，接雨水]] 前后缀分解 | 本篇 单调栈 |
> | --- | --- | --- |
> | 枚举对象 | 每一**列** | 每一**层**（横条） |
> | 一次算出 | 这一列能接多少水 | 一个横向矩形的水 |
> | 依据 | `min(左边最高, 右边最高) - h[i]` | 弹出坑底，用左右两堵墙夹出矩形 |
> 
> 单调栈版本的每一次 `pop` 都对应**填平一个横条**，三个角色由栈自然给出：
> 
> ```text
> bottom = 弹出的那根（坑底）
> left   = 弹完之后的新栈顶（左边那堵墙）
> right  = 当前的 i（右边那堵墙）
>
> dh = min(h[left], h[i]) - h[bottom]        # 这一层的厚度
> w  = i - left - 1                          # 这一层的宽度（左右墙之间）
> ```
> 
> **`w` 为什么是 `i - left - 1` 而不是 `i - left`？** 因为两堵墙本身不装水，只有它们**中间**的部分才是坑。
> 
> **栈空为什么要 `break`？** 弹掉坑底后如果栈空了，说明左边**没有墙**，水会直接流走，这一层不存在。
> 
> `st` 里存的是**下标**，不是高度。它的语义可以用一句话钉死：
> **栈里存的是「目前为止，从右往左看还能看见的那些柱子」——也就是还没被更高柱子挡住的、有资格当「左墙」的候选。**
> 由此自动得到两条不变量：
>
>1. **栈内高度从栈底到栈顶单调不增**（因为每次 push 前，比自己矮的都被弹光了）。
>2. 栈里相邻两个下标之间的柱子，**高度一定都比它们俩矮**（否则那根不会被弹掉）。

> [!success]- 代码实现
> 
> ```python
> class Solution:
>     def trap(self, height: List[int]) -> int:
>         ans = 0
>         st = []   # 使用的栈
>         for i, h in enumerate(height):
>             while st and h >= height[st[-1]]:
>                 bottom_h = height[st.pop()]            # 坑底高度
>                 if not st:                             # 左边没有墙，水流走
>                     break
>                 left = st[-1]
>                 dh = min(height[left], h) - bottom_h   # 这一层的厚度
>                 ans += dh * (i - left - 1)             # 厚度 × 宽度
>             st.append(i)
>         return ans
> ```
> 
> - **主流程**：栈里维护一个高度递减的「墙」序列；每来一根更高的柱子，就把它左边所有比它矮的坑一层层填掉。
> - **易错位置**：`i - left - 1` 的那个 `-1`、栈空时的 `break`、以及 `dh` 用的是 `min(左墙, 右墙)` 而不是某一边。
> - 

> [!tip]- 这题的等号为什么反而无所谓
> 
> 和 739 不同，接雨水这里写 `>=` 或 `>` **都对**（我用 3000 组随机数据对拍过，两版与逐列暴力完全一致）。
> 
> 原因在于**这题算的是面积，不是「第一个严格更大的位置」**：遇到等高的柱子时，若用 `>` 不弹，等高的柱子会留在栈里；后来真正更高的柱子到来时再弹它，算出的 `dh` 恰好是 0（`min(左墙, 右墙) - bottom` 中 bottom 与墙同高），**贡献 0，不会重复计数**。
> 
> 反过来说：**面积类题目对等号不敏感，位置类题目对等号极其敏感**。判断依据是「等号情况会不会产生非零贡献」，不要一律照抄。

## 易错点

> [!warning]- 易错点
> 
> - **等号方向写反**（739 类最高频）：从右往左查询用 `>=`，从左往右结算用 `>`。两种视角混着背必串——**只精熟一种**。
> - **栈里存值而不是下标**：存了温度值就算不出 `st[-1] - i` 这个天数差；84、42 也都需要下标算宽度。**默认存下标**。
> - **接雨水漏了 `-1`**：`w = i - left - 1`，两堵墙自己不装水。
> - **接雨水忘了判栈空**：弹掉坑底后栈空说明左边没墙，必须 `break`（或 `continue`），否则 `st[-1]` 会取到错误的元素——注意 Python 的负下标不报错，会**安静地给出错误答案**。
> - **把「暂时无用」当「永远无用」的反例来质疑 pop**：单调栈能成立的前提就是永久淘汰论证；如果某题里被遮蔽的元素**还可能有用**（比如要求「第二大」），那就不是单调栈的场景。
> - **误以为 `while` 会让复杂度退化成 $O(n^2)$**：见下方摊还分析。

## 复杂度

> [!summary]- 复杂度
> 
> - **时间 $O(n)$** —— 每个下标**最多入栈一次、出栈一次**。内层 `while` 的总执行次数被这个**摊还上界**卡死，和外层循环的次数无关。这也是新手最容易误判的地方：看到「循环套循环」就以为是 $O(n^2)$，实际上所有 `while` 加起来最多跑 $n$ 次。
> - **空间 $O(n)$** —— 栈。最坏情况是严格单调数组（739 从右往左遇到严格递减数组时，全部元素都会留在栈里）。
> - 对比 [[1.1 相向双指针，接雨水]]：相向双指针版的接雨水是 $O(1)$ 空间，**比单调栈更省**；但单调栈的写法能迁移到 84 柱状图最大矩形，双指针不能。

## 一句话总结

单调栈 = **及时去掉无用数据，保证栈中有序**——核心是那条永久淘汰论证：**被「更近且不更小」的元素遮蔽的候选，此后永远无用**，所以敢 pop；剩下的全是方向（从左还是从右）和等号（严格还是非严格）的排列组合。

## 模板归纳

看到「**上一个 / 下一个 更大 / 更小的元素**」，或者「某个量由**左右第一个比它大 / 小的位置**决定」（雨水、矩形面积、区间贡献），三步落笔：

1. **定方向**：要找**右边**的 → 从右往左（栈是候选池，自己查自己）；要找**左边**的，或者要**结算矩形** → 从左往右（栈是欠债人，来人给他们结算）。
2. **定等号**：先问「**等值元素对我有没有用**」。位置类（739）等值无用 ⇒ 该方向的比较符含等号；面积类（42）等值贡献为 0 ⇒ 含不含都行。
3. **写循环**：`while` 弹到不满足为止，再取栈顶、再入栈——**三步顺序不能换**。

```python
# 模板 A：从右往左，栈 = 候选答案池（求「下一个更大」）
st = []
for i in range(n - 1, -1, -1):
    while st and a[i] >= a[st[-1]]:     # 求「下一个更小」就把 >= 换成 <=
        st.pop()                        # 被遮蔽者，永久淘汰
    ans[i] = st[-1] if st else -1       # 栈顶即答案；空栈表示不存在
    st.append(i)

# 模板 B：从左往右，栈 = 欠债人（求「下一个更大」，顺便结算）
st = []
for i, x in enumerate(a):
    while st and x > a[st[-1]]:         # 严格大于才够格结算
        j = st.pop()
        ans[j] = i                      # 也可以在这里算面积（42 / 84）
    st.append(i)
```
