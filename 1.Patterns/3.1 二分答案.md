# 二分答案 Binary Search on Answer

## 解决什么问题

不在数组里找元素，而是**在答案的取值范围里二分**。识别信号非常固定：

```text
求「最大 / 最小可行值」 + 答案是个整数范围 + 范围大到不能枚举
```

关键转化：**把「求最优值」变成「判断某个值可不可行」**。直接求最优往往很难，但给定一个候选答案 `x` 去验证「`x` 行不行」通常是道简单题——这就是 `check(x)`。

与 [[3.0 二分查找 红蓝染色法]] 的唯一区别：`mid` 不再是数组下标，而是**候选答案本身**。模板和推导过程完全一样。

## 统一模板

> [!tip]- 核心思路：三个必答问题
> 
> 拿到题先回答这三问，代码就是机械翻译：
> 
> 1. **答案是什么？** 明确 `mid` 的物理含义（几份合金 / 什么速度 / 多大容量），以及取值范围 `[lo, hi]`。
> 2. **`check(x)` 怎么写？** 「`x` 这个答案可行吗」，返回布尔值。这一步通常是道贪心或模拟题。
> 3. **`check` 往哪边单调？** 决定找第一个 True 还是最后一个 True。
> 
> **单调性从何而来**：几乎所有二分答案题的单调性都是这句常识——
> 
> ```text
> 能造 x 份 ⟹ 一定也能造更少份      （True 在左边 → 找最后一个 True）
> x 速度能吃完 ⟹ 更快的速度也能吃完   （True 在右边 → 找第一个 True）
> ```
> 
> 写不出这句话，就说明这题不能二分答案。

> [!success]- 两个模板：最大化 / 最小化
> 
> 沿用 [[3.0 二分查找 红蓝染色法]] 的开区间，`left`、`right` 依然是「已确认的两种颜色」，只是颜色的含义换成了可行 / 不可行：
> 
> ```python
> # ① 求最大可行值：True True True False False —— 找最后一个 True
> left, right = lo - 1, hi + 1     # left 已知可行，right 已知不可行
> while left + 1 < right:
>     mid = (left + right) // 2
>     if check(mid):
>         left = mid               # 可行，答案至少是 mid，往大了试
>     else:
>         right = mid
> return left                      # ← 返回 left
> 
> # ② 求最小可行值：False False True True True —— 找第一个 True
> left, right = lo - 1, hi + 1     # left 已知不可行，right 已知可行
> while left + 1 < right:
>     mid = (left + right) // 2
>     if check(mid):
>         right = mid              # 可行，答案至多是 mid，往小了试
>     else:
>         left = mid
> return right                     # ← 返回 right
> ```
> 
> 两版**只差两处**：`check` 为真时更新哪个指针，以及最后返回谁。记忆锚点：**求最大返回 `left`，求最小返回 `right`**——返回的永远是「可行」的那一侧。
> 
> 边界取 `lo-1` / `hi+1` 是为了让哨兵落在合法范围**之外**，保证真实答案不会被夹掉。

## 变体一：2915. 数量最多的最大合金数（求最大可行值）

给多台机器的配方、金属库存、单价和预算，求最多能造多少份合金（每份必须用同一台机器）。

> [!tip]- 为什么是二分答案
> 
> 「最多能造多少份」= 求最大可行值。单调性显然：**预算够造 `num` 份，就一定够造 `num-1` 份**，所以 `check` 呈 `True...True False...False`，找最后一个 True。
> 
> `check(num)` 就是一道简单的模拟题——造 `num` 份要花多少钱：
> 
> $$money = \sum_i \max(0,\ comp[i] \times num - stock[i]) \times cost[i]$$
> 
> 逐项含义：`comp[i] * num` 是总需求，减去库存 `stock[i]` 是**还需购买**的量（`max(0, ...)` 是因为库存够了就不用买，不能算成负花费），再乘单价。最后判断 `money <= budget`。
> 
> 每台机器配方不同，必须**分别二分再取最大值**。

> [!success]- Python 实现
> 
> ```python
> class Solution:
>     def maxNumberOfAlloys(self, n: int, k: int, budget: int,
>                           composition: list[list[int]],
>                           stock: list[int], cost: list[int]) -> int:
>         ans = 0
>         upper = min(stock) + budget + 1        # 安全上界，见下方说明
> 
>         for comp in composition:               # 每台机器分别二分
>             def check(num: int) -> bool:
>                 money = 0
>                 for have, need, price in zip(stock, comp, cost):
>                     required = need * num
>                     if required > have:                  # 只买缺的部分
>                         money += (required - have) * price
>                         if money > budget:               # 提前剪枝
>                             return False
>                 return True
> 
>             left, right = ans, upper           # left 从已知答案起步，剪枝
>             while left + 1 < right:
>                 mid = (left + right) // 2
>                 if check(mid):
>                     left = mid
>                 else:
>                     right = mid
>             ans = left                         # 求最大 → 取 left
>         return ans
> ```
> 
> - 主流程：外层枚举机器，内层二分该机器的最大产量，全局取最大。
> - 关键变量：`left` 恒为「已知可行」，`right` 恒为「已知不可行」，循环中始终成立。
> - 两个剪枝：`money > budget` 时立即返回 False，不必算完所有金属；`left = ans` 让后续机器只在「比当前答案更大」的范围里搜。
> - **上界为什么是 `min(stock) + budget + 1`**：造一份合金每种金属至少要 1 个，最省的情况是先用光库存（至少 `min(stock)` 份），之后每份至少花 1 元，预算最多再撑 `budget` 份。`+1` 保证 `upper` 落在不可行侧。

## 变体二：875. 爱吃香蕉的珂珂（求最小可行值）

给定每堆香蕉数 `piles` 和小时数 `h`，求能在 `h` 小时内吃完的**最小速度** `k`。

> [!success]- 与变体一「什么不变、什么改变」
> 
> **不变**：开区间模板、先写 `check` 再套壳的流程。
> **改变**：单调性方向反了——速度越快越容易吃完，所以是 `False...False True...True`，找**第一个** True，`check` 为真时收缩 `right`，最后返回 `right`。
> 
> ```python
> class Solution:
>     def minEatingSpeed(self, piles: list[int], h: int) -> int:
>         def check(k: int) -> bool:                       # 速度 k 能否吃完
>             return sum((p + k - 1) // k for p in piles) <= h   # 上取整求小时数
> 
>         left, right = 0, max(piles)      # 0 一定不可行，max(piles) 一定可行
>         while left + 1 < right:
>             mid = (left + right) // 2
>             if check(mid):
>                 right = mid              # 可行，试更小的速度
>             else:
>                 left = mid
>         return right                     # 求最小 → 取 right
> ```
> 
> - `(p + k - 1) // k` 是**整数上取整**的惯用写法（吃剩半堆也要占满一小时），等价于 `math.ceil(p / k)` 但不引入浮点误差，细节见 [[Python_除法与取整]]。
> - 边界为何天然合法：`k = max(piles)` 时每堆一小时，共 `len(piles) <= h` 小时（题目保证），必可行；`k = 0` 无意义，正好当红哨兵。

## 易错点

> [!warning]- 易错点
> 
> - **没先写清 `check(x)` 就动手**：`check` 含义一含糊，`left`/`right` 的移动方向必写反。铁律：先把 `check` 写成一个能独立测试的函数，再套模板。
> - **返回错边界**：求**最大**可行值返回 `left`，求**最小**可行值返回 `right`。写反了答案恰好差 1，且样例常常也能过，极难查。
> - **上界设太小**：`right` 必须落在**确定不可行**的位置，否则真实答案被截断（返回值就是那个错误上界）。宁可设宽一点——多算一轮只是 $O(\log)$ 的代价。
> - **把 `mid` 当成数组下标**：二分答案里 `mid` 是候选答案（份数、速度、容量），不是下标，不要拿去索引数组。
> - **忘记库存 / 已有量**：花费只算**缺口** $\max(0,\ need \times num - have)$，直接按总需求计价会大幅高估。
> - **`check` 里溢出或超时**：`comp[i] * num` 在大 `num` 下可能很大（Python 无溢出但会慢），加提前剪枝 `if money > budget: return False`。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = O(\log(\text{答案范围}) \times \text{单次 check 的代价})$。
> 
> - 2915 合金：$O(k \cdot n \cdot \log U)$——`k` 台机器，每次 `check` 遍历 `n` 种金属，二分 $\log U$ 轮。
> - 875 香蕉：$O(n \log(\max piles))$——每次 `check` 遍历所有堆。
> - 空间均为 $O(1)$。
> - **注意**：$\log$ 因子很小（$U = 10^9$ 也只有 30 轮），瓶颈几乎总在 `check` 的实现上——优化先优化 `check`。

## 一句话总结

二分答案 = 把「**求**最优值」换成「**验证**某个值可不可行」，在答案值域上找可行与不可行的分界点；难点从来不在二分，而在写对 `check`。

## 模板归纳

看到「**最多 / 最少 / 最大 / 最小** + 答案是整数且范围巨大」，先想二分答案，五步落笔：

1. **定义答案**：`mid` 表示什么？范围 `[lo, hi]` 是多少？
2. **写 `check(x)`**：给定答案 `x`，判断可行性（常是贪心 / 模拟 / 前缀和）。
3. **验单调性**：能说出「`x` 可行 ⟹ 比 `x` 更小（大）的也可行」才能二分。
4. **选模板**：求最大 → `check` 真则 `left = mid`，返回 `left`；求最小 → `check` 真则 `right = mid`，返回 `right`。
5. **定边界**：`left` 放在确定不可行侧，`right` 放在确定可行侧（或反之），宁宽勿窄。

```text
"能造 x 个，则一定能造更少"        → 求最大可行值，返回 left
"x 速度能完成，则更快也能完成"      → 求最小可行值，返回 right
"最多 / 最大"                     → True True False False，找最后一个 True
"最少 / 最小"                     → False False True True，找第一个 True
```
