# 峰值与旋转数组

## 解决什么问题

这类题的数组**不是整体有序**，但仍能二分。因为二分的真正前提从来不是「有序」，而是：

> 能否根据某个判断条件，每次**稳定地排除一半**。

所以做法完全不变——依旧是 [[3.0 二分查找 红蓝染色法]] 的开区间模板，**唯一要动脑的是重新定义 `is_blue(mid)`**（什么叫「已进入答案侧」）。

> [!summary]- 三题速查表
> 
> | 题目 | 数组特征 | `is_blue(mid)` | 返回 |
> | --- | --- | --- | --- |
> | 162. 寻找峰值 | 相邻不等，看局部趋势 | `nums[mid] > nums[mid+1]` | `right`（下标） |
> | 153. 旋转数组最小值 | 升序数组被旋转 | `nums[mid] <= nums[-1]` | `nums[right]`（**值**） |
> | 33. 搜索旋转数组 | 旋转 + 找 target | 跨段判断，见下 | `right`，需验存在性 |
> 
> 记忆方式：**峰值看坡度、最小值看是否进入右小段、搜 target 看同不同段。**

## 统一模板

> [!success]- 依旧是红蓝染色，只换 `is_blue`
> 
> ```python
> left, right = -1, len(nums)          # 注意：峰值/最小值题 right 取 len(nums)-1
> while left + 1 < right:
>     mid = (left + right) // 2
>     if is_blue(mid):
>         right = mid                  # mid 已进入答案侧
>     else:
>         left = mid
> return right
> ```
> 
> `is_blue(mid)` 的统一语义：**`mid` 是否已经到达或越过答案位置**——若是蓝色，答案只可能在 `mid` 或它左边，所以收缩 `right`。

## 变体一：162. 寻找峰值

返回**任意一个**峰值下标（`nums[i]` 比左右邻居都大，题目视两端外侧为 $-\infty$，且保证相邻元素不等）。

> [!tip]- 为什么无序也能二分
> 
> 不需要找全局最大值，只要找**任意**局部峰值——这是能二分的关键。只看 `nums[mid]` 与 `nums[mid+1]` 的坡度：
> 
> - `nums[mid] > nums[mid+1]`：正在**下坡** → 从 `mid` 往左走一定能撞到峰（最差 `mid` 自己就是），峰在左侧或就是 `mid` → 蓝色，`right = mid`
> - `nums[mid] < nums[mid+1]`：正在**上坡** → 右边一定有峰（一直升上去，最差撞到右端 $-\infty$ 边界）→ 红色，`left = mid`
> 
> 两种情况都保证「被保留的那半边必然含峰」，所以永不漏解。

> [!success]- 代码
> 
> ```python
> class Solution:
>     def findPeakElement(self, nums: list[int]) -> int:
>         left, right = -1, len(nums) - 1      # ← 注意是 n-1
>         while left + 1 < right:
>             mid = (left + right) // 2
>             if nums[mid] > nums[mid + 1]:    # 下坡 → 蓝
>                 right = mid
>             else:                            # 上坡 → 红
>                 left = mid
>         return right
> ```
> 
> **`right` 为什么取 `len(nums)-1` 而不是 `len(nums)`**：代码里要访问 `nums[mid+1]`，而 `mid` 最大可能取到 `right-1`。若 `right = n`，`mid` 可达 `n-1`，`nums[mid+1]` 就越界。取 `n-1` 后 `mid` 最大为 `n-2`，恰好安全——同时最后一个元素仍可能是答案（作为 `right` 的初值被返回）。

> [!example]- 推演 `nums = [1,2,3,1]`
> 
> ```text
> left=-1, right=3
> mid=1: nums[1]=2 < nums[2]=3  上坡 → left=1
> mid=2: nums[2]=3 > nums[3]=1  下坡 → right=2
> left+1 == right，结束，返回 2   （nums[2]=3 是峰值）
> ```

## 变体二：153. 寻找旋转排序数组中的最小值

升序数组被旋转后（元素互不相同），返回最小值。

> [!tip]- 用 `nums[-1]` 把数组切成两段
> 
> 旋转数组 = 两段升序拼接，且**左段所有元素都大于右段所有元素**：
> 
> ```text
> [4, 5, 6, 7, 0, 1, 2]
>  └─ 左大段 ─┘ └右小段┘        end = nums[-1] = 2
> ```
> 
> 拿末尾元素 `end = nums[-1]` 当参照物，就得到一个干净的单调判定：
> 
> - `nums[i] > end` → 在**左大段**（红）
> - `nums[i] <= end` → 在**右小段**（蓝）
> 
> **最小值就是右小段的第一个元素**，所以目标是「找第一个 `nums[i] <= nums[-1]` 的位置」——标准红蓝染色。
> 
> 用 `<=` 而不是 `<` 是为了兼容**没有旋转**的情况（此时整个数组都算右小段，返回 `nums[0]`，正确）。

> [!success]- 代码
> 
> ```python
> class Solution:
>     def findMin(self, nums: list[int]) -> int:
>         left, right = -1, len(nums) - 1      # 末尾必属右小段，可直接当蓝哨兵
>         while left + 1 < right:
>             mid = (left + right) // 2
>             if nums[mid] <= nums[-1]:        # 进入右小段 → 蓝
>                 right = mid
>             else:
>                 left = mid
>         return nums[right]                   # ← 返回值，不是下标
> ```
> 
> 推演 `[4,5,6,7,0,1,2]`：`mid=2` 时 `6 > 2` 仍在左段 → `left=2`；`mid=4` 时 `0 <= 2` 已入右段 → `right=4`；最终 `nums[4] = 0`。
> 
> `right` 初值取 `n-1` 而非 `n`：末尾元素本身一定在右小段（它就是 `end`），直接当蓝哨兵，省一轮判断。

> [!tip]- 另一种常见写法：比较 `nums[mid]` 与 `nums[right]`
> 
> ```python
> left, right = 0, len(nums) - 1
> while left < right:
>     mid = (left + right) // 2
>     if nums[mid] > nums[right]:
>         left = mid + 1          # mid 在左大段，最小值在右边
>     else:
>         right = mid             # mid 在右小段，最小值在左边或就是 mid
> return nums[left]
> ```
> 
> 不用固定 `nums[-1]` 而用动态的 `nums[right]` 当参照，逻辑同样成立，面试里也很常见。**但别和开区间模板混用**——这版是左闭右闭，`left = mid + 1` 的 `+1` 不能省。

## 变体三：33. 搜索旋转排序数组

旋转数组中找 `target`，存在返回下标，否则 `-1`。

> [!tip]- 核心：把「跨段」也翻译成红蓝
> 
> 本质仍是找第一个 `>= target` 的位置，麻烦在于 `nums[mid]` 和 `target` 可能**不在同一段**，直接比大小会错。所以先各自定位：
> 
> ```python
> end = nums[-1]
> nums[i] > end   → i 在左大段        target > end   → target 在左大段
> nums[i] <= end  → i 在右小段        target <= end  → target 在右小段
> ```
> 
> 四种组合，逐个判断「`mid` 是否已到达或越过 target」,也就是target是否被蓝色包裹：
> 
> | `nums[mid]` 在 | `target` 在 | 是否蓝色 | 理由 |
> | --- | --- | --- | --- |
> | 左大段 | 左大段 | `nums[mid] >= target` | 同段，正常比较 |
> | 左大段 | 右小段 | `False` | 左段整体在 target **之前**，还没到 |
> | 右小段 | 左大段 | `True` | 右段整体已**越过** target |
> | 右小段 | 右小段 | `nums[mid] >= target` | 同段，正常比较 |
> 
> 把上表按 `nums[mid]` 所在段合并，就是两行代码。

> [!success]- 红蓝染色版（模板统一，推荐纳入自己的体系）
> 
> ```python
> class Solution:
>     def search(self, nums: list[int], target: int) -> int:
>         end = nums[-1]
> 
>         def is_blue(i: int) -> bool:
>             if nums[i] > end:                          # mid 在左大段
>                 return target > end and nums[i] >= target
>             else:                                      # mid 在右小段
>                 return target > end or nums[i] >= target
> 
>         left, right = -1, len(nums)
>         while left + 1 < right:
>             mid = (left + right) // 2
>             if is_blue(mid):
>                 right = mid
>             else:
>                 left = mid
> 
>         if right == len(nums) or nums[right] != target:   # 必须验存在性
>             return -1
>         return right
> ```
> 
> 两行 `return` 就是上表的合并：左大段时「target 也在左段**且**已够大」才算蓝；右小段时「target 在左段（已越过）**或**已够大」就算蓝。
> 
> 若觉得布尔表达式绕，可展开成四个 `if`，逻辑完全等价：
> 
> ```python
> def is_blue(i):
>     mid_in_left = nums[i] > end
>     target_in_left = target > end
>     if mid_in_left and target_in_left:      return nums[i] >= target
>     if mid_in_left and not target_in_left:  return False
>     if not mid_in_left and target_in_left:  return True
>     return nums[i] >= target
> ```
> 当然也可以写成
> ```python
> 
>  def is_blue(i):
>     mid_in_left = nums[i] > end
>     target_in_left = target > end
>     # 不同段
> 	# target 没有被蓝色包裹
>     if mid_in_left and not target_in_left:  return False
> 	 # target 被蓝色包裹
>     if not mid_in_left and target_in_left:  return True
>      #同段，正常比较
>     return nums[i] >= target
> ```
> 

> [!success]- 判断哪半边有序版（面试更直观，最常用）
> 
> ```python
> class Solution:
>     def search(self, nums: list[int], target: int) -> int:
>         left, right = 0, len(nums) - 1
>         while left <= right:
>             mid = (left + right) // 2
>             if nums[mid] == target:
>                 return mid
>             if nums[left] <= nums[mid]:                  # 左半边有序
>                 if nums[left] <= target < nums[mid]:
>                     right = mid - 1
>                 else:
>                     left = mid + 1
>             else:                                        # 右半边有序
>                 if nums[mid] < target <= nums[right]:
>                     left = mid + 1
>                 else:
>                     right = mid - 1
>         return -1
> ```
> 
> 思路：旋转数组从中间切开，**至少有一半是有序的**。判断出有序的那半边后，看 `target` 是否落在其值域内——在就搜那半边，不在就搜另一半。
> 
> **两版怎么选**：这版更直观、面试白板上更好讲，且提前命中直接返回；红蓝染色版胜在与 `3.0`/`3.1` 共用同一套模板，不必额外记忆。建议**主写这版、能讲红蓝版**。注意这版是左闭右闭，`±1` 一个都不能省。

## 易错点

> [!warning]- 易错点
> 
> - **`right` 初值取错导致越界**（162）：要访问 `nums[mid+1]` 就必须 `right = len(nums)-1`；写成 `len(nums)` 直接 IndexError。
> - **返回下标还是返回值**（153）：`findMin` 要的是**最小值** `nums[right]`，不是位置 `right`。
> - **忘记验存在性**（33）：二分只找到「第一个 >= target」的位置，必须 `if right == len(nums) or nums[right] != target: return -1`，两个条件缺一不可。
> - **跨段时直接比大小**：`nums[mid]` 和 `target` 不同段时，`nums[mid] < target` 毫无意义——必须先判段。这是 33 题最核心的坑。
> - **只判断了 target 在哪段，没判断 `nums[mid]` 在哪段**：两个都要定位，四种组合才完整。
> - **两套模板混用**：红蓝染色版是开区间（`left = mid`，无 ±1），有序区间版是闭区间（`left = mid + 1`，必须 ±1）。混着写必死循环。
> - **忽略「相邻元素不等」的前提**（162）：正因题目保证不等，才不存在「平坡」这种无法判方向的情况。
> - **忘记数组可能根本没旋转**（153/33）：用 `<=` 比较 `nums[-1]` 天然覆盖这种退化情形。

## 复杂度

> [!summary]- 复杂度
> 
> 三题均为时间 $O(\log n)$、空间 $O(1)$——每轮判定排除一半，与是否有序无关，只与「能否稳定二分」有关。
> 
> 33 题两种写法同阶；有序区间版可能因提前命中 `nums[mid] == target` 更早返回，但最坏情况一致。

## 一句话总结

数组不整体有序照样能二分——**只要能定义出「哪半边一定含答案」，就能红蓝染色**；这三题变的从来只有 `is_blue`，模板一个字没改。

## 模板归纳

看到「数组不是整体有序，但要 $O(\log n)$」，按五步走：

1. 数组真的整体有序吗？不是 → 它有没有**局部结构**（坡度、分段）？
2. 找一个**参照物**：峰值题用 `nums[mid+1]`（比邻居），旋转题用 `nums[-1]`（比末尾）。
3. 定义 `is_blue(mid)` = 「`mid` 是否已到达或越过答案侧」。
4. 套开区间模板，蓝则 `right = mid`，红则 `left = mid`。
5. 收尾三问：返回**下标**还是**值**？`right` 初值要不要留一格防越界？答案可能不存在吗（要验）？

```text
峰值   → nums[mid] > nums[mid+1]   （看坡度，下坡为蓝）
最小值 → nums[mid] <= nums[-1]     （看是否进入右小段）
搜 target → 先判 mid 与 target 各在哪段，再决定红蓝
```
