# 快慢指针：中点、判环、环入口与重排

## 解决什么问题

链表**不能随机访问**——没有下标，`len()` 也没有，想知道「中间在哪」「有没有绕回来」只能靠走。快慢指针 Fast & Slow Pointers 用**速度差**把这些问题一趟解决。识别信号：

```text
单链表 + 要找中点 / 判断成环 / 定位环入口 / 只允许 O(1) 额外空间
```

对照组：这些题都能用哈希表存访问过的节点来做，但那是 $O(n)$ 空间。**快慢指针的全部价值就是把空间压到 $O(1)$**，面试问「能否优化空间」问的就是这个。

四道题共用一套骨架，差别只在「相遇之后做什么」：

| 题号 | 难度 | 做什么 |
| --- | --- | --- |
| **876. 链表的中间结点** | 简单 | `fast` 到头时 `slow` 就在中点 |
| 141. 环形链表 | 简单 | `fast` 追上 `slow` 就是有环 |
| **142. 环形链表 II** | 中等 | 相遇后再走一轮，第二次相遇点是入口 |
| 143. 重排链表 | 中等 | 找中点 → 反转后半段 → 交替合并 |

## 统一模板：一次两步 vs 一次一步

> [!tip]- 核心思路：循环条件为什么是 `while fast and fast.next`
> 
> ```python
> slow = fast = head
> while fast and fast.next:
>     slow = slow.next
>     fast = fast.next.next
> ```
> 
> 两个判断各管一件事，**缺一个就会崩**：
> 
> - `fast` 存在 → 保证 `fast.next` 这次取值合法；
> - `fast.next` 存在 → 保证 `fast.next.next` 这次取值合法。
> 
> 它同时也是**奇偶长度的统一写法**：链表长度为奇数时 `fast` 停在最后一个节点（`fast.next` 为 `None`），为偶数时 `fast` 直接越过末尾变成 `None`。两种情况都由这一个条件接住。
> 
> **无环时必然终止**：`fast` 每轮前进 2，最多 $n/2$ 轮就走完。**有环时必然相遇**：两者都进环后，`fast` 每轮向 `slow` 逼近 1 个身位，间距只减不增，所以一定会撞上——这也是为什么步长必须是 2 和 1，步长差不为 1 时可能永远跨过去。

> [!success]- 876. 找中点（模板本体）
> 
> ```python
> class Solution:
>     def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
>         slow = fast = head
>         while fast and fast.next:
>             slow = slow.next
>             fast = fast.next.next
>         return slow
> ```
> 
> - 主流程：`fast` 走到头，`slow` 恰好走了一半。
> - **偶数长度返回哪个中点，由 `fast` 的起点决定**，这是本篇最实用的一个开关：
> 
> | 初始化 | `1 -> 2 -> 3 -> 4` 返回 | 用在哪 |
> | --- | --- | --- |
> | `fast = head` | `3`（**第二个**中点） | 876 本题、143 重排 |
> | `fast = head.next` | `2`（**第一个**中点，即前半段末尾） | 想显式断成两段时 |
> 
> - 易错位置：`fast = head.next` 时 `head` 为空会抛异常，用这种写法必须先判空。

## 变体一：141 / 142 判环与找入口

> [!success]- 141. 判断有没有环
> 
> ```python
> class Solution:
>     def hasCycle(self, head: Optional[ListNode]) -> bool:
>         slow = fast = head
>         while fast and fast.next:
>             slow = slow.next
>             fast = fast.next.next
>             if slow is fast:            # 用 is 比对象身份，不是比值
>                 return True
>         return False
> ```
> 
> - 主流程：能走到 `fast` 为空说明无环；中途撞上说明有环。
> - 易错位置：**判相遇必须用 `is`**。链表里可以有重复值，`slow.val == fast.val` 会把两个不同节点误判成相遇。`is` 比的是对象身份（见 [[Python_赋值与拷贝]]）。
> - 判断要写在**移动之后**：初始 `slow` 和 `fast` 都在 `head`，先判会立刻误报有环。

![](assets/4.1%20环入口推导.svg)

> [!tip]- 142 为什么第二次相遇一定在入口
> 
> 记 `a` 为 head 到入口的距离，`b` 为入口到相遇点的距离（按行进方向），`c` 为相遇点回到入口的距离，环长即 `b + c`。第一次相遇时 `slow` 走了 `a + b`，`fast` 走了 `2(a + b)`，而 `fast` 只是多绕了 `k` 圈：
> 
> $$2(a+b) = (a+b) + k(b+c) \;\Longrightarrow\; a + b = k(b+c) \;\Longrightarrow\; a = (k-1)(b+c) + c$$
> 
> 这个式子的读法是：**从 `head` 走 `a` 步，和从相遇点走 `c` 步，落点是同一个节点（入口），两者只差整数个环长。** 所以让一个指针回到 `head`、另一个留在相遇点，两人同速走，必然在入口碰面。
> 
> 一个常见的错误说法是「`a` 是环长的整数倍」——只有 `k = 1` 且 `c = 0` 时才成立。准确的说法是「`a` 与 `c` 只差整数个环长」。

> [!example]- 顺带回答：慢指针走的距离一定小于环长吗？
> 
> 结论对，但要限定成「**慢指针进入环之后**走的距离小于环长」，而不是它从 `head` 出发的总距离。
> 
> 理由：`slow` 刚进环的那一刻，`fast` 已经在环里某处，记 `fast` 到 `slow` 的**顺行间距**为 `d`（`0 ≤ d < L`，`L` 为环长）。此后每走一轮间距恰好减 1，所以最多 `d` 轮就追上，而 `d < L`。
> 
> 极端情形正好卡在边界：`fast` 只比 `slow` 快一个身位时（`d = L - 1`），要走 `L - 1` 轮才相遇，仍然不到一整圈。因此相遇点相对入口的偏移量 `b` 必定小于环长。

> [!success]- 142. 找环入口
> 
> ```python
> class Solution:
>     def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
>         slow = fast = head
>         while fast and fast.next:
>             slow = slow.next
>             fast = fast.next.next
>             if slow is fast:                 # 第一次相遇
>                 while slow is not head:      # 两人同速走，第二次相遇即入口
>                     slow = slow.next
>                     head = head.next
>                 return slow
>         return None
> ```
> 
> - 主流程：第一段找相遇点（快慢），第二段找入口（同速）。
> - 关键变量：第二段复用 `head` 当第二个指针，省一个变量；不介意的话另起一个 `p = head` 可读性更好。
> - 易错位置：第二个 `while` 的条件是 `slow is not head`，**如果相遇点恰好就是入口**（`a = 0`，即整条链表就是一个环），循环体一次都不进，直接返回，这是正确行为。

## 变体二：143. 重排链表（三个模板串起来）

把 `1 → 2 → 3 → 4 → 5` 变成 `1 → 5 → 2 → 4 → 3`：头尾交替。

> [!tip]- 拆成三个已经会的动作
> 
> 1. **找中点**（本篇）→ 2. **反转后半段**（[[4.0 反转链表]]）→ 3. **交替合并**。
> 
> 这里有个容易被忽略的巧合：`reverseList(mid)` 的第一步就是 `mid.next = None`，**它顺手把前后两段断开了**，所以不需要额外写断开语句。代价是 `mid` 这个节点同时是前半段的尾和反转后后半段的尾——两段共用它。
> 
> 于是合并的循环条件必须是 `while head2.next`，**不能写 `while head2`**：走到 `head2` 是那个共用节点时就该停手，再往下接会让它指向自己，直接成环。

> [!success]- 143 代码
> 
> ```python
> class Solution:
>     def middleNode(self, head):
>         slow = fast = head
>         while fast and fast.next:
>             slow = slow.next
>             fast = fast.next.next
>         return slow
> 
>     def reverseList(self, head):
>         pre = None
>         cur = head
>         while cur:
>             nxt = cur.next
>             cur.next = pre
>             pre = cur
>             cur = nxt
>         return pre
> 
>     def reorderList(self, head: Optional[ListNode]) -> None:
>         mid = self.middleNode(head)
>         head2 = self.reverseList(mid)    # 顺带把 mid.next 置空 = 断开两段
>         while head2.next:                # 到共用节点就停，写成 while head2 会成环
>             nxt = head.next
>             nxt2 = head2.next
>             head.next = head2            # 前段节点 → 后段节点
>             head2.next = nxt             # 后段节点 → 前段的下一个
>             head = nxt
>             head2 = nxt2
> ```
> 
> - 主流程：中点 → 反转 → 每轮把后半段的一个节点插到前半段两个节点之间。
> - 关键变量：`nxt` / `nxt2` 必须**在改指针之前**同时存好，理由和 [[4.0 反转链表]] 里的 `nxt` 完全一样。
> - 边界：题目保证链表非空。`head` 为 `None` 时最后一行会抛异常，复用到别处记得补 `if not head or not head.next: return`。
> - 另一种等价写法是显式断开：`middleNode` 改用 `fast = head.next` 拿到**前半段末尾**，再 `head2 = mid.next; mid.next = None`。两种都对，选一种记熟即可，别混着写。

## 易错点

> [!warning]- 易错点
> 
> - **循环条件漏一半**：`while fast` 会在 `fast.next.next` 处抛 `AttributeError`；`while fast.next` 在 `fast` 已是 `None` 时同样崩。两个都要判，且顺序不能反。
> - **比的是值而不是身份**：写成 `slow.val == fast.val` 就错了——链表可以有重复值，判相遇只能用 `slow is fast`。
> - **相遇判断写在移动之前**：初始两指针同在 `head`，会立刻误判成有环。
> - **搞错偶数长度的中点**：`fast = head` 返回第二个中点，`fast = head.next` 返回第一个中点。题目要哪个就选哪个，别背死一种。
> - **说「a 是环长的整数倍」**：准确说法是 `a` 与 `c` 只差整数个环长，`a = (k-1)(b+c) + c`。
> - **重排链表反转了整条链**：`reverseList(head)` 会把前半段一起毁掉，必须从中点开始反转。
> - **重排链表的合并条件写成 `while head2`**：前后两段共用中点节点，多走一轮会让它指向自己，链表成环，判题直接超时。
> - **写成 `.nxt` 而不是 `.next`**：Python 不会报错，只是给对象**新增**一个属性，链表其实没被改动——这类 bug 最难查。

## 复杂度

> [!summary]- 复杂度
> 
> 四题同阶：时间 $O(n)$，空间 $O(1)$。
> 
> - 找中点 / 判环：指针最多把链表走两遍（`fast` 走 2 步，等于扫两趟）。
> - 找环入口：第一段最多 $O(n)$，第二段最多再走 `a + c` 步，仍是 $O(n)$。
> - 重排链表：找中点 $O(n)$ + 反转 $O(n)$ + 合并 $O(n)$，三段相加仍是 $O(n)$。
> - 空间全部是 $O(1)$——只用常数个指针，没有哈希表、没有数组、没有递归栈。**这正是快慢指针相对「哈希表记录访问过的节点」的唯一优势。**

## 一句话总结

快慢指针的本质是**用速度差换信息**：无环时快指针先到终点，于是慢指针落在中点；有环时快指针必定追上慢指针，而相遇位置满足 $a = (k-1)(b+c) + c$，于是再同速走一轮就能定位入口。

## 模板归纳

看到「**单链表 + 中点 / 成环 / 只允许 $O(1)$ 空间**」，三步落笔：

1. **先写骨架**（所有题都一样）：

```python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
```

2. **想清楚要在哪一刻取值**：
   - 循环**自然结束**时取 `slow` → 中点（876、143）。
   - 循环**中途** `slow is fast` → 有环（141）。
3. **要定位入口就再走一轮**：一个指针回 `head`，两人同速走，相遇即入口（142）。要拆链表就接 [[4.0 反转链表]] 的模板（143）。

```python
# 判环 + 找入口的完整骨架
slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next
    if slow is fast:                 # 有环
        while slow is not head:      # 同速走，第二次相遇即入口
            slow, head = slow.next, head.next
        return slow
return None                          # 无环
```
