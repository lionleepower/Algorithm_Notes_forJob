# 删除链表：前驱、哨兵与固定间距

## 解决什么问题

链表删除的本质只有一句话：**让前驱节点跳过目标节点**。

```python
prev.next = prev.next.next
```

被跳过的节点其实还在内存里，只是没人引用了；Python / Java 这类带垃圾回收的语言会自动回收它，C++ 则需要手动 `delete`，否则内存泄漏。

**难点从来不在这一句，而在于「怎么拿到前驱」**。整个专题就是围绕这个问题的三种回答：

| 题号 | 难度 | 前驱问题怎么解决 |
| --- | --- | --- |
| 237. 删除链表中的节点 | 中等 | **拿不到前驱** → 让当前节点伪装成下一个 |
| **19. 删除倒数第 N 个结点** | 中等 | 用**固定间距**的两个指针把「倒数」换算成「同步走」 |
| 83. 删除排序链表中的重复元素 | 简单 | 已排序 ⇒ 重复必相邻，`cur` 天然就是前驱 |
| **82. 删除排序链表中的重复元素 II** | 中等 | 头节点也可能被删 → 必须加 `dummy` |

## 统一模板：站在前驱上，该删就跳过

> [!tip]- 核心思路：`cur` 永远站在「待检查节点的前一个」
> 
> ```python
> dummy = ListNode(0, head)
> # 我一般更喜欢写成ListNode(next=head)      # 头节点可能被删时必须有它
> cur = dummy
> while cur.next:
>     if 该删掉 cur.next:
>         cur.next = cur.next.next    # 跳过，cur 原地不动
>     else:
>         cur = cur.next              # 保留，才前进
> return dummy.next
> ```
> 
> 两条纪律，几乎所有删除题的 bug 都出在这里：
> 
> 1. **循环变量站在前驱上，不是站在被检查的节点上**。判断条件写 `cur.next`，删除写 `cur.next = cur.next.next`。
> 2. **删完不要移动 `cur`**。删掉一个之后，新的 `cur.next` 是个**还没检查过**的节点；立刻前进就会漏掉连续重复的情况（`1 -> 1 -> 1` 只会删掉一个）。**只有在「决定保留」时才前进。**
> 
> **什么时候需要 `dummy`**：判据只有一条——**头节点是否可能被删**。可能就加，返回统一写 `dummy.next`；不可能就不用加（见下面 83 与 82 的对比）。`dummy` 的作用是让「删头节点」和「删中间节点」变成同一种接线操作，详见 [[Python_链表指针与区间反转]]。

## 变体一：237. 只给你一个节点

题目直接把待删节点 `node` 交给你，**拿不到 `head`，也就拿不到前驱**，并保证 `node` 不是尾节点。

> [!tip]- 拿不到前驱，就别删自己——删下一个
> 
> 既然改不了前驱的 `next`，那就换个目标：**把下一个节点的值抄过来，然后跳过下一个节点**。
> 
> ```python
> node.val = node.next.val      # 我伪装成下一个节点
> node.next = node.next.next    # 再把真正的下一个节点删掉
> ```
> 
> 从外部看，链表里那个值确实消失了；但被回收的是**下一个**节点对象，`node` 本身还活着。
> 
> **为什么不能写 `node = node.next`**：这只是把局部变量重新绑定到另一个对象，前驱的 `next` 一个字都没变，链表毫发无损（变量移动 vs 修改 `next` 的区别见 [[Python_链表指针与区间反转]]）。
> 
> **「保证不是尾节点」这个前提是必需的**：尾节点没有下一个可以抄，这招就失效了——那种情况只能靠前驱。

> [!success]- 237 代码
> 
> ```python
> class Solution:
>     def deleteNode(self, node):
>         node.val = node.next.val
>         node.next = node.next.next
> ```

## 变体二：19. 删除倒数第 N 个

![](assets/4.2%20前后指针固定间距.svg)

> [!tip]- 把「倒数」翻译成「间距」
> 
> 单链表只能往前走，数不出「倒数第几个」。但**两个指针之间的间距是恒定的**：让 `right` 先走 `n` 步，之后两人同速前进，间距永远是 `n`。
> 
> 于是 `right` 停在**尾节点**时，`left` 正好落在倒数第 `n+1` 个——**也就是待删节点的前驱**，正是我们要的东西。
> 
> 两个细节：
> 
> - **循环条件是 `while right.next`，不是 `while right`**。要让 `right` 停在尾节点（而不是越过它变成 `None`），`left` 才停在前驱上。写成 `while right` 会让 `left` 多走一步，删错节点。
> - **两个指针都从 `dummy` 出发**。这样 `n` 等于链表长度（即删头节点）时，`left` 停在 `dummy` 上依然有效，不需要任何特判。

> [!success]- 19 代码
> 
> ```python
> class Solution:
>     def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
>         dummy = ListNode(next=head)
>         right = dummy
>         for _ in range(n):              # 先拉开 n 的间距
>             right = right.next
> 
>         left = dummy
>         while right.next:               # right 停在尾节点
>             left = left.next
>             right = right.next
> 
>         left.next = left.next.next      # left 是待删节点的前驱
>         return dummy.next
> ```
> 
> - 主流程：拉开间距 → 同步走到底 → 前驱跳过。
> - 关键变量：`right` 只负责制造间距，`left` 才是真正干活的前驱。
> - 易错位置：`while right` 写成 `while right.next` 之外的形式；返回 `head` 而不是 `dummy.next`（删掉头节点时 `head` 已经是野指针）。

## 变体三：83 / 82 排序链表去重（对照着记）

两题的输入完全一样，**只差「重复的留不留一个」**，但代码结构差别很大。

> [!tip]- 关键分水岭：头节点会不会被删
> 
> | | 83. 重复只保留一个 | 82. 重复的全部删掉 |
> | --- | --- | --- |
> | `1 -> 1 -> 2 -> 3 -> 3` | `1 -> 2 -> 3` | `2` |
> | 头节点会被删吗 | **不会**（重复至少留一个） | **会**（`1 -> 1 -> 2` 的头就被删了） |
> | 需要 `dummy` 吗 | 不需要 | **必须** |
> | `cur` 站在哪 | 站在**保留区的最后一个**节点上 | 站在**待检查区间的前驱**上 |
> | 比较谁 | `cur.val` 与 `cur.next.val` | `cur.next.val` 与 `cur.next.next.val` |
> | 返回 | `head` | `dummy.next` |
> 
> 两题共享的前提是同一个：**链表已排序 ⇒ 相同的值必然连续出现**，所以只用比相邻的，不需要哈希表。
> 
> 82 为什么要往前看**两个**（`cur.next.next`）：它必须在**动手之前**就判断出「这一段是不是重复段」。只看一个的话，等发现重复时第一个节点已经被 `cur` 认领成保留节点了，收不回来。

> [!success]- 83：重复只保留一个
> 
> ```python
> class Solution:
>     def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
>         if head is None:
>             return head
>         cur = head
>         while cur.next:
>             if cur.next.val == cur.val:
>                 cur.next = cur.next.next   # 删掉重复的那个，cur 不动
>             else:
>                 cur = cur.next             # 值不同才前进
>         return head
> ```
> 
> - 关键变量：`cur` 是「已确定保留」的最后一个节点，它自己永远不会被删——所以不需要 `dummy`。
> - 易错位置：删完立刻 `cur = cur.next` 会漏掉三连及以上的重复（`1 -> 1 -> 1`）。
> - 头节点判空是必需的：`while cur.next` 在 `cur` 为 `None` 时会抛异常。

> [!success]- 82：重复的一个都不留
> 
> ```python
> class Solution:
>     def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
>         dummy = ListNode(next=head)
>         cur = dummy
>         while cur.next and cur.next.next:
>             val = cur.next.val
>             if cur.next.next.val == val:          # 发现重复段
>                 while cur.next and cur.next.val == val:
>                     cur.next = cur.next.next      # 把值等于 val 的全部删光
>             else:
>                 cur = cur.next                    # 不重复才前进
>         return dummy.next
> ```
> 
> - 主流程：往前看两个 → 发现重复就记下 `val` → 内层一次性删光所有等于 `val` 的 → 否则前进一步。
> - 关键变量：`val` 必须**先存下来**，因为内层删除会不断改变 `cur.next`，边删边读 `cur.next.val` 会读到已经换掉的节点。
> - 易错位置：内层 `while` 里不能移动 `cur`（它是整个重复段的前驱，要一直站在原地）；内层的 `cur.next and` 不能省，删到链表末尾时 `cur.next` 会变成 `None`。

## 易错点

> [!warning]- 易错点
> 
> - **删完立刻移动指针**：删除后新的 `cur.next` 还没检查过，立刻前进会漏删连续重复。纪律是「**删了不动，留了才走**」。
> - **该用 `dummy` 却没用**：判据是「头节点是否可能被删」。82、19 必须用；83 不用（重复至少保留一个，头不会消失）。
> - **返回 `head` 而不是 `dummy.next`**：一旦头节点被删，`head` 指向的就是已经不在链表里的节点。
> - **19 的循环条件写成 `while right`**：`right` 会越过尾节点变成 `None`，`left` 多走一步，删成倒数第 `n-1` 个。
> - **82 边删边读 `cur.next.val`**：必须先把重复值存进 `val`，否则内层第一次删除后读到的就不是原来那个值了。
> - **82 内层漏了 `cur.next and`**：重复段一直延伸到链表末尾时，`cur.next` 变 `None`，再读 `.val` 抛异常。
> - **237 写成 `node = None` 或 `node = node.next`**：只改了局部变量绑定，链表结构没有任何变化。
> - **以为「删除」是把节点从内存里抹掉**：链表删除只是断开引用；C++ 里还要手动 `delete`，Python 交给垃圾回收。

## 复杂度

> [!summary]- 复杂度
> 
> | 题 | 时间 | 空间 | 来源 |
> | --- | --- | --- | --- |
> | 237 | $O(1)$ | $O(1)$ | 只碰当前节点和它的下一个 |
> | 19 | $O(n)$ | $O(1)$ | 两个指针合计走一趟半，仍是线性 |
> | 83 | $O(n)$ | $O(1)$ | 每个节点最多被访问一次 |
> | 82 | $O(n)$ | $O(1)$ | 虽有内层 `while`，但每个节点**最多被删或跳过一次**，摊还仍是线性 |
> 
> 全部是 $O(1)$ 额外空间——没有哈希表、没有新建节点（`dummy` 是常数个）、没有递归栈。

## 一句话总结

链表删除只有一个动作——**让前驱跳过目标**；四道题的差别全在「怎么拿到前驱」：拿不到就伪装成下一个（237），倒数第几个就用固定间距换算（19），排序去重就让 `cur` 停在前驱上（83 / 82），而只要**头节点可能被删**，就先加 `dummy`。

## 模板归纳

看到「**单链表 + 删除若干节点**」，三步落笔：

1. **问一句：头节点可能被删吗？** 可能 → 先写 `dummy = ListNode(next=head)`，最后 `return dummy.next`；不可能 → 直接用 `head`。
2. **让循环变量站在前驱上**，条件写 `while cur.next`（往前看两个就再加 `and cur.next.next`）。
3. **删了不动，留了才走**：

```python
dummy = ListNode(next=head)
cur = dummy
while cur.next:
    if 该删(cur.next):
        cur.next = cur.next.next     # 删掉，cur 原地不动
    else:
        cur = cur.next               # 保留，才前进
return dummy.next
```

两个特例单独记：**拿不到前驱**（237）就抄下一个节点的值再跳过它；**倒数第 n 个**（19）就让 `right` 先走 `n` 步，再同步走到 `right.next` 为空。
