# 链表进阶：合并、归并排序与随机链表复制

## 解决什么问题

链表进阶题只有三个新动作，Hot100 的 21 / 23 / 148 / 138 全在里面：

| 动作 | 关键工具 | 题 |
| --- | --- | --- |
| **两路合并** | 哨兵 + 尾插 | 21. 合并两个有序链表 |
| **多路合并** | 分治 或 最小堆 | 23. 合并 K 个升序链表 |
| **原地归并排序** | 快慢指针找中点 + 断开 | 148. 排序链表 |
| **带附加指针的深拷贝** | 哈希映射 或 节点交织 | 138. 随机链表的复制 |

一条主线：**21 是原子操作，23 和 148 都是「把问题拆成若干次 21」**。先把 21 写到闭着眼能写，后两题才有意义。

## 变体一：21. 合并两个有序链表（原子操作）

> [!tip]- 核心思路：哨兵 + 一个尾指针，永远只做「接上更小的那个」
>
> 不用哨兵就要处理「结果链表还是空的」这个特例，每次尾插都得判一次。哨兵 `dummy` 让「尾指针」从第一步起就合法——同 [[4.2 删除链表]]。
>
> **不变量**：`cur` 始终指向已合并部分的最后一个节点；`l1` / `l2` 始终指向各自剩余部分的第一个节点。
>
> 循环结束时**必有一条链走空**，直接把另一条整体接上即可（链表的天然优势：不用像数组那样逐个搬运）。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def mergeTwoLists(self, l1, l2):
>         dummy = ListNode()
>         cur = dummy
>         while l1 and l2:
>             if l1.val <= l2.val:       # <= 而非 < ：保持稳定性
>                 cur.next, l1 = l1, l1.next
>             else:
>                 cur.next, l2 = l2, l2.next
>             cur = cur.next
>         cur.next = l1 or l2            # 剩下的整条接上
>         return dummy.next
> ```
>
> **易错位置**：忘记 `cur = cur.next`（尾指针不动，后面全被覆盖）；返回 `dummy` 而不是 `dummy.next`。

## 变体二：23. 合并 K 个升序链表

> [!tip]- 核心思路：两种解法，复杂度相同，说清取舍才算会
>
> 设总节点数 $N$，链表数 $k$。
>
> **解法 A：分治两两合并**（推荐主答）
> 像归并排序的合并层：第一轮 $k$ 条合成 $k/2$ 条，第二轮 $k/4$……共 $\log k$ 轮，每轮所有节点各被扫一次。
>
> $$O(N \log k)$$
>
> **为什么不能顺序合并**：用结果依次和第 `i` 条合并，第 `i` 条的节点会被后续反复扫描，退化成 $O(Nk)$。
>
> **解法 B：最小堆**
> 把 $k$ 条链表的头节点全部入堆，每次弹出最小的接到结果上，再把它的 `next` 推进去。堆里恒有 $\le k$ 个元素，每个节点进出堆各一次：同样 $O(N\log k)$。
>
> **Python 的坑**：`ListNode` 没有实现 `__lt__`，元组 `(val, node)` 在 `val` 相同时会去比较 `node` 而抛 `TypeError`。修法是插入一个**唯一序号**做防撞键：`(node.val, i, node)`。详见 [[c++python 堆与栈]]。
>
> **取舍**：分治不需要额外结构、常数更小；堆的写法在「链表数据流式到达」时更自然。面试给分治，被追问再给堆。

> [!success]- 代码实现（分治 + 堆两版）
>
> ```python
> class Solution:
>     def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
>         def merge(a, b):                    # 就是变体一
>             dummy = cur = ListNode()
>             while a and b:
>                 if a.val <= b.val:
>                     cur.next, a = a, a.next
>                 else:
>                     cur.next, b = b, b.next
>                 cur = cur.next
>             cur.next = a or b
>             return dummy.next
>
>         def divide(lo: int, hi: int):       # 闭区间 [lo, hi]
>             if lo > hi:
>                 return None
>             if lo == hi:
>                 return lists[lo]
>             mid = (lo + hi) // 2
>             return merge(divide(lo, mid), divide(mid + 1, hi))
>
>         return divide(0, len(lists) - 1)
> ```
>
> 堆版：
>
> ```python
> import heapq
>
> def mergeKLists(self, lists):
>     h = [(node.val, i, node) for i, node in enumerate(lists) if node]
>     heapq.heapify(h)                        # O(k) 建堆
>     dummy = cur = ListNode()
>     while h:
>         _, i, node = heapq.heappop(h)
>         cur.next = node
>         cur = node
>         if node.next:
>             heapq.heappush(h, (node.next.val, i, node.next))
>     return dummy.next
> ```
>
> **易错位置**：堆版必须先过滤掉 `None`（空链表）；元组的第二位 `i` 是防撞键，不能省。

## 变体三：148. 排序链表

要求 $O(n\log n)$ 时间、$O(1)$ 额外空间。

> [!tip]- 核心思路：链表天生适合归并排序，快排反而难写
>
> **为什么是归并不是快排**：快排依赖**随机访问**来做分区和取 pivot，链表做不到；而归并的合并操作在链表上**只改指针、不搬数据**，甚至比数组版更省空间（数组归并需要 $O(n)$ 辅助数组）。
>
> **自顶向下（递归）三步**
> 1. **找中点并断开**：快慢指针（[[4.1 快慢指针，环形链表]]），但这里要拿到**中点的前驱**才能断链。
> 2. 递归排序左右两半。
> 3. 用变体一的 `merge` 接起来。
>
> **断链是本题的命门**：不断开的话左半部分仍连着右半部分，递归永远看到整条链，**死循环**。
>
> **自底向上（迭代）是 $O(1)$ 空间的真正答案**：递归版的栈是 $O(\log n)$，严格说不满足 $O(1)$。迭代版按步长 `1, 2, 4, 8, ...` 逐层合并，不用递归栈。能说出这个区别是加分项，现场写递归版即可。

> [!success]- 代码实现（自顶向下）
>
> ```python
> class Solution:
>     def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
>         if not head or not head.next:            # 0 或 1 个节点，天然有序
>             return head
>
>         # 1. 快慢指针找中点前驱，然后断开
>         slow, fast = head, head.next             # fast 先走一步：保证 slow 落在左半的末尾
>         while fast and fast.next:
>             slow = slow.next
>             fast = fast.next.next
>         mid = slow.next
>         slow.next = None                         # 断链！漏了必死循环
>
>         # 2. 分别排序
>         left = self.sortList(head)
>         right = self.sortList(mid)
>
>         # 3. 合并
>         dummy = cur = ListNode()
>         while left and right:
>             if left.val <= right.val:
>                 cur.next, left = left, left.next
>             else:
>                 cur.next, right = right, right.next
>             cur = cur.next
>         cur.next = left or right
>         return dummy.next
> ```
>
> **关键细节**：`fast = head.next` 而不是 `head`。若两者都从 `head` 起步，两个节点的链会切成「空 + 两个」，递归参数没变小，**无限递归**。
> 验证用例：`[2, 1]`——这是唯一能暴露该 bug 的最小用例。

## 变体四：138. 随机链表的复制

每个节点除 `next` 外还有一个 `random` 指针，指向链表中任意节点或 `null`，要求深拷贝。

> [!tip]- 核心思路：难点是「拷贝时目标节点还没被创建」
>
> 顺序遍历建新节点时，`random` 可能指向后面尚未创建的节点——**指针无处可指**。两种破法：
>
> **解法 A：哈希映射（推荐）**
> 两遍遍历：第一遍只建节点并记下 `原节点 -> 新节点` 的映射；第二遍再用这张表把 `next` 和 `random` 一次性接好。
> 本质是**先把所有节点造出来，再谈连线**——「建点」与「连边」分离，是图/链表深拷贝的通用套路。
>
> ```python
> class Solution:
>     def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
>         if not head:
>             return None
>         mp = {}
>         cur = head
>         while cur:                                  # 第一遍：只建点
>             mp[cur] = Node(cur.val)
>             cur = cur.next
>         cur = head
>         while cur:                                  # 第二遍：连边
>             mp[cur].next = mp.get(cur.next)         # get 顺手处理 None
>             mp[cur].random = mp.get(cur.random)
>             cur = cur.next
>         return mp[head]
> ```
>
> **解法 B：节点交织，$O(1)$ 空间**
> 三步：① 把新节点插在每个原节点后面，变成 `A -> A' -> B -> B' -> ...`；② `A'.random = A.random.next`（原节点的 random 的下一个正好是它的副本）；③ 拆分成两条链。
> 空间 $O(1)$，但三趟遍历都容易写错，**面试先给 A，被问到空间再给 B**。

## 易错点

> [!warning]- 易错点
>
> **1. 148 找中点不断链**
> 最高频错误，表现为超时或栈溢出，且小用例可能侥幸通过。
>
> **2. 148 的 `fast` 起点写成 `head`**
> `[2,1]` 直接无限递归。记忆法：**要中点前驱，就让 `fast` 先走一步。**
>
> **3. 23 顺序合并**
> 能 AC 但 $O(Nk)$，被追问复杂度时才发现——必须分治或用堆。
>
> **4. 堆里放了不可比较的对象**
> `(val, node)` 撞值即 `TypeError`。加序号。
>
> **5. 138 只拷贝 `next`**
> 建好链后再补 `random` 时，若没有映射表就只能 $O(n)$ 定位每个 random，总计 $O(n^2)$。
>
> **6. 138 用 `mp[cur.next]` 而不是 `mp.get(cur.next)`**
> 末节点的 `next` 是 `None`，字典里没有这个键，直接 `KeyError`。要么用 `get`，要么预置 `mp[None] = None`。
>
> **7. 合并类题目忘了 `cur = cur.next`**
> 尾指针不前移，每次都覆盖同一个 `next`，结果只剩两个节点。
>
> **8. 返回 `dummy` 而不是 `dummy.next`**
> 输出会多一个值为 0 的头节点。写完扫一眼 `return`。

## 复杂度

> [!summary]- 复杂度
>
> - **21**：时间 $O(n + m)$ —— 每个节点只被接一次；空间 $O(1)$（只改指针）。
> - **23**：时间 $O(N\log k)$ —— 分治 $\log k$ 层、每层扫 $N$ 个节点；或堆中恒有 $\le k$ 个元素、每节点进出堆各一次。空间：分治 $O(\log k)$ 递归栈，堆 $O(k)$。
> - **148**：时间 $O(n\log n)$ —— $\log n$ 层，每层合并总代价 $O(n)$；空间 $O(\log n)$ 递归栈（自底向上版为 $O(1)$）。
> - **138**：解法 A 时间 $O(n)$、空间 $O(n)$（映射表）；解法 B 时间 $O(n)$、空间 $O(1)$。

## 一句话总结

链表进阶只有一个原子操作——**哨兵 + 尾插的两路合并**；23 是「合并做 $\log k$ 层」，148 是「先劈开再合并」，而 138 的破法是**把「建点」和「连边」拆成两遍**。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 「合并 / 归并 / 有序链表」$\to$ 哨兵 + 尾插，先写 `merge(a, b)`
- 「K 路」$\to$ 分治（$\log k$ 层）或最小堆，**绝不顺序合并**
- 「链表排序」$\to$ 归并（不是快排），先找中点**并断开**
- 「深拷贝 / 带额外指针」$\to$ 哈希映射，**建点与连边分两遍**

**落笔三步**

1. 一律先写 `dummy = cur = ListNode()`，最后 `return dummy.next`。
2. 涉及切分时，把「断链」那一行**单独写一行并加注释**——它是最容易被顺手漏掉的一步。
3. 写完用 `[]`、`[1]`、`[2,1]` 三个用例过一遍：空、单点、恰好触发中点边界。
