# 二叉树的构造与展开：105 / 108 / 114

## 解决什么问题

前面的树题都是**给树、求答案**；这一类反过来——**给序列、造树**，或**把树改造成另一种形状**。考的是同一件事：**遍历序列与树结构的对应关系**。

| 题 | 输入 $\to$ 输出 | 关键洞察 |
| --- | --- | --- |
| 105. 从前序与中序构造 | 两个序列 $\to$ 树 | 前序给**根**，中序给**左右分界** |
| 108. 有序数组转 BST | 有序数组 $\to$ 平衡 BST | 有序数组就是 BST 的**中序**；取中点当根 |
| 114. 展开为链表 | 树 $\to$ 单链（右斜） | 顺序是**前序**，倒着遍历改指针 |

## 变体一：105. 从前序与中序遍历序列构造二叉树

> [!tip]- 核心思路：前序定根，中序切分左右
> 
> - **前序 Preorder `[根 | 左子树… | 右子树…]`** $\to$ 第一个元素是根
> - **中序 Inorder `[左子树… | 根 | 右子树…]`** $\to$ 找到根的位置，左边全是左子树、右边全是右子树，顺便知道了**左子树大小 $L$**
> 
> 有了 $L$，前序也能切成 `[根][左 L 个][右剩下]`，两边各自递归。
> 
> **追问：为什么「前序 + 后序」不行**——两者都分不出左右边界（只有一个孩子时无法区分是左是右），答案不唯一。**中序是必需品。**

> [!example]- 示例推演：`preorder = [3,9,20,15,7]`，`inorder = [9,3,15,20,7]`
> 
> ```text
> 前序首元素 3 是根
> 中序里 3 在下标 1  ->  左子树 1 个节点，右子树 3 个节点
> 
>   左：前序 [9]        中序 [9]          -> 叶子 9
>   右：前序 [20,15,7]  中序 [15,20,7]
>        根 20，中序里 20 在下标 1 -> 左 [15]，右 [7]
> 
>        3
>       / \
>      9   20
>         /  \
>        15   7
> ```

> [!success]- 第一版：切片写法（先写这版，理解思路）
> 
> ```python
> class Solution:
>     def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
>         if not preorder:                             # 两序列长度始终相等，判哪个都行；下一行要读 preorder[0]，判它更直接
>             return None
>         root = TreeNode(preorder[0])                 # 前序首元素是根
>         mid = inorder.index(preorder[0])             # 根在中序中的位置，也就是左子树大小
>         root.left  = self.buildTree(preorder[1:mid+1], inorder[:mid])
>         root.right = self.buildTree(preorder[mid+1:], inorder[mid+1:])
>         return root
> ```
> 
> **四个切片怎么来的**（以 `preorder = [3,9,20,15,7]`，`inorder = [9,3,15,20,7]` 为例，`mid = 1`）
> 
> `mid` 是根在中序里的下标，根前面全是左子树，所以 **`mid` 同时就是左子树的节点个数**。
> 
> ```text
> 中序按「根的位置」切：
>   inorder = [9, 3, 15, 20, 7]
>              ↑  ↑  ↑
>            左  根  右
>   inorder[:mid]   = [9]           根左边的
>   inorder[mid+1:] = [15, 20, 7]   根右边的（mid 是根本身，跳过）
> 
> 前序按「左子树的个数」切（前序自己看不出左子树到哪结束，靠 mid 借来的信息）：
>   preorder = [3, 9, 20, 15, 7]
>               ↑  ↑   ↑
>              根  左   右
>   preorder[1:mid+1] = [9]           跳过根，取接下来的 mid 个（切片右端不含，所以 +1）
>   preorder[mid+1:]  = [20, 15, 7]   剩下的全是右子树
> ```
> 
> 切出来的「左子树前序 + 左子树中序」「右子树前序 + 右子树中序」又是原问题的形态，递归即可。
> 
> 记法：**中序按根的位置切，前序按左子树个数切**——两者恰好都是 `mid`。
> 
> 代码和思路一一对应，能 AC。两个成本：`index` 每层线性查找、切片每层拷贝数组，最坏（链状树）$O(n^2)$。

> [!success]- 第二版：哈希表 + 下标（面试版，$O(n)$）
> 
> 只改两处：`index` 换成预建的 `dic`，切片换成传下标。
> 
> ```python
> class Solution:
>     def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
>         dic = {v: i for i, v in enumerate(inorder)}     # 值 -> 中序下标，O(1) 定位根
> 
>         def recur(root: int, left: int, right: int) -> Optional[TreeNode]:
>             """root：当前子树在前序中的起点；[left, right]：当前子树在中序中的闭区间"""
>             if left > right:
>                 return None
>             node = TreeNode(preorder[root])
>             i = dic[preorder[root]]                      # 根在中序中的位置
>             node.left  = recur(root + 1, left, i - 1)
>             node.right = recur(root + 1 + (i - left), i + 1, right)   # 前序起点跳过根 + 整棵左子树
>             return node
> 
>         return recur(0, 0, len(inorder) - 1)
> ```
> 
> - **为什么前序不用传终点**：子树有多大已经由中序区间 `[left, right]` 决定，前序只需知道「从哪开始读」。
> - **唯一要动脑的一行**：右子树在前序中的起点 $=$ `root + 1 + 左子树大小`，左子树大小 $=$ `i - left`。
> - **前提**：节点值互不相同（105 保证了），否则 `dic` 会覆盖；面试时主动说出来。

## 变体二：108. 将有序数组转换为二叉搜索树

> [!tip]- 核心思路：有序数组 = BST 的中序序列；取中点当根就平衡了
> 
> 1. BST 的中序遍历严格递增（见 [[5.3 二叉搜索树]]）$\Rightarrow$ 有序数组**就是**目标树的中序序列。
> 2. 要求**高度平衡** $\Rightarrow$ 左右子树节点数尽量相等 $\Rightarrow$ 根取**中点**。
> 
> ```python
> class Solution:
>     def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:
>         def build(lo: int, hi: int) -> Optional[TreeNode]:   # 闭区间 [lo, hi]
>             if lo > hi:
>                 return None
>             mid = (lo + hi) // 2
>             node = TreeNode(nums[mid])
>             node.left  = build(lo, mid - 1)
>             node.right = build(mid + 1, hi)
>             return node
>         return build(0, len(nums) - 1)
> ```
> 
> **和 105 是同一个模子**：都是「定根 $\to$ 切两半 $\to$ 递归」，只是 105 的根由前序给出，108 的根由「要平衡」指定。`mid` 左偏右偏都能过，答案不唯一。
> 
> **追问：109 有序链表转 BST**——链表不能 $O(1)$ 取中点：快慢指针找中点（$O(n\log n)$），或**按中序顺序边遍历链表边建树**（$O(n)$，更漂亮）。

## 变体三：114. 二叉树展开为链表

把树原地改成「全部右孩子相连」的单链，顺序与**前序遍历**一致。

> [!tip]- 核心思路：正着做会丢右子树，所以倒着做
> 
> 直觉写法：处理根 $\to$ 展开左 $\to$ 展开右。但**一旦把左子树接到 `root.right` 上，原来的右子树就找不到了**。
> 
> **推荐解法：按前序的逆序（右 $\to$ 左 $\to$ 根）访问，用 `prev` 记住上一个访问的节点**：
> 
> ```python
> class Solution:
>     def flatten(self, root: Optional[TreeNode]) -> None:
>         self.prev = None
>         def dfs(node):
>             if not node:
>                 return
>             dfs(node.right)        # 先右
>             dfs(node.left)         # 再左
>             node.right = self.prev # 根：接上「后一个」节点
>             node.left = None
>             self.prev = node
>         dfs(root)
> ```
> 
> 为什么不会丢：**改写 `node.right` 之前，两棵子树都已经处理完了**——这正是后序位置的意义（见 [[5.0 递归算法]]）。
> 
> **追问 $O(1)$ 空间**：对每个节点，找到其左子树的**最右节点**，把原右子树接到它下面，再把左子树整体挪到右边。
> 
> ```python
> def flatten(self, root):
>     cur = root
>     while cur:
>         if cur.left:
>             pre = cur.left
>             while pre.right:            # 左子树的最右节点
>                 pre = pre.right
>             pre.right = cur.right       # 原右子树挂到它后面
>             cur.right = cur.left        # 左子树整体右移
>             cur.left = None
>         cur = cur.right
> ```

## 易错点

> [!warning]- 易错点
> 
> **1. 105 右子树前序起点写成 `i + 1`**
> `i` 是中序里的下标，前序里要从 `root + 1 + (i - left)` 开始；混用两个序列的下标是本题头号错误。
> 
> **2. 105 递归终止写漏**
> 第一版靠 `not preorder`，第二版靠 `left > right`；漏了就 `RecursionError`。
> 
> **3. 108 用 `sorted(nums)`**
> 输入已有序，多此一举；若输入无序题目就变了（无序数组建 BST 无法保证平衡）。
> 
> **4. 114 忘记 `node.left = None`**
> 题目要求左指针全为 `null`，留着旧左指针输出的是一棵怪树。
> 
> **5. 114 用正序前序 + 就地改指针**
> 改完 `root.right` 后原右子树丢失。要么先存变量，要么改成逆序遍历。
> 
> **6. 递归里用普通局部变量当 `prev`**
> 闭包里赋值会创建新局部变量，必须用 `self.prev` 或 `nonlocal`——见 [[Python_nonlocal与闭包]]。

## 复杂度

> [!summary]- 复杂度
> 
> - **105 第一版**：最坏 $O(n^2)$ —— 链状树时每层 `index` 查找 + 切片拷贝都是 $O(n)$，共 $n$ 层。
> - **105 第二版**：时间 $O(n)$ —— 哈希表定位根 $O(1)$，每个节点恰好构造一次；空间 $O(n)$ —— 哈希表 + 递归栈 $O(h)$。
> - **108**：时间 $O(n)$ —— 每个元素恰好当一次根；空间 $O(\log n)$ 递归栈（树平衡）。
> - **114**：递归版时间 $O(n)$、空间 $O(h)$；迭代版时间 $O(n)$（每条边最多走两次）、空间 $O(1)$。

## 一句话总结

构造类题目的全部信息量在于「**谁是根、左右怎么分**」：前序给根、中序给分界、有序数组用中点保平衡；114 的教训是——**要就地改指针，就先把递归做完，再在后序位置动手**。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 「给两个遍历序列，构造树」$\to$ 先问**哪个序列给根、哪个给分界**；没有中序就先怀疑答案不唯一
- 「有序数组 / 有序链表 $\to$ 平衡 BST」$\to$ 取中点当根，天然平衡
- 「原地把树变成另一种结构」$\to$ 想清楚**改指针会不会弄丢还没访问的子树**；会，就改用后序或逆序

**构造两步**

1. 先用切片写出能 AC 的版本，确认「定根 $\to$ 切两半 $\to$ 递归」的思路。
2. 再升级：哈希表定位根 + 传下标代替切片；下标区间只写一种约定（闭区间或左闭右开），所有端点由「左子树大小」推出。
