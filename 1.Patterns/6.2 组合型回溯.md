# 组合型回溯

## 解决什么问题

从 $n$ 个候选里**恰好选 $k$ 个**、元素无顺序——组合 Combination。相对 [[6.1 子集型回溯]] 只多了一条长度约束 $|path| = k$，但正是这条约束带来了剪枝 Pruning 的空间：**剩下的数不够凑齐 $k$ 个时，整棵子树可以提前砍掉**，方案数从 $2^n$ 收缩到 $C(n,k)$ 量级。

## 统一模板：倒序枚举

答案视角「枚举下一个选谁」，但让候选池从大往小收缩：`dfs(i)` 表示候选池只剩 $[1, i]$，从中再挑 `d = k - len(path)` 个； ==另外面对这类问题，我们往往还可以往dfs中多去加入几个参数来解决，例如dfs(t,n)==。

> [!tip]- 核心思路：让「剩余可选个数」等于参数本身
> 
> 倒序枚举下，候选池 $[1, i]$ 的大小**就是 `i`**。于是组合最关键的剪枝——「剩的不够凑齐 $k$ 个就撤」——直接写成 `if i < d: return`，零换算、一眼可读。
> 
> 正序版候选池是 $[i, n]$，大小 $n - i + 1$，同一条剪枝要写成 `n - i + 1 < d`，多一层算术，`+1` 容易弄错。

> [!success]- 77. 组合（倒序 + 剪枝完整版）
> 
> ```python
> class Solution:
>     def combine(self, n: int, k: int) -> List[List[int]]:
>         ans = []
>         path = []
>         def dfs(i):
>             d = k - len(path)              # 还需要选几个
>             if d == 0:
>                 ans.append(path.copy())
>                 return
>             if i < d:                      # 剪枝：剩下的数不够了
>                 return
>             for j in range(i, d - 1, -1):  # j 一路取到 d 为止
>                 path.append(j)
>                 dfs(j - 1)
>                 path.pop()
>         dfs(n)
>         return ans
> ```
> 
> - 主流程：每层枚举「下一个选谁」，选了 `j` 后候选池收缩为 $[1, j-1]$。
> - 关键变量：`d` 是还差几个；`append`/`pop` 成对夹住递归，见 [[状态恢复]]。
> - 易错位置：`range` 的 stop 写 `d - 1` 是开区间偏移——数学约束是 $j \ge d$，推导见 [[剪枝]] 与 [[Python_range]]。

## 为什么「可以」倒序，为什么「偏爱」倒序

**倒序不是必须的**：正序从 `dfs(1)` 开始、`for j in range(i, n + 1): dfs(j + 1)` 同样正确——两者是同一棵搜索树换了遍历顺序（见 [[递归树]]），不变量都是「候选池只剩某个区间，从中再挑 $d$ 个」。偏爱倒序有两个理由：

1. **剪枝写起来更顺**——剩余可选个数就是 `i` 本身（上面 tip 已展开）。这纯粹是可读性和剪枝便利，不是正确性要求。
2. **天然对应组合数递推** $C(n,k) = C(n-1,k-1) + C(n-1,k)$：站在数字 $n$ 面前只问「选它 / 不选它」，两条分支都把规模降到 $n-1$；正序要绕一下才能对上这个式子。

## 剪枝的两个位置

`if i < d: return`（入口拦截）和 `range(i, d - 1, -1)`（不让 `j` 走进无效区）是**同一个剪枝的两个等价位置**——只留一处也对，两处都写只是更保险。推导细节单独拆在 [[剪枝]]。

> [!example]- 推演：n = 4, k = 2 的剪枝效果
> 
> ```text
> dfs(4)  d=2 → j 取 4, 3, 2（j=1 被剪：选 1 后池子空了还差 1 个）
> ├─ j=4 → dfs(3)  d=1 → j 取 3, 2, 1 → 收 [4,3] [4,2] [4,1]
> ├─ j=3 → dfs(2)  d=1 → j 取 2, 1    → 收 [3,2] [3,1]
> └─ j=2 → dfs(1)  d=1 → j 取 1       → 收 [2,1]
> ```
> 
> 恰好 $C(4,2) = 6$ 个答案，没有一条白跑的分支。

## 典型变体

### 变体一：77. 组合，换「选 / 不选」的切法

骨架换成 [[6.1 子集型回溯]] 的输入视角：站在数字 `i` 面前问选不选。「什么不变」：剪枝条件 `i < d` 原样保留。「什么改变」：**边界必须显式写**——循环版池子空了 range 自动为空，二叉版没有循环兜底，「不选」分支只有 `i` 在变，不写边界就一路 `i-1` 掉下去直到爆栈。

> [!success]- 77. 组合（选 / 不选版）
> 
> ```python
> class Solution:
>     def combine(self, n: int, k: int) -> List[List[int]]:
>         ans = []
>         path = []
>         def dfs(i):
>             d = k - len(path)
>             if d == 0:
>                 ans.append(path.copy())
>                 return
>             if i < d:                # 一条语句同时承担边界(i==0)和剪枝
>                 return
>             dfs(i - 1)               # 不选 i
>             path.append(i)           # 选 i
>             dfs(i - 1)
>             path.pop()
>         dfs(n)
>         return ans
> ```
> 
> - 两个 `return` 的顺序不能反：先判成功（选够 $k$ 个），再判失败——反过来，最后一个数刚好在池子见底前一层选中的方案会被误杀。
> - `if i == 0` 只是 `if i < d` 的弱化版，被后者包含，见 [[剪枝]]。

### 变体二：216. 组合总和 III

「什么不变」：倒序枚举骨架、长度约束照旧。「什么改变」：多带一个参数 `t`（剩余目标和），多一条约束剪枝 `t < 0`；收答案要同时满足「选够 $k$ 个」和「和恰好用完」。

> [!success]- 216. 组合总和 III
> 
> ```python
> class Solution:
>     def combinationSum3(self, k: int, n: int) -> List[List[int]]:
>         ans = []
>         path = []
>         def dfs(i, t):
>             if t < 0:                    # 剪枝：候选全为正，和超了救不回来
>                 return
>             if len(path) == k:
>                 if t == 0:
>                     ans.append(path.copy())
>                 return
>             for j in range(i, 0, -1):
>                 path.append(j)
>                 dfs(j - 1, t - j)
>                 path.pop()
>         dfs(9, n)
>         return ans
> ```
> 
> - 选/不选版的坑：「不选」分支 `path` 不增长、`t` 不减小，唯一在变的是 `i`——**池子空了必须自己收手**（`if i == 0 or t < 0: return`），循环版这个边界藏在 range 里是免费的。
> - 进一步可加可行性剪枝 `i < k - len(path)`，与 77 完全同一条。

### 变体三：39. 组合总和 —— 元素可以重复使用

给定**互不相同**的候选数组和目标 `target`，同一个数**可以被无限次选取**，返回所有和为 `target` 的组合。

「什么不变」：选 / 不选的二叉骨架、`t` 参数、`t < 0` 剪枝，全部照抄 216。「什么改变」——**只改一个字母**：

![](assets/6.2%20选了之后%20i%20往哪走.svg)

前面 77 / 216 的「选中」分支都写 `dfs(i-1, ...)`（倒序）或 `dfs(i+1, ...)`（正序），下标单调前进，所以每个数最多用一次。39 只要把这一处改成 `dfs(i, ...)`：下标**原地不动**，下一层还能再选同一个数，重复几次由剩余的 `t` 自己决定。

![](assets/6.2%20组合总和%20原地重选.svg)

> [!success]- 39. 组合总和（选 / 不选版）
> 
> ```python
> class Solution:
>     def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
>         n = len(candidates)
>         ans, path = [], []
>         def dfs(i, t):
>             if t == 0:                       # 先判成功
>                 ans.append(path.copy())
>                 return
>             if i == n or t < 0:              # 再判失败：候选用尽 / 超额
>                 return
>             dfs(i + 1, t)                    # 不选 candidates[i]，从此不再考虑它
>             path.append(candidates[i])
>             dfs(i, t - candidates[i])        # 选，且仍可再选 ← 全篇唯一的 i 不变
>             path.pop()
>         dfs(0, target)
>         return ans
> ```
> 
> - **为什么答案不会重复**：「不选」那条写的是 `dfs(i + 1, t)`，一旦跳过 `candidates[i]` 就永不回头。于是每个数字「用几个」这件事**只在一个地方被决定**，一个组合对应唯一一组计数，天然不重样——不需要任何去重代码。
> - **两个 `return` 的顺序不能反**：先判 `t == 0` 收答案，再判 `i == n or t < 0`。这与变体一 77 选/不选版是同一条纪律。
> - **本题该用正序**：77 偏爱倒序是因为「剩余可选个数恰好等于 `i`」让剪枝好写，而 39 没有「恰好 k 个」的长度约束，那个好处不存在；`candidates` 又是任意数组而非 $1 \ldots n$，正序 `dfs(0, target)` 更自然。**倒序是 77 的便利，不是组合型的教条。**
> - 题目保证 `candidates` 元素互不相同且全为正数——全正是 `t < 0` 剪枝成立的前提，和 216 一样。

> [!warning]- 最容易犯的错：把「选」写成 `dfs(i + 1, t - candidates[i])`
> 
> 改回 `i + 1` 之后代码**照样跑、照样出答案、不报任何错**，但每个数只能用一次，答案会少一大半——`candidates = [2,3,6,7]`、`target = 7` 本应得到 `[2,2,3]` 和 `[7]` 两个组合，改错后只剩 `[7]` 一个。
> 
> 这类错误没有异常栈可查，只能靠**先想清楚「这道题的元素能不能复用」，再决定下标往哪走**。同一个坑在完全背包里叫「正序遍历容量」，见 [[7.2 背包以及完全背包]]。

> [!tip]- 另一种写法：答案视角枚举「选谁」，实测快 6 倍
> 
> ```python
> class Solution:
>     def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
>         n = len(candidates)
>         ans, path = [], []
>         def dfs(i, t):
>             if t == 0:
>                 ans.append(path.copy())
>                 return
>             for j in range(i, n):            # 从 i 开始，允许再次选中 j 自己
>                 if candidates[j] <= t:       # 先判再递归，不进负数分支
>                     path.append(candidates[j])
>                     dfs(j, t - candidates[j])    # 传 j 不是 j+1 ← 同样是「原地」
>                     path.pop()
>         dfs(0, target)
>         return ans
> ```
> 
> 两版结果完全一致（400 组随机对拍验证），但在 39 的最坏规模（`candidates` 取 $2 \ldots 31$、`target = 40`，6131 个答案）下实测 **0.019 s vs 0.123 s**，差约 6 倍。
> 
> 原因不在渐进复杂度，而在**空转的结点**：选 / 不选版每跳过一个候选就要单独压一层栈，30 个候选就是 30 层纯「不选」的链；循环版的 `for` 一次就掠过它们，而且 `candidates[j] <= t` 把越界分支挡在递归之前，连函数调用都省了。
> 
> 两种视角的完整对照见 [[6.1 子集型回溯]] 的「两种视角怎么选」。**选 / 不选版胜在思路直白、和 216 一脉相承；循环版胜在快、且天然对应「下一个选谁」的口述方式**，面试推荐后者。

### 变体四：22. 括号生成

长得不像组合，骨架完全一样：$2n$ 个**格子**排成一排，每格必须填 `(` 或 `)`——候选池从数字换成固定的两个字符。也可以看成「从 $2n$ 个位置里选 $n$ 个放左括号」，就完全退化成组合，只是多了前缀约束。

> [!tip]- 真正的难点：把全局合法翻译成局部判断
> 
> 合法 $\iff$ (1) 左括号共 $n$ 个；(2) **任意前缀**里右括号数 $\le$ 左括号数。
> 
> 第二条的直觉：每个右括号都必须找得到左边一个未配对的左括号；前缀里右括号一旦超额，后面怎么填都救不回来——**错误不可逆，正是剪枝成立的前提**（见 [[剪枝]]）。
> 
> 两个 if 就是这两条约束：`open < n` 才能填 `(`；`i - open < open`（已填右括号数 < 左括号数）才能填 `)`。`i - open` 用减法天然表示右括号数，省掉第二个计数器。

> [!success]- 22. 括号生成
> 
> ```python
> class Solution:
>     def generateParenthesis(self, n: int) -> List[str]:
>         m = n * 2
>         ans = []
>         path = [''] * m              # 定长数组，按下标覆写
>         def dfs(i, open):
>             if i == m:
>                 ans.append(''.join(path))
>                 return
>             if open < n:             # 左括号还有存货
>                 path[i] = '('
>                 dfs(i + 1, open + 1)
>             if i - open < open:      # 手上有未配对的左括号
>                 path[i] = ')'
>                 dfs(i + 1, open)
>         dfs(0, 0)
>         return ans
> ```
> 
> - 没有 `path.pop()`：定长数组按下标覆写，下一条分支自然盖掉 `path[i]`。**pop 的本质不是「清理」，而是「让兄弟分支看到干净的状态」**——覆写达成同样效果，见 [[状态恢复]]。
> - 两个 if 不可能同时不成立（那意味着 `i == 2n`，已在开头返回），所以这棵树**没有死胡同、没有白跑的分支**，不需要 `t < 0` 那种失败回收。

## 易错点

> [!warning]- 易错点
> 
> - **把 `d - 1` 当成剪枝逻辑**：数学约束是 $j \ge d$（选了 `j` 后池子 $[1, j-1]$ 得装下还差的 $d-1$ 个），`- 1` 只是 `range` 开区间的语法偏移；混在一起记，换道题就写错下界。
> - **选/不选版漏写边界**：循环版 `i == 0` 时 range 为空自动停；二叉版必须显式 `return`，否则 `i` 无限递减爆栈——边界是不是自动的，正是两种切法的分水岭。
> - **两个 `return` 顺序写反**：先判成功（选够 $k$ 个）再判失败（池子空），反了会误杀边界上刚好凑齐的方案。
> - **39 把「选」写成 `dfs(i + 1, ...)`**：静默退化成「每个数只用一次」，答案少一大半且不报错。元素能否复用，决定下标动不动。
> - **39 把「不选」也写成 `dfs(i, t)`**：那就原地打转永不前进，直接爆栈。「不选」必须前进，「选」才留在原地——两条分支的下标待遇正好相反。
> - **`path.copy()` 写成 `path`**：存引用不存快照，见 [[Python_赋值与拷贝]]。

## 复杂度

> [!summary]- 复杂度
> 
> - 77：叶子共 $C(n,k)$ 个，每条路径长 $k$、拷贝 $O(k)$ → 时间 $O(k \cdot C(n,k))$——剪枝保证没有白跑的分支；空间 $O(n)$（选/不选版递归深度到 $n$；枚举版仅 $O(k)$），不计答案。
> - 216：候选池固定 9 个数，上界同型 $O(k \cdot C(9,k))$；空间 $O(k)$。
> - 39：答案数没有简洁闭式，上界由「每个候选取几个」的组合数决定；单条路径最长 $\lfloor target / \min(candidates) \rfloor$，拷贝一次 $O(\text{len})$。空间为递归深度 $O(n + target/\min)$——选/不选版两段深度相加，循环版只有 $O(target/\min)$。
> - 22：合法串共卡特兰数 $\frac{1}{n+1}\binom{2n}{n}$ 个，树无死分支、节点数与答案数同阶，每个答案 `join` 花 $O(n)$ → 时间 $O\bigl(n \cdot \frac{1}{n+1}\binom{2n}{n}\bigr)$；空间 $O(n)$（递归深度 $2n$ + 定长 `path`）。

## 一句话总结

组合型 = 子集型 + 「恰好 $k$ 个」：这条约束就是剪枝的来源——倒序枚举让「剩余可选个数」直接等于参数 `i`，一句 `i < d` 砍掉所有注定失败的子树；而「选中后下标动不动」这一个字母，又把它分成了「每个元素用一次」（77 / 216）和「可无限复用」（39）两个世界。

## 模板归纳

**触发信号**：

- 「恰好选 $k$ 个」「所有长度为 k 的组合」——长度约束是组合型的身份证
- 「和 / 代价为定值」——多带一个剩余目标 `t`，多一条 `t < 0` 剪枝
- 「同一个元素可以重复使用 / 无限供应」——「选」那条分支的下标**原地不动**（39），本质是完全背包
- 定长填格子、每格候选固定（如括号生成）——组合型换了候选池，约束翻译成前缀条件

**落笔步骤**：倒序 `dfs(i)`（池 $[1, i]$）→ 算 `d = k - len(path)` → 先判 `d == 0` 收答案、再判 `i < d` 剪枝 → `for j in range(i, d - 1, -1)` 枚举。改用选/不选切法时，记得边界不再免费，必须显式写。

**下笔前先问一句**：这道题的元素**能不能重复用**？不能就让下标前进（`i±1`），能就让它原地不动（`i`）。这一个字母同时区分了 77/216 与 39，也是 0-1 背包与完全背包的分界。
