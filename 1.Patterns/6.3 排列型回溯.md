# 排列型回溯

## 解决什么问题

把 $n$ 个数排成一行、**每个数恰好用一次、顺序不同算不同方案**——排列 Permutation。本质是「有 $n$ 个坑位，依次决定每个坑填谁」。

和 [[6.2 组合型回溯]] 的分水岭：组合无序，每层从上一个数之后往下选；排列有序，**每层都要从头扫全部候选**，后面的数可以排在前面。方案数从 $C(n,k)$ 涨到 $n!$。

![](assets/6.3%20排列递归树%20候选池收缩.svg)

## 三种写法：记的是「谁还能用」还是「谁被占了」

同一棵递归树（见 [[递归树]]），区别只在**怎么记账**——而记账方式直接决定了「要不要恢复现场」。

![](assets/6.3%20三种记账方式.svg)

> [!tip]- 核心思路：`dfs(i, ...)` 表示前 i 个坑已填好
> 
> `i` = 填到哪个坑，递归到 `i == n` 说明坑填满，收一个答案。差别只在第二个维度：
> 
> | 写法 | 怎么记账 | `path` 怎么写 | 要还什么 |
> | --- | --- | --- | --- |
> | ① 候选池 + 覆盖式 | `s` 是剩余候选，传 `s - {x}` | `path[i] = x` | **什么都不用还** |
> | ② 占用表 + 覆盖式 | `on_path[j]` 记下标是否被占 | `path[i] = x` | 还 `on_path` |
> | ③ 候选池 + 追加式 | `s` 是剩余候选，传 `s - {x}` | `path.append(x)` | 还 `path` |
> 
> 三者结果等价。**面试首选 ②**：没有新建集合的开销（见复杂度）。判断「要不要还」的标准只有一条——**这个状态的旧值会不会被兄弟分支读到**。

> [!success]- 写法 ①②：46. 全排列（覆盖式 `path`，两版对照）
> 
> ```python
> # ① 候选池版：池子里只留合法的
> class Solution:
>     def permute(self, nums: List[int]) -> List[List[int]]:
>         n = len(nums)
>         ans, path = [], [0] * n
>         def dfs(i, s):
>             if i == n:
>                 ans.append(path.copy())     # 定长 path，拷贝快照，见 [[Python_赋值与拷贝]]
>                 return
>             for x in s:                     # 枚举第 i 坑的所有填法
>                 path[i] = x
>                 dfs(i + 1, s - {x})         # s-{x} 新建集合，不改上一层，见 [[Python_set]]
>         dfs(0, set(nums))
>         return ans
> ```
> 
> ```python
> # ② 占用表版：经典写法，面试更常见
> class Solution:
>     def permute(self, nums: List[int]) -> List[List[int]]:
>         n = len(nums)
>         ans, path = [], [0] * n
>         on_path = [False] * n
>         def dfs(i):
>             if i == n:
>                 ans.append(path.copy())
>                 return
>             for j in range(n):              # 排列：每层从 0 扫全部下标
>                 if not on_path[j]:
>                     path[i] = nums[j]       # path 存值，on_path 记下标，别混
>                     on_path[j] = True
>                     dfs(i + 1)
>                     on_path[j] = False      # 只还这一个，谁占谁还
>         dfs(0)
>         return ans
> ```
> 
> - 主流程：第 `i` 层只写 `path[i]` 这一格，一定先写后递归。
> - 关键变量：`path[i]` 的 `i` 是递归深度，`on_path[j]` 的 `j` 是数字在 `nums` 中的位置。
> - 易错位置：`for j in range(n)` 必须从 0 开始扫，写成 `range(i, n)` 就退化成组合了。

> [!success]- 写法 ③：候选池 + 追加式 `path`（两种免恢复机制各用一半）
> 
> ```python
> class Solution:
>     def permute(self, nums: List[int]) -> List[List[int]]:
>         n = len(nums)
>         path, ans = [], []
>         t = set(nums)
>         def dfs(i, s):
>             if i == n:
>                 ans.append(path.copy())
>                 return
>             for x in s:
>                 path.append(x)              # 追加式：path 是全树共用的栈
>                 dfs(i + 1, s - {x})         # 候选池：s 是本层独有的副本
>                 path.pop()                  # ← 所以 path 要还，s 不用
>         dfs(0, t)
>         return ans
> ```
> 
> 这一版**正好把两种机制各用了一半**，也因此最能说明「要不要还」的判据：
> 
> - `s` 走的是「每层一份新副本」，上一层的 `s` 从没被动过 $\to$ **不用还**。
> - `path` 走的是「全树共用一个栈」，长度就是当前层号 $\to$ **必须 `pop()`**，否则下一个分支会接着上一条路径继续长。
> 
> 和写法 ① 一比就清楚了：① 的 `path` 是定长数组、按深度定位，所以连 `path` 都不用还；③ 换成 `append` 之后，`path` 立刻从「每层独占一格」变成「全树共享一个栈」，恢复义务就回来了。**改的不是变量的作用域，是它的访问方式。**
> 
> - `i` 和 `len(path)` 在这一版里恒等，所以基线条件写 `len(path) == n` 也对；留着 `i` 更省事，也和 ①② 对得上。
> - 收答案仍必须 `path.copy()`：`path` 会被后续分支继续改，存引用就全变成同一个列表，见 [[Python_赋值与拷贝]]。

## 核心：为什么 `path` 不用恢复，`on_path` 却要

两个数组待遇完全不同，判断标准不是「哪个变量是共享的」，而是「哪个变量的状态**会被兄弟分支读到**」。

| 数组 | 下标含义 | 兄弟分支会撞车吗 | 要不要恢复 |
| --- | --- | --- | --- |
| `path[i]`（覆盖式） | `i` = 递归深度 | 不会，每层独占一格 | 不用，下次进来先覆盖再用 |
| `path`（追加式） | 长度 = 递归深度 | 会，整棵树共用一个栈 | **必须还**，`path.pop()` |
| `on_path[j]` | `j` = 数字在 `nums` 的位置 | 会，整棵树共用一张表 | **必须还**，`on_path[j] = False` |
| `s`（候选池） | 本层独有的副本 | 不会，上层的 `s` 没被改过 | 不用 |

> [!tip]- 深度定位 vs 全局共享
> 
> `path[i]` 的 `i` 就是当前层号，第 3 层永远只碰 `path[3]`，兄弟分支互不污染，而且下次进来一定先覆盖再读——所以不需要还。当 `i == n` 时，`path[0..n-1]` 全被本条路径刚写过，旧值不可能残留。这是「深度定位 + 无条件覆盖」的不变量。
> 
> `on_path` 则是整棵树共享的一张占用表。第 1 层把 `on_path[0]` 设 True，是告诉所有子孙「0 号被我占了」；子树探索完必须撤销，否则兄弟分支会误以为 0 号仍被占用，永远用不到那个数字。
> 
> 「借了要还」在这里依然成立，只是**还的对象随写法而变**：写法 ② 还 `on_path`，写法 ③ 还 `path`，写法 ① 两个都不用还。完整机制见 [[状态恢复]]，其中候选池的 `s - {x}` 属于第三种免恢复手段：每层拿一份不可变副本，从没动过上一层。

> [!example]- 推演：nums = [1, 2, 3]
> 
> ```text
> dfs(0, {1,2,3})
>  └ x=1: path=[1,_,_]  dfs(1, {2,3})
>     ├ x=2: path=[1,2,_]  dfs(2, {3})
>     │   └ x=3: path=[1,2,3]  dfs(3,{}) → 收 [1,2,3]
>     └ x=3: path=[1,3,_]  dfs(2, {2})
>         └ x=2: path=[1,3,2]           → 收 [1,3,2]
> ```
> 
> 回到 `dfs(1,·)` 的第二轮时，它手上的 `s` 依然是 `{2,3}`——候选池版从没被改过；占用表版则是靠 `on_path` 被还原成进来时的样子。

## 候选池为什么必须是 `set`

> [!warning]- 把 `dfs(0, set(nums))` 写成 `dfs(0, nums)` 会直接报错
> 
> 崩在递归那一行：
> 
> ```python
> for x in s:              # list 可以遍历，这行没事
>     path[i] = x
>     dfs(i + 1, s - {x})  # ← TypeError
> ```
> 
> ```text
> TypeError: unsupported operand type(s) for -: 'list' and 'set'
> ```
> 
> Python 里 `-` 是集合专属的差集运算。`list` 只支持 `+`（拼接）和 `*`（重复），**没有减法**——因为 `list` 是「有序序列」，删掉一个元素涉及位置移动，语义不唯一（删第几个？删所有相同的？），所以干脆不给它定义 `-`。`set` 是「无序的成员集合」，删元素语义明确，差集是数学上的标准运算，所以 `-` 存在。见 [[Python_set]]。

> [!tip]- 这个算法真正依赖 `set` 的哪个能力：不是去重，是「造副本」
> 
> 它要的只有一条：
> 
> > **给我一个新的候选池，内容是原来的减去 `x`，同时不许动原来的那个。**
> 
> 这正是候选池版不需要恢复现场的原因——每层拿到自己的一份副本。`set` 用一个 `-` 就把这件事办了。
> 
> `list` 做不到 `-`，但能用切片拼接实现同样的语义：
> 
> ```python
> def dfs(i, s):                        # s 是 list
>     if i == n:
>         ans.append(path.copy())
>         return
>     for j in range(len(s)):
>         path[i] = s[j]
>         dfs(i + 1, s[:j] + s[j+1:])   # 造一个去掉第 j 个的新 list
> ```
> 
> `s[:j] + s[j+1:]` 干的事和 `s - {x}` 一模一样：**造一个新的、少一个元素的容器，原容器不动**。类比：`set` 版是「复印名单，划掉一个名字」，`list` 版是「重新誊抄一份，跳过第 j 个人」——手法不同，结果都是给下一层一份干净的副本，原件保持完好。

> [!warning]- `set` 候选池的真实代价：`nums` 有重复时会**返回空列表**
> 
> 46. 全排列保证元素互不相同，所以候选池版没问题。但一旦有重复，比如 `nums = [1, 1, 2]`：
> 
> ```python
> n = len(nums)          # 3
> t = set(nums)          # {1, 2}，只剩 2 个元素
> ```
> 
> 池子最多只能填满 2 个坑，`i` 永远到不了 3，递归**一个答案都收不到**——`permute([1,1,2])` 返回 `[]`。不是「答案少了几个」，是全军覆没，而且不报错，很难查。
> 
> 上面那个 `list` 切片版保留了两个 1，能产生全部 6 个（带重复的）排列；47. 全排列 II 要的是去重后的 3 个，得先排序再加「同层跳过相同元素」的剪枝，见 [[剪枝]]。
> 
> **所以候选池版的适用前提是「元素互不相同」**，这一点写 46 可以不提，写 47 必须换写法。

## 例题：51. N 皇后 —— 排列的伪装

N 皇后表面在「摆棋子」，真身是「枚举列的一个排列 + 用 `r±c` 过滤对角线冲突」。整个设计的精髓：**把约束编码进数据结构，而不是编码进检查逻辑**。

> [!tip]- 第一步：换表示法，让「每行一个」免费
> 
> 二维 `board[r][c]` 允许一行塞三个皇后，非法状态它都能表示，你得自己派代码巡查。换成一维：
> 
> ```python
> col = [0] * n     # col[r] = 第 r 行的皇后放在第几列
> ```
> 
> `col[2]` 只能存一个数，**根本没能力**表示「第 2 行两个皇后」。鸽笼原理保证 n 行放 n 个必然每行恰好一个，没丢任何合法解。**第一个约束，零代码。**

> [!tip]- 第二步：列约束一来，问题退化成全排列
> 
> 加上「每列也只能一个」，即 `col` 各元素两两不同——这就是 $0 \ldots n-1$ 的一个**排列**：
> 
> $$\text{N 皇后的解} \subset 0 \ldots n-1 \text{ 的全排列}$$
> 
> 搜索空间从 $n^n$ 掉到 $n!$，而且代码跟 permute 一模一样，只在中间插一道过滤。第二个约束交给候选池 `s - {c}`，删掉用过的列。**它就是 permute，只是插了一道过滤。**

> [!success]- 51. N 皇后
> 
> ```python
> class Solution:
>     def solveNQueens(self, n: int) -> List[List[str]]:
>         ans = []
>         col = [0] * n
>         def valid(r, c):
>             for R in range(r):              # 只看已放好的第 0..r-1 行
>                 C = col[R]
>                 if r + c == R + C or r - c == R - C:
>                     return False            # 找到一个冲突就立刻否决
>             return True                     # 全部看完才通过——必须在循环外
>         def dfs(r, s):
>             if r == n:
>                 ans.append(['.' * c + 'Q' + '.' * (n - 1 - c) for c in col])
>                 return
>             for c in s:
>                 if valid(r, c):
>                     col[r] = c
>                     dfs(r + 1, s - {c})
>         dfs(0, set(range(n)))
>         return ans
> ```
> 
> - 骨架就是 permute：`col[r]=c` 对应 `path[i]=x`，`dfs(r+1, s-{c})` 对应 `dfs(i+1, s-{x})`。
> - `valid` 的不变量：`col[0..r-1]` 是有效数据，`col[r..n-1]` 是残留垃圾，但只循环 `range(r)`，永远读不到垃圾区——和 `path` 不用清理同一件事。
> - `return True` 是**关于全体的断言**，必须等全体看完，只能放循环外；放循环里等于看第一个人就宣布「全场没人反对」。`r=0` 时循环体一次没进，正确答案 `True` 恰好由循环外的兜底提供。

### 对角线为什么是加减法：几何问题代数化

同一条对角线上的格子坐标满足恒等式。沿 ↘ 走一步行 +1 列 +1，`r - c` 不变；沿 ↙ 走一步行 +1 列 -1，`r + c` 不变。

![](assets/6.3%20N皇后%20对角线门牌号.svg)

于是「两皇后同对角线」这个**几何**问题变成「两个数字相等」这个**代数**问题。等价于常见的 `abs(r-R) == abs(c-C)`（行差等于列差），但直接比门牌号更省事。

> [!tip]- 为什么按行推进：决策顺序规范化去重
> 
> `dfs(r)` 一层管一行，r 从 0 到 n-1。若「想放哪放哪」，先放 (0,1) 再 (1,3) 和先放 (1,3) 再 (0,1) 是同一棋盘，同一个解会被数很多遍。固定「第 r 层只决定第 r 行」，每个解在递归树里对应唯一一条路径——去重不靠事后过滤，靠**决策顺序规范化**从源头杜绝。和子集型「第 i 层只决定第 i 个元素选不选」同理。

## 三个约束的分工

| 约束 | 由谁保证 | 代价 |
| --- | --- | --- |
| 每行一个 | 数据结构 `col` 的形状 | 零代码 |
| 每列一个 | 候选池 `s - {c}` | 零额外检查 |
| 对角线 | `valid()` 显式检查 | $O(r)$ |

三个约束，两个被「设计掉」，只剩一个真检查。**好的搜索算法，一大半功夫花在让约束自动满足上，而不是花在检查上。**

## N 皇后进阶：把 `valid()` 扫描换成 $O(1)$ 占用表

`valid(r, c)` 每次要回扫 `range(r)` 逐行比对，$O(r)$。既然对角线的门牌号就是 `r+c` 和 `r-c`，那完全可以照搬 permute 占用表版的思路：**给两条对角线也各开一张占用表**，冲突判断从「扫描」降成「查表」。连列约束都不再需要候选池——`on_path` 一张表就够。

> [!success]- 51. N 皇后（三张占用表，$O(1)$ 判断）
> 
> ```python
> class Solution:
>     def solveNQueens(self, n: int) -> List[List[str]]:
>         ans = []
>         col = [0] * n
>         on_path = [False] * n           # 列占用
>         m = 2 * n - 1
>         diag1 = [False] * m             # ↙ 对角线 r+c
>         diag2 = [False] * m             # ↘ 对角线 r-c
>         def dfs(r):
>             if r == n:
>                 ans.append(['.' * c + 'Q' + '.' * (n - 1 - c) for c in col])
>                 return
>             for c in range(n):
>                 if not on_path[c] and not diag1[r + c] and not diag2[r - c]:
>                     col[r] = c
>                     on_path[c] = diag1[r + c] = diag2[r - c] = True
>                     dfs(r + 1)
>                     on_path[c] = diag1[r + c] = diag2[r - c] = False
>         dfs(0)
>         return ans
> ```
> 
> - 三张表全是**全局共享的占用表**，所以三个都得「谁占谁还」——和 permute 占用表版的 `on_path` 完全同理，见 [[状态恢复]]。`col[r]` 依旧不用还：按深度定位、无条件覆盖。
> - 链式赋值 `on_path[c] = diag1[r+c] = diag2[r-c] = True/False` 上下严格对称，一眼看出配对——**回溯最怕占用和恢复不成对，这种写法从形式上就防住了**。

> [!warning]- `diag2[r - c]` 为什么没越界：Python 负数下标回绕
> 
> `r - c` 的范围是 $-(n-1) \ldots n-1$，**带负数**。按理应写 `diag2[r - c + n - 1]` 平移到 $0 \ldots 2n-2$。但直接写 `diag2[r - c]` 居然对——因为 Python 负下标从尾部回绕：
> 
> ```text
> r-c =  0      → 下标 0
> r-c =  n-1    → 下标 n-1        正数占 [0, n-1]
> r-c = -1      → 下标 2n-2
> r-c = -(n-1)  → 下标 n          负数占 [n, 2n-2]
> ```
> 
> 两段区间恰好互不重叠、正好铺满 `m = 2n-1` 个格子，每条 ↘ 对角线仍对应唯一槽位。但这是**「碰巧成立」**：它依赖 `m` 精确等于 $2n-1$，多一个少一个就撞车。稳妥、可读的写法是显式偏移 `diag2[r - c + n - 1]`。

> [!summary]- 两版怎么选
> 
> | 判断冲突 | 代价 |
> | --- | --- |
> | `valid()` 扫描 | 时间 $O(r)$ 逐行比对；无额外空间 |
> | 三张布尔表 | 时间 $O(1)$ 查表；空间 $O(n)$ + 三张表都要回溯恢复 |
> 
> 用空间换时间的经典取舍。`valid()` 版胜在零额外空间、代码短；布尔表版胜在冲突判断 $O(1)$、和 permute 占用表版一脉相承。

## 易错点

> [!warning]- 易错点
> 
> - **忘记 `on_path[j] = False`**：最高频错误。后果不是崩溃，而是答案严重变少——每个数字全局只用一次，最后只剩 1 个（甚至 0 个）排列。
> - **追加式 `path` 忘记 `pop()`**：写法 ③ 的同类错误。`path` 会一路越长越长，收到的「答案」长度失控。判据同上：全树共享的状态必须还。
> - **恢复写在 `if` 外面**：`on_path[j] = False` 必须严格包在 `if not on_path[j]` 内部、跟 `on_path[j] = True` 配对；写到外面会把别的分支占的位也清掉。谁占谁还，见 [[状态恢复]]。
> - **`path[i] = j` 写成下标**：要填的是 `nums[j]`（值），`on_path` 记的才是下标，两者别混。
> - **`for j in range(i, n)`**：排列不是组合，每层必须从 0 扫全部下标，后面的数可以排在前面；写成 `range(i, n)` 就变子集/组合了。
> - **`ans.append(path)` 忘 copy**：存引用不存快照，见 [[Python_赋值与拷贝]]。
> - **候选池版遇到重复元素**：`set(nums)` 把重复合并，池子填不满坑位，静默返回 `[]`。46 保证互不相同才能这么写。
> - **把 `dfs(0, nums)` 传成 list**：`list` 没有 `-` 运算，`TypeError`。要么传 `set`，要么改用切片拼接。
> - **N 皇后 `return True` 放进循环**：全称断言必须等全体看完，只能在循环外。

## 复杂度

> [!summary]- 复杂度
> 
> | 写法 | 时间 | 空间（不含答案） |
> | --- | --- | --- |
> | ① 候选池 + 覆盖式 | $O(n^2 \cdot n!)$ | $O(n^2)$ |
> | ② 占用表 + 覆盖式 | $O(n \cdot n!)$ | $O(n)$ |
> | ③ 候选池 + 追加式 | $O(n^2 \cdot n!)$ | $O(n^2)$ |
> 
> 叶子共 $n!$ 个。占用表版每层是 $O(n)$ 扫描但**不复制任何东西**，栈上只有 $n$ 个整数帧；候选池版每层要新建一个 $O(n)$ 集合，深度 $n$ 层就挂了 $O(n^2)$ 的集合——写法 ③ 的 `append`/`pop` 是 $O(1)$，省不掉集合那份开销，所以和 ① 同阶。
> 
> N 皇后再叠加 `valid` 每次 $O(r)$，但被对角线过滤掉的分支远多于 $n!$，实际远快于上界。

## 一句话总结

排列 = 逐位填坑 + 一份「谁还能用」的记账：记账方式决定恢复义务——**独占的（按深度定位的 `path[i]`、每层新建的候选池 `s`）不用还，共享的（`on_path`、追加式 `path`）必须还**；N 皇后不是摆棋子，是枚举列的排列再用 `r±c` 过滤对角线。

## 模板归纳

**触发信号**：

- 「所有排列」「顺序不同算不同方案」「每个数用一次」——排列的身份证
- 「每行/每列/每个位置恰好一个、两两不同」——本质是排列（N 皇后、数独）
- 需要一张「谁被用过」的全局表，且这张表会被兄弟分支读到 → 用完必须还原

**落笔步骤**：定长 `path` + `on_path`（或候选池 `s`）→ `dfs(i)`，`i == n` 收答案 → `for j in range(n)` 从 0 扫全部，`if not on_path[j]` 过滤 → 写 `path[i]`、置 `on_path[j]=True`、递归、`on_path[j]=False` 还原。约束型（N 皇后）先想「能不能把约束编码进数据结构」，剩下的才用 `valid` 检查。

**落笔前先问一句**：我这个状态是**独占**的还是**共享**的？独占不用还，共享必须还——这一条同时管住 `path`、`on_path` 和候选池。
