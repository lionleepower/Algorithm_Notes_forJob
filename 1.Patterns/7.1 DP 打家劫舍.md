# 198. 打家劫舍

## 题目

一排房子每间有金额 `nums[i]`，不能偷相邻两间，求能偷到的最大金额。

## 思路

看到「每个元素选或不选 + 相邻约束 + 求最值」，先写回溯的「选/不选」分支；再发现子问题只由下标 `i` 决定、且大量重复，就升级成 DP。这是最典型的一维线性 DP 入门题。

> [!tip]- 核心思路：把 dfs 当成一份合同
> 
> 递归函数不是「一段会跑的代码」，而是一份**语义合同**：
> 
> $$dfs(i) = \text{只考虑前 } i+1 \text{ 间房（下标 } 0\sim i\text{）能偷到的最大金额}$$
> 
> 那行 `max` 之所以保证最大，是因为对第 `i` 间房**只有两种态度，不重不漏**：
> 
> - **不偷 `i`** → 收益全来自前 `i-1` 间 → 这类最好的是 `dfs(i-1)`
> - **偷 `i`** → 必须放弃 `i-1` → 这类最好的是 `dfs(i-2) + nums[i]`
> 
> 两类瓜分了所有方案，所以全体最大值 = `max(两类各自的冠军)`——不是「碰巧取了个大的」，而是**对一个完备分类各取冠军再决总冠军**，漏一类才会错。base case `i < 0` 返回 0，由数学归纳法 `dfs(n-1)` 自然正确，**不需要在脑中展开整棵递归树**（见 [[递归树]]）。

> [!example]- 示例推演 `nums = [1,2,3,1]`
> 
> ```text
> dfs(3) = max( dfs(2),           # 不偷 3
>               dfs(1) + 1 )      # 偷 3，跳过 2
> dfs(2) = max( dfs(1), dfs(0)+3 ) = max(2, 1+3) = 4
> dfs(1) = max( dfs(0), dfs(-1)+2 ) = max(1, 2) = 2
> 结果 dfs(3) = max(4, 2+1) = 4      # 偷 nums[0]+nums[2] = 1+3
> ```

## 代码实现

> [!success]- 四版演进：朴素递归 → 记忆化 → 递推 → 滚动变量
> 
> ```python
> from functools import cache
> from typing import List
> 
> # ① 朴素递归：正确但 O(1.618^n)，同一子问题反复重算
> def rob1(nums: List[int]) -> int:
>     def dfs(i):
>         if i < 0:
>             return 0
>         return max(dfs(i - 1), dfs(i - 2) + nums[i])
>     return dfs(len(nums) - 1)
> 
> # ② 记忆化搜索：memo 兜住重叠子问题，塌缩到 O(n)
> def rob2(nums: List[int]) -> int:
>     n = len(nums)
>     memo = [-1] * n
>     def dfs(i):
>         if i < 0:                  # base case 必须排在查表之前
>             return 0
>         if memo[i] != -1:
>             return memo[i]
>         memo[i] = max(dfs(i - 1), dfs(i - 2) + nums[i])
>         return memo[i]
>     return dfs(n - 1)
> 
> # ②′ 面试速写：@cache 自动记忆化（机制见 Python_cache）
> def rob2b(nums: List[int]) -> int:
>     @cache
>     def dfs(i: int) -> int:
>         if i < 0:
>             return 0
>         return max(dfs(i - 1), dfs(i - 2) + nums[i])
>     return dfs(len(nums) - 1)
> 
> # ③ 递推（自底向上）：直接算「归」，无递归栈
> def rob3(nums: List[int]) -> int:
>     n = len(nums)
>     f = [0] * (n + 2)              # f[i+2] 对应 dfs(i)，+2 消掉负下标判断
>     for i, x in enumerate(nums):
>         f[i + 2] = max(f[i + 1], f[i] + x)
>     return f[n + 1]                # n+1 = (n-1)+2
> 
> # ④ 滚动变量：状态只依赖前两项，空间压到 O(1)
> def rob4(nums: List[int]) -> int:
>     f0 = f1 = 0
>     for x in nums:
>         f0, f1 = f1, max(f1, f0 + x)
>     return f1
> ```
> 
> - 主流程：四版**递推式完全相同** `f(i)=max(f(i-1), f(i-2)+nums[i])`，区别只在「谁来存中间结果」。
> - 关键变量：`memo[i]` / `f[i+2]` / `f1` 都表示「前 `i+1` 间的最大金额」，同一份合同的三种载体。
> - `@cache` 与手写 memo **逐字对应**：建 dict、以参数为 key 查表、算完写回；区别是 dict 不需哨兵值、天然支持多维参数。面试写 `@cache` 快，手写更能证明懂机制，C++ 里必须手写。

> [!tip]- 进阶一：入口参数怎么定——看 `i` 是「下标」还是「数量」
> 
> 这是 DP 最易忽略却决定一切的分岔口：
> 
> ```text
> rob:         dfs(i) = 考虑【下标 0..i】的房子     → i 是下标 → 入口 dfs(n-1)
> climbStairs: dfs(i) = 爬到【第 i 阶】的方法数     → i 是数量 → 入口 dfs(n)
> ```
> 
> 定入口只有一句话：**把定义里的 `i` 替换成「完整问题」对应的值**，不需要背「数组题用 n-1」。反证：打家劫舍若改定义 `dfs(i)=前 i 间的最大金额`（`i` 是数量），入口就变 `dfs(n)`、base 变 `i<=0`、取值变 `nums[i-1]`——`n-1` 和 `n` 是**你定义的属性**，不是题目的属性。（递推版 `f=[0]*(n+2)` 用的就是这种「挪成数量」的偏移，负下标问题自动消失。）

> [!tip]- 进阶二：base case 问两件事
> 
> 边界迷茫，是因为在问「代码需要什么才不崩」。应反过来——**base 是定义在边界处的取值**：
> 
> 1. **语义上边界该返回什么？** rob 没房可偷 → `0`；climbStairs `dfs(0)` 站起点没爬 → `1`。求最值空集常为 0，求方案数空集常为 1，两者不能混。
> 2. **能到达的越界值都接住了吗？** 纯机械检查转移最多往回退几步：rob 有 `i-1`、`i-2`，从 `i=0` 能退到 `-1` 和 `-2`，所以必须写 `if i < 0`（写 `i == -1` 会漏 `-2` 爆栈）。
> 
> 口诀：**转移里最多往回退几步，base 就得盖住几格**，退 2 步写 `<`，别写 $==$。

## 易错点

> [!warning]- 易错点
> 
> - **查表写在 base case 之前**：Python 里 `memo[-1]` 不报错，会静默返回列表最后一项，`dfs(-1)` 可能返回真实金额而非 0，答案错且极难查。铁律：先合法性边界，再查表优化。
> - **哨兵 `-1` 的隐含前提**：`-1` 表示「尚未计算」，只在「真实答案不可能是 -1」时成立（本题金额非负）；答案可能为负的 DP 要改用 `None` 或独立 `visited` 数组（见 [[记忆化搜索]]）。
> - **`cache` 撞名**：局部变量若叫 `cache` 会遮住 `from functools import cache`，习惯用 `memo`。
> - **递推下标偏移**：`f` 开 `n+2`、返回 `f[n+1]`，`+2` 为省掉负下标判断；少偏一位就越界或取错值。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = \text{状态个数} \times \text{单个状态的转移时间}$。
> 
> - 朴素递归：$O(1.618^{n})$——调用次数呈 Fibonacci 式指数增长。
> - 记忆化 / 递推：状态数 $n$、单次转移 $O(1)$ ⇒ 时间 $O(n)$。memo 把递归树剪成一条链，指数塌缩为线性。
> - 空间：记忆化 $O(n)$ memo + $O(n)$ 栈；递推 $O(n)$；滚动变量 $O(1)$。

## 一句话总结

`max` 保证最大不是它有魔力，而是「选/不选」这个分类不重不漏地覆盖了所有方案——DP 的正确性来自完备分类，效率来自把重叠子问题缓存成一条链。

## 模板归纳

看到「每个元素选/不选 + 相邻或容量约束 + 求最值 / 计数」，条件反射走三步：

1. 写出合同 `dfs(i) = 前 i+1 个的最优值`，用「选/不选」凑出转移方程。
2. 确认**无后效性**（答案只由参数决定）→ 加 memo 变记忆化。
3. 看清依赖项后翻成递推，必要时用滚动变量压空间。

```python
# 一维 DP 通用骨架
@cache
def dfs(i):
    if i < 0:
        return 0                      # base case
    return combine(dfs(i - 1), dfs(i - 2) + a[i])   # combine = max / min / +
```
