# DP 补漏：网格路径、乘积最大子数组与最长有效括号

## 解决什么问题

[[7.0 DP]] 的主线已经覆盖了「选/不选」「背包」「双序列」「状态机」「区间」「树形」，本篇补三块 Hot100 里剩下的：

| 类型 | 题 | 新在哪 |
| --- | --- | --- |
| **网格路径 DP** | 62. 不同路径、64. 最小路径和 | 状态是二维坐标，转移只有两个来源 |
| **一维状态不够用** | 152. 乘积最大子数组 | 负数破坏单调性 $\Rightarrow$ **再开一条状态** |
| **强制以 i 结尾 + 分类讨论** | 32. 最长有效括号 | 状态定义与答案取法不一致 |

顺带两个「其实已被覆盖」的：279 完全平方数、139 单词拆分，都是 [[7.2 背包以及完全背包]] 的完全背包，见文末。

## 变体一：62 / 64 网格路径 DP

> [!tip]- 核心思路：只能右和下 $\Rightarrow$ 每格只有两个来源
>
> `f[i][j]` 定义为「从起点走到 `(i, j)`」的方案数（62）或最小代价（64）。因为只能向右或向下，**到 `(i,j)` 的最后一步只可能来自上方或左方**，于是：
>
> $$f[i][j] = f[i-1][j] \; \square \; f[i][j-1]$$
>
> 62 的 $\square$ 是 `+`（方案数相加），64 是 `min(...) + grid[i][j]`（代价取小）。**同一个骨架，换聚合函数**——这与 [[7.2 背包以及完全背包]] 里「最值 vs 计数」只差一个运算符是同一件事。
>
> **边界**：第一行只能从左来、第一列只能从上来。两种处理方式：
> - 显式初始化第一行第一列（直观）
> - 多开一圈：`f` 尺寸 $(m+1) \times (n+1)$，62 令 `f[0][1] = 1`（制造一个「虚拟入口」），64 令边界为 `inf` 但 `f[0][1] = 0`。**哨兵法能消掉所有 `if i == 0` 分支**。
>
> **滚动数组**：`f[i][*]` 只依赖 `f[i-1][*]` 和同行左边，所以可以压成一维，正序遍历即可（此时 `f[j]` 是上一行的值、`f[j-1]` 是本行已更新的值，正好对应两个来源）。空间 $O(mn) \to O(n)$。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def uniquePaths(self, m: int, n: int) -> int:
>         f = [1] * n                       # 第一行全是 1（只能一路向右）
>         for _ in range(1, m):
>             for j in range(1, n):
>                 f[j] += f[j - 1]          # 上方(旧值) + 左方(新值)
>         return f[-1]
>
>     def minPathSum(self, grid: List[List[int]]) -> int:
>         m, n = len(grid), len(grid[0])
>         f = [float('inf')] * (n + 1)
>         f[1] = 0                          # 哨兵：让 (0,0) 的两个来源里恰好有一个是 0
>         for i in range(m):
>             for j in range(n):
>                 f[j + 1] = min(f[j + 1], f[j]) + grid[i][j]
>         return f[n]
> ```
>
> **关键变量**：一维滚动时，`f[j]` 在被赋值**之前**代表上一行、**之后**代表本行——这个「原地新旧混用」正是滚动数组的核心，写的时候要在心里标注每个下标是新是旧。
> **补充**：62 也有组合数解法 $\binom{m+n-2}{m-1}$，一行搞定，可以作为加分项提一句。

## 变体二：152. 乘积最大子数组

> [!tip]- 核心思路：负数把「最小」变成「最大」的原料，所以必须同时维护两条状态
>
> 类比 53 最大子数组和：`f[i] = max(f[i-1] + x, x)`——加法里「更大的前缀」永远更有希望。
> ```python
> class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        for i in range(1, len(nums)):
            nums[i] += max(nums[i - 1], 0)
        return max(nums)
> ```
> 注意这里的标准写法是：
> ```python
> class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        f = [0] * len(nums)
        f[0] = nums[0]
        for i in range(1, len(nums)):
            f[i] = max(f[i - 1], 0) + nums[i]
        return max(f)
> ```
> 
>
> 乘法不成立：`x` 为负时，**上一步的最小值（很负）乘上它反而变成最大值**。只记 `f[i-1]` 的最大值，信息不足以推出 `f[i]`——这就是**无后效性被破坏**（见 [[重叠子问题与无后效性]]）。
>
> **修法：加一维状态。** 同时维护
>
> $$mx[i] = \max(x,\; mx[i-1]\cdot x,\; mn[i-1]\cdot x), \qquad mn[i] = \min(\text{同样三项})$$
>
> 三个候选的含义：`x` 表示「从我这里重新开始」，另两项表示「接上前面」。
>
> 这是 [[7.0 DP]] 那条原则最干净的例子——**状态必须装下所有影响未来的信息**；装不下就加维度，而不是打补丁。
>
> **`0` 会自动处理**：乘到 0 时 `mx = mn = 0`，下一步的 `x` 分支会让它重新起跳，不需要特判。

> [!example]- 示例推演：`nums = [2, -5, -2, -4, 3]`
>
> ```text
> x = 2    mx = 2                    mn = 2
> x = -5   mx = max(-5,-10,-10)= -5  mn = min(-5,-10,-10) = -10
> x = -2   mx = max(-2,10,20) = 20   mn = min(-2,10,20)   = -2     ← mn 翻身成 mx
> x = -4   mx = max(-4,-80,8) = 8    mn = min(-4,-80,8)   = -80
> x = 3    mx = max(3,24,-240)= 24   mn = min(...)        = -240
>
> 答案 24
> ```
>
> 第三步是全题的关键：`20` 来自 `mn = -10` 乘 `-2`——**只维护 `mx` 就永远得不到它**。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def maxProduct(self, nums: List[int]) -> int:
>         ans = mx = mn = nums[0]
>         for x in nums[1:]:
>             # 必须先算出新值再一起赋值，否则 mn 会用到已被覆盖的 mx
>             mx, mn = max(x, mx * x, mn * x), min(x, mx * x, mn * x)
>             ans = max(ans, mx)
>         return ans
> ```
>
> **易错位置**：`mx, mn = ...` 必须**同时赋值**。写成两行会让第二行用到刚更新的 `mx`，得到错误的 `mn`——Python 的元组同时赋值恰好帮了忙，C++ 里必须显式存临时变量。

## 变体三：32. 最长有效括号

> [!tip]- 核心思路：强制「以 i 结尾」，然后对 `s[i]` 分两种情况
>
> 状态：`f[i]` = **以下标 `i` 结尾**的最长有效括号长度。强制结尾的理由同 [[7.4 线性dp 最长递增子序列]]——不强制就无法写出转移。
>
> 于是答案是 `max(f)`，**不是 `f[n-1]`**。这是「状态定义」与「答案位置」不一致的典型，容易忘。
>
> **转移**（只在 `s[i] == ')'` 时可能非零）：
>
> - **情况 1：`s[i-1] == '('`** —— 直接配成一对：
>   $$f[i] = f[i-2] + 2$$
> - **情况 2：`s[i-1] == ')'`** —— 前面已有一段长 `f[i-1]` 的合法串，跨过它去看更前面那个字符。设 `j = i - f[i-1] - 1`，若 `s[j] == '('`，则它和 `s[i]` 配成一对，把中间整段包住：
>   $$f[i] = f[i-1] + 2 + f[j-1]$$
>   末尾的 `f[j-1]` 是**再接上更前面已经合法的一段**，漏了它 `"()(())"` 就会算错。
>
> **栈解法（更推荐现场写）**
>
> 栈里存**下标**，栈底始终保留「最后一个未匹配右括号的下标」当作**分隔哨兵**：
> - 遇 `(`：下标入栈
> - 遇 `)`：先弹栈；弹空了说明它自己就是新的分隔符，把它的下标压进去；否则当前有效长度 = `i - st[-1]`
>
> 初始压入 `-1` 作为哨兵（表示「有效段的左边界前一格」），可以省掉所有空栈判断——又一次哨兵消分支，同 [[2.3 栈 括号匹配与表达式解码]]。

> [!success]- 代码实现（栈 + DP 两版）
>
> ```python
> class Solution:
>     def longestValidParentheses(self, s: str) -> int:
>         st = [-1]                       # 哨兵：最后一个未匹配右括号的下标
>         ans = 0
>         for i, ch in enumerate(s):
>             if ch == '(':
>                 st.append(i)
>             else:
>                 st.pop()
>                 if not st:              # 弹空 -> 自己成为新的分隔符
>                     st.append(i)
>                 else:
>                     ans = max(ans, i - st[-1])
>         return ans
> ```
>
> DP 版：
>
> ```python
> def longestValidParentheses(self, s: str) -> int:
>     n = len(s)
>     f = [0] * n
>     for i in range(1, n):
>         if s[i] != ')':
>             continue
>         if s[i - 1] == '(':
>             f[i] = (f[i - 2] if i >= 2 else 0) + 2
>         else:
>             j = i - f[i - 1] - 1                     # 跨过中间那段合法串
>             if j >= 0 and s[j] == '(':
>                 f[i] = f[i - 1] + 2 + (f[j - 1] if j >= 1 else 0)
>     return max(f, default=0)
> ```
>
> **易错位置**：两个 `i >= 2` / `j >= 1` 的下标保护；以及最后是 `max(f)` 而非 `f[-1]`。

## 顺带：279 与 139 其实是完全背包

> [!tip]- 三题一模一样，只换「物品」是什么
>
> | 题 | 物品 | 背包容量 | 求什么 |
> | --- | --- | --- | --- |
> | 322. 零钱兑换 | 硬币面额 | 金额 | 最少个数 |
> | 279. 完全平方数 | $1, 4, 9, \ldots, \lfloor\sqrt n\rfloor^2$ | `n` | 最少个数 |
> | 139. 单词拆分 | 字典里的单词 | 字符串长度 | 能否恰好装满（布尔） |
>
> 完全背包的一维写法**容量正序遍历**（每件物品可重复取），这一条和 0-1 背包的倒序是唯一区别，推导见 [[7.2 背包以及完全背包]]。
>
> ```python
> # 139. 单词拆分
> def wordBreak(self, s: str, wordDict: List[str]) -> bool:
>     words = set(wordDict)                       # O(1) 判存在
>     n = len(s)
>     f = [False] * (n + 1)
>     f[0] = True                                 # 空串天然可拆
>     for i in range(1, n + 1):
>         for j in range(i):
>             if f[j] and s[j:i] in words:        # 前 j 个可拆，且 s[j:i] 是单词
>                 f[i] = True
>                 break
>     return f[n]
> ```
>
> 139 的状态是**布尔可达性**而非最值，所以聚合运算符是 `or`；`f[0] = True` 就是背包里的「容量 0 恰好装满」，与 [[8.0 前缀和与哈希]] 的 `cnt[0] = 1` 是同一类空基准哨兵。

## 易错点

> [!warning]- 易错点
>
> **1. 152 分两行赋值**
> 第二行用到被覆盖的 `mx`。必须同时赋值或用临时变量。
>
> **2. 152 只维护最大值**
> 遇 `[-2, 3, -4]` 立刻出错（答案 24 需要 `mn` 翻身）。
>
> **3. 32 返回 `f[n-1]`**
> 状态是「以 i 结尾」，答案必须 `max(f)`。空串时 `max` 会抛异常，用 `max(f, default=0)`。
>
> **4. 32 情况 2 漏了 `f[j-1]`**
> `"()(())"` 会得到 4 而非 6。这一项表示「把前面已经合法的一段也接上」。
>
> **5. 64 的滚动数组把 `inf` 初值写错**
> 求最小值时边界必须是 `inf`，但**入口格必须是 0**，否则整张表全是 `inf`。
>
> **6. 62 用 DFS 暴搜**
> $m, n \le 100$ 时组合数爆炸。看到「有多少条路径」且只能单向走 $\to$ 直接 DP 或组合数。
>
> **7. 139 用贪心最长匹配**
> `s = "aaaaab"`, `wordDict = ["a","aa","aaa","aaaa","aaaaa"]` 类用例会失败。**能否拆分**是可达性问题，必须 DP 或记忆化。

## 复杂度

> [!summary]- 复杂度
>
> - **62 / 64**：时间 $O(mn)$ —— 每格算一次，转移 $O(1)$；空间 $O(n)$（滚动数组）或 $O(mn)$。62 的组合数解法是 $O(\min(m,n))$。
> - **152**：时间 $O(n)$，空间 $O(1)$ —— 两个滚动变量。
> - **32**：时间 $O(n)$，空间 $O(n)$（DP 表或栈）；栈解法同样 $O(n)$ / $O(n)$。
> - **139**：时间 $O(n^2 \cdot L)$ —— 双层下标循环，每次切片与哈希比较 $O(L)$；空间 $O(n + \text{字典})$。

## 一句话总结

网格路径是「只有两个来源」的最简二维 DP；**152 教的是一维状态装不下信息时要加状态而不是打补丁**；32 教的是「以 i 结尾」的状态定义必须配 `max(f)` 的答案取法。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 「网格 + 只能右/下 + 路径数或最小代价」$\to$ 二维 DP，来源恰好两个，之后压成一维
- 「子数组 + 乘法 / 除法 / 带符号」$\to$ 立刻怀疑**要不要同时维护最大和最小**
- 「最长合法子串 / 子数组」$\to$ 先试「**以 i 结尾**」的定义，答案取 `max(f)`
- 「能否拼出 / 最少几个，元素可重复用」$\to$ 完全背包，容量**正序**

**自检两问**

1. 我的状态**装得下所有影响未来的信息**吗？装不下就加一维（152）。
2. 我的答案在 `f[n-1]` 还是 `max(f)`？强制结尾的定义一律取 `max`（32、[[7.4 线性dp 最长递增子序列]]）。
