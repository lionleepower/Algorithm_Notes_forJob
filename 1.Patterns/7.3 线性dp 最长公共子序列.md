# 线性 DP：最长公共子序列与编辑距离

## 解决什么问题

**两个序列**放一起比较，问「最长公共…」「最少操作数」「最多匹配…」——这类题统称**双序列线性 DP**。识别信号：

```text
输入是两个字符串 / 数组 + 求最值 + 答案与「顺序」有关但与「连续」无关
```

先钉死一个前提：**子序列可以不连续，但相对顺序必须保持**（`"ace"` 是 `"abcde"` 的子序列，`"aec"` 不是）。连续的那类叫**子串**，是另一套解法（滑动窗口或另一种 DP），别混。

与前两篇的区别一眼看清：

| 专题 | 状态 | 决策对象 |
| --- | --- | --- |
| [[7.1 DP 打家劫舍]] | `dfs(i)` 一个下标 | 第 `i` 个元素**选或不选** |
| [[7.2 背包以及完全背包]] | `dfs(i, c)` 下标 + 容量 | 第 `i` 个物品选几次 |
| **本篇** | `dfs(i, j)` **两个下标** | 最右一对字符**怎么配** |

## 统一模板

> [!tip]- 核心思路：两个下标 = 两侧各剩多少没处理
> 
> 合同定义（两题共用）：
> 
> $$dfs(i, j) = \text{只考虑 } s[0..i] \text{ 与 } t[0..j] \text{ 这两个前缀时的答案}$$
> 
> 两个下标各自表示「**这一侧还剩多少字符没处理**」。所有转移都在回答同一个问题：
> 
> > **最右边的 `s[i]` 和 `t[j]`，这一步怎么消化掉？**
> 
> 于是分支只有三种，按「这一步吃掉了谁」区分——这就是全部：
> 
> | 分支 | 吃掉了 | 指针怎么退 |
> | --- | --- | --- |
> | 两个配成一对 | `s[i]` 和 `t[j]` | `dfs(i-1, j-1)` |
> | 只让 `s[i]` 退场 | 只有 `s[i]`（`t[j]` 还留着） | `dfs(i-1, j)` |
> | 只让 `t[j]` 退场 | 只有 `t[j]`（`s[i]` 还留着） | `dfs(i, j-1)` |
> 
> **`dfs(i-1, j)` 不等于「不选 s[i]」**——它的准确含义是「`s[i]` 退场，但 `t[j]` 还在场上，仍可被配对也仍可被抛弃」。这个语义差别是理解后面「支配关系」的钥匙。

> [!success]- 通用骨架
> 
> ```python
> from functools import cache
> 
> @cache
> def dfs(i, j):
>     if i < 0 or j < 0:
>         return BASE                       # 见各题，LCS 是 0，编辑距离是 j+1 / i+1
>     if s[i] == t[j]:
>         return dfs(i - 1, j - 1) + w_match
>     return combine(dfs(i - 1, j), dfs(i, j - 1), ...)   # combine = max / min
> return dfs(n - 1, m - 1)                  # 入口：两个下标都取到末尾
> ```
> 
> 三个开关决定是哪道题：`combine` 取 `max` 还是 `min`、匹配的权重 `w_match`、以及 base case。

## 变体一：1143. 最长公共子序列（求最大）

求两个字符串的最长公共子序列长度。

![](assets/7.3%20LCS%20转移图.svg)

> [!tip]- 核心思路：max 的候选允许重、不允许漏
> 
> 完整的转移本可以写成「三支全塞进 `max`」，但两种情况下各有一支（或两支）是**冗余**的，可以剪掉：
> 
> | 情况 | 支配者（留下） | 被支配（可剪） |
> | --- | --- | --- |
> | `s[i] == t[j]` | `dfs(i-1, j-1) + 1` | `dfs(i-1, j)`、`dfs(i, j-1)` |
> | `s[i] != t[j]` | `dfs(i-1, j)`、`dfs(i, j-1)` | `dfs(i-1, j-1)` |
> 
> **不等时为什么能剪掉对角 `dfs(i-1, j-1)`？** 用集合语言最清楚。记 $F(i,j)$ 为两前缀的所有公共子序列构成的集合，则
> 
> $$F(i-1,\ j-1) \subseteq F(i-1,\ j)$$
> 
> 因为任何一个「`s[0..i-1]` 与 `t[0..j-1]` 的公共子序列」，**本身就已经是「`s[0..i-1]` 与 `t[0..j]` 的公共子序列」**——只不过恰好没用到 `t[j]`。多给一个字符，老方案一个都不会失效。所以对角这个候选在 `dfs(i-1, j)` 的搜索空间里**已被完整枚举过**，写不写都不影响正确性，只影响常数。
> 
> **相等时为什么能只留对角？** 交换论证：若某最优解没把 `s[i]`、`t[j]` 配成对，总能把它俩换进来而不变短，所以**一定存在一个最优解配上它俩**，对角支反过来支配另外两支。

> [!example]- 一个能看出差距的例子
> 
> `s = "ax"`，`t = "ba"`，取 `i=1`（`'x'`）、`j=1`（`'a'`），两字符不等：
> 
> ```text
> dfs(0, 1)   s="a",  t="ba"  → 1    ← 'a' 与 t[1]='a' 配上了
> dfs(1, 0)   s="ax", t="b"   → 0
> dfs(0, 0)   s="a",  t="b"   → 0    ← 「都退场」，严格更差
> ```
> 
> `dfs(0,0)` 把 `t[1]='a'` 也一起扔了，而这个字符**本来还有用**。「都退场」永远只是「让一个退场」的更保守子情况，不可能反超。

> [!success]- 三版演进：递归 → 二维递推 → 一维滚动
> 
> ```python
> from functools import cache
> 
> # ① 递归 + 记忆化（面试主推，能推导）
> class Solution:
>     def longestCommonSubsequence(self, text1: str, text2: str) -> int:
>         n, m = len(text1), len(text2)
> 
>         @cache
>         def dfs(i, j):
>             if i < 0 or j < 0:
>                 return 0                       # 空串与谁的 LCS 都是 0
>             if text1[i] == text2[j]:
>                 return dfs(i - 1, j - 1) + 1
>             return max(dfs(i - 1, j), dfs(i, j - 1))
>         return dfs(n - 1, m - 1)
> 
> # ② 二维递推：下标整体 +1，f[i+1][j+1] 对应 dfs(i, j)
> class Solution:
>     def longestCommonSubsequence(self, text1: str, text2: str) -> int:
>         n, m = len(text1), len(text2)
>         f = [[0] * (m + 1) for _ in range(n + 1)]   # 第 0 行/列全 0 = base case
>         for i, x in enumerate(text1):
>             for j, y in enumerate(text2):
>                 if x == y:
>                     f[i + 1][j + 1] = f[i][j] + 1
>                 else:
>                     f[i + 1][j + 1] = max(f[i][j + 1], f[i + 1][j])
>         return f[n][m]
> 
> # ③ 一维滚动：只保留一行，用 pre 手动兜住「左上角」
> class Solution:
>     def longestCommonSubsequence(self, text1: str, text2: str) -> int:
>         m = len(text2)
>         f = [0] * (m + 1)
>         for x in text1:
>             pre = f[0]                              # pre 暂存 f[i][j]（左上角旧值）
>             for j, y in enumerate(text2):
>                 tmp = f[j + 1]                      # 先存下本格旧值 f[i][j+1]
>                 f[j + 1] = pre + 1 if x == y else max(f[j + 1], f[j])
>                 pre = tmp                           # 旧值成为下一轮的左上角
>         return f[m]
> ```
> 
> - 主流程：三版**转移式完全相同**，区别只在「谁来存中间结果」——和 [[7.1 DP 打家劫舍]] 的四版演进是同一回事。
> - 下标 `+1` 偏移的用意：把状态从「下标」挪成「数量」，第 0 行/列天然就是 base case，负下标问题自动消失。
> - 递推里 `f[i][j+1]` 是**上方**（`dfs(i-1, j)`）、`f[i+1][j]` 是**左方**（`dfs(i, j-1)`）、`f[i][j]` 是**左上**——对照上方转移图看。

> [!warning]- 一维滚动的 `pre`：这里是全篇最易错处
> 
> 压成一维后，`f[j]` 在**本轮已被更新**成新值 `f[i+1][j]`，而 `f[j+1]` **尚未更新**仍是旧值 `f[i][j+1]`。于是：
> 
> ```text
> f[j]     → 已更新 → 就是"左方"  f[i+1][j]      ✓ 直接可用
> f[j+1]   → 未更新 → 就是"上方"  f[i][j+1]      ✓ 直接可用
> f[i][j]  → "左上角" → 已经被上一轮的写入覆盖了  ✗ 必须手动保存
> ```
> 
> 所以要用 `pre` 把左上角**在被覆盖前**存下来：每轮先 `tmp = f[j+1]`（本格旧值），写完新值后 `pre = tmp`，下一轮的左上角就位。
> 
> 对比 [[7.2 背包以及完全背包]]：背包一维只依赖**同一行的左边**，靠调整遍历方向（正序/倒序）就能解决；这里依赖**左、上、左上三个方向**，方向控制不了左上角，只能额外拿一个变量兜住。**这是两类一维优化的根本差异。**

## 变体二：72. 编辑距离（求最小）

把 `s` 变成 `t`，每步可插入 / 删除 / 替换一个字符，求最少操作数。

![](assets/7.3%20编辑距离对齐图.svg)

> [!tip]- 核心思路：别想「怎么编辑」，想「怎么对齐」
> 
> 把 `s` 写上排、`t` 写下排，允许在任一排插空格，则每一列只有三种形态：
> 
> | 这一列 | 含义 | 代价 |
> | --- | --- | --- |
> | `s[i]` 对 `t[j]` | 相同 = 匹配；不同 = **替换** | 0 或 1 |
> | `s[i]` 对 空 | s 有、t 没有 → **删除** | 1 |
> | 空 对 `t[j]` | t 有、s 没有 → **插入** | 1 |
> 
> 编辑距离 = 最优对齐的总代价。三个递归分支就是在穷举「**最右边那一列长什么样**」，三种形态不重不漏，`min` 挑最便宜的。指针怎么退，只看这一列**消耗了谁**：
> 
> - **替换**：同时用掉 `s[i]` 和 `t[j]` → `dfs(i-1, j-1) + 1`
> - **删除**：只用掉 `s[i]`（`t[j]` 没被消耗，还留着）→ `dfs(i-1, j) + 1`
> - **插入**：只用掉 `t[j]`（`s[i]` 一个字符都没花掉，还留着）→ `dfs(i, j-1) + 1`
> 
> **插入为什么是 `j` 退、`i` 不动**：插进去的字符是凭空造的，它立刻和 `t[j]` 配对然后双双出场，而你手里原有的 `s[0..i]` 还一个都没用掉。

> [!tip]- 两个常见疑问
> 
> **为什么只操作 `s` 就够，不用考虑动 `t`？**
> 「在 t 里删一个字符」和「在 s 里插一个字符」是**同一个对齐结果**，只是叙述方向相反。既然目标是让两串重合，双向操作能达到的对齐单向也能达到，代价相同，所以约定只改 `s`，搜索空间不损失。
> 
> **base case 为什么是 `j+1` / `i+1`？**
> 不是凭感觉加 1，是合同推出来的：
> 
> - `i < 0`：`s` 空了，`t` 还剩 `j+1` 个字符没对上 → 只能逐个**插入** → 返回 `j+1`
> - `j < 0`：`t` 空了，`s` 还剩 `i+1` 个多余字符 → 只能逐个**删除** → 返回 `i+1`
> 
> 剩下的字符必须全部处理，每个恰好 1 次操作。**注意这里两个边界不能合并成 `return 0`**——这是与 LCS 最大的结构差异。

> [!success]- 递归 + 二维递推
> 
> ```python
> from functools import cache
> 
> # ① 递归 + 记忆化
> class Solution:
>     def minDistance(self, s: str, t: str) -> int:
>         n, m = len(s), len(t)
> 
>         @cache
>         def dfs(i, j):
>             if i < 0:
>                 return j + 1                  # s 空了，插入 j+1 次
>             if j < 0:
>                 return i + 1                  # t 空了，删除 i+1 次
>             if s[i] == t[j]:
>                 return dfs(i - 1, j - 1)      # 免费匹配，代价 0
>             return min(dfs(i - 1, j),         # 删除
>                        dfs(i, j - 1),         # 插入
>                        dfs(i - 1, j - 1)) + 1 # 替换
>         return dfs(n - 1, m - 1)
> 
> # ② 二维递推：注意第 0 行、第 0 列不再是全 0
> class Solution:
>     def minDistance(self, s: str, t: str) -> int:
>         n, m = len(s), len(t)
>         f = [[0] * (m + 1) for _ in range(n + 1)]
>         f[0] = list(range(m + 1))                   # f[0][j] = j：空串插 j 次
>         for i, x in enumerate(s):
>             f[i + 1][0] = i + 1                     # f[i][0] = i：删 i 次
>             for j, y in enumerate(t):
>                 if x == y:
>                     f[i + 1][j + 1] = f[i][j]
>                 else:
>                     f[i + 1][j + 1] = min(f[i + 1][j], f[i][j + 1], f[i][j]) + 1
>         return f[n][m]
> ```
> 
> - **相等时为什么能直接 `dfs(i-1, j-1)` 而不比较另两支**：同样的支配论证——免费方案不可能比花 1 块钱的方案更贵，即 $dfs(i-1,j-1) \le dfs(i-1,j)+1$ 且 $dfs(i-1,j-1) \le dfs(i,j-1)+1$。
> - 也可以**不剪枝**，写成一行统一式，让 `min` 自己挑：
> 
> ```python
> return min(dfs(i-1, j) + 1,
>            dfs(i, j-1) + 1,
>            dfs(i-1, j-1) + (s[i] != t[j]))   # 指示器：相等免费，不等付 1
> ```

> [!tip]- 为什么 `+ (s[i] != t[j])` 能当 1 / 0 用
> 
> 因为 **Python 里 `bool` 是 `int` 的子类**——`True` 和 `False` 本来就是 `1` 和 `0`。`+` 只认识数字，于是布尔以本来面目参与运算，末尾那个括号就成了「这一列要不要付替换费」的**代价指示器**：相等免费，不等付 1。
> 
> 一个坑先记住：**这招不通用**，Java / Go 里 `bool` 与 `int` 完全隔离，必须显式写 `(s[i] != t[j] ? 1 : 0)`。
> 
> 机制、跨语言对照和另外几个坑（`True is 1` 为假、`isinstance` 会放行布尔、字典 key 撞车）见 [[Python_bool与int]]。

## 两题对照（套模板时看这张表）

> [!summary]- LCS vs 编辑距离：什么不变、什么改变
> 
> **完全不变**：`dfs(i, j)` 的双下标合同、「最右一对怎么消化」的三分支框架、下标 `+1` 偏移的递推写法、三版演进路径。
> 
> **改变的只有四处**：
> 
> | | 1143. LCS | 72. 编辑距离 |
> | --- | --- | --- |
> | `combine` | `max`（求最长） | `min`（求最少） |
> | 相等时 | `dfs(i-1,j-1) + 1`（配对得分） | `dfs(i-1,j-1)`（免费，代价 0） |
> | 不等时 | `max(dfs(i-1,j), dfs(i,j-1))`<br>**只有两支** | `min(三支) + 1`<br>**三支都要** |
> | base | `i<0 or j<0` → `0` | `i<0` → `j+1`；`j<0` → `i+1`<br>**两个边界分开写** |
> 
> 最关键的一处差异：**不等时 LCS 只要两支，编辑距离要三支**。因为 LCS 里「两个都退场」被「只退一个」包含（多一个字符不会让老方案失效），而编辑距离里「替换」是一个**真实且不可替代的操作**——用一次操作同时消化两个字符，删除+插入要花两次，替换严格更优，不能剪。

## 易错点

> [!warning]- 易错点
> 
> - **把「子序列」当「子串」**：子序列可以不连续，只要求相对顺序。若题目要的是连续子串（如 718. 最长重复子数组），转移完全不同——不等时直接归 0，不能取 `max` 继承。
> - **不等时给编辑距离剪掉了对角支**：LCS 能剪是因为被包含，编辑距离**不能剪**，替换是不可替代的操作。这是最容易「照搬 LCS 模板」翻车的地方。
> - **编辑距离的两个 base 写成一个**：`if i < 0 or j < 0: return 0` 是错的，必须分开返回 `j+1` 和 `i+1`，否则少算了「把剩余字符全部处理掉」的代价。
> - **一维滚动漏了 `pre`**：直接用 `f[j]` 当左上角必错——`f[j]` 已经被本轮更新成左方了。必须用 `tmp`/`pre` 把旧值传下去，顺序是「先存 `tmp` → 再写 `f[j+1]` → 最后 `pre = tmp`」，三步一步都不能换位。
> - **递推下标偏移搞混**：`f[i+1][j+1]` 才对应 `dfs(i, j)`；`f[i][j+1]` 是上方、`f[i+1][j]` 是左方，写反了方向就错。
> - **`@cache` 撞名或忘记加**：不加记忆化就是 $O(2^{n+m})$ 指数爆炸；局部变量别叫 `cache`，会遮住 `functools.cache`（见 [[Python_cache]]）。
> - **入口写错**：`dfs(n-1, m-1)` 是因为定义里 `i`、`j` 都是**下标**；若改成「前 `i` 个」的数量语义，入口就变 `dfs(n, m)`（见 [[7.1 DP 打家劫舍]] 的「进阶一」）。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = \text{状态个数} \times \text{单次转移}$。
> 
> - 状态数 $= n \times m$（两个下标的组合），单次转移 $O(1)$ ⇒ 时间 $O(nm)$，两题同阶。
> - 不加记忆化的朴素递归是 $O(2^{n+m})$——每层分裂两到三支，必须记忆化。
> - 空间：记忆化 $O(nm)$ + 递归栈 $O(n+m)$；二维递推 $O(nm)$；**一维滚动 $O(\min(n,m))$**（可把较短的串放内层进一步省空间）。
> - 注意一维滚动只能求**长度 / 距离**；若要还原**具体的子序列或操作序列**，必须保留完整二维表回溯路径。

## 一句话总结

双序列 DP 的全部功夫在一句话上——**最右边的 `s[i]` 和 `t[j]` 这一步怎么消化**；三种消化方式决定三个分支，`max` / `min` 与 base case 决定是哪道题。

## 模板归纳

看到「**两个字符串 / 数组** + 求最长匹配 / 最少操作 / 最多保留」，四步落笔：

1. **写合同**：`dfs(i, j) = s[0..i] 与 t[0..j] 的答案`，两个下标都是**下标**语义，入口 `dfs(n-1, m-1)`。
2. **分支只问一句**：最右边的 `s[i]`、`t[j]` 怎么消化？配成一对 → `dfs(i-1,j-1)`；只退 `s[i]` → `dfs(i-1,j)`；只退 `t[j]` → `dfs(i,j-1)`。
3. **定 `combine` 与 base**：求最长用 `max`、base 归 0；求最少操作用 `min`、base 是剩余长度。拿不准时**三支全塞进去别剪枝**，`max`/`min` 会自己挑——候选允许重、不允许漏。
4. **加 `@cache`**；需要压空间再翻二维递推（下标 `+1` 偏移），最后才考虑一维滚动（**记得用 `pre` 兜左上角**）。

```python
# 双序列 DP 通用骨架
@cache
def dfs(i, j):
    if i < 0 or j < 0:
        return BASE(i, j)                    # LCS: 0；编辑距离: j+1 / i+1
    return combine(dfs(i - 1, j - 1) + w(s[i], t[j]),   # 配成一对
                   dfs(i - 1, j)     + w_del,           # 只退 s[i]
                   dfs(i,     j - 1) + w_ins)           # 只退 t[j]
```
