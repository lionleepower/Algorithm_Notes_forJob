# 线性 DP：最长递增子序列 LIS

## 解决什么问题

**一个序列**内部求「最长递增 / 最多能保留几个 / 最少删几个」——这类题统称 **LIS 模型（Longest Increasing Subsequence）**。识别信号：

```text
输入是单个数组 + 求最长 + 答案与「顺序」有关但与「连续」无关 + 能否接上取决于「值的大小」
```

先钉死前提：**子序列可以不连续，但相对顺序必须保持**（`[3,6,2,7]` 是 `[0,3,1,6,2,2,7]` 的子序列）。连续的那类叫子串，是另一套解法。

本篇与前三篇的分水岭在**状态语义**，这也是最容易套错模板的地方：

| 专题 | 状态 | `nums[i]` 是否强制被选 | 答案 |
| --- | --- | --- | --- |
| [[7.1 DP 打家劫舍]] | `dfs(i)`：**前** `i+1` 间房的最优解 | 否，可选可不选 | `dfs(n-1)` |
| [[7.2 背包以及完全背包]] | `dfs(i, c)`：下标 + 容量 | 否 | `dfs(n-1, C)` |
| [[7.3 线性dp 最长公共子序列]] | `dfs(i, j)`：两个前缀 | 否 | `dfs(n-1, m-1)` |
| **本篇 300. LIS** | `dfs(i)`：**以** `nums[i]` **结尾** | **是，强制选** | `max(dfs(i))` |

## 思路一：$O(n^2)$ 的 DP —— 全部信息量都在定义里

![](assets/7.4%20LIS%20状态定义.svg)

$$dfs(i) = \text{以 } nums[i] \textbf{ 结尾} \text{ 的最长严格递增子序列长度}$$

「以 i 结尾」不是随手加的修饰，它是这道题唯一走得通的状态设计。转移、base case、入口，全都是从这句定义推出来的。

> [!tip]- 为什么必须「以 i 结尾」：后效性的标准修法
> 
> 先试更自然的前缀定义：
> 
> $$dfs(i) = nums[0..i] \text{ 范围内的 LIS 长度}$$
> 
> 推不下去。假设 `dfs(i-1)` 算出 3，现在要决定 `nums[i]` 能不能接上去——**信息不够**：这个 3 只告诉你长度，不告诉你那条子序列的结尾是几。而「能不能接」恰恰只取决于结尾值。
> 
> 这就是**有后效性**：子问题的返回值不足以支撑父问题做决策（见 [[重叠子问题与无后效性]]）。
> 
> 修复办法只有一个——**把缺失的信息塞进状态**。缺的是「上一个选的数是谁」，那就规定 `nums[i]` 必须被选中且作为结尾。状态一锁定结尾，转移条件 `nums[j] < nums[i]` 就是纯粹的局部判断，后效性消失。
> 
> > **通用原则：当「能否转移」依赖于上一步选了什么具体的值，就把那个值锁进状态。**
> 
> 这正是 LIS 与打家劫舍的根本分水岭：打家劫舍的「能否选」只依赖下标是否相邻，不依赖值，所以前缀语义够用。
> 
> 代价是：定义变强了，答案就不再是单个状态——这是下面「入口」一节的伏笔。

> [!tip]- 转移：为什么「枚举上一个选谁」不重不漏
> 
> ```python
> for j in range(i):
>     if nums[j] < nums[i]:
>         res = max(res, dfs(j))
> return res + 1
> ```
> 
> 这里用的不是回溯常见的「选/不选」二元分支，而是**枚举上一个元素是谁**。
> 
> 它为什么是完美划分？取任意一条以 `nums[i]` 结尾的递增子序列，把最后一个元素 `nums[i]` 摘掉：
> 
> - 要么变成空 → 对应 `res = 0` 那一支；
> - 要么剩下的部分**必然是以某个 `nums[j]` 结尾的递增子序列**，且这个 `j` 唯一确定（就是倒数第二个元素的下标）。
> 
> 所以「按倒数第二个元素的下标 j 分类」+「空」构成了对所有情况**互斥且完备**的划分。`max` 在这里没有魔法，就是在一个完整分类上取最优。

> [!tip]- base case 去哪了？它是隐式的
> 
> 代码里没有 `if i == 0: return 1`，却是对的：
> 
> ```python
> res = 0                    # ← 这就是 base case
> for j in range(i): ...     # i == 0 时循环体一次都不执行
> return res + 1             # → 返回 1
> ```
> 
> 关键：**`res = 0` 承担的不是「下标越界」，而是「前驱为空」这个分类分支。** `i == 0` 只是触发它的场景之一——`nums = [5, 1]` 里的 `i = 1` 前面明明有元素，但没有比 1 小的，for 一个都没命中，同样走 `res = 0` 返回 1。
> 
> 印证那条原则：**base case 由语义决定，不由下标决定**。这里的语义是「只有 `nums[i]` 自己一个元素的子序列，长度为 1」，天然被初始值兜住，不需要显式边界判断。

> [!tip]- 入口为什么是 max 而不是 dfs(n-1)
> 
> 判据一句话：**`dfs(n-1)` 能当答案，当且仅当定义本身具有「前缀最优」语义**（即它已经包含了「不选 `nums[n-1]`」的情况）。
> 
> | | 打家劫舍 198 | LIS 300 |
> | --- | --- | --- |
> | `dfs(i)` 语义 | 前 `i+1` 间房的最优解（**前缀**） | 以 `nums[i]` **结尾**的最优解（**必选 i**） |
> | 状态间有无包含关系 | 有，`dfs(i)` 已涵盖 `dfs(i-1)` | 无，各管各的结尾 |
> | 答案 | `dfs(n-1)` | `max(dfs(i) for i in range(n))` |
> 
> LIS 的定义强制选中 `nums[i]`，那 `dfs(n-1)` 就只是「必须以最后一个元素结尾」的答案，漏掉了 LIS 不以 `nums[n-1]` 收尾的所有情况，所以必须在 n 个互斥的结尾上取 `max`。
> 
> > 记法：**定义里带「必须包含 i」的，答案就是 max；带「前 i 个」的，答案就是最后一个状态。**

> [!success]- 代码：递归 + 记忆化 → 递推
> 
> ```python
> from functools import cache
> from typing import List
> 
> # ① 递归 + 记忆化（面试主推，能当场推导）
> class Solution:
>     def lengthOfLIS(self, nums: List[int]) -> int:
>         n = len(nums)
> 
>         @cache
>         def dfs(i: int) -> int:
>             res = 0                          # 前驱为空的分支，即隐式 base case
>             for j in range(i):
>                 if nums[j] < nums[i]:        # 严格递增；非降改成 <=
>                     res = max(res, dfs(j))
>             return res + 1                   # +1 = 把 nums[i] 自己算上
>         return max(dfs(i) for i in range(n))
> 
> # ② 递推：dfs 改名 f，递归改循环，递归边界改初始值
> class Solution:
>     def lengthOfLIS(self, nums: List[int]) -> int:
>         n = len(nums)
>         f = [0] * n
>         for i in range(n):
>             for j in range(i):
>                 if nums[j] < nums[i]:
>                     f[i] = max(f[i], f[j])
>             f[i] += 1                        # 注意：+1 在内层循环之外
>         return max(f)
> ```
> 
> - 主流程：外层枚举结尾 `i`，内层枚举前驱 `j`，取合法前驱里最大的 `f[j]` 再 `+1`。
> - 关键变量：`f[i]` 是「以 i 结尾」的长度，**不是**「前 i 个的答案」，所以最后要 `max(f)`。
> - 易错位置：`f[i] += 1` 若写进内层循环，就变成每命中一个 `j` 加一次，错得很隐蔽。等价写法是初始化 `f = [1] * n` 再写 `f[i] = max(f[i], f[j] + 1)`，**二选一，别混着写**。
> - **不能滚动优化**：`f[i]` 依赖前面**所有**的 `f[j]`，不是固定常数个，整个数组都得留着。这是 LIS 与爬楼梯 / [[7.1 DP 打家劫舍]] 的又一个区别。

## 思路二：转成 LCS 看（了解即可）

> [!tip]- LIS 等价于「nums 与 排序去重后的 nums」的 LCS
> 
> ```text
> nums        = [1, 3, 3, 2, 4]
> 排序去重后   = [1, 2, 3, 4]
> LCS         = [1, 3, 4] 或 [1, 2, 4]   长度 3 = LIS 长度
> ```
> 
> 直觉：排序后的数组给出了「递增」这个约束的全部合法排列，两者的公共子序列既保持原数组顺序、又保持递增。
> 
> **必须去重**，否则相同元素会在 LCS 里被匹配两次，把严格递增算成非降。
> 
> 价值只在于「一题两看」，把它接到 [[7.3 线性dp 最长公共子序列]] 的模板上；复杂度仍是 $O(n^2)$（还多一次排序），**面试不要主动写这个版本**。

## 思路三：$O(n\log n)$ 的贪心 + 二分（面试加分项）

![](assets/7.4%20交换状态与状态值.svg)

$O(n^2)$ 是及格线，这个是加分项，而且思路完全不同——它不再是 DP，是贪心。做法来自一个通用技巧：**交换状态与状态值**。

$$g[k] = \text{当前扫描到的所有长度为 } k+1 \text{ 的递增子序列中，最小的那个结尾元素}$$

> [!tip]- 两条性质 + 处理规则
> 
> 1. **`g` 严格递增。** 反证：若 `g[k] >= g[k+1]`，把那条长度 `k+2` 的子序列砍掉最后一个，就得到一条长度 `k+1`、结尾小于 `g[k]` 的子序列，与「`g[k]` 是最小」矛盾。→ 所以可以二分。
> 2. **`len(g)` 就是答案。**
> 
> 处理每个 `x`：在 `g` 中二分找第一个 $\ge x$ 的位置 `k`（即 `bisect_left`）
> 
> - 找到了 → `g[k] = x`（长度不变，但结尾变小）
> - 没找到（x 比 g 中所有数都大）→ `g.append(x)`（长度 +1）
> 
> **为什么替换不会丢解？** `g[k]` 的语义是「长度 k+1 可达的最小结尾」，替换正是在维护这个最小值；而结尾越小，未来越多的数能接在它后面——「更小总是不劣」的单调性就是贪心成立的依据。同时，被替换掉的那个较大值所证明的事实（「长度 k+1 是可达的」）已经被 `len(g)` 记住了，不会因替换而丢失。
> 
> **和思路一的联系：** `bisect_left` 返回的 `k` 加 1，正好就是 $O(n^2)$ 版里的 `f[i]`。也就是说 **`g` 是把 `f` 按值分组后取的最小值**——两种解法算的是同一个东西，只是二分版用有序性把「扫一遍找最大 `f[j]`」压成了 $O(\log n)$。

> [!example]- 手动跑 nums = [10,9,2,5,3,7,101,18]
> 
> ```text
> x=10   bisect_left([], 10)     = 0 = len(g) → append    g=[10]
> x=9    bisect_left([10], 9)    = 0 < len    → g[0]=9    g=[9]
> x=2    bisect_left([9], 2)     = 0 < len    → g[0]=2    g=[2]
> x=5    bisect_left([2], 5)     = 1 = len(g) → append    g=[2,5]
> x=3    bisect_left([2,5], 3)   = 1 < len    → g[1]=3    g=[2,3]
> x=7    bisect_left([2,3], 7)   = 2 = len(g) → append    g=[2,3,7]
> x=101  bisect_left(..., 101)   = 3 = len(g) → append    g=[2,3,7,101]
> x=18   bisect_left(..., 18)    = 3 < len    → g[3]=18   g=[2,3,7,18]
> → len(g) = 4  ✓
> ```
> 
> 看最后两步：`101` 进来时长度就已经涨到 4，`18` 只是把结尾从 101 压到 18。**长度不变、结尾变小**——这就是替换操作的全部意义，它在为后面可能出现的数留路。

> [!success]- 代码：标准版 / 紧凑版 / 原地版
> 
> ```python
> from bisect import bisect_left
> from typing import List
> 
> # ① 标准版（面试写这版，意图最清楚）
> class Solution:
>     def lengthOfLIS(self, nums: List[int]) -> int:
>         g = []                              # g[k] = 长度 k+1 的 IS 的最小结尾
>         for x in nums:
>             j = bisect_left(g, x)           # 第一个 >= x 的位置
>             if j == len(g):
>                 g.append(x)                 # x 比所有结尾都大 → 长度 +1
>             else:
>                 g[j] = x                    # 长度不变，结尾变小
>         return len(g)
> 
> # ② 紧凑版：append 后 g[j] = x 是自我赋值，无害
> j = bisect_left(g, x)
> if j == len(g):
>     g.append(x)
> g[j] = x
> 
> # ③ 原地版：额外空间 O(1)，拿 nums 的前缀当 g（ng <= i，永不覆盖未读元素）
> class Solution:
>     def lengthOfLIS(self, nums: List[int]) -> int:
>         ng = 0                              # g 的当前长度
>         for x in nums:
>             j = bisect_left(nums, x, 0, ng) # 只在 nums[0:ng] 这段里二分
>             if j == ng:
>                 nums[ng] = x
>                 ng += 1
>             else:
>                 nums[j] = x
>         return ng
> ```
> 
> - 关键变量：`g`（或 `nums[0:ng]`）**始终严格递增**，这是能二分的前提，也是全篇的核心不变量。
> - 版本取舍：面试默认写 ①；③ 提一句「可以原地做到额外空间 $O(1)$」即可，不必真写；② 可读性差，不推荐。
> - C++ 对应：`bisect_left` 就是 `lower_bound`，替换写 `*it = x`，追加写 `push_back`。

> [!warning]- `g` 本身不是一个合法的 LIS
> 
> `nums = [3,4,1,2]` 跑完得到 `g = [1,2]`，虽然碰巧也是一条合法子序列，但很多情况下 `g` 里的元素在原数组中的下标顺序是乱的。
> 
> **只有长度是对的。** 要还原具体序列，必须另存前驱指针（或者退回 $O(n^2)$ 版按 `f` 回溯路径）。

## 变体：允许相同元素（非严格递增）

> [!tip]- 严格 / 非严格只差一个字母
> 
> | 题目要求 | $O(n^2)$ 版 | $O(n\log n)$ 版 |
> | --- | --- | --- |
> | 严格递增（本题 300） | `nums[j] < nums[i]` | `bisect_left` / `lower_bound` |
> | 非降，允许相等 | `nums[j] <= nums[i]` | `bisect_right` / `upper_bound` |
> 
> 想清楚为什么：`nums = [1,1]` 求**严格**递增答案是 1。`bisect_left(g=[1], 1)` 返回 0，小于 `len(g)` → 替换，长度不变 ✓；若换成 `bisect_right` 返回 1，等于 `len(g)` → append，长度变 2，那正是**非降**的答案。
> 
> 一句话：**`left` 会撞上相等元素并替换掉它，`right` 会跳过相等元素去追加**——这就是全部差别。改的时候和 `nums[i]` 相同的 `g[j]` 不用动，要改的是第一个严格大于 `nums[i]` 的 `g[j]`。
> 
> ```text
> nums = [1, 6, 7, 2, 2, 5, 2]   非严格递增
> g: [1] → [1,6] → [1,6,7] → [1,2,7] → [1,2,2] → [1,2,2,5] → [1,2,2,2]
> ```

> [!success]- 非严格递增代码（在原地版上只改一个函数名）
> 
> ```python
> from bisect import bisect_right
> from typing import List
> 
> class Solution:
>     def lengthOfNonDecreasingSubseq(self, nums: List[int]) -> int:
>         ng = 0
>         for x in nums:
>             j = bisect_right(nums, x, 0, ng)   # 唯一改动：left → right
>             if j == ng:
>                 nums[ng] = x
>                 ng += 1
>             else:
>                 nums[j] = x
>         return ng
> ```

## 易错点

> [!warning]- 易错点
> 
> - **严格 vs 非严格搞反**：严格用 `nums[j] < nums[i]` / `bisect_left`，非降用 `nums[j] <= nums[i]` / `bisect_right`。二分版只差一个函数名，考试最爱在这里下刀。
> - **答案写成 `dfs(n-1)` / `f[n-1]`**：定义强制选中 `nums[i]`，各状态互不包含，必须 `max(f)`。这是套打家劫舍模板最常翻的车。
> - **`f[i] += 1` 写进内层循环**：变成「每命中一个合法 j 就加一次」，样例还可能碰巧过，错得很隐蔽。
> - **想优化成滚动变量**：`f[i]` 依赖前面所有状态，依赖个数不是常数，**不可滚动**。
> - **以为 `g` 就是那条 LIS**：`g` 只保证长度正确，元素顺序未必对应原数组，要还原序列得另存前驱。
> - **`@cache` 装饰实例方法**：LeetCode 上没问题，但工程里 `lru_cache` 会持有 `self` 引用导致对象无法回收（内存泄漏），面试被追问可以提一嘴（见 [[Python_cache]]）。
> - **`max()` 对空序列抛异常**：本题约束 $n \ge 1$ 所以安全，但改题或复用模板时记得处理 `n == 0`。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = \text{状态个数} \times \text{单次转移}$。
> 
> - **DP 版**：状态数 $n$，单次转移 $O(n)$（内层扫一遍前缀）⇒ 时间 $O(n^2)$；空间 $O(n)$——记忆化表 / `f` 数组，递归版另加 $O(n)$ 栈。
> - **贪心 + 二分版**：$n$ 次二分，每次 $O(\log n)$ ⇒ 时间 $O(n\log n)$；空间 $O(n)$（最坏 `g` 存满），原地版可降到额外空间 $O(1)$。
> - 不加 `@cache` 的朴素递归是指数级，必须记忆化（见 [[记忆化搜索]]）。
> - 若要**还原具体子序列**而不只是长度，两版都需额外 $O(n)$ 记录前驱，且二分版必须靠前驱指针回溯。

## 一句话总结

LIS 的全部功夫在一句定义上——**「以 `nums[i]` 结尾」**：锁住结尾才消除后效性，代价是答案必须取 `max(f)`；再把这个定义的状态与状态值一交换（`g[k]` = 长度 k+1 的最小结尾），$O(n^2)$ 就塌缩成 $O(n\log n)$。

## 模板归纳

看到「**单个数组** + 求最长递增 / 最多保留 / 最少删除 + 能否接上取决于**值的大小**」，四步落笔：

1. **写合同**：`f[i] = 以 nums[i] 结尾的答案`。判据——只要「能否转移」依赖上一步选的**具体值**，就必须把这个值锁进状态（对照打家劫舍：只依赖下标相邻关系，前缀语义就够）。
2. **写转移**：枚举「上一个选谁」，`f[i] = max(f[j] | j < i 且 nums[j] < nums[i]) + 1`。分类依据是「倒数第二个元素的下标」，不重不漏。
3. **定入口**：定义带「必须包含 i」⇒ 答案 `max(f)`；带「前 i 个」⇒ 答案 `f[n-1]`。base case 由 `res = 0` 隐式兜住，不用写。
4. **要更快就交换状态与状态值**：`g[k] = 长度 k+1 的最小结尾`，`g` 严格递增所以能二分，`len(g)` 即答案。严格用 `bisect_left`，非降用 `bisect_right`。

```python
# LIS 通用骨架（两版对照）

# ① O(n^2)：状态 = 下标，值 = 长度，答案 max(f)
for i in range(n):
    f[i] = max((f[j] for j in range(i) if nums[j] < nums[i]), default=0) + 1

# ② O(n log n)：状态 = 长度，值 = 最小结尾，答案 len(g)
for x in nums:
    j = bisect_left(g, x)          # 非降版换成 bisect_right
    if j == len(g):
        g.append(x)
    else:
        g[j] = x
```
