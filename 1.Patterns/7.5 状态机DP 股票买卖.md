# 状态机 DP：股票买卖系列

## 解决什么问题

题目里出现**互斥的身份 / 持仓 / 模式**，且今天能做什么取决于昨天处于哪种身份——这类题统称**状态机 DP（State Machine DP）**。识别信号：

```text
序列上逐天决策 + 存在有限个互斥状态（持有 / 未持有 / 冷冻中）+ 状态之间只有固定几条转移边
```

做法固定成两步：**先画状态机图，再把每条边翻译成一个 `max` 分支**。图画对了，代码只是誊写。

整个股票系列就是同一张图的加料版，先把地图铺开——**它们的差别全部落在「边」上，骨架一个字都不用改**：

| 题号 | 约束 | 相对母题改了什么 |
| --- | --- | --- |
| **122. 买卖股票的最佳时机 II** | 不限交易次数（母题） | —— |
| 309. 含冷冻期 | 卖出后隔一天才能买 | 买入边改读 `dfs(i-2, False)` |
| 714. 含手续费 | 每笔交易付 `fee` | 卖出边多减一个 `fee` |
| **188. 最佳时机 IV** | **至多** k 笔 | 加一维 `j`（交易预算） |
| 121. 最佳时机 | 只能买卖一次 | 188 取 `k = 1` |
| 123. 最佳时机 III | 至多两笔 | 188 取 `k = 2` |
| Follow up | **恰好** / **至少** k 笔 | 只改 base case |

## 统一模板：两个状态、四条边

![](assets/7.5%20股票状态机转移图.svg)

> [!tip]- 核心思路：先钉死语义契约，其余全被唯一确定
> 
> $$dfs(i,\ hold) = \text{只考虑前 } i \text{ 天（0..i），且第 } i \text{ 天} \textbf{结束时}\text{持股状态为 } hold \text{ 的最大利润}$$
> 
> `hold` 不是「今天要不要买」，而是**今天收盘那一刻手里有没有股票**。这一句定死之后，入口、base case、转移全部被唯一确定。
> 
> 还有一条等价读法很有用：**第 `i-1` 天的结束就是第 `i` 天的开始**，所以 `dfs(i-1, ·)` 也可以读成「第 `i` 天开市时」的最优值。
> 
> **转移 = 站在今天的状态，反推昨天。** 因为 `dfs(i-1, ·)` 已经把「第 i 天之前的所有事」结算完了，所以**第 i 天的买卖动作，发生在从 `i-1` 状态跳到 `i` 状态的那条边上**：
> 
> | 今天的状态 | 来源一：什么也不做 | 来源二：今天动手 |
> | --- | --- | --- |
> | `hold = True`（收盘有货） | 昨天就有货 `dfs(i-1, True)` | 昨天没货，今天**买入** `dfs(i-1, False) - prices[i]` |
> | `hold = False`（收盘空仓） | 昨天就没货 `dfs(i-1, False)` | 昨天有货，今天**卖出** `dfs(i-1, True) + prices[i]` |
> 
> 每个状态恰好两个来源，穷举分类**无重叠、无遗漏**。
> 
> **`-prices[i]` 出现在 `hold=True` 分支里并不矛盾**：减号代表「买入动作」，而买入的结果正是「变成持股」。花钱与到货是同一条边的两面。

> [!tip]- base case：为什么必须是 -inf 而不是 0
> 
> `i < 0` 表示「第 0 天还没开始」。此时：
> 
> - 不持股是合法的，利润 `0`；
> - **持股是不可能的**——还没开过市，凭空多一支股票。
> 
> 用 `-inf` 而不是 `0` 或 `-1`，是因为它要在 `max` 里**永远输**，等价于「这条路不存在」。验证：
> 
> ```text
> dfs(0, True) = max(dfs(-1, True), dfs(-1, False) - prices[0])
>              = max(-inf,          0 - prices[0])   = -prices[0]   ✓ 第 0 天买入
> ```
> 
> 若写成 `0`，就变成 `max(0, -prices[0]) = 0`，相当于宣称「你可以免费持有一支股票」，整个答案被污染。
> 
> **`-inf` 是「非法状态」的编码方式**——这个手法在下面 188 的 `j < 0` 和哨兵列里会反复出现，是全篇的主线。
> 
> **入口 `dfs(n-1, False)`**：最后一天收盘还攥着股票，一定不优于把它卖掉（或当初就别买），所以 $\max(dfs(n-1,0),\ dfs(n-1,1)) = dfs(n-1, 0)$，直接取 `hold=False`。

> [!success]- 122. 不限次数：递归 → 递推 → 滚动变量
> 
> ```python
> from functools import cache
> from math import inf
> from typing import List
> 
> # ① 递归 + 记忆化（面试主推）
> class Solution:
>     def maxProfit(self, prices: List[int]) -> int:
>         n = len(prices)
> 
>         @cache
>         def dfs(i: int, hold: bool) -> int:
>             if i < 0:
>                 return -inf if hold else 0        # 开市前持股 = 非法
>             if hold:
>                 # 今天收盘有货：昨天就有货，或昨天没货今天买
>                 return max(dfs(i - 1, True), dfs(i - 1, False) - prices[i])
>             return max(dfs(i - 1, False), dfs(i - 1, True) + prices[i])
>         return dfs(n - 1, False)
> 
> # ② 递推：i 维 +1 偏移，f[i+1] 对应 dfs(i)
> class Solution:
>     def maxProfit(self, prices: List[int]) -> int:
>         n = len(prices)
>         f = [[0] * 2 for _ in range(n + 1)]
>         f[0][1] = -inf                            # 只有「开市前持股」需要设非法
>         for i, p in enumerate(prices):
>             f[i + 1][0] = max(f[i][0], f[i][1] + p)
>             f[i + 1][1] = max(f[i][1], f[i][0] - p)
>         return f[n][0]
> 
> # ③ 滚动变量：只依赖上一行，两个变量就够
> class Solution:
>     def maxProfit(self, prices: List[int]) -> int:
>         f0, f1 = 0, -inf
>         for p in prices:
>             new_f0 = max(f0, f1 + p)              # 必须先用旧 f1 算 f0
>             f1 = max(f1, f0 - p)                  # 再用旧 f0 更新 f1
>             f0 = new_f0
>         return f0
> ```
> 
> - 主流程：三版**转移式完全相同**，区别只在「谁来存中间结果」——和 [[7.1 DP 打家劫舍]] 的四版演进是同一回事。
> - 关键变量：`f0` / `f1` 是「昨天收盘空仓 / 持股」的最优利润，`hold` 直接当下标用（布尔即 0/1，见 [[Python_bool与int]]）。
> - 易错位置：滚动版**必须用临时变量**。若先写 `f0 = max(f0, f1 + p)` 再算 `f1`，第二行读到的就是**今天的** `f0` 而不是昨天的，相当于允许同一天先卖后买赚差价。

## 变体一：309. 含冷冻期（改一条边）

卖出后无法在第二天买入（冷冻期 1 天）。

> [!tip]- 为什么只改买入边，且是 i-2 不是 i-1
> 
> 冷冻期约束的是**买入**这个动作：今天要买，说明昨天必须没有卖出动作。而「昨天没卖」等价于「**前天收盘时就已经空仓**」——如果前天空仓、昨天也空仓，中间不可能发生卖出。
> 
> 所以买入边的来源从「昨天空仓」收紧成「**前天**空仓」：
> 
> ```text
> dfs(i, True) = max(dfs(i-1, True), dfs(i-2, False) - prices[i])
>                                        ↑ 唯一的改动
> ```
> 
> **卖出边一个字都不用改**，因为约束不针对卖出。
> 
> `i-2` 可能等于 `-2`，但 `if i < 0` 这一行把所有负下标一并接住了，返回 `0`（不持股）——语义上正确：开市前当然处于「空仓且无冷冻」。

> [!success]- 309 代码（与 122 只差一个字）
> 
> ```python
> from functools import cache
> from math import inf
> from typing import List
> 
> class Solution:
>     def maxProfit(self, prices: List[int]) -> int:
>         n = len(prices)
> 
>         @cache
>         def dfs(i: int, hold: bool) -> int:
>             if i < 0:
>                 return -inf if hold else 0
>             if hold:
>                 return max(dfs(i - 1, True), dfs(i - 2, False) - prices[i])
>             return max(dfs(i - 1, False), dfs(i - 1, True) + prices[i])
>         return dfs(n - 1, False)
> ```
> 
> 递推与空间优化同理：因为依赖回退到了 `i-2`，滚动时要多留一个变量 `pre_f0`（对应 `f[i-1][0]`），本质和 [[7.1 DP 打家劫舍]] 里「滚动两个变量」是同一件事。

## 变体二：714. 含手续费（改一个数）

每完成一笔交易付 `fee`。把手续费记在**卖出**那一端（记在买入端也行，**但只能记一次**）：

```python
return max(dfs(i - 1, False), dfs(i - 1, True) + prices[i] - fee)   # 卖出时付费
```

其余与 122 完全一致。买卖各扣一次是最常见的错，这与 188 里「预算只在一端扣」是同一条纪律。

## 变体三：188. 至多 k 笔交易（加一维）

> [!tip]- 语义契约：j 是「这个子问题的交易预算」，不是全局计数器
> 
> $$dfs(i,\ j,\ hold) = \text{前 } i \text{ 天内} \textbf{至多}\text{还能完成 } j \text{ 笔交易、第 } i \text{ 天收盘状态为 } hold \text{ 的最大利润}$$
> 
> 一笔交易 = 买 + 卖**一对**。只要不重复计数，在哪一端扣预算都行，本篇统一选择**在卖出时扣**：
> 
> - 买入：`dfs(i-1, j, False) - prices[i]` —— 交易还没闭合，预算不动
> - 卖出：`dfs(i-1, j-1, True) + prices[i]` —— 今天用掉一笔，前缀只剩 `j-1` 笔可用
> 
> 若买入时也减，一次交易扣两次预算，答案偏小。**「j 只在一个端点减」是这道题的核心不变量。**

> [!warning]- 两个 base case 的先后顺序不能换
> 
> ```python
> if j < 0: return -inf            # 必须在前：非法状态
> if i < 0: return -inf if hold else 0
> ```
> 
> 反例 `k = 0, prices = [1, 5]`，正确答案是 `0`。假如先判 `i < 0`：
> 
> ```text
> dfs(0, -1, True)  = max(dfs(-1,-1,True), dfs(-1,-1,False) - 1)
>                   = max(-inf,            0 - 1)               = -1   ← 泄漏！
> dfs(1,  0, False) = max(dfs(0,0,False),  dfs(0,-1,True) + 5)  = 4    ✗
> ```
> 
> `dfs(-1, -1, False)` 被 `i < 0` 分支拦下返回 `0`，**「预算已透支」这个信息被吞掉了**，于是白送一笔交易。先判 `j < 0` 就堵死了：任何 `j` 为负的状态，无论 `i` 多少、无论 hold 与否，一律 `-inf`。
> 
> > **原则：非法性判断优先于终止性判断。**

> [!example]- 验证 k = 1, prices = [1, 5]
> 
> ```text
> dfs(1,1,False) = max( dfs(0,1,False),  dfs(0,0,True) + 5 )
> dfs(0,1,False) = max( dfs(-1,1,False), dfs(-1,0,True) + 1 ) = max(0, -inf) = 0
> dfs(0,0,True)  = max( dfs(-1,0,True),  dfs(-1,0,False) - 1 ) = max(-inf, -1) = -1
>              ⇒ max(0, -1 + 5) = 4   ✓
> ```
> 
> 注意 `dfs(0,0,True)` 等于 `-1`：第 0 天买入后预算仍是 `0`，因为**买入不扣**，直到第 1 天卖出时才用 `j-1` 把它扣掉。

![](assets/7.5%20哨兵列与下标平移.svg)

> [!success]- 188 三版：递归 → 递推（哨兵列）→ 空间优化
> 
> ```python
> from functools import cache
> from math import inf
> from typing import List
> 
> # ① 递归 + 记忆化
> class Solution:
>     def maxProfit(self, k: int, prices: List[int]) -> int:
>         n = len(prices)
> 
>         @cache
>         def dfs(i: int, j: int, hold: bool) -> int:
>             if j < 0:
>                 return -inf                       # 预算透支 = 非法，必须排在前面
>             if i < 0:
>                 return -inf if hold else 0
>             if hold:
>                 return max(dfs(i-1, j, True), dfs(i-1, j, False) - prices[i])
>             return max(dfs(i-1, j, False), dfs(i-1, j-1, True) + prices[i])
>         return dfs(n - 1, k, False)
> 
> # ② 递推：i 维 +1、j 维 +1，两次下标平移
> class Solution:
>     def maxProfit(self, k: int, prices: List[int]) -> int:
>         n = len(prices)
>         f = [[[-inf] * 2 for _ in range(k + 2)] for _ in range(n + 1)]
>         for j in range(1, k + 2):                 # 故意从 1 开始，第 0 列留作哨兵
>             f[0][j][0] = 0
>         for i, p in enumerate(prices):
>             for j in range(1, k + 2):
>                 f[i+1][j][0] = max(f[i][j][0], f[i][j-1][1] + p)   # 卖出：预算 j-1 → j
>                 f[i+1][j][1] = max(f[i][j][1], f[i][j][0]   - p)   # 买入：预算不变
>         return f[n][k+1][0]
> 
> # ③ 空间优化：只依赖上一行，去掉 i 维；j 必须倒序
> class Solution:
>     def maxProfit(self, k: int, prices: List[int]) -> int:
>         f = [[-inf] * 2 for _ in range(k + 2)]
>         for j in range(1, k + 2):
>             f[j][0] = 0
>         for p in prices:
>             for j in range(k + 1, 0, -1):         # 倒序：保证读到的是上一行
>                 f[j][1] = max(f[j][1], f[j][0] - p)
>                 f[j][0] = max(f[j][0], f[j-1][1] + p)
>         return f[k+1][0]
> ```
> 
> - 下标映射：`i ∈ [-1, n-1]` → `f[i+1] ∈ [0, n]`（`n+1` 行）；`j ∈ [-1, k]` → `f[·][j+1] ∈ [0, k+1]`（**`k+2` 列**）。多出来那一列不是浪费，它就是递归里 `if j < 0: return -inf` 的位置。
> - **哨兵列自动实现约束**：`f[·][0][·]` 从头到尾没被写过，恒为 `-inf`。于是 `j+1 = 1`（真实预算 0）时，卖出边 `f[i][0][1] + p` 恒为 `-inf`，「预算为 0 不能再卖」这个约束**不需要任何 if 判断**。
> - 空间优化的 `j` **必须倒序**：`f[j][0]` 依赖 `f[j-1][1]`，正序会读到本轮刚更新的值（跨行串味）。这条方向规则与 [[7.2 背包以及完全背包]] 的 0-1 背包一维倒序是同一个道理。

## 恰好 / 至少 / 至多：差别只在 base case

> [!tip]- 三变体对照（与 7.2 背包三兄弟同构）
> 
> 骨架、转移、入口 `dfs(n-1, k, False)` 全都不动，**只改 `i < 0` 那一行和 `j` 的越界处理**：
> 
> | 变体 | `i < 0` 时的返回 | 转移里 `j` 的处理 |
> | --- | --- | --- |
> | **至多** k 笔（188 本题） | `-inf if hold else 0`——用不完不惩罚 | `j-1`，且 `if j < 0: return -inf` 排最前 |
> | **恰好** k 笔 | `0 if (not hold and j == 0) else -inf` | 同上，不钳制 |
> | **至少** k 笔 | `0 if (not hold and j == 0) else -inf` | `max(j-1, 0)` **钳制**，`j` 永不为负 |
> 
> 读法：
> 
> - **至多**：`j` 是预算上限，剩多少都算达标，所以 base 只管 `hold`。
> - **恰好**：`j` 是必须用满的配额，走到头还剩预算（`j > 0`）就是没达标 → `-inf`。
> - **至少**：`j` 是**还欠多少笔**，还清后再交易不该被惩罚，所以把负数状态**折叠到 0**；`j = 0` 这一层自动退化成「无限次交易」，也就是 122 母题。
> 
> 这三条与 [[7.2 背包以及完全背包]] 的「恰好 / 至多 / 至少」三兄弟**完全同构**：都是「合法性由 base 定义，越界处理由语义定义」。
> 
> 递推版的初始化对照（下标已 +1 平移）：
> 
> | 变体 | 初始化 | 说明 |
> | --- | --- | --- |
> | 至多 | `f[0][j][0] = 0`（`j ≥ 1`），其余 `-inf` | 第 0 列是哨兵 |
> | 恰好 | **只有** `f[0][1][0] = 0`，其余全 `-inf` | `f[0][1]` 才是「恰好完成 0 笔」的状态 |
> | 至少 | `f[0][0][0] = 0`，其余 `-inf`，**不需要哨兵列** | 因为 `f[i][-1][·]` 与 `f[i][0][·]` 等价，`f[i][0][·]` 就是无限次交易的最优值 |

> [!example]- 至少 k 笔：两个手算样例
> 
> ```text
> k = 1, prices = [5, 1]        # 必须交易一次，只能亏着做
> dfs(1,1,False) = max( dfs(0,1,False), dfs(0,0,True) + 1 )
> dfs(0,1,False) = -inf                  ← j=1 未清零，开市前不算达标
> dfs(0,0,True)  = 0 - 5 = -5
>              ⇒ max(-inf, -5 + 1) = -4  ✓ 被迫亏 4
> 
> k = 0                          # 至少 0 笔 ≡ 不限次数，退化成 122
> ```

## 易错点

> [!warning]- 易错点
> 
> - **base 写成 0 而不是 `-inf`**：`dfs(-1, True) = 0` 等于宣称「可以免费白拿一支股票」，答案整体偏大。凡是「不可能的状态」，都要用 `-inf` 让它在 `max` 里永远输。
> - **base case 顺序写反**：`if i < 0` 放在 `if j < 0` 前面，会让「预算透支」的信息被吞掉，`k = 0` 时白送一笔交易。**非法性判断永远优先于终止性判断。**
> - **预算 `j` 两端都扣**：买入和卖出各减 1，一笔交易扣两次，答案偏小。同理 714 的 `fee` 也只能扣一次。
> - **递推只开 `k+1` 列**：`j = 0` 时 `f[i][j-1]` 变成 `f[i][-1]`，Python 负下标不报错，会**静默取到最后一列**，错得毫无征兆。必须 `k+2` 列 + 循环从 1 开始。
> - **初始化写成 `for j in range(k+2)`**：把哨兵列也置 0，等价于调换了两个 base case 的顺序，`k = 0` 时又白送一笔交易。
> - **滚动版忘了临时变量**：`f0` 和 `f1` 必须同时来自「昨天」。先更新 `f0` 再算 `f1`，等于允许同一天先卖后买。
> - **空间优化的 `j` 用了正序**：`f[j][0]` 依赖 `f[j-1][1]`，正序会读到本轮新值，必须倒序（对照 [[7.2 背包以及完全背包]]）。
> - **冷冻期把 `i-2` 写到卖出边**：约束只针对买入，卖出边不动。
> - **`@cache` 装饰实例方法**：LeetCode 上没问题，工程里会持有 `self` 引用导致对象无法回收（见 [[Python_cache]]）。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = \text{状态个数} \times \text{单次转移}$，本系列单次转移都是 $O(1)$（每个状态最多两条入边）。
> 
> | 题型 | 状态数 | 时间 | 空间 |
> | --- | --- | --- | --- |
> | 122 / 309 / 714 | $2n$ | $O(n)$ | 递推 $O(n)$，滚动 $O(1)$ |
> | 188（至多 k 笔） | $2nk$ | $O(nk)$ | 递推 $O(nk)$，滚动 $O(k)$ |
> 
> - 递归版另加 $O(n)$ 递归栈；不加 `@cache` 会退化成指数级（见 [[记忆化搜索]]）。
> - 当 $k \ge n/2$ 时，交易次数约束形同虚设，可直接退化成 122 的 $O(n)$ 解法——这是 188 的常见常数优化。

## 一句话总结

状态机 DP 的全部功夫在**画图**上：节点是「收盘时的互斥状态」，边是「今天的动作」，`±prices[i]` 是走这条边的代价，`-inf` 是「这个状态不存在」的编码——冷冻期改边的**来源**，手续费改边的**权重**，至多 k 笔给整张图加一维**预算**，而恰好 / 至少 / 至多只改 **base case**。

## 模板归纳

看到「**逐天/逐位决策 + 有限个互斥身份 + 今天能做什么取决于昨天是什么身份**」，四步落笔：

1. **画状态机**：先数清有几个节点（本系列 2 个：持有 / 未持有），再数清每个节点有哪几条入边（本系列 2 条：什么也不做 / 今天动手）。
2. **写合同**：`dfs(i, 状态) = 前 i 天、第 i 天收盘时处于该状态的最优值`。**「收盘时」这三个字必须写进定义**，否则转移会前后错位一天。
3. **翻译边**：每条入边一个 `max` 分支，边上的收益/代价写成 `± prices[i]`。base case 里把**不可能的状态**设成 `-inf`；若有多个 base，**非法性判断排在终止性判断前面**。
4. **加约束就加维度**：次数限制加 `j`（**只在一端扣**），冷冻期改边的来源下标，手续费改边的权重。最后按需 递推（下标平移 + 哨兵列）→ 滚动（注意临时变量与倒序）。

```python
# 状态机 DP 通用骨架
@cache
def dfs(i, state):
    if 非法(state):  return -inf          # 非法优先
    if i < 0:        return BASE(state)   # 再判边界：合法 0，不可能 -inf
    return max(dfs(i - 1, s) + w(s, state, i) for s in 入边来源(state))
# 入口：末态一定取「空仓/无负担」的那个状态
```
