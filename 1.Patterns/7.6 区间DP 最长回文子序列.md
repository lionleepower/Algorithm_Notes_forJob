# 区间 DP：最长回文子序列与枚举分割点

## 解决什么问题

**一个序列**上，答案由「**一段连续区间**」决定，且这段区间**从两端往中间收缩**——回文、合并石子、多边形剖分、括号匹配都属此类。识别信号：

```text
单个字符串 / 数组 + 求最值 + 答案依赖「一段区间的内部结构」而不是「一个前缀」
```

和前几篇的分界线只有一句话：**下标是「前缀边界」还是「区间两端」**。

| 专题 | 状态 | `i`、`j` 的语义 | 状态怎么缩小 |
| --- | --- | --- | --- |
| [[7.3 线性dp 最长公共子序列]] | `dfs(i, j)` | **两个串各自的前缀** | 从右端单向砍 |
| [[7.4 线性dp 最长递增子序列]] | `f(i)` | 一个前缀 + 强制结尾 | 从右端单向砍 |
| **本篇 区间 DP** | `dfs(i, j)` | **同一个串上一个窗口的左右边界** | 从**两端**往中间夹 |

**为什么回文类必须用区间？** 因为「回文」的判定天然是「首尾配对、向中间递进」：每做一次决策，左端和右端**同时在动**，一个下标表达不了「左边砍到哪、右边砍到哪」，必须一对下标。这不是巧合，是回文类题目一律用区间 DP 的根本原因。

## 统一模板

> [!tip]- 核心思路：合同写死成「闭区间内部的答案」
> 
> $$dfs(i, j) = \text{区间 } [i,\ j] \text{（闭区间）内部的答案}$$
> 
> 三件事跟着合同自动确定：
> 
> - **入口**：把定义里的「区间」替换成「完整问题」= 整个序列 ⇒ `dfs(0, n - 1)`。
> - **base**：合同在最小区间处该返回什么（空区间 / 单元素）。
> - **转移**：只对**区间边界这一步**分类讨论，子问题必须是**更短的区间**。
> 
> 区间 DP 分两大子类，转移形态完全不同，这是本篇最该记住的一点：
> 
> | 子类 | 决策问的是什么 | 分支数 | 子问题 | 代表题 |
> | --- | --- | --- | --- | --- |
> | **缩边界型** | 两个**端点**怎么处理？ | $O(1)$ 支 | 边界缩一格 | 516 最长回文子序列 |
> | **选分割点型** | 在**哪里切开**？ | $O(n)$ 支（枚举 `k`） | 一分为二，两块都算 | 1039 多边形三角剖分 |
> 
> 看到 `for k in range(i+1, j)` 里套 `dfs(i, k) + dfs(k, j)` 这个形状，就该条件反射：**选分割点型**，时间会比缩边界型多带一个 $O(n)$。

> [!success]- 通用骨架
> 
> ```python
> from functools import cache
> 
> # 缩边界型
> @cache
> def dfs(i, j):
>     if i > j:  return BASE_EMPTY          # 空区间
>     if i == j: return BASE_SINGLE         # 单元素，别漏
>     if match(i, j):
>         return dfs(i + 1, j - 1) + w      # 两端成对处理
>     return combine(dfs(i + 1, j), dfs(i, j - 1))
>
> # 选分割点型
> @cache
> def dfs2(i, j):
>     if is_base(i, j): return BASE
>     return combine(dfs2(i, k) + dfs2(k, j) + cost(i, k, j)
>                    for k in range(i + 1, j))
>
> return dfs(0, n - 1)                      # 入口恒为「整个区间」
> ```

## 变体一：516. 最长回文子序列（缩边界型）

给一个字符串 `s`，求它**最长回文子序列**的长度（子序列可以不连续，但相对顺序不变）。

![](assets/7.6%20区间DP%20端点决策.svg)

> [!tip]- 核心思路：只问一句「两个端点怎么处理」
> 
> 回文子序列有一条硬性质：**它在原串里的首尾两个字符必须相等**。整个分类就建立在这条性质上。
> 
> **情况 A：`s[i] == s[j]` → 直接 `dfs(i+1, j-1) + 2`，不取 max。**
> 
> 最容易犯嘀咕的地方：万一不用这两个端点反而更长呢？不会。**交换论证**：设 $T$ 是区间 $[i,j]$ 的某个最优回文子序列，首尾字符落在原串位置 $p < q$（$i \le p < q \le j$，且 $s[p]$ 与 $s[q]$ 相等）。把 $T$ 的头尾这两个字符**替换成位置 $i$ 和 $j$ 的字符**：中间部分 $T'$ 原本落在 $(p, q)$ 内，必然也落在 $(i, j)$ 内；而 $s[i]$ 与 $s[j]$ 相等，所以 $s[i] + T' + s[j]$ 仍是回文，**长度一模一样**。
> 
> 结论：**总存在一个最优解恰好用上了两个端点**，所以对角支支配另外两支，不需要 max。
> 
> **情况 B：`s[i] != s[j]` → `max(dfs(i+1, j), dfs(i, j-1))`。**
> 
> 既然首尾必须相等而这俩不等，它们**不可能同时充当答案的首尾**——至少有一个端点是废的。于是「丢左端」「丢右端」两支覆盖了全部可能。两支有重叠（都丢的方案在两边各被数了一次），但 [[7.3 线性dp 最长公共子序列]] 那句话在这里同样适用：**候选允许重，不允许漏**，`max` 会自己挑。
> 
> **为什么不用补第四支 `dfs(i+1, j-1)`？** 同样的支配关系：任何「两端都不用」的方案本身已经是 `dfs(i+1, j)` 搜索空间里的一员（只不过恰好没用到 `s[j]`）。写了不错，只是白算。

> [!example]- 示例推演：`s = "bbbab"`
> 
> ```text
> dfs(0,4)  s[0]='b' == s[4]='b'  → dfs(1,3) + 2
>   dfs(1,3)  s[1]='b' != s[3]='a' → max(dfs(2,3), dfs(1,2))
>     dfs(2,3)  'b' != 'a' → max(dfs(3,3), dfs(2,2)) = max(1, 1) = 1
>     dfs(1,2)  'b' == 'b' → dfs(2,1) + 2 = 0 + 2 = 2     ← i > j 命中空区间
>   dfs(1,3) = max(1, 2) = 2
> dfs(0,4) = 2 + 2 = 4        答案 "bbbb"
> ```
> 
> 两个 base 在这一棵树里各命中一次：`dfs(3,3)` 走 `i == j` 返回 1，`dfs(2,1)` 走 `i > j` 返回 0。**缺任何一个都不行。**

### 从递归翻到递推

![](assets/7.6%20区间DP%20填表方向.svg)

> [!success]- 三版实现：递归 → 二维递推 → 一维滚动
> 
> ```python
> from functools import cache
>
> # ① 递归 + 记忆化（面试主推，能推导）
> class Solution:
>     def longestPalindromeSubseq(self, s: str) -> int:
>         n = len(s)
>
>         @cache
>         def dfs(i, j):
>             if i > j:                       # 空区间
>                 return 0
>             if i == j:                      # 单字符，本身就是长度 1 的回文
>                 return 1
>             if s[i] == s[j]:
>                 return dfs(i + 1, j - 1) + 2
>             return max(dfs(i + 1, j), dfs(i, j - 1))
>         return dfs(0, n - 1)
>
> # ② 二维递推：i 倒序、j 正序（从依赖方向读出来的）
> class Solution:
>     def longestPalindromeSubseq(self, s: str) -> int:
>         n = len(s)
>         f = [[0] * n for _ in range(n)]
>         for i in range(n - 1, -1, -1):      # 需要 i+1 先算好 → i 倒序
>             f[i][i] = 1                     # 单字符 base
>             for j in range(i + 1, n):       # 需要 j-1 先算好 → j 正序
>                 if s[i] == s[j]:
>                     f[i][j] = f[i + 1][j - 1] + 2
>                 else:
>                     f[i][j] = max(f[i + 1][j], f[i][j - 1])
>         return f[0][n - 1]                  # 答案在右上角
>
> # ③ 一维滚动：和 LCS 同构，用 pre 兜住「左下角」
> class Solution:
>     def longestPalindromeSubseq(self, s: str) -> int:
>         n = len(s)
>         f = [0] * n
>         for i in range(n - 1, -1, -1):
>             f[i] = 1
>             pre = 0                         # pre = f[i+1][i]，空区间 = 0
>             for j in range(i + 1, n):
>                 tmp = f[j]                  # 本格旧值 = f[i+1][j]（下方）
>                 f[j] = pre + 2 if s[i] == s[j] else max(f[j], f[j - 1])
>                 pre = tmp                   # 旧值成为下一轮的左下角
>         return f[n - 1]
> ```
> 
> - **主流程**：三版转移式完全相同，区别只在「谁来存中间结果」——和 [[7.1 DP 打家劫舍]] 的四版演进是同一回事。
> - **`i` 倒序、`j` 正序不是背的**：依赖是 `f[i+1][j-1]`（左下）、`f[i+1][j]`（下方）、`f[i][j-1]`（左方）。需要**更大的 `i`** 先算好 ⇒ `i` 倒序；需要**更小的 `j`** 先算好 ⇒ `j` 正序。
> - **`j` 从 `i+1` 起步**：`j < i` 的下三角是空区间恒为 0，压根不用填；答案在**右上角** `f[0][n-1]`。
> - **一维版的 `pre`**：依赖左、下、左下三个方向，方向控制不了左下角，只能额外拿变量兜住——机制与 [[7.3 线性dp 最长公共子序列]] 的一维滚动完全一致，那边兜的是左上角，这边因为 `i` 倒序变成左下角。

> [!warning]- 本题最经典的坑：`i == j` 这一格绝不能省
> 
> 如果只写 `if i > j: return 0`，那么 `dfs(i, i)` 会落进 `s[i] == s[j]` 分支（同一个字符当然相等），返回 `dfs(i+1, i-1) + 2`，也就是 `0 + 2 = 2`。
> 
> **一个字符被当成两个用了。** 这个错误不报错、不越界，只会让答案默默偏大——是本题唯一的静默 bug 点。
> 
> 用 [[7.0 DP]] 的**两步法**检查就不会漏：
> 
> 1. **语义**：`i > j` 是空区间 → 0；`i == j` 是单字符 → 1。
> 2. **可达性**：从长度为 2 的区间 `dfs(i, i+1)` 出发，对角支走到 `dfs(i+1, i)`（`i > j` ✓ 可达），单侧支走到 `dfs(i+1, i+1)`（`i == j` ✓ 可达）。**两格都被转移够得着，就都得盖住。**

## 变体二：1039. 多边形三角剖分的最低得分（选分割点型）

凸多边形顶点按顺时针给出权值 `values`，把它剖分成 `n-2` 个三角形，每个三角形得分为三顶点权值之积，求总得分最小值。

![](assets/7.6%20区间DP%20枚举分割点.svg)

> [!tip]- 核心思路：`i`、`j` 不再是字符下标，而是「封口边」的两个端点
> 
> $$dfs(i, j) = \text{由顶点 } i,\ i{+}1,\ \dots,\ j \text{ 依次相连、再用弦 } (i, j) \text{ 封口的子多边形，其三角剖分最低得分}$$
> 
> 关键在「**封口**」两个字：区间 $[i, j]$ 描述的不是一段序列，而是**一块被切下来的子多边形**——边界由原多边形上一串连续边 $(i, i{+}1), \dots, (j{-}1, j)$ 加上一条封口边 $(i, j)$ 组成。入口 `dfs(0, n-1)` 的封口边 $(0, n{-}1)$ 本来就是原多边形的一条真实边，所以整个多边形被完整覆盖。
> 
> **`for k` 看起来像盲目穷举，其实背后有一条很干净的性质**：
> 
> > 封口边 $(i, j)$ 在任何一个合法剖分里，都必然**恰好属于一个三角形**。
> 
> 因为 $(i, j)$ 是这块子多边形的**边界边**，只有一侧有图形，所以贴着它的三角形有且仅有一个，那个三角形的第三个顶点 `k` 必满足 $i < k < j$。于是分类天然**不重不漏**：
> 
> - **不漏**：`k` 取遍 $(i, j)$ 之间所有顶点，穷尽了「贴着 $(i,j)$ 的三角形长什么样」的全部可能。
> - **不重**：`k` 不同 ⇒ 三角形不同 ⇒ 剖分方案必然不同，两两互斥。**注意这里是严格划分**，和 LCS / 516 的「候选允许重」不一样。
> 
> **为什么切完能干净地相加？** 三角形 $(i, k, j)$ 一落定，剩下的被劈成左块（顶点 `i..k`，封口边 $(i,k)$）和右块（顶点 `k..j`，封口边 $(k,j)$）。两块只在顶点处接触，内部再无公共区域，**也不能跨块连对角线**（连了就穿过中间那个三角形了）。所以两块互不干扰，各自最优即整体最优——这就是无后效性在几何上的体现（见 [[重叠子问题与无后效性]]）。

> [!example]- 示例验证：`values = [3, 7, 4, 5]`
> 
> 四边形只有两种剖分方式，正好能看清 `k` 在枚举什么：
> 
> ```text
> 剖分 A：连对角线 (0,2)
>   三角形 (0,1,2) = 3*7*4 = 84
>   三角形 (0,2,3) = 3*4*5 = 60      合计 144   ← k=2
>
> 剖分 B：连对角线 (1,3)
>   三角形 (0,1,3) = 3*7*5 = 105
>   三角形 (1,2,3) = 7*4*5 = 140     合计 245   ← k=1
>
> dfs(0,3) = min(245, 144) = 144
> ```
> 
> `k` 枚举的正是「**跟封口边 (0,3) 组队的第三个顶点是谁**」——两种情况恰好穷尽，没有第三种。

> [!success]- 递归 + 两种递推外壳
> 
> ```python
> from functools import cache
> from math import inf
>
> # ① 递归 + 记忆化
> class Solution:
>     def minScoreTriangulation(self, values: List[int]) -> int:
>         n = len(values)
>
>         @cache
>         def dfs(i, j):
>             if i + 1 == j:                  # 只剩两个顶点，退化成线段，切不出三角形
>                 return 0
>             res = inf
>             for k in range(i + 1, j):
>                 res = min(res, dfs(i, k) + dfs(k, j)
>                                + values[i] * values[j] * values[k])
>             return res
>         return dfs(0, n - 1)
>
> # ② 递推写法一：i 倒序、j 正序（和 516 同款）
> class Solution:
>     def minScoreTriangulation(self, values: List[int]) -> int:
>         n = len(values)
>         f = [[0] * n for _ in range(n)]     # j == i+1 的格子天然是 0，无需初始化
>         for i in range(n - 3, -1, -1):
>             for j in range(i + 2, n):
>                 f[i][j] = min(f[i][k] + f[k][j] + values[i] * values[j] * values[k]
>                               for k in range(i + 1, j))
>         return f[0][n - 1]
>
> # ③ 递推写法二：按区间长度 L 从小到大（推荐当默认写法）
> class Solution:
>     def minScoreTriangulation(self, values: List[int]) -> int:
>         n = len(values)
>         f = [[0] * n for _ in range(n)]
>         for L in range(2, n):               # L = j - i，从 2 起（跨度 1 得分为 0）
>             for i in range(n - L):
>                 j = i + L
>                 f[i][j] = min(f[i][k] + f[k][j] + values[i] * values[k] * values[j]
>                               for k in range(i + 1, j))
>         return f[0][n - 1]
> ```
> 
> - **关键变量**：`k` 是分割点，含义是「和封口边组队的第三个顶点」；`f[i][j]` 依赖的都是**更短的区间**（`dfs(i,k)` 与 `dfs(k,j)` 跨度都小于 `j - i`），所以两种外壳等价。
> - **为什么推荐按长度 `L` 遍历**：选分割点型只要求「短区间先算」，按 `L` 递增天然满足，不用去推 `i` / `j` 的方向；缩边界型才需要从依赖方向反推倒序 / 正序。**方向搞反是这类题最常见的翻车点。**
> - **`i` 从 `n-3` 起步**：跨度至少为 2 才需要计算，即 `i + 2 <= n - 1`。

> [!warning]- 这个 base 不能省，省了不是「返回 0」而是「返回 inf」
> 
> 若删掉 `if i + 1 == j: return 0`：当 `j == i + 1` 时 `range(i+1, j)` 是**空的**，循环一次都不进，`res` 保持初值 `inf` 被直接返回，整条链路被 `inf` 污染。
> 
> 这是「**先赋 `inf` 再 `min`**」这种写法的通病：**空循环会静默漏出哨兵值**。凡是转移写成 `res = inf` + `for` + `min` 的题，都要专门检查「循环可能为空吗」。
> 
> 另外注意可达性：转移里 $k \in (i, j)$，所以子调用跨度永远 $\ge 1$，**`j - i == 1` 是能到达的最小状态，`i == j` 根本不可达**，不用管——和 516 必须写两个 base 正好相反。

## 两题对照（套模板时看这张表）

> [!summary]- 516 vs 1039：什么不变、什么改变
> 
> **完全不变**：`dfs(i, j)` 表示「一段闭区间内部的答案」、入口恒为 `dfs(0, n-1)`、子问题必须是更短的区间、`@cache` + 从依赖方向翻递推的套路。
> 
> **改变的是转移形态**：
> 
> | | 516. 最长回文子序列 | 1039. 多边形三角剖分 |
> | --- | --- | --- |
> | 子类 | 缩边界型 | 选分割点型 |
> | `i`、`j` 语义 | 字符下标（窗口两端） | 顶点编号（**封口边**两端） |
> | 决策 | 两个端点怎么处理 | 在哪里切开（枚举 `k`） |
> | 分支数 | $O(1)$ 支 | $O(n)$ 支 |
> | 子问题 | 边界缩一格，**一支** | 一分为二，**两块都要算** |
> | 分类性质 | 候选允许重（`max` 兜底） | 严格划分，不重不漏 |
> | base | `i > j` → 0；`i == j` → 1（**两格都要**） | `i + 1 == j` → 0（`i == j` 不可达） |
> | 时间 | $O(n^2)$ | $O(n^3)$ |
> | 能否压一维 | 能（同 LCS，用 `pre`） | **不能**（依赖整张二维表） |

> [!tip]- 交叉验证：LPS 其实等于「串与其逆序串的 LCS」
> 
> $$\text{LPS}(s) = \text{LCS}(s,\ \text{reverse}(s))$$
> 
> 回文的定义就是「正着读等于反着读」，所以 `s` 里最长的回文子序列，等价于 `s` 与它逆序串的最长公共子序列。这条等式能让你把 516 直接套进 [[7.3 线性dp 最长公共子序列]] 的模板，$O(n^2)$ 同阶。
> 
> 但**区间 DP 的写法更本质**：它直接刻画了「两端向中间夹」这个动作，LCS 转化只是一条绕道。面试里说出这条等式能加分，落笔还是写区间 DP。

## 易错点

> [!warning]- 易错点
> 
> - **`i == j` 的 base 漏写**（516 专属静默 bug）：单字符会落进「相等」分支返回 2，答案默默偏大，不报错不越界。凡是「两端同时缩」的转移，必然同时够得着 `i > j` 和 `i == j` 两格。
> - **`res = inf` + 空循环**（1039 专属）：分割点范围为空时哨兵值原样漏出，整条链路被 `inf` 污染。写 `min` 型转移先问一句「`for` 可能一次都不进吗」。
> - **递推方向搞反**：`i` 必须**倒序**（依赖 `i+1`）、`j` 必须**正序**（依赖 `j-1`）。拿不准就改用**按区间长度 `L` 从小到大**的外壳，它对两个子类都成立。
> - **忘了区间 DP 只填上三角**：`j < i` 是空区间恒为 0，`j` 要从 `i+1`（或 `i+2`）起步；答案在**右上角** `f[0][n-1]`，不是 `f[n-1][n-1]`。
> - **把「子序列」当「子串」**：516 求的是**子序列**（可不连续）。若题目要连续的**子串**（如 5. 最长回文子串、647. 回文子串），状态要改成布尔的「`s[i..j]` 是不是回文」，或者干脆用中心扩展法——**是另一套解法，别混**，完整写法见 [[15.0 字符串 KMP与回文中心扩展]]。
> - **把 1039 的 `k` 写成 `range(i, j+1)`**：`k` 必须严格在 $(i, j)$ 内，取到端点会得到跨度为 0 的子问题，直接死循环 / 无限递归。
> - **不加记忆化**：区间 DP 的朴素递归是指数级，`@cache` 不能忘（见 [[Python_cache]]、[[记忆化搜索]]）。

## 复杂度

> [!summary]- 复杂度
> 
> 通用公式：$\text{时间} = \text{状态个数} \times \text{单次转移}$。区间 DP 的状态数恒为 $O(n^2)$（上三角，严格说约 $n^2/2$），差别全在单次转移。
> 
> - **516 缩边界型**：单次转移 $O(1)$ ⇒ 时间 $O(n^2)$；空间 $O(n^2)$（记忆化 / 二维表），一维滚动可降到 $O(n)$。
> - **1039 选分割点型**：单次转移要枚举 `k`，是 $O(n)$ ⇒ 时间 $O(n^3)$；空间 $O(n^2)$。
> - **为什么选分割点型压不成一维**：它依赖的是整张二维表上**同一行的左段与同一列的下段**（`f[i][k]` 与 `f[k][j]`，`k` 跑遍中间），不像背包只依赖同一行、也不像 516 只依赖相邻一行，没有可以滚掉的维度。
> - 递归写法额外有 $O(n)$ 递归栈；一维滚动只能求**长度 / 得分**，要还原**具体方案**必须保留完整二维表回溯。

## 一句话总结

区间 DP 的合同永远是「**一段闭区间内部的答案**」，全部功夫在**区间边界这一步怎么处理**——缩边界型问「两个端点怎么办」（相等就成对吃掉，交换论证保证不亏；不等就至少丢一个，`max` 兜底），选分割点型问「在哪里切开」（枚举 `k`，严格划分，代价多一个 $O(n)$）。

## 模板归纳

看到「**单个序列 / 环 / 多边形** + 求最值 + 答案由一段区间决定 + 从两端收缩」，四步落笔：

1. **写合同**：`dfs(i, j) = 区间 [i, j] 内部的答案`，入口恒为 `dfs(0, n-1)`。**先确认 `i`、`j` 是「区间两端」不是「两个前缀」**——这是区间 DP 与线性 DP 的分水岭。
2. **判子类**：决策是「两个端点怎么处理」→ 缩边界型（$O(1)$ 支）；是「在哪里切开」→ 选分割点型（枚举 `k`，$O(n)$ 支）。
3. **定 base，用两步法**：先算语义（空区间 / 单元素各返回什么），再检查转移**最多退到哪一格**，够得着的格子必须全部盖住。缩边界型通常两格都要，选分割点型往往只有一格可达。
4. **加 `@cache`**；要翻递推就按「短区间先算」——保险写法是按区间长度 `L` 从小到大，或从依赖方向反推 `i` 倒序 / `j` 正序。

```python
# 区间 DP 通用骨架
@cache
def dfs(i, j):
    if is_base(i, j):
        return BASE                                   # 空区间 / 单元素 / 退化区间
    # 子类 A：缩边界——只看两个端点
    if match(i, j):
        return dfs(i + 1, j - 1) + w
    return combine(dfs(i + 1, j), dfs(i, j - 1))
    # 子类 B：选分割点——枚举 k，一分为二
    # return combine(dfs(i, k) + dfs(k, j) + cost(i, k, j) for k in range(i + 1, j))
return dfs(0, n - 1)
```
