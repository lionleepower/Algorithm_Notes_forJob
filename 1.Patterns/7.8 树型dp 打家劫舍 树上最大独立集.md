# 树形 DP：打家劫舍 III 与树上最大独立集

## 解决什么问题

**最大独立集 Maximum Independent Set**：从图中选出尽量多的点，使这些点**两两不相邻**；常见变形是**最大化点权之和**。一般图上这是 NP-hard，但**树上有多项式解**——因为树没有环，约束只沿着父子边传递。识别信号：

```text
一棵树 + 每个点有权值 + 「相邻两点不能同时选」+ 求最大收益
```

同属树形 DP，本篇和上一篇是**两条不同的主线**，先分清再套模板：

| 主线 | 答案的形态 | 每次 dfs 干什么 | 代表题 |
| --- | --- | --- | --- |
| [[7.7 树型DP 树的直径]] **路径型** | 一条**路径** | 双轨：**报拐点** + **传单链**，要 `nonlocal` 擂台 | 543 / 124 / 2246 |
| **本篇 选点型** | 一个**点集** | 单轨：把「选 / 不选」两份答案**打包进返回值** | 337 / 没有上司的舞会 |
| 常见套路 | —— | ① **选或不选**（本篇）② **枚举选哪个**（[[7.7 树型DP 树的直径]] 的拐点） | —— |

> [!tip]- 出发点：树和子树的关系，就是原问题和子问题的关系
> 
> **树天然具有递归的特点**：一棵树 = 根 + 若干棵子树，而子树本身还是一棵树。所以思考树形 DP 只需要回答一个问题：
> 
> > **如何由子问题（各个子树的答案）算出原问题（整棵树的答案）？**
> 
> 剩下的分歧只在「**子树要向上汇报什么**」——汇报得不够，父亲没法决策（本篇的核心陷阱）；汇报得刚好，转移就是两行加法。

## 为什么 198 的写法搬不过来

[[7.1 DP 打家劫舍]] 的转移是 `max(dfs(i-1), dfs(i-2) + nums[i])`，它依赖一个隐含前提：**元素排成一条线，「跳过相邻」可以翻译成「下标减 2」**。树上这个翻译立刻失效：

- `i-1` 对应「孩子们」，但有两个；
- `i-2` 对应「孙子们」，可能有四个；
- 一旦写 `node.val + dfs(四个孙子)`，就得手动展开 `node.left.left`、`node.left.right`……还要处理空节点，代码又丑又容易漏。

根本问题是：**「跳两层」是对约束的一种间接编码，只在链状结构上好用。** 树上必须换一种编码方式——**不再用「位置」编码约束，而是用「这个点选没选」编码。**

## 统一模板：返回 (选, 不选) 二元组

![](assets/7.8%20树型DP%20一个max不够.svg)

> [!tip]- 核心思路：为什么一个 `max` 一定不够
> 
> 约束「相邻两点不能同时选」**只作用在一条边的两端**。所以父亲要做决策，唯一需要知道的是：
> 
> > **我的孩子自己有没有被选？**
> 
> 而**不是**「孩子那棵子树的最大值是多少」。这就是关键分岔口——如果 `dfs(node)` 只返回一个 `max`，你拿到的是「左子树最好能偷多少」，但**你不知道这笔钱里有没有包含 `node.left` 本身**：有的话你不能选 `node`，没有的话你可以选。**信息被 `max` 抹掉了，父亲无法做决策。**
> 
> 所以合同必须写成两份：
> 
> $$dfs(node) = (\ \underbrace{rob}_{\text{强制\textbf{选} node 时，该子树的最大值}},\ \underbrace{notRob}_{\text{强制\textbf{不选} node 时，该子树的最大值}}\ )$$
> 
> 这就是**状态机 DP** 的做法：**把「抹掉就没法用」的那一位信息，提升成状态的一个维度**——和 [[7.5 状态机DP 股票买卖]] 里给 `dfs(i, hold)` 加一维「持股身份」是同一个思想。

![](assets/7.8%20树型DP%20两条转移.svg)

> [!tip]- 两条转移，各自的理由
> 
> ```python
> rob     = node.val + l_not_rob + r_not_rob
> not_rob = max(l_rob, l_not_rob) + max(r_rob, r_not_rob)
> ```
> 
> **第一行**：既然前提是「选了 node」，约束立刻生效——左右孩子**必须**不选，只能取 `l_not_rob` / `r_not_rob`，**没有 `max` 可选**。
> 
> 注意**约束到此为止**：孙子层完全自由，而这份自由**已经被打包在 `l_not_rob` 的定义里了**（「不选 left 的前提下，left 那棵子树随便偷的最大值」）。**这就是为什么不需要手动去够孙子。**
> 
> **第二行**：前提是「不选 node」，左右孩子**没有任何限制**，选不选都合法，各取自己两种情况里更大的那个。
> 
> 两个容易被跳过的合法性依据：
> 
> - **为什么能写 `max(l_rob, l_not_rob)`？** 因为对左孩子而言，「选」和「不选」是**不重不漏的完备分类**，取冠军即全局冠军——和 198 里 `max` 的正确性来源是同一条。
> - **为什么左右可以分别取 `max` 再相加？** 因为左右子树之间**没有任何一条边相连**，约束不耦合，两边的最优可以自由组合。（如果题目改成「整棵树最多选 k 个」，这条立刻崩掉，必须多加一维 `k`。）

## 变体一：337. 打家劫舍 III（二叉树）

房子排列成二叉树，**两个直接相连的房子不能在同一晚被劫**，求最高金额。

![](assets/7.8%20树型DP%20示例推演.svg)

> [!success]- 代码实现
> 
> ```python
> class Solution:
>     def rob(self, root: Optional[TreeNode]) -> int:
>         def dfs(node):
>             if node is None:
>                 return 0, 0                      # 空树：两种前提下都是 0
>             l_rob, l_not_rob = dfs(node.left)    # 后序：必须先算完儿子
>             r_rob, r_not_rob = dfs(node.right)
>             rob = l_not_rob + r_not_rob + node.val
>             not_rob = max(l_rob, l_not_rob) + max(r_rob, r_not_rob)
>             return rob, not_rob
>         return max(dfs(root))                    # 根不受约束，两种都合法
> ```
> 
> - **主流程**：一次后序 DFS，每个节点返回二元组；**依赖方向是「父依赖子」**，所以两行 `dfs(node.left/right)` 必须写在转移前面。
> - **关键变量**：`rob` / `not_rob` 是**两个前提下各自的最优**，不是「最优值 + 次优值」。
> - **入口 `max(dfs(root))`**：根没有父亲，两种前提都合法，取大的。`max` 直接作用在元组上即可。
> - **不需要 `@cache`**：见下方说明。

> [!example]- 示例推演：`root = [3,2,3,null,3,null,1]`
> 
> ```text
> 两个叶子 3、1      → (3, 0)  (1, 0)      rob = 自己，notRob = 0
> 节点 2（右子叶 3） → rob    = 2 + 0 + 0        = 2
>                     notRob = 0 + max(3, 0)    = 3      ← 不选 2 反而更好
> 节点 3（右子叶 1） → rob    = 3 + 0 + 0        = 3
>                     notRob = 0 + max(1, 0)    = 1
> 根 3               → rob    = 3 + 3 + 1        = 7     ← 用的是儿子的 notRob
>                     notRob = max(2,3)+max(3,1) = 6
>
> 答案 = max(7, 6) = 7      选中的是「根 + 两个孙子」
> ```
> 
> 节点 2 那一层最能说明问题：**`notRob` 比 `rob` 还大**。如果只返回一个 `max`（3），父亲根本分不清这个 3 里有没有含节点 2 自己。

## 变体二：没有上司的舞会（一般树 / 多叉树）

洛谷 P1352：每个职员有快乐值，**直接上司和下属不能同时到场**，求最大快乐值总和——这就是**一般树上的最大独立集**，和 337 只差「儿子有几个」。

> [!tip]- 从二叉推广到多叉：`for` 循环累加
> 
> 二叉是「左 + 右」，多叉就是「**对所有儿子求和**」：
> 
> $$\begin{aligned}\text{选} &= \Big(\sum_{y \in child(x)} \text{不选}_y\Big) + val_x \\ \text{不选} &= \sum_{y \in child(x)} \max(\text{选}_y,\ \text{不选}_y)\end{aligned}$$
> 
> 注意**两条式子的形状完全没变**，只是「左 + 右」变成了 $\sum$。原因还是那一句：**约束只沿父子边生效，兄弟之间互不干扰，所以可以逐个儿子独立累加。**
> 
> 对比 [[7.7 树型DP 树的直径]] 的多叉版（2246）：那边因为要挑**最大的两条链**，必须写「先配对、再更新」的滚动擂台；**这边只是求和，没有任何顺序要求**——这是路径型与选点型在多叉树上的最大差别。

> [!success]- 代码实现（洛谷 P1352 完整可提交）
> 
> ```python
> import sys
> input = sys.stdin.readline
> sys.setrecursionlimit(10 ** 5)               # n 可达 6000，链状树会爆默认上限
>
> n = int(input())
> happy = [0] + [int(input()) for _ in range(n)]     # 1-indexed
> g = [[] for _ in range(n + 1)]
> has_boss = [False] * (n + 1)
> for _ in range(n - 1):
>     l, k = map(int, input().split())         # l 的直接上司是 k
>     g[k].append(l)
>     has_boss[l] = True
> root = next(i for i in range(1, n + 1) if not has_boss[i])   # 没有上司的那个人
>
> def dfs(x):
>     choose = happy[x]                        # 选 x：先把自己的快乐值记上
>     not_choose = 0                           # 不选 x
>     for y in g[x]:
>         c, nc = dfs(y)
>         choose += nc                         # 选了 x ⇒ 儿子只能不选
>         not_choose += max(c, nc)             # 不选 x ⇒ 儿子自由，取冠军
>     return choose, not_choose
>
> print(max(dfs(root)))
> ```
> 
> - **初值就是 base case**：`choose` 初值 `happy[x]`、`not_choose` 初值 `0`，叶子进不了循环直接返回 `(happy[x], 0)` ✓ —— 不需要显式写叶子分支。判据仍是 [[7.7 树型DP 树的直径]] 里那条：**初值是否恰好等于边界的语义值**。
> - **找根**：树用 `parent` 关系给出时，根就是「没有出现在任何 `l` 位置」的那个点，别默认是 1 号。
> - **若给的是无向边列表**，`g` 存双向边，`dfs(x, fa)` 里跳过 `y == fa`，写法同 2246。

> [!summary]- 337 vs 没有上司的舞会：什么不变、什么改变
> 
> **完全不变**：`(选, 不选)` 二元组合同、两条转移的形状与理由、入口取 `max`、后序遍历、$O(n)$ 复杂度、不需要记忆化。
> 
> **改变的只有一处**：
> 
> | | 337（二叉树） | 没有上司的舞会（一般树） |
> | --- | --- | --- |
> | 儿子怎么合并 | 左 + 右，写死两项 | `for y in g[x]` 累加 |
> | 空节点 | `return 0, 0` 兜底 | 无空节点概念，**靠初值兜底** |
> | 建图 | 题目直接给 `TreeNode` | 需要从 `parent` 建邻接表并找根 |

## 与 198 逐字对照

> [!summary]- 树形 DP 就是这样从 198 长出来的
> 
> [[7.1 DP 打家劫舍]] 其实也能写成状态机形式，写出来会发现和本题**逐字对应**：
> 
> | | 198（链） | 337（树） |
> | --- | --- | --- |
> | 前驱个数 | 1 个（`i-1`） | 2 个（left、right） |
> | 选自己 | `notRob[i-1] + x` | `l_not_rob + r_not_rob + val` |
> | 不选自己 | `max(rob[i-1], notRob[i-1])` | `max(l_rob,l_not_rob) + max(r_rob,r_not_rob)` |
> | 入口 | 最后一个位置取 `max` | `max(dfs(root))` |
> 
> **唯一的区别是前驱从 1 个变成 2 个，于是「取一个」变成「两边各取一个再相加」。** 树形 DP 相对线性 DP 的全部改动就这么多。
> 
> 反过来也说明：198 里那个 `dfs(i-2)` 写法之所以能省掉状态维度，是因为链上「前驱只有一个」，可以用下标间接编码；一旦前驱变多，就只能老老实实把「选没选」提成一维。

> [!tip]- 为什么这里不需要 `@cache`
> 
> 因为**根本没有重叠子问题**。198 里 `dfs(3)` 和 `dfs(4)` 都会调 `dfs(2)`，才需要 memo；**树上每个 `node` 只有一个父亲，`dfs(node)` 天然只被调用一次**。
> 
> 递归本身就是自底向上的一遍**后序遍历**——依赖方向是「父依赖子」，所以必须先 `dfs(left)`、`dfs(right)` 再算自己。
> 
> **那 DP 表在哪？就存在每次递归的返回值里，用完即弃。** 这和 [[7.7 树型DP 树的直径]] 是同一条结论，也是树形 DP 与前六篇 DP 在实现上的最大差异（参见 [[重叠子问题与无后效性]]）。

> [!tip]- 这题为什么不需要 `nonlocal`
> 
> 对照 [[7.7 树型DP 树的直径]]：那边的「拐点路径」在当前节点已经分叉成 Y 字形，**没法作为子树的答案向上合成**，只能当场记进 `nonlocal ans` 擂台。
> 
> 本题不同——「这棵子树在两种前提下各能拿多少」**本身就是一个可以向上合成的完整答案**，打包进返回值即可，全程没有共享状态。
> 
> **判据**：这个量能不能作为「子树的答案」向上合成？能 → 返回值；不能 → 才用擂台。详见 [[Python_nonlocal与闭包]]。

## 易错点

> [!warning]- 易错点
> 
> - **`not_rob` 写成 `l_rob + r_rob`**：错。「不选 node」**不等于**「必须选孩子」，孩子仍然可以不选，漏了一整类方案。必须是 `max(l_rob, l_not_rob) + max(r_rob, r_not_rob)`。
> - **`rob` 里给孩子加了 `max`**：错。选了 node 就**锁死**孩子必须不选，这里**没有选择权**，写 `max` 会选出「父子同时被选」的非法方案，答案偏大。
> - **空节点返回 `0`（单值）而不是 `(0, 0)`**：类型不匹配，解包直接崩。空树在两种前提下都是 0。
> - **最后写成 `dfs(root)[0]` 或 `dfs(root)[1]`**：错。根不受任何约束，两种前提都合法，**必须取 `max`**。
> - **想用一个 `max` 返回值糊过去**：这是本题的核心陷阱——信息被抹掉后父亲无法决策，见上方核心思路。
> - **多叉版忘了找根**：`parent` 数组给出的树，根是「没有上司」的那个点，不一定是 0 或 1 号；从 `parent[0]` 建图还要小心负下标造环（见 [[7.7 树型DP 树的直径]] 的建图坑）。
> - **递归深度**：链状树会超过 Python 默认上限 1000，洛谷这类题必须 `sys.setrecursionlimit`。

## 复杂度

> [!summary]- 复杂度
> 
> - **时间 $O(n)$** —— 每个节点恰好访问一次，单次转移是常数次加法与 `max`；多叉版内层 `for` 累计起来正好是总边数 $n-1$，仍是 $O(n)$。
> - **空间 $O(h)$** —— 递归栈深度等于树高；最坏（链状树）$O(n)$，平衡树 $O(\log n)$。多叉版另有邻接表 $O(n)$。
> - **没有记忆化开销**：无重叠子问题，DP 表就是返回值本身，用完即弃。

## 一句话总结

当「**最优值里有没有用到自己**」这一位信息会影响父节点的决策时，就不能只返回一个 `max`——**把它提升成状态的一维，返回 `(选, 不选)` 二元组**；于是「选」锁死儿子不选、「不选」让儿子各取冠军，树形 DP 就是这样从 198 长出来的。

## 模板归纳

看到「**一棵树** + **相邻两点不能同时选** + 求最大收益」，四步落笔：

1. **先分主线**：答案是一条**路径** → [[7.7 树型DP 树的直径]] 的双轨骨架；答案是一个**点集** → 本篇的选点型。
2. **问一句「父亲需要知道什么」**：如果父亲的决策依赖「儿子自己选没选」，就**不能只返回 `max`**——把这一位提成状态维度，返回 `(选, 不选)`。
3. **写两条转移**：**选** ⇒ 儿子锁死不选，直接加 `not`；**不选** ⇒ 儿子自由，各取 `max` 再加。多叉就把「左 + 右」换成 `for` 累加。
4. **定 base 与入口**：空节点 `(0, 0)`（或让初值直接充当叶子语义）；入口 `max(dfs(root))`，因为根没有父亲。

```python
# 树上最大独立集通用骨架（选或不选）
def dfs(x):
    choose, not_choose = val[x], 0        # 初值即叶子语义
    for y in children(x):                 # 二叉树写成 left / right 两项
        c, nc = dfs(y)
        choose     += nc                  # 选 x ⇒ 儿子必须不选，无 max
        not_choose += max(c, nc)          # 不选 x ⇒ 儿子自由，取冠军
    return choose, not_choose

return max(dfs(root))                     # 根无约束，两种前提取大
```
