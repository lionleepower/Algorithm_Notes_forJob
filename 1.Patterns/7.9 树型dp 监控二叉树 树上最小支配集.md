# 树形 DP：监控二叉树与树上最小支配集

## 解决什么问题

**最小支配集 Minimum Dominating Set**：选出尽量少（或权值尽量小）的点，使得**每个点要么自己被选，要么有一个邻居被选**——也就是「全覆盖」。识别信号：

```text
一棵树 + 「每个点都必须被看到 / 被覆盖 / 被服务」+ 求最少数量或最小代价
```

它和上一篇是一对**互为镜像**的经典问题，放在一起记最省力：

| | [[7.8 树型dp 打家劫舍 树上最大独立集]] | **本篇 最小支配集** |
| --- | --- | --- |
| 约束 | 相邻两点**不能同时选** | 每个点**都必须被覆盖** |
| 目标 | **最大**化点权和 | **最小**化点权和 |
| 父亲需要知道 | 孩子**选没选**（1 bit） | 孩子**被谁覆盖**（3 种可能） |
| 状态个数 | 2 | **3** |
| 哨兵 | 无 | `inf` 堵死非法路径 |

> [!tip]- 先诊断：为什么状态突然从 2 个变成 3 个
> 
> 337 里两个状态，是因为约束只作用在**一条边的两端**，父亲只要知道「孩子选没选」。这里状态变成三个，是因为**约束换了性质**——从「不能同时选」变成「必须被覆盖」，父亲要知道的是「**谁负责覆盖我的孩子**」。
> 
> 而「被覆盖」的来源恰好有三个方向：**自己装、父亲装、儿子装**。所以状态维度就是 3。
> 
> 看晕的常见原因：把这三个当成了「选 / 不选」的变体。它们回答的其实是**另一个问题**——不是「选不选」，而是「**谁负责覆盖我**」。
> 
> 一句话记住：**树形 DP 的状态个数 = 父亲做决策时，必须从孩子那里拿到的信息量。** 多一位不嫌多，少一位就一定错。

## 统一模板：三份合同

![](assets/7.9%20树型DP%20三色状态.svg)

> [!tip]- 三份合同（这是全篇的地基）
> 
> `dfs(node)` 返回三个数，**共同前提**是：node 的整棵子树里，**除了 node 自己以外的所有节点都已被覆盖**。三者的区别只在 node 自己的处境：
> 
> $$\begin{aligned} choose\ (\text{蓝}) &= \text{node 自己装摄像头时，该子树的最少代价} \\ byFa\ (\text{黄}) &= \text{node 不装、指望\textbf{父亲}覆盖它时，该子树的最少代价} \\ byChildren\ (\text{红}) &= \text{node 不装、由某个\textbf{儿子}覆盖它时，该子树的最少代价} \end{aligned}$$
> 
> **关键是理解 `by_fa`**：父亲的摄像头**不在这棵子树里**，所以站在子树内部看，node 是「**欠着一份覆盖**」的状态。这份债由调用者（父亲）来还——它是一个**只对父亲有意义的中间态**，到了根就必须丢掉（见下文）。

![](assets/7.9%20树型DP%20允许矩阵.svg)

> [!tip]- 三条转移，逐条给理由
> 
> 每条转移都在回答同一句话：**node 处在这个状态时，儿子的三个状态里哪些还合法？**
> 
> **① `choose`：node 装了**
> 
> ```python
> choose = min(l_choose, l_by_fa, l_by_children) + min(r_三个) + 1
> ```
> 
> node 装了 → 两个儿子**已经被 node 覆盖了**，儿子怎么处理自己完全自由：自己装、指望父亲（也就是 node）、被自己的儿子覆盖，三种都合法，取最便宜的。`+1` 是 node 这台摄像头。
> 
> 注意 `l_by_fa` 这一支**在这里才是合法的**——它欠的那笔债，正好由 node 这台摄像头还上了。
> 
> **② `by_fa`：node 不装，等父亲来救**
> 
> ```python
> by_fa = min(l_choose, l_by_children) + min(r_choose, r_by_children)
> ```
> 
> node 没有摄像头 → 儿子**得不到任何来自 node 的覆盖**，必须自力更生：要么自己装，要么被自己的儿子覆盖。
> 
> `l_by_fa` 在这里被排除，因为它的含义是「左儿子指望 node 覆盖它」，而 node 是空的。**这一条被排除，正是 `by_fa` 与 `choose` 的唯一差别**——也是全篇最容易写错的一格。
> 
> **③ `by_children`：node 不装，靠儿子**
> 
> ```python
> by_children = min(l_choose + r_by_children,      # 左装、右靠自己的儿子
>                   l_by_children + r_choose,      # 右装、左靠自己的儿子
>                   l_choose + r_choose)           # 两个都装
> ```
> 
> 要求变成：**至少有一个儿子装了摄像头**。同时另一个儿子仍然必须被覆盖、且仍然不能指望 node。于是穷举「谁装」。

> [!warning]- 为什么第三项「两个都装」不能省
> 
> 这是最容易被当成冗余删掉的地方。先看叶子的三元组：
> 
> ```text
> dfs(leaf) → (choose = 1, by_fa = 0, by_children = inf)
>                                                  ↑ 叶子没有儿子，红这条路不存在
> ```
> 
> 于是当 node 的两个儿子**都是叶子**时：
> 
> ```text
> l_choose + r_by_children = 1 + inf = inf
> l_by_children + r_choose = inf + 1 = inf
> l_choose + r_choose      = 1 + 1   = 2      ← 只有这一项是有限的
> ```
> 
> 现实含义：node 靠一个叶子来覆盖，那**另一个叶子**既没有摄像头、上面的 node 也没有、自己又没有儿子——只能自己再装一台，所以是 2。
> 
> **错误真正暴露的位置在上一层。** 只有两层时 `choose` 还能兜住答案；把树加深一层就现原形——七个节点的满二叉树 `[0,0,0,0,0,0,0]`：正确答案是 **2**（两个中间节点各装一台），删掉第三项会算成 **3**。
> 
> （其实前两项里的 `r_by_children` 本该写成 `min(r_choose, r_by_children)`，原写法把这个 `min` 展开成了第三项，两者等价。）

> [!warning]- 空节点为什么是 `(inf, 0, 0)`
> 
> ```python
> if node is None:
>     return inf, 0, 0
> ```
> 
> 一个个对：
> 
> - **`choose = inf`**：空节点**不可能装**摄像头 → 用 `inf` 表示「此路不通」，它会在外层的 `min` 里自动被淘汰。这是求最小值 DP 里表示不可达的标准手法（对照 [[7.5 状态机DP 股票买卖]] 用 `-inf` 编码非法状态，同一个思想的反向版）。
> - **`by_fa = 0`**：空节点**不需要被覆盖**，也不产生成本。
> - **`by_children = 0`**：严格说空节点没有儿子，这一项语义上不成立；但因为空节点根本不需要覆盖，把它当成「这一侧零约束、零成本」是安全的，且能让父亲的转移式**不用特判 `None`**。
> 
> 验证：node 的左儿子是空时，`by_fa` 那一侧算 `min(inf, 0) = 0` ✓；`by_children` 里凡是「左儿子装摄像头」的分支都含 `inf` ✓，走不通。**`inf` 负责堵死非法路径，`0` 负责让合法路径不受干扰**——一个哨兵干两件事。

> [!warning]- 最后为什么是 `min(choose, by_children)`，不能是 `min(三个)`
> 
> 先记一个事实：
> 
> $$byFa \le byChildren \quad \text{恒成立}$$
> 
> 因为 `by_fa` 的约束**更松**（node 自己不用在子树内被覆盖），任何 `by_children` 的合法方案自动也是 `by_fa` 的合法方案，所以 `by_fa` 永远不会更贵。
> 
> 正因为如此，根节点必须**主动排除** `by_fa`——root 没有父亲，那笔「欠债」永远还不上；留着它不仅会返回一个 root 未被覆盖的错误答案，而且因为它**恒更小，一定会被 `min` 选中**。
> 
> 这也是 `by_fa` 存在的全部意义：**它是一个只对父亲有意义的中间态，到了顶层就得丢掉。**

## 变体一：968. 监控二叉树

在二叉树的节点上装摄像头，每台可监控**自己、父节点、所有子节点**，求覆盖全树的最少摄像头数。

> [!success]- 代码实现
> 
> ```python
> from math import inf
>
> class Solution:
>     def minCameraCover(self, root: Optional[TreeNode]) -> int:
>         def dfs(node):
>             if node is None:
>                 return inf, 0, 0                       # 蓝不可能 / 黄不欠债 / 红零成本
>             l_choose, l_by_fa, l_by_children = dfs(node.left)
>             r_choose, r_by_fa, r_by_children = dfs(node.right)
>
>             choose = (min(l_choose, l_by_fa, l_by_children)
>                       + min(r_choose, r_by_fa, r_by_children) + 1)
>             by_fa = min(l_choose, l_by_children) + min(r_choose, r_by_children)
>             by_children = min(l_choose + r_by_children,
>                               l_by_children + r_choose,
>                               l_choose + r_choose)
>             return choose, by_fa, by_children
>
>         choose, _, by_children = dfs(root)
>         return min(choose, by_children)                # 根没有父亲，丢掉 by_fa
> ```
> 
> - **主流程**：一次后序 DFS，每个节点返回三元组；三条转移各对应「允许矩阵」的一行。
> - **关键变量**：`by_fa` 是**欠债态**，只在父亲装了摄像头时才被允许兑现。
> - **易错位置**：`by_fa` 里误用 `l_by_fa`、`by_children` 漏第三项、空节点 `choose` 写成 0、最后写成 `min(三个)`。

## 变体二：带点权的最小支配集

**变形 1**：在节点 `x` 安装摄像头需要花费 `cost[x]`，求监控所有节点的最小花费。

> [!success]- 只改一个字
> 
> ```python
> choose = (min(l_choose, l_by_fa, l_by_children)
>           + min(r_choose, r_by_fa, r_by_children) + cost[node])   # 把 +1 换成 +cost[x]
> ```
> 
> 其余**一个字都不用动**。原因很直接：三个状态的定义、允许矩阵、`inf` 哨兵、根的处理，全都与「一台摄像头值多少钱」无关——`+1` 本来就只是 `cost[x] ≡ 1` 的特例。
> 
> 这也是把 968 理解成「**树上最小权支配集**」而不是「摄像头题」的好处：换皮不换骨。

## 变体三：保安站岗（一般树 + 化简）

**变形 2**：一个红色节点有 3 个儿子呢？4 个呢？——推广到**一般树**（洛谷 P2458 保安站岗：每个点有站岗费用，要求每个点被自己或邻居看到，求最小总费用）。

![](assets/7.9%20树型DP%20红色化简.svg)

> [!tip]- 核心思路：红色不是枚举出来的，是黄色的一次「最小升级」
> 
> 二叉树的红色靠穷举「谁装」；`k` 个儿子就有 $2^k - 1$ 种组合，**太麻烦**。换个角度看：
> 
> $$\begin{aligned} \text{蓝} &= \sum_{y} \min(\text{蓝}_y,\ \text{黄}_y) + cost_x \\ \text{黄} &= \sum_{y} \min(\text{蓝}_y,\ \text{红}_y) \\ \text{红} &= \text{黄} + \max\Big(0,\ \min_{y}(\text{蓝}_y - \text{红}_y)\Big) \end{aligned}$$
> 
> **红色的推导**：红要求「至少一个儿子是蓝」，而黄是「每个儿子各自在蓝/红里取最优、不管有没有蓝」。所以红只需要在黄的基础上**补一次升级**：
> 
> - 若黄里**已经有儿子选了蓝** ⇒ 说明某个 $\text{蓝}_y - \text{红}_y \le 0$ ⇒ `max(0, ...)` 取 0，**一分不加**，因为要求已经自动满足。
> - 若**所有儿子都选了红** ⇒ 所有差值都为正 ⇒ 必须挑**差值最小**的那个儿子升级成蓝，多付 $\min_y(\text{蓝}_y - \text{红}_y)$。
> 
> 于是 $2^k$ 的枚举被压成一次求和 + 一次求最小值，**单个节点 $O(k)$**。
> 
> **算例**（三个儿子的 `(蓝, 红)` 分别是 `(5,2) (7,6) (5,1)`）：
> 
> ```text
> 黄 = min(5,2) + min(7,6) + min(5,1) = 2 + 6 + 1 = 9      三个都选了红，一个蓝也没有
> 差值 = 5-2=3,  7-6=1,  5-1=4        最小是 1（第 2 个儿子）
> 红 = 9 + 1 = 10
> ```

> [!success]- 代码实现（洛谷 P2458 保安站岗）
> 
> ```python
> import sys
> from math import inf
> input = sys.stdin.readline
> sys.setrecursionlimit(10 ** 5)
>
> n = int(input())
> cost = [0] * (n + 1)
> g = [[] for _ in range(n + 1)]
> is_child = [False] * (n + 1)
> for _ in range(n):
>     a = list(map(int, input().split()))
>     i, k, m = a[0], a[1], a[2]              # 编号、费用、儿子数
>     cost[i] = k
>     for y in a[3:3 + m]:
>         g[i].append(y)
>         is_child[y] = True
> root = next(i for i in range(1, n + 1) if not is_child[i])
>
> def dfs(x):
>     blue = cost[x]                          # 蓝：自己装
>     yellow = 0                              # 黄：不装，等父亲
>     delta = inf                             # min(蓝_y - 红_y)，升级成蓝的最小差价
>     for y in g[x]:
>         b, ye, r = dfs(y)
>         blue   += min(b, ye)                # 蓝：x 装了，儿子的债由 x 还（红被黄支配，可省）
>         yellow += min(b, r)                 # 黄：儿子只能蓝或红
>         delta = min(delta, b - r)
>     red = yellow + max(0, delta) if g[x] else inf   # 叶子没有儿子，红不可达
>     return blue, yellow, red
>
> b, _, r = dfs(root)
> print(min(b, r))                            # 根排除黄
> ```
> 
> - **`blue` 里为什么写 `min(b, ye)` 而不是三个取 min**：因为 $\text{红}_y \ge \text{黄}_y$ 恒成立（红的约束更严），红这一支永远被黄支配，**写了也选不中**——二叉树版写 `min(三个)` 只是没做这步剪枝，两者等价。
> - **叶子**：`blue = cost[x]`、`yellow = 0`、`red = inf`（没有儿子可依靠）——初值直接充当 base case，不需要显式分支。
> - **找根**：树用「谁是谁的儿子」给出时，根是**从没当过儿子**的那个点，别默认是 1 号。
> - 若给的是**无向边列表**，`g` 存双向边并在 `dfs(x, fa)` 里跳过 `y == fa`，写法同 [[7.7 树型DP 树的直径]] 的 2246。

> [!summary]- 968 vs 保安站岗：什么不变、什么改变
> 
> **完全不变**：三份合同的语义、允许矩阵（哪些儿子状态合法）、`inf` 哨兵、根排除黄、$O(n)$ 复杂度、不需要记忆化。
> 
> **改变的只有两处**：
> 
> | | 968（二叉树） | 保安站岗（一般树） |
> | --- | --- | --- |
> | 儿子怎么合并 | 左 + 右，写死两项 | `for y in g[x]` 累加 |
> | 红色怎么算 | 穷举三种「谁装」 | **黄 + max(0, min(蓝−红))** |
> | 空节点 | `(inf, 0, 0)` 兜底 | 无空节点概念，**靠初值兜底**（红取 `inf`） |
> | 代价 | `+1` | `+cost[x]` |

## 易错点

> [!warning]- 易错点
> 
> - **`by_fa` 里误用了 `l_by_fa`**：node 没摄像头，儿子指望它就是**空头支票**。这是三条转移里唯一的区别点，也是最高频的错。
> - **`by_children` 漏掉「两个都装」**：两个叶子儿子的场景会被算成 `inf`。浅树上 `choose` 还能兜住，**深一层就会给出错误答案**（七点满二叉树：正确 2，漏项后 3）。
> - **空节点 `choose` 写成 `0`**：等于允许在空位置装摄像头，答案偏小——这是三个哨兵里最致命的一个。
> - **最后写成 `min(三个)`**：`by_fa` 恒最小、必被选中，root 漏覆盖。
> - **想套 337 的两状态**：覆盖来源有三个方向，二元组表达不下。**先问「父亲需要知道什么」，再决定状态个数。**
> - **一般树版忘了叶子的红是 `inf`**：若写成 `yellow + max(0, inf)` 会溢出成 `inf` 还好，但若把 `delta` 初值写成 0，叶子的红会等于 0，等价于「没有儿子也能被儿子覆盖」，答案偏小。
> - **变量名拼错但拼得一致**：能跑，但复查时极易看漏（原稿代码里 `chlidren` 就是一例）。

## 复杂度

> [!summary]- 复杂度
> 
> - **时间 $O(n)$** —— 每个节点访问一次；二叉版单次转移是常数；一般树版单个节点 $O(k)$（`k` 是儿子数），累计起来正好是总边数 $n-1$，仍是 $O(n)$。
> - **若红色不化简、直接枚举「哪个儿子装」**，单个节点会退化成 $O(k^2)$（枚举 `k` 次、每次求和 `k` 项），总体最坏 $O(n^2)$；化简后回到 $O(n)$。
> - **空间 $O(h)$** —— 递归栈深度等于树高，最坏 $O(n)$；一般树版另有邻接表 $O(n)$。
> - 同样**不需要 `@cache`**：每个节点只被唯一的父亲调用一次（见 [[重叠子问题与无后效性]]）。

## 一句话总结

337 的父亲只需要知道孩子「**选没选**」，所以两个状态；968 的父亲需要知道孩子「**被谁覆盖**」，而来源有自己 / 父亲 / 儿子三种，所以三个状态——**树形 DP 的状态个数，等于父亲做决策时必须从孩子那里拿到的信息量**，多一位不嫌多，少一位就一定错。

## 模板归纳

看到「**一棵树** + **每个点都必须被覆盖 / 被看到** + 求最小数量或代价」，四步落笔：

1. **先数状态**：问一句「**父亲要做决策，必须知道孩子的什么**」。答案是「被谁覆盖」⇒ 来源有自己 / 父亲 / 儿子三种 ⇒ **三个状态**。（若问的是「选没选」⇒ 两个状态，回 [[7.8 树型dp 打家劫舍 树上最大独立集]]。）
2. **写三份合同**：共同前提是「子树里除自己外全部已覆盖」，区别只在自己的处境。**黄（等父亲）是欠债态**，只有父亲装了才能兑现。
3. **画允许矩阵再抄式子**：node 蓝 ⇒ 儿子三种全允许；node 黄 ⇒ 儿子不能是黄；node 红 ⇒ 儿子不能是黄，**且至少一个蓝**。
4. **定哨兵与出口**：空节点 `(inf, 0, 0)`；根 `min(蓝, 红)`，**必须排除黄**。多叉树把红色化简成「黄 + 一次最小升级」。

```python
# 树上最小（权）支配集通用骨架
def dfs(x):
    blue, yellow, delta = cost[x], 0, inf
    for y in children(x):
        b, ye, r = dfs(y)
        blue   += min(b, ye)               # 蓝：x 装了，儿子欠的债由 x 还
        yellow += min(b, r)                # 黄：x 没装，儿子不能指望 x
        delta = min(delta, b - r)          # 升级成蓝的最小差价
    red = yellow + max(0, delta) if children(x) else inf
    return blue, yellow, red

blue, _, red = dfs(root)
return min(blue, red)                      # 根没有父亲，丢掉黄
```
