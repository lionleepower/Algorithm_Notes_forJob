# 前缀和 + 哈希：和为 K 的子数组与路径总和 III

## 解决什么问题

**「有多少个子数组 / 路径的和等于 $k$」**，且数组**含负数**——滑动窗口在这里彻底失效。

识别信号：

```text
求「和为定值」的子数组个数 + 元素可正可负 + 只要个数不要具体方案
```

## 思路

子数组和可以写成两个前缀和之差，于是「找一段和为 $k$ 的区间」变成「找一对差为 $k$ 的前缀和」；配对问题交给哈希表，一次遍历即可。

> [!tip]- 核心思路：把「区间问题」翻译成「配对问题」
>
> **第一步：定义前缀和（下标约定是全篇最容易出错的地方）**
>
> $$s[0] = 0, \qquad s[i] = \sum_{t=0}^{i-1} nums[t]$$
>
> 即 `s[i]` 表示**前 $i$ 个元素**的和，长度为 $n+1$。于是任意子数组：
>
> $$\text{sum}(nums[l \ldots r]) = s[r+1] - s[l]$$
>
> **为什么必须有 `s[0] = 0`？** 它代表「空前缀」，是「子数组从下标 0 开始」这种情况的唯一表示。漏了它，所有以 0 开头的答案全部丢失。这个哨兵后面会以 `cnt[0] = 1` 的形式再出现一次。
>
> **第二步：改写目标**
>
> $$s[r+1] - s[l] = k \iff s[l] = s[r+1] - k$$
>
> 固定右端点 $r$，问题变成：**在 $r$ 左边，有多少个前缀和等于 $s[r+1]-k$。**
> 这是一个纯粹的「查有多少个数等于某值」——哈希计数表的标准场景，$O(1)$ 完成。
>
> **第三步：为什么这里不能用滑动窗口**
>
> 滑窗成立的前提是**单调性**：右指针右移，窗口和必须单调不减；这样「和太大就缩左边」才是有效操作。
> 数组含负数时，右移可能让和变小，「缩左边」也可能让和变大——**收缩方向失去意义**，二指针无法定位。
>
> 这是 [[1.2 滑动窗口]] 的边界：**滑窗管「全正数 + 求最长/最短」，前缀和哈希管「有负数 + 求个数」。**

## 变体一：560. 和为 K 的子数组

给整数数组 `nums` 和整数 `k`，返回**和为 `k` 的连续子数组的个数**。

> [!example]- 示例推演：`nums = [1, -1, 1]`，`k = 1`
>
> `cnt` 表示「已出现的前缀和 $\to$ 次数」，初始 `cnt = {0: 1}`（空前缀）。
>
> ```text
> 起始      s = 0     cnt = {0:1}
>
> 读 1      s = 1     查 cnt[1-1] = cnt[0] = 1  -> ans = 1   （子数组 [1]）
>                     记 cnt = {0:1, 1:1}
>
> 读 -1     s = 0     查 cnt[0-1] = cnt[-1] = 0 -> ans = 1
>                     记 cnt = {0:2, 1:1}
>
> 读 1      s = 1     查 cnt[1-1] = cnt[0] = 2  -> ans = 3   （[1,-1,1] 与 [1]）
>                     记 cnt = {0:2, 1:2}
>
> 答案 3
> ```
>
> 注意最后一步一次性 `+2`：`cnt[0] = 2` 代表**两个不同的左端点**（空前缀 和 下标 2 处的前缀）都能与当前右端点配成 $k$。**哈希表存的是次数不是布尔值**，正因为要数个数。

> [!success]- 代码实现
>
> **Python**
>
> ```python
> from collections import defaultdict
>
> class Solution:
>     def subarraySum(self, nums: List[int], k: int) -> int:
>         cnt = defaultdict(int)
>         cnt[0] = 1              # 空前缀，对应 s[0] = 0
>         s = 0
>         ans = 0
>         for x in nums:
>             s += x
>             ans += cnt[s - k]   # 先查：只统计「严格在左边」的前缀
>             cnt[s] += 1         # 后记：当前前缀留给未来的右端点
>         return ans
> ```
>
> **C++**
>
> ```cpp
> class Solution {
> public:
>     int subarraySum(vector<int>& nums, int k) {
>         unordered_map<long long, int> cnt{{0, 1}};
>         long long s = 0;
>         int ans = 0;
>         for (int x : nums) {
>             s += x;
>             auto it = cnt.find(s - k);
>             if (it != cnt.end()) ans += it->second;
>             ++cnt[s];
>         }
>         return ans;
>     }
> };
> ```
>
> **主流程**：滚动累加前缀和 $\to$ 查表配对 $\to$ 把自己登记进表。
>
> **关键变量**
> - `s`：当前前缀和，滚动变量，不需要真的开数组
> - `cnt[v]`：**在当前位置左侧**，前缀和等于 `v` 的位置个数
> - `cnt[0] = 1`：空前缀哨兵
>
> **易错位置**：`ans += cnt[s-k]` 与 `cnt[s] += 1` 的**先后顺序**，见下方易错点第 2 条。

> [!warning]- 易错点
>
> **1. 忘记 `cnt[0] = 1`**
> 所有「从下标 0 开始」的子数组会被漏掉。
> 验证用例：`nums = [1], k = 1`。正确答案 1；漏掉哨兵得 0。
>
> **2. 先记后查（顺序反了）**
> 写成：
> ```python
> cnt[s] += 1
> ans += cnt[s - k]      # 错
> ```
> 当 `k = 0` 时，`cnt[s-k]` 就是 `cnt[s]`，而当前位置刚被记进去，等于**让自己和自己配对**，凭空多出一个长度为 0 的"子数组"。
> 验证用例：`nums = [1], k = 0`。正确答案 0；顺序反了得 1。
>
> **本质**：哈希表的不变量是「**严格位于当前右端点左侧**的前缀和集合」。查询必须发生在自己入表之前，不变量才成立。
>
> **3. 想用滑动窗口**
> 验证用例：`nums = [1, -1, 0], k = 0`，答案 3。窗口和不单调，滑窗给不出正确结果。
>
> **4. 误以为要去重**
> 求的是**子数组个数**（按位置区分），值相同的不同区间要分别计数——所以是 `defaultdict(int)` 计数，不是 `set`。
>
> **5. C++ 溢出**
> $n \le 2 \times 10^4$、$|nums[i]| \le 1000$，前缀和最大 $2 \times 10^7$ 不溢出 `int`，但 `s - k` 中 `k` 可达 $10^7$ 量级，**统一用 `long long` 更稳**。Python 无此问题。

## 变体二：437. 路径总和 III

给二叉树和目标值 `targetSum`，求**路径和等于 `targetSum` 的路径数目**。路径必须**向下**，但不必从根开始、不必在叶子结束。

> [!tip]- 核心思路：同一个模板，把「数组」换成「根到当前节点的链」
>
> 「向下的路径」= 某条根到节点的链上的**一段连续区间**。所以：
>
> | 560 | 437 |
> | --- | --- |
> | 数组下标 $0 \ldots i$ | 根到当前节点的路径 |
> | 前缀和 `s` | 根到当前节点的**路径和** |
> | 哈希表 = 左侧所有前缀 | 哈希表 = **当前祖先链上**的所有前缀 |
> | 一维从左到右扫 | 树上 DFS 深入 / 回退 |
>
> **唯一的新东西是「回退」。** 数组是一条直线，走过的前缀永远有效；树有分叉，**左子树的前缀对右子树无效**（它们不在同一条根到节点的链上）。
>
> 所以哈希表的不变量必须是：**`cnt` 恰好记录当前递归栈上这条链的所有前缀和**。
> 维护方式就是 [[6.0 回溯型算法]] 的借还平衡：进入时 `cnt[s] += 1`，**退出时 `cnt[s] -= 1`**。
>
> 一句话：**560 的哈希表随时间单调增长，437 的哈希表随深度借还。**

> [!success]- 代码实现
>
> **Python**
>
> ```python
> from collections import defaultdict
>
> class Solution:
>     def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
>         cnt = defaultdict(int)
>         cnt[0] = 1                      # 空前缀：路径从根开始的情况
>         ans = 0
>
>         def dfs(node, s):
>             nonlocal ans
>             if node is None:
>                 return
>             s += node.val
>             ans += cnt[s - targetSum]   # 先查
>             cnt[s] += 1                 # 后记
>             dfs(node.left, s)
>             dfs(node.right, s)
>             cnt[s] -= 1                 # 还：离开这条链
>
>         dfs(root, 0)
>         return ans
> ```
>
> **C++**
>
> ```cpp
> class Solution {
>     unordered_map<long long, int> cnt;
>     int target, ans = 0;
>
>     void dfs(TreeNode* node, long long s) {
>         if (!node) return;
>         s += node->val;
>         auto it = cnt.find(s - target);
>         if (it != cnt.end()) ans += it->second;
>         ++cnt[s];
>         dfs(node->left, s);
>         dfs(node->right, s);
>         --cnt[s];                        // 还
>     }
> public:
>     int pathSum(TreeNode* root, int targetSum) {
>         target = targetSum;
>         cnt[0] = 1;
>         dfs(root, 0);
>         return ans;
>     }
> };
> ```
>
> **主流程**：DFS 携带路径和 $\to$ 查表配对 $\to$ 登记 $\to$ 递归左右 $\to$ **撤销登记**。
>
> **关键变量**
> - `s`：根到当前节点的路径和，**作参数传递**（天然随栈回退，不用手动还原）
> - `cnt`：**共享白板**，跨分支可见，所以必须手动还原
>
> 注意这两者的差别：`s` 是值传递的局部量，函数返回自动失效；`cnt` 是闭包外的共享结构，必须显式 `-= 1`。这正是 [[6.0 回溯型算法]] 里「path 借还」与「参数天然回退」的同一对概念，也可参考 [[状态恢复]]。

> [!warning]- 易错点
>
> **1. 忘记 `cnt[s] -= 1`**
> 最典型的错误。左子树的前缀和会污染右子树，答案**偏大**且不报错。
> 验证用例：根 `1`，左子 `1`，右子 `1`，`targetSum = 2`。正确答案 2（根-左、根-右）；漏还原会多算。
>
> **2. 撤销的位置放错**
> 必须放在**两个递归之后**。放在两次递归之间，右子树就看不到当前节点的前缀；放在递归之前，等于没登记。
>
> **3. 查询与登记的顺序**
> 和 560 同一条：`ans += cnt[s-target]` 必须在 `cnt[s] += 1` 之前。
> 当 `targetSum = 0` 时，顺序反了会把「长度为 0 的空路径」算进去。
>
> **4. 忘记 `cnt[0] = 1`**
> 所有**从根开始**的路径会被漏掉。
>
> **5. 用 `defaultdict` 时的隐形键增长**
> `cnt[s - targetSum]` 这个读操作会在 `defaultdict` 中**自动插入键值 0**。不影响正确性（0 次不会被误加），但会让字典变大。追求干净可写 `cnt.get(s - targetSum, 0)`。
>
> **6. 节点值可能为负**
> 题目允许负值，这正是不能用「和超了就剪枝」的原因——也正是必须用前缀和哈希而非双指针的原因，与 560 完全同源。
>
> **7. 暴力解法的复杂度**
> 「以每个节点为起点各 DFS 一次」是 $O(n^2)$（链状树），能过但不是最优解。面试要说出 $O(n)$ 的这一版。

## 同族：只有前缀和、不需要哈希的三道

有些题只用到「前缀和 / 前后缀分解」这半边，不需要配对，因此也不需要哈希表。

> [!tip]- 238 除自身以外数组的乘积 · 53 最大子数组和
>
> **238. 除自身以外数组的乘积**（不许用除法）
> 答案 `ans[i] = 前缀积(0..i-1) × 后缀积(i+1..n-1)`。两遍扫描：先左往右累乘写进 `ans`，再右往左用一个滚动变量乘上去，$O(1)$ 额外空间（不计返回数组）。
> **前后缀分解**是「去掉自己」类问题的通用招式：凡是「对每个 $i$，求不含 $i$ 的某种聚合」，都先想它。
>
> ```python
> def productExceptSelf(self, nums: List[int]) -> List[int]:
>     n = len(nums)
>     ans = [1] * n
>     for i in range(1, n):
>         ans[i] = ans[i - 1] * nums[i - 1]   # 左前缀积
>     suf = 1
>     for i in range(n - 1, -1, -1):
>         ans[i] *= suf                        # 乘上右后缀积
>         suf *= nums[i]
>     return ans
> ```
>
> **53. 最大子数组和**
> 用前缀和视角：$\max_{r} \big( s[r] - \min_{l < r} s[l] \big)$——边扫边维护「历史最小前缀和」。
> 这与 Kadane（`f[i] = max(f[i-1], 0) + nums[i]`）是同一件事的两种说法：Kadane 的「前面为负就丢掉」等价于「把 $\min s[l]$ 更新成当前值」。面试说其中一种即可，但要能指出二者等价。
>这里我们先去使用前缀和：
>```python
>class Solution:
>	def maxSubArray(self, nums: List[int]) -> int:
>	ans = -inf
        min_pre_sum = pre_sum = 0
        for x in nums:
            pre_sum += x  # 当前的前缀和
            ans = max(ans, pre_sum - min_pre_sum)  # 减去前缀和的最小值
            min_pre_sum = min(min_pre_sum, pre_sum)  # 维护前缀和的最小值
        return ans
>	
>```
> **303 / 304 区域和检索**是最裸的前缀和：预处理一次，查询 $O(1)$。二维版记牢容斥式 `S[i][j] - S[i-k][j] - S[i][j-k] + S[i-k][j-k]`。

## 复杂度

> [!summary]- 复杂度
>
> **560. 和为 K 的子数组**
> 时间：$O(n)$，空间：$O(n)$
> 为什么：一次遍历，每步哈希查询与插入均摊 $O(1)$；最坏情况所有前缀和互不相同，表大小 $O(n)$。
>
> **437. 路径总和 III**
> 时间：$O(n)$，空间：$O(n)$
> 为什么：每个节点恰好被访问一次；哈希表在任一时刻只存**当前链**上的前缀（大小 $O(h)$），加上递归栈 $O(h)$，最坏链状树退化为 $O(n)$。
>
> **238 / 53**：时间 $O(n)$，空间 $O(1)$（不计返回数组）。
>
> 对比暴力：$O(n^2)$ $\to$ $O(n)$，省下的正是「对每个右端点重新扫左边」这一层。

## 一句话总结

前缀和把「区间求和」变成「两点作差」，哈希把「找配对」变成「查计数」；560 的哈希表随时间**只增不减**，437 的哈希表随深度**借了要还**——差别只在数组是直线而树有分叉。

>
> 这是本模板的**第二个分岔**，比模板本身更常被追问：
>
> | 问题类型 | 哈希表存 | 为什么 |
> | --- | --- | --- |
> | 求**个数**（560） | 前缀和 $\to$ **出现次数** | 每个左端点都算一个方案 |
> | 求**最长/最短**（525、523） | 前缀和 $\to$ **最早下标**，且**只在首次出现时写入** | 要最长，左端点越靠前越好，后来的重复值没有价值 |
>
> 写错这一条会得到「代码结构完全正确但答案系统性偏小」的现象。

## 模板归纳

**触发信号**

- 「子数组 / 子串 / 向下路径」+「和为定值」+「个数」
- 数组**含负数**，或看到 `0` 与 `1`、奇数与偶数这类可映射成 $\pm 1$ 的二元结构
- 想用滑窗但发现「收缩」没有意义

**落笔四步**

1. **定义前缀和并写死下标语义**：`s[i]` = 前 $i$ 个元素之和，`s[0] = 0`。语义定了，哨兵 `cnt[0] = 1` 就是它的直接推论，不用背。
2. **改写目标为配对式**：`s[r] - s[l] = k` $\Rightarrow$ 查 `s[l] = s[r] - k`。
3. **决定哈希表存什么**：数个数存**次数**，求长度存**最早下标**。
4. **确定表的生命周期**：一维数组 $\to$ 只增；树上 / 需要「当前链」语义 $\to$ **进入登记、退出撤销**。

**自检两问**（写完立刻验）

- `cnt[0] = 1` 写了吗？（测 `nums=[1], k=1`）
- 查询在登记**之前**吗？（测 `nums=[1], k=0`）
