# 哈希实战：分组、最长连续序列与原地哈希

## 解决什么问题

哈希表在面试里只有三种用法，Hot100 的数组题几乎全落在这三格：

| 用法 | 键是什么 | 代表题 |
| --- | --- | --- |
| **配对**：找「另一半」 | 需要的那个值 | 1. 两数之和、[[8.0 前缀和与哈希]] |
| **分组**：把同类塞进一桶 | 同类元素的**不变量（签名）** | 49. 字母异位词分组 |
| **判存在**：$O(1)$ 问「在不在」 | 元素本身 | 128. 最长连续序列 |

真正要练的是第二格的**「怎么设计签名」**，和第三格的**「怎么保证不重复枚举」**。

最后再加一条反向技巧：当**值域和下标一一对应**时，数组自己就是哈希表，可以把空间降到 $O(1)$。

## 变体一：49. 字母异位词分组

把互为字母异位词的字符串分到同一组。

> [!tip]- 核心思路：分组的关键是给每一类找一个「规范签名」
>
> 分组问题的通式：`groups[签名(x)].append(x)`。难点从来不在哈希表，而在**签名函数**——它必须满足：
>
> **同类必同签名（完备），异类必异签名（无冲突）。**
>
> 字母异位词的定义是「字符多重集合相同」，所以任何**丢掉顺序、保留计数**的表示都可以当签名：
>
> | 签名方案 | 复杂度 | 备注 |
> | --- | --- | --- |
> | `''.join(sorted(s))` | $O(nk\log k)$ | 最短，面试首选 |
> | 26 长度计数元组 | $O(nk)$ | 更快，需强调 `tuple` 才可哈希 |
> | 质数乘积 | $O(nk)$ | **不要用**，溢出且难自证无冲突 |
>
> 用计数当签名时必须转成 `tuple`：`list` 不可哈希（可变对象没有稳定的 `__hash__`），这是本题唯一的语言坑，见 [[Python_dict]] 的「键必须可哈希」。

> [!success]- 代码实现
>
> ```python
> from collections import defaultdict
>
> class Solution:
>     def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
>         groups = defaultdict(list)
>         for s in strs:
>             cnt = [0] * 26
>             for ch in s:
>                 cnt[ord(ch) - ord('a')] += 1
>             groups[tuple(cnt)].append(s)     # tuple 才可哈希
>         return list(groups.values())
> ```
> 或者是：
> ```python
>class Solution:
>    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        d= {}
>        for s in strs:
>            sorted_s = "".join(sorted(s))
>            if sorted_s not in d:
>                d[sorted_s] = []
>            d[sorted_s].append(s)
>       return list(d.values())
>```
>
> **主流程**：对每个串算签名 $\to$ 丢进对应桶 $\to$ 返回所有桶。
> **关键变量**：`groups[签名] -> 该组所有原串`。
> **易错位置**：忘记 `tuple(...)` 会直接抛 `TypeError: unhashable type: 'list'`。

## 变体二：128. 最长连续序列

无序数组中找最长的连续（数值相差 1）序列长度，要求 $O(n)$。

> [!tip]- 核心思路：只从「序列起点」起跳，才把 $O(n^2)$ 压回 $O(n)$
>
> 朴素想法：把所有数丢进 `set`，对每个 `x` 向右一直找 `x+1, x+2, ...`。
> 这是对的但会退化：`[1,2,3,...,n]` 会从每个位置各走一遍，$O(n^2)$。
>
> **关键剪枝：只有当 `x-1` 不在集合里时，`x` 才是某段连续序列的起点，才允许向右扩。**
>
> 为什么这就变成 $O(n)$：每段连续序列**只会被它的起点扫一次**，整个过程中「向右扩」的总步数等于所有序列长度之和 $\le n$。加上外层的 $n$ 次判断，总计 $O(n)$。
>
> 这条「只从起点出发」的思想和单调栈里「永久淘汰」是同一类：**先证明大量枚举是重复的，再把它们剪掉**，而不是换更快的数据结构。

> [!example]- 示例推演：`nums = [100, 4, 200, 1, 3, 2]`
>
> ```text
> s = {1, 2, 3, 4, 100, 200}
>
> x=100  99 不在 s   -> 是起点，向右：101 不在 -> 长度 1
> x=4    3  在 s     -> 跳过（不是起点）
> x=200  199 不在 s  -> 起点，长度 1
> x=1    0  不在 s   -> 起点，向右 2,3,4 -> 长度 4   ← 答案
> x=3    2  在 s     -> 跳过
> x=2    1  在 s     -> 跳过
> ```
>
> 6 个元素里只有 3 个进入了「向右扩」，扩的总步数是 4 + 1 + 1。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def longestConsecutive(self, nums: List[int]) -> int:
>         s = set(nums)                 # 去重 + O(1) 判存在
>         ans = 0
>         for x in s:                   # 遍历 set 而非 nums，天然跳过重复值
>             if x - 1 in s:
>                 continue              # 不是起点，交给起点去数
>             y = x + 1
>             while y in s:
>                 y += 1
>             ans = max(ans, y - x)
>         return ans
> ```
>
> **主流程**：建集合 $\to$ 只对起点向右扩 $\to$ 取最大长度。
> **关键不变量**：`x` 进入 `while` 时，`x` 一定是一段极大连续区间的左端点。
> **易错位置**：漏掉 `if x - 1 in s: continue` 会 TLE；遍历 `nums` 而非 `s` 在大量重复值时也会退化。

## 变体三：值域受限时，不用哈希表也行

> [!tip]- 41 原地哈希 · 136 异或 · 169 摩尔投票
>
> 三道题的共同前提都是「值域被题目卡死了」，于是可以把 $O(n)$ 空间省成 $O(1)$。
>
> **41. 缺失的第一个正数**（要求 $O(n)$ 时间、$O(1)$ 空间）
>
> 答案一定落在 $[1, n+1]$ 内——`n` 个数最多占满 `1..n`。于是把数组自己当哈希表：**让值 `v` 回到下标 `v-1`**，最后第一个「下标与值对不上」的位置就是答案。
>
> ```python
> def firstMissingPositive(self, nums: List[int]) -> int:
>     n = len(nums)
>     for i in range(n):
>         # while 不是 if：换来的新值可能还需要继续归位
>         while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
>             j = nums[i] - 1
>             nums[i], nums[j] = nums[j], nums[i]
>     for i in range(n):
>         if nums[i] != i + 1:
>             return i + 1
>     return n + 1
> ```
>
> 三个坑：
> 1. **必须用 `while` 不是 `if`**——一次交换换回来的新值也可能不在自己家。
> 2. 交换条件写 `nums[nums[i]-1] != nums[i]`（比值），不要写 `nums[i] != i+1`（比位置）：遇到重复值会**死循环**。
> 3. Python 的 `nums[i], nums[j] = nums[j], nums[i]` 里，如果把 `j` 写成 `nums[i]-1` 内联，右侧求值顺序会让 `nums[i]` 先被改写而出错——**先把 `j` 存下来**。
>
> 总交换次数 $\le n$（每次交换至少让一个数永久归位），所以仍是 $O(n)$。
>
> **136. 只出现一次的数字**
>
> 全体异或。依据两条性质：$x \oplus x = 0$、$x \oplus 0 = x$，且异或满足交换律，成对的自然湮灭。
>
> ```python
> def singleNumber(self, nums: List[int]) -> int:
>     return reduce(xor, nums)   # 或 ans = 0; for x in nums: ans ^= x
> ```
>
> **169. 多数元素**（出现次数 $> \lfloor n/2 \rfloor$）
>
> 摩尔投票：维护「候选 + 票数」，同则加票、异则减票、票数归零就换人。
> 正确性来自「众数出现次数严格大于其余所有数之和」——每次抵消消掉一个众数和一个非众数，众数的优势永不消失。
>
> ```python
> def majorityElement(self, nums: List[int]) -> int:
>     cand, cnt = None, 0
>     for x in nums:
>         if cnt == 0:
>             cand = x
>         cnt += 1 if x == cand else -1
>     return cand
> ```
>
> 面试提示：先说哈希计数 $O(n)$ 空间，再说排序取中位数，最后给摩尔投票 $O(1)$ 空间——展示的是**空间意识**，不是记忆力。

## 易错点

> [!warning]- 易错点汇总
>
> **1. 用 `list` 当哈希键**（49）
> `TypeError: unhashable type: 'list'`。可变对象不可哈希，必须 `tuple(...)`。
>
> **2. 128 漏掉起点判断**
> 代码看起来完全正确，只是超时；面试里说不出「为什么是 $O(n)$」等于没做出来。
>
> **3. 128 用排序做**
> 排序 $O(n\log n)$ 能 AC，但题目明写要求 $O(n)$，面试官一定会追问。可以先说排序解法再给哈希解法。
>
> **4. 41 用 `if` 代替 `while`**
> 只归位一次，剩下的错位不会被修复，答案偏小且难以察觉。
>
> **5. 41 改了原数组**
> 题目允许，但面试要主动说明「以破坏输入为代价换 $O(1)$ 空间」。
>
> **6. 摩尔投票没有前提检查**
> 169 保证众数存在才能直接返回；229（求出现次数 $> n/3$）必须**二次扫描验证**候选。

## 复杂度

> [!summary]- 复杂度
>
> - **49**：时间 $O(nk)$（26 计数）或 $O(nk\log k)$（排序签名），$n$ 为串数、$k$ 为串长；空间 $O(nk)$ 存所有分组。
> - **128**：时间 $O(n)$ —— 每段连续序列只被其起点扫一次，扩展总步数 $\le n$；空间 $O(n)$ 存集合。
> - **41**：时间 $O(n)$ —— 每次交换至少让一个元素永久归位，交换总数 $\le n$；空间 $O(1)$。
> - **136 / 169**：时间 $O(n)$，空间 $O(1)$，各扫一遍。

## 一句话总结

哈希表只做三件事——**配对、分组、判存在**；分组难在设计签名，判存在难在**只从起点枚举**；而当值域被题目锁死时，数组下标本身就是最省的哈希表。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 「把 X 归到同一类」$\to$ 分组：先想**签名函数**，再想哈希表
- 「$O(n)$ 找连续 / 重复 / 缺失」$\to$ 集合判存在，并检查**是否会重复枚举**
- 「要求 $O(1)$ 额外空间」+「值域是 `1..n` 或元素成对出现」$\to$ 原地哈希 / 异或 / 摩尔投票

**分组三步**

1. 写出「两个元素同类」的**数学定义**（异位词 = 字符计数相同）。
2. 把这个定义做成一个**可哈希对象**（`tuple` / 排序后字符串）。
3. `defaultdict(list)` 一行入桶，返回 `list(d.values())`。

**判存在的自检**：我这次向外扩展，会不会有另一个元素把同一段再扩一遍？会 $\to$ 加起点条件。
