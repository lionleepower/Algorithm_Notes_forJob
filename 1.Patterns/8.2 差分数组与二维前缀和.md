# 差分数组与二维前缀和

## 解决什么问题

[[8.0 前缀和与哈希]] 解决的是「静态数组 + 多次区间**查询**」。把这个坐标系往两个方向各推一格，就是本篇：

| 方向 | 场景 | 工具 |
| --- | --- | --- |
| 从「查询」换成「**修改**」 | 对区间反复加值，最后才看结果 | **差分数组**（前缀和的逆运算） |
| 从「一维」升到「**二维**」 | 查子矩阵的和 / 给子矩阵整体加值 | **二维前缀和 / 二维差分**（容斥） |

识别信号：

```text
区间加值 + 修改次数 q 很多 + 全部改完才查询      →  差分
子矩阵求和 + 查询次数很多 + 矩阵不变            →  二维前缀和
```

**关键前提**：差分和前缀和都要求**修改与查询分成两个阶段**。一旦「改一次查一次」交替进行，就必须上树状数组 / 线段树，见 [[9.2 并查集 与 字典树]] 之后的数据结构线。

## 统一模板

> [!tip]- 核心思路：前缀和与差分互为逆运算
>
> $$d[i] = a[i] - a[i-1], \qquad a[i] = \sum_{t \le i} d[t]$$
>
> 因为 `a` 是 `d` 的前缀和，所以**改动 `d[l]` 会影响 `a` 从 `l` 开始的整条后缀**。这正是我们要的效果：
>
> $$\text{区间 } [l, r] \text{ 全体} +v \iff d[l] \mathrel{+}= v,\quad d[r+1] \mathrel{-}= v$$
>
> `d[l] += v` 让整条后缀抬高 $v$，`d[r+1] -= v` 在 `r` 之后把它压回去——**一次区间修改被压成两次单点修改**，$O(n)$ 变 $O(1)$。

![](assets/8.2%20差分%20打点与还原.svg)

> [!success]- 模板代码
>
> ```python
> from itertools import accumulate
>
> d = [0] * (n + 1)              # 必须开 n+1，因为 r 最大是 n-1，要写 d[n]
> for l, r, v in ops:            # r 是闭区间右端
>     d[l] += v
>     d[r + 1] -= v
> a = list(accumulate(d[:n]))    # 一次前缀和还原
> ```
>
> - 关键变量：`d` 全程只有单点加减，最后一次 `accumulate` 才产出真正的数组。
> - 易错位置：减号必须打在 `r + 1`；数组必须开 `n + 1` 长。两条都错在同一个原因——**差分作用的是后缀，撤销要发生在区间的下一格**。

## 典型变体

### 变体一：1109. 航班预订统计（差分裸模板）

`bookings[i] = [first, last, seats]` 表示航班编号 `first` 到 `last`（闭区间，从 1 开始编号）每班预订 `seats` 个座位，求每班航班的总座位数。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def corpFlightBookings(self, bookings: List[List[int]], n: int) -> List[int]:
>         d = [0] * (n + 1)
>         for first, last, seats in bookings:
>             d[first - 1] += seats     # 题目 1-indexed，数组 0-indexed
>             d[last] -= seats          # last 对应下标 last-1，撤销点是 last
>         return list(accumulate(d[:n]))
> ```
>
> - 主流程：打点 → 一次前缀和。$O(n + q)$ 完胜朴素的 $O(nq)$。
> - 易错位置：题目下标从 1 开始，`first - 1` 与 `last` 这一对偏移最容易写反。写之前先在草稿上标一遍：**闭区间右端 `r` 的撤销点是 `r + 1`，换算成 0-indexed 就是 `last`**。

### 变体二：1094. 拼车（值域即下标）

`trips[i] = [num, from, to]`，乘客在 `from` 上车、`to` 下车，问容量为 `capacity` 的车能否完成。

> [!tip]- 核心思路：「下车」天然对应差分的右端开区间
>
> 乘客在 `to` **下车**，意味着 `to` 这一站车上已经没有他了——区间是左闭右开 `[from, to)`。于是撤销点恰好就是 `to` 本身，**不需要 `+1`**。
>
> 这是差分题唯一需要动脑的地方：**先分清区间是闭是开，再决定减号打在 `r` 还是 `r+1`**。
>
> 题目给了 `to <= 1000`，值域固定，可以直接开定长数组，连离散化都省了。

> [!success]- 代码实现
>
> ```python
> class Solution:
>     def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
>         d = [0] * 1001                 # 站点值域 0..1000
>         for num, frm, to in trips:
>             d[frm] += num
>             d[to] -= num               # 右端开区间，不加 1
>         s = 0
>         for x in d:
>             s += x
>             if s > capacity:           # 边还原边判断，不必存整个数组
>                 return False
>         return True
> ```
>
> - 空间优化：还原时用一个滚动变量 `s` 即可，不需要真的生成 `a`。

### 变体三：值域太大怎么办 —— 扫描线（会议室 II、2251 花期内花的数目）

差分要开定长数组，值域到 $10^9$ 时直接崩。此时把**稠密的差分数组换成稀疏的事件列表**：

> [!tip]- 核心思路：只在「发生变化的那些点」上记录
>
> 差分数组里绝大多数格子是 0，真正有值的只有 $2q$ 个端点。既然如此就不要开数组了，直接把这 $2q$ 个点排序后扫一遍——**这就是扫描线，本质是差分的稀疏版**。
>
> 排序的一个隐藏细节：把事件写成 `(时刻, +1)` 与 `(时刻, -1)`，元组默认排序会让**同一时刻的 `-1` 排在 `+1` 前面**（因为 $-1 < 1$）。这正好等于「先下车再上车」，对应「区间端点接触不算冲突」的题意（会议室 II 就是这样）。若题意要求接触也算冲突，就把 `-1` 改成 `(时刻, 2)` 之类的键强行排到后面。

> [!success]- 代码实现
>
> ```python
> def max_overlap(intervals: List[List[int]]) -> int:
>     events = []
>     for s, e in intervals:
>         events.append((s, 1))
>         events.append((e, -1))
>     events.sort()                       # 同一时刻 -1 在前：先结束再开始
>     cur = ans = 0
>     for _, v in events:
>         cur += v
>         ans = max(ans, cur)
>     return ans
> ```
>
> - 复杂度：$O(q\log q)$，代价全在排序，与值域无关。
> - 这条路和 [[11.0 区间问题 排序、合并与不相交子集]] 是同一族题的两种视角：**11.0 排的是区间，这里排的是端点**。问「合并成几段」排区间，问「同一时刻重叠几个」排端点。

### 变体四：304. 二维区域和检索（二维前缀和）

给定不变的矩阵，多次查询子矩阵 `(r1, c1)` 到 `(r2, c2)` 的和。

一维的「两点作差」升到二维就是「四角容斥」：

![](assets/8.2%20二维前缀和%20容斥.svg)

> [!tip]- 核心思路：建表和查询是同一个容斥，方向相反
>
> 定义 `S[i][j]` 为左上角 $i \times j$ 那块矩形的和（**1-indexed，多开一圈全 0 的哨兵**）。
>
> **建表**——横条加竖条会把左上角重复算一次：
>
> $$S[i][j] = S[i-1][j] + S[i][j-1] - S[i-1][j-1] + a[i-1][j-1]$$
>
> **查询**——整块减去上条、左条，左上角被减了两次要补回来：
>
> $$\text{sum} = S[r_2+1][c_2+1] - S[r_1][c_2+1] - S[r_2+1][c_1] + S[r_1][c_1]$$
>
> **为什么必须多开一圈**：建表时 `i-1`、`j-1` 会取到 $-1$，查询时 `r1` 可以是 0。多开一圈 0 之后，这些越界访问全部落在合法的 0 上，两个公式一个 `if` 都不用写——和 [[8.0 前缀和与哈希]] 里 `s[0] = 0` 的哨兵是同一个手法。

> [!success]- 代码实现
>
> ```python
> class NumMatrix:
>     def __init__(self, matrix: List[List[int]]):
>         m, n = len(matrix), len(matrix[0])
>         self.s = [[0] * (n + 1) for _ in range(m + 1)]
>         for i, row in enumerate(matrix):
>             for j, x in enumerate(row):
>                 self.s[i + 1][j + 1] = (self.s[i][j + 1] + self.s[i + 1][j]
>                                         - self.s[i][j] + x)
>
>     def sumRegion(self, r1: int, c1: int, r2: int, c2: int) -> int:
>         s = self.s
>         return s[r2 + 1][c2 + 1] - s[r1][c2 + 1] - s[r2 + 1][c1] + s[r1][c1]
> ```
>
> - 主流程：构造时 $O(mn)$ 建表，之后每次查询 $O(1)$。
> - 易错位置：四个下标的 `+1` 与不 `+1`。记法：**减号项的那一维取「边界本身」，加号项取「边界 +1」**。

### 变体五：二维差分（2132 用邮票贴满网格图）

给子矩阵整体加值，是一维差分的直接推广——端点从 2 个变成 **4 个角**：

```python
d[r1][c1]         += v
d[r1][c2 + 1]     -= v
d[r2 + 1][c1]     -= v
d[r2 + 1][c2 + 1] += v
```

还原时做两遍前缀和（先按行、再按列，或反过来）。加减号的分布和二维前缀和查询公式完全一致——**因为它们本来就是同一个容斥**。

## 易错点

> [!warning]- 易错点
>
> **1. 减号打在 `r` 还是 `r+1`**
> 全篇最高频的错。判据只有一条：**`r` 自己要不要享受这次修改**。要（闭区间）就打 `r+1`，不要（开区间，如 1094 的下车站）就打 `r`。
>
> **2. 差分数组只开 `n` 长**
> `r` 取到 `n-1` 时要写 `d[n]`，越界。Python 下标 `-1` 不报错，会静默写到最后一格，答案错得毫无征兆——和 [[7.10 DP 补漏 网格路径与两类特殊状态]] 里的负下标坑同源。
>
> **3. 题目 1-indexed 忘了换算**
> 1109 是典型：`first` 要减 1，`last` 不减。两个偏移不一致，凭直觉写必错。
>
> **4. 二维前缀和忘了多开一圈**
> 于是被迫写四个 `if` 判边界，写着写着就漏一种情况。多开一圈是**成本最低的除错手段**。
>
> **5. 二维查询的四项符号记反**
> 记「整块 − 上条 − 左条 + 左上角」，加号永远只有两项：整块和左上角。
>
> **6. 用扫描线时同一时刻的排序**
> `(t, +1)` 与 `(t, -1)` 谁在前，直接决定「端点接触算不算重叠」。默认排序是 `-1` 在前（先结束后开始），恰好对应「不算重叠」。题意相反时必须手动指定排序键。

## 复杂度

> [!summary]- 复杂度
>
> | 场景 | 朴素 | 本篇 | 差在哪 |
> | --- | --- | --- | --- |
> | $q$ 次区间加 + 一次全查 | $O(nq)$ | $O(n + q)$ | 每次修改从 $O(n)$ 压成 $O(1)$ |
> | 值域巨大的区间加 | 开不出数组 | $O(q\log q)$ | 扫描线，排序主导，与值域无关 |
> | 建二维前缀和 | — | $O(mn)$ 时间 / $O(mn)$ 空间 | 每格算一次 |
> | 单次子矩阵查询 | $O(mn)$ | $O(1)$ | 四次查表 |
>
> 差分和前缀和的空间都是 $O(n)$（二维 $O(mn)$）；1094 那种「边还原边判断」的写法可以把还原阶段的额外空间降到 $O(1)$。

## 一句话总结

**前缀和把「区间查询」压成两点作差，差分把「区间修改」压成两点打点**——两者互为逆运算；升到二维后，两点变四角，公式仍是同一个容斥。

## 模板归纳

**触发信号**：

- 出现「对区间 `[l, r]` 全部加上 v」且这样的操作有很多次 $\to$ **差分**
- 出现「同一时刻最多有几个 / 最多重叠几层」$\to$ **差分或扫描线**（看值域大小二选一）
- 出现「查询子矩阵的和」且矩阵不变 $\to$ **二维前缀和**

**三步落笔**：

1. **定区间开闭**——问自己「右端点 `r` 自己要不要被改到」，决定减号打在 `r` 还是 `r+1`。
2. **定数组长度**——一维开 `n+1`，二维开 `(m+1) × (n+1)`，多出来的那一圈是哨兵，不是浪费。
3. **定还原时机**——所有修改打完点之后**只做一次** `accumulate`；中途需要读值就说明选错工具了，该上线段树。

**值域检查**：动手前先看数据范围。值域 $\le 10^5$ 直接开数组；值域到 $10^9$ 改用扫描线（排端点）或离散化。
