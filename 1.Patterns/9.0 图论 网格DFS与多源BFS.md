# 图论入口：网格 DFS 与多源 BFS

## 解决什么问题

网格题（`grid[i][j]`）本质是**一张隐式图**：格子是点，四相邻是边。不需要建邻接表，`(i, j)` 就是节点编号。

三类问题、三种走法，**选错的代价是 $O(n)$ 变指数**：

| 问法 | 用什么 | 为什么 |
| --- | --- | --- |
| 有几个连通块 / 块多大 | **DFS 或 BFS，走过就永久标记** | 只要走遍，不关心顺序 |
| 最少几步 / 最少几分钟 | **BFS，按层扩散** | 第一次到达即最短，DFS 做不到 |
| 枚举所有路径（可重复经过） | **回溯，走完要还原** | 见 [[6.0 回溯型算法]] |

**「永久标记」和「用完还原」是本篇最重要的分水岭**，写反了就是死循环或答案错误。

## 统一模板

> [!tip]- 核心思路：网格 = 图，`visited` 的生命周期决定题型
>
> **共同骨架**
>
> ```python
> DIRS = ((-1, 0), (1, 0), (0, -1), (0, 1))   # 上下左右，写成常量避免手抖
>
> for dx, dy in DIRS:
>     x, y = i + dx, j + dy
>     if 0 <= x < m and 0 <= y < n and 可以走(x, y):
>         ...
> ```
>
> **唯一的分岔：标记什么时候撤销**
>
> | | 连通块（200、994） | 路径搜索（79） |
> | --- | --- | --- |
> | 标记语义 | 「这个格子**已经被算过**」 | 「这个格子**在当前路径上**」 |
> | 撤销 | **永不撤销** | 递归返回后**必须撤销** |
> | 复杂度 | $O(mn)$，每格进出各一次 | 指数级，靠剪枝活命 |
>
> 判据一句话：**「答案是格子的集合」就永久标记；「答案是格子的序列」就借了要还。**
>
> **DFS 还是 BFS？** 连通块两者等价（BFS 更抗爆栈：$200 \times 200$ 全陆地时递归深度 4 万，Python 默认递归限制 1000，DFS 需 `setrecursionlimit` 或改迭代）。**最短步数只能 BFS。**

## 变体一：200. 岛屿数量

`'1'` 是陆地、`'0'` 是水，求四连通岛屿的个数。

> [!tip]- 核心思路：每次「发现新陆地」就答案加一，然后把整块沉掉
>
> 外层双重循环负责**发现**，内层 DFS/BFS 负责**吞掉整块**。
> 因为一块陆地只会被它最左上的那个格子发现（其余格子在 DFS 时就被标记了），所以计数不会重复——这与 [[8.1 哈希实战 分组、连续序列与原地哈希]] 里 128 的「只从起点扩」是同一条论证。
>
> 标记方式两种：开 `visited` 数组，或**直接把 `'1'` 改成 `'0'`**（原地标记，省空间但破坏输入，面试要主动说明）。

> [!success]- 代码实现（DFS 原地标记 + BFS 备选）
>
> ```python
> class Solution:
>     def numIslands(self, grid: List[List[str]]) -> int:
>         m, n = len(grid), len(grid[0])
>
>         def dfs(i: int, j: int) -> None:
>             if not (0 <= i < m and 0 <= j < n) or grid[i][j] != '1':
>                 return
>             grid[i][j] = '0'                 # 进门就标记，且永不还原
>             dfs(i - 1, j); dfs(i + 1, j)
>             dfs(i, j - 1); dfs(i, j + 1)
>
>         ans = 0
>         for i in range(m):
>             for j in range(n):
>                 if grid[i][j] == '1':
>                     ans += 1                  # 发现一块新岛
>                     dfs(i, j)                 # 整块沉掉
>         return ans
> ```
>
> 深度不放心时改 BFS，骨架不变：
>
> ```python
> from collections import deque
>
> def bfs(i, j):
>     q = deque([(i, j)])
>     grid[i][j] = '0'                          # 入队即标记（关键）
>     while q:
>         x, y = q.popleft()
>         for dx, dy in ((-1,0),(1,0),(0,-1),(0,1)):
>             a, b = x + dx, y + dy
>             if 0 <= a < m and 0 <= b < n and grid[a][b] == '1':
>                 grid[a][b] = '0'
>                 q.append((a, b))
> ```
>
> **主流程**：扫描发现 $\to$ 计数 $\to$ 吞掉整块。
> **关键不变量**：外层循环遇到 `'1'` 时，它一定属于一个**尚未统计过**的岛。
> **易错位置**：BFS 必须**入队时标记**，不能出队时才标记（见易错点 2）。

## 变体二：994. 腐烂的橘子

每分钟腐烂橘子会传染四邻的新鲜橘子，问几分钟后全部腐烂，不可能则返回 `-1`。

> [!tip]- 核心思路：多源 BFS —— 把所有起点一次性放进第 0 层
>
> 直觉「对每个烂橘子各跑一次 BFS 取最小」是错的方向（也慢）。正解是**把所有初始烂橘子同时入队**，此后就是普通 BFS。
>
> **为什么合法**：等价于虚构一个超级源点 $S$，向每个烂橘子连一条 0 权边。从 $S$ 出发的 BFS 层号，正好等于「到最近烂橘子的距离」——而这就是每个新鲜橘子实际腐烂的时刻。
>
> **「一层 = 一分钟」靠什么保证**：`for _ in range(len(q))` 一次性弹完当前层，与 [[5.4 层序遍历]] 完全同构。写成边弹边算会把不同分钟混在一起。
>
> **返回 -1 的判定**：BFS 结束后仍有 `fresh > 0`，说明那部分与任何烂橘子不连通。所以要**全程维护新鲜橘子计数**，而不是最后再扫一遍（扫一遍也对，但计数写法更顺）。

> [!example]- 示例推演：`[[2,1,1],[1,1,0],[0,1,1]]`
>
> ```text
> 初始 q = [(0,0)]          fresh = 6   t = 0
>
> 第 1 层：弹 (0,0) -> (0,1),(1,0) 腐烂    fresh = 4   t = 1
> 第 2 层：弹 2 个  -> (0,2),(1,1) 腐烂    fresh = 2   t = 2
> 第 3 层：弹 2 个  -> (2,1) 腐烂          fresh = 1   t = 3
> 第 4 层：弹 1 个  -> (2,2) 腐烂          fresh = 0   t = 4
> 队空，fresh == 0 -> 答案 4
> ```
>
> 注意 `t` 只在「这一层确实腐烂了新东西」之后才加，否则最后会多算一分钟。

> [!success]- 代码实现
>
> ```python
> from collections import deque
>
> class Solution:
>     def orangesRotting(self, grid: List[List[int]]) -> int:
>         m, n = len(grid), len(grid[0])
>         q = deque()
>         fresh = 0
>         for i in range(m):
>             for j in range(n):
>                 if grid[i][j] == 2:
>                     q.append((i, j))        # 所有源点一次性入队
>                 elif grid[i][j] == 1:
>                     fresh += 1
>
>         t = 0
>         while q and fresh:                   # fresh == 0 时立刻停，避免多加一分钟
>             t += 1
>             for _ in range(len(q)):          # 严格按层出队 = 一层一分钟
>                 x, y = q.popleft()
>                 for dx, dy in ((-1,0),(1,0),(0,-1),(0,1)):
>                     a, b = x + dx, y + dy
>                     if 0 <= a < m and 0 <= b < n and grid[a][b] == 1:
>                         grid[a][b] = 2       # 入队即标记
>                         fresh -= 1
>                         q.append((a, b))
>         return -1 if fresh else t
> ```
>
> **关键变量**：`fresh` 既是终止条件也是「是否有解」的判据。
> **易错位置**：`while q and fresh` 中的 `fresh` 不能省——只写 `while q` 会在最后一层空转一次，答案多 1。

## 变体三：79. 单词搜索（网格上的回溯）

> [!tip]- 核心思路：从「找连通块」跨到「找路径」，标记必须还原
>
> 79 要找的是**一条按顺序匹配单词的路径**，同一格子在**不同路径**里可以重复使用，只是在**同一条路径**里不能。所以 `visited` 的语义变成「在当前路径上」，递归返回后必须撤销——这就是 [[6.0 回溯型算法]] 的借还平衡（另见 [[状态恢复]]）。
>
> **`dfs(i, j, k)` 的三个参数分两类**：
>
> | 参数 | 含义 | 是什么 |
> | --- | --- | --- |
> | `i, j` | 现在站在棋盘的哪一格 | **空间位置** |
> | `k` | 正在匹配 `word` 的第几个字符 | **匹配进度**，也就是递归深度 |
>
> 所以 `dfs(i, j, k)` 读作「**站在 `(i, j)`，试图用这一格匹配 `word[k]`**」。往四周走时传 `k + 1`，意思是「这一格对上了，下一格去配下一个字符」。
>
> `k` 就是 [[6.3 排列型回溯]] 里 `dfs(i)` 的那个 `i`——「填到第几个坑」换成「配到第几个字符」，同一个东西。200 / 994 只需要 `(i, j)`，因为答案是格子的**集合**，无所谓顺序；79 多出 `k`，正是因为答案是格子的**序列**，状态必须记住「已经走到单词的哪一步」。
>
> 收尾条件写 `k == len(word) - 1` 而不是 `len(word)`：判断发生在**当前格已经匹配上 `word[k]` 之后**，所以 `k` 指到最后一个字符就说明整个单词配完了，不用再多走一步。
>
> ```python
> DIRS = ((-1, 0), (1, 0), (0, -1), (0, 1))     # 与本篇统一模板同一个常量
>
> class Solution:
>     def exist(self, board: List[List[str]], word: str) -> bool:
>         m, n = len(board), len(board[0])       # 提到 dfs 外，别在每次递归里重算
>
>         def dfs(i: int, j: int, k: int) -> bool:
>             if board[i][j] != word[k]:         # 失配（被标记过的格子也会在这里失配）
>                 return False
>             if k == len(word) - 1:             # 最后一个字符也对上了
>                 return True
>             board[i][j] = ''                   # 借：就地标记「在当前路径上」
>             for dx, dy in DIRS:
>                 x, y = i + dx, j + dy
>                 if 0 <= x < m and 0 <= y < n and dfs(x, y, k + 1):
>                     return True                # 任一方向搜到就直接收工
>             board[i][j] = word[k]              # 还：还原成原字符
>             return False
>
>         return any(dfs(i, j, 0) for i in range(m) for j in range(n))
> ```
>
> **三个细节**
> 1. **用 `''` 当标记，不要用 `'#'`**。空串永远不等于任何单个字符，所以「已在路径上」天然失配；换成 `'#'` 就得额外担保这个字符不出现在 `word` 里，多一条心智负担。
> 2. 还原时写 `board[i][j] = word[k]`，因为能走到这里必然说明这一格等于 `word[k]`；不放心就用临时变量存原值。
> 3. `m, n` 必须提到 `dfs` 外面。写成 `len(board)` / `len(board[0])` 放在递归入口，每个结点都要多算两次长度——这是本题最常见的白给开销。

> [!tip]- 拆开看 `board[i][j] = word[k]`：为什么要还原，以及为什么还原成 `word[k]`
>
> **① 为什么要还原**
>
> 关键在标记的**语义**：`board[i][j] = ''` 的意思是「这一格**在我当前这条路径上**」，不是「这一格来过」。
>
> 对比变体一 200：那里把 `'1'` 改成 `'0'` 后**永不还原**，因为答案是格子的**集合**——一个格子归到某座岛就永远归它了，别的路径不需要它。而 79 的答案是**路径**：同一个格子可以出现在很多条候选路径里，只是不能在同一条里走两次。所以路径走完（无论成败）就得把这一格**交还给其他路径**。
>
> **不还原会怎样**——一个最小反例：
>
> ```text
> board = [["A","A","A","B"]]      word = "AAB"      正确答案 True，唯一路径 (0,1)→(0,2)→(0,3)
> ```
>
> ```text
> 不还原：
>   起点(0,0) 标记 → 走到(0,1) 标记 → 卡住失败      此时棋盘剩 "__AB"
>   起点(0,1)：这一格还是 ''，连第一道 if 都过不了 ✗
>   起点(0,2)：标记后邻居 (0,3)='B'，但此刻要配的是 word[1]='A' ✗
>   → 返回 False（错）
>
> 还原：
>   起点(0,0) 失败后棋盘复原成 "AAAB"
>   起点(0,1) → (0,2) → (0,3)='B' ✓ 返回 True
> ```
>
> 第一次探索只是**试错**，试完必须把现场恢复原样，否则后面的起点会踩在上一次的残留上——这就是 [[6.0 回溯型算法]] 说的「借了要还」，另见 [[状态恢复]]。
>
> **② 为什么还原成 `word[k]` 而不是别的**
>
> 因为函数第一行就是：
>
> ```python
> if board[i][j] != word[k]:
>     return False
> ```
>
> 能往下执行到标记那一行，**必然说明 `board[i][j]` 原本就等于 `word[k]`**。所以 `word[k]` 就是这一格的原字符，直接写回去即可，不用额外变量。
>
> 觉得这个推理绕，用临时变量也完全等价，而且改代码时不容易出错：
>
> ```python
> tmp = board[i][j]        # 存原字符
> board[i][j] = ''
> ...
> board[i][j] = tmp        # 原样放回
> ```

> [!tip]- 边界检查放调用方还是被调用方：两种写法都对，选和模板一致的那个
>
> 越界判断有两个放法，功能等价：
>
> | | 写法 | 特点 |
> | --- | --- | --- |
> | **调用方拦截** | `if 0 <= x < m and 0 <= y < n and dfs(x, y, k+1)` | 和本篇 200 / 994 的统一模板**逐字一致**；越界连函数调用都不发生 |
> | **被调用方拦截** | `dfs` 入口写 `if not (0 <= i < m and ...) or board[i][j] != word[k]` | 所有非法情况一道 `if` 全挡住，只需记一处 |
>
> 推荐**调用方拦截 + `for dx, dy in DIRS`**，理由不是性能而是**复用**：200、994、79 共用同一副骨架，换题时只改「可以走(x, y)」那半句。手写四次 `dfs(i-1,j,...) or dfs(i+1,j,...) or ...` 在四方向时还行，一旦要八方向或对角线就得重写四行。
>
> 如果写成循环，**方向元组一定要提成模块级常量**。写成 `for x, y in (i, j-1), (i, j+1), (i-1, j), (i+1, j)` 每次递归都要现场构造 5 个元组：$6\times6$ 全 `A` 的最坏用例下实测 1.88 s，提成 `DIRS` 常量后 1.36 s，**白省 27%**。四次展开写法 1.10 s 最快，但差距在下面这条剪枝面前完全不值一提。

> [!warning]- 真正决定生死的是剪枝，不是上面那些写法差异
>
> 79 的经典 TLE 用例是「棋盘全是同一个字母、单词最后一位失配」，比如 $6\times6$ 全 `A` 配 `word = "AAAAAAAAAAAAAAB"`。三种写法都在 **1.1 ~ 1.9 s** 徘徊，谁也救不了谁。
>
> 加两条预处理，同一个用例掉到 **0.0006 s**——快三个数量级：
>
> ```python
> from collections import Counter
>
> cnt = Counter(c for row in board for c in row)
> if cnt & Counter(word) != Counter(word):      # 棋盘根本凑不齐 word 的字符
>     return False
> if cnt[word[-1]] < cnt[word[0]]:              # 末字符更稀有 ⇒ 倒着搜，起点更少
>     word = word[::-1]
> ```
>
> - 第一条是**可行性剪枝**：多重集包含判断，语义见 [[Python_dict]] 的「Counter 的比较运算」。
> - 第二条是**起点选择**：`any(dfs(i, j, 0) ...)` 会从每个等于 `word[0]` 的格子起手，`word[0]` 越稀有，起手点越少。反转单词不改变答案（路径反过来还是一条合法路径）。
>
> 面试里能主动说出第二条，比把四个方向写对更值钱——它体现的是「**先想清楚哪一端搜索空间小**」，和 [[3.1 二分答案]] 里挑判定方向、[[8.1 哈希实战 分组、连续序列与原地哈希]] 里 128「只从序列起点扩」是同一种思维。

## 易错点

> [!warning]- 易错点汇总
>
> **1. 该永久标记的地方做了还原**
> 200 里如果 DFS 结束把 `'0'` 改回 `'1'`，同一块岛会被反复统计并**无限递归**。
> 判据回顾：答案是格子**集合** $\to$ 不还原；答案是格子**序列** $\to$ 还原。
>
> **2. BFS 出队时才标记**
> 同一个格子可能被多个邻居同时推进队列，出队时才标记会导致**重复入队**，最坏指数爆炸。
> 铁律：**入队即标记**（BFS 的 `visited` 表示「已被安排」，不是「已被处理」）。
>
> **3. 994 的分钟数多 1**
> 忘记 `fresh` 终止条件，最后一层没有新腐烂却仍 `t += 1`。
> 验证用例：一行两格、一个空地一个烂橘子，没有新鲜橘子，答案是 0 而不是 1。
>
> **4. 994 全是空地**
> `grid` 无新鲜橘子时答案是 `0` 不是 `-1`。`fresh == 0` 初始即成立，代码天然返回 `t = 0`。
>
> **5. 用 DFS 求最短步数**
> DFS 第一次到达终点的路径不是最短；要正确必须遍历所有路径，指数级。
> **「最少步数 / 最短时间」永远先想 BFS。**
>
> **6. 递归深度爆栈**
> $200 \times 200$ 全陆地时 DFS 深度可达 40000。Python 默认限制 1000，需 `sys.setrecursionlimit(250000)` 或直接用 BFS。面试主动提这一点是加分项。
>
> **7. 79 的方向元组写在循环里**
> `for x, y in (i, j-1), (i, j+1), (i-1, j), (i+1, j)` 每次递归现场构造 5 个元组，实测比提成 `DIRS` 常量慢 27%。方向是常量，就该放在函数外面。
>
> **8. 边界判断顺序**
> `if 0 <= x < m and 0 <= y < n and grid[x][y] == 1` —— 越界检查必须**写在取值之前**，Python 里 `grid[-1]` 不报错而是取到最后一行，会静默出错。

## 复杂度

> [!summary]- 复杂度
>
> - **200 / 994**：时间 $O(mn)$ —— 每个格子最多入队/递归一次，每次看 4 个方向；空间 $O(mn)$ —— 最坏情况队列或递归栈装下所有格子。
> - **79**：时间 $O(mn \cdot 3^L)$（$L$ 为单词长度）—— 每个起点出发，除来路外每步 3 个方向；空间 $O(L)$ 递归栈（原地标记不额外开数组）。这个上界是**紧的**：全同字符的棋盘能把它跑满，所以 79 的实战关键在剪枝而非常数优化（见变体三）。
> - 多源 BFS 相比「每个源点各跑一次」的 $O(k \cdot mn)$，直接降到 $O(mn)$，这是本篇最大的性能点。

## 一句话总结

网格就是图，四个方向就是边；**连通块用「永久标记」的 DFS/BFS，最短时间用「按层出队」的多源 BFS，找路径用「借了要还」的回溯**——三者代码骨架相同，只差 `visited` 活多久。

## 模板归纳

**触发信号 $\to$ 条件反射**

- 二维 `grid` + 「有几个 / 面积多大」$\to$ 遍历发现 + DFS 吞块，**永久标记**
- 「最少几步 / 几分钟 / 最短距离」+ 边权都是 1 $\to$ **BFS 按层**，绝不用 DFS
- 有**多个起点同时扩散** $\to$ 多源 BFS，起点全部入初始队列
- 「是否存在一条路径 / 列出所有路径」$\to$ 回溯，**标记用完要还**

**落笔四步**

1. 写死方向常量 `DIRS`，别在循环里手写四份。
2. 定 `visited` 的语义：**已算过**（不还原）还是**在路径上**（要还原）。
3. BFS 一律**入队即标记**；要分层就 `for _ in range(len(q))`。
4. 收尾检查「还有没有没访问到的」——它往往就是 `-1` / 不连通的判据。
