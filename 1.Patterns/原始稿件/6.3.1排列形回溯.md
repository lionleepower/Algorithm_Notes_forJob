```python
class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        ans = []
        path = [0] * n
        def dfs(i, s):
            if i == n:
                ans.append(path.copy())
                return
            for x in s:
                path[i] = x
                dfs(i+1, s-{x})
        dfs(0,set(nums))
        return ans
```
### 整体框架

排列问题的本质是：**有 n 个坑位，依次决定每个坑填谁**。

```
dfs(i, s) 的含义：
  前 i 个坑已经填好了
  s 是还没被用过的数字
  任务：把第 i 个坑到最后一个坑填完
```

所以 `i` 是"填到哪儿了"，`s` 是"还剩什么可用"。递归到 `i == n` 说明坑填满了，收下一个答案。
### set 在这里干什么

`s` 就是**候选池**。排列的约束是"每个数只能用一次"，用集合表示"还没用过的数"最自然：

python

```python
for x in s:          # 枚举第 i 个坑的所有可能填法
    path[i] = x
    dfs(i+1, s-{x})  # 这个数用掉了，从候选池里去掉
```

关键在 `s - {x}` 这个**集合差集**运算。它不修改 `s`，而是**新建一个集合**返回：

python

```python
s = {1, 2, 3}
t = s - {2}   # t 是新集合 {1, 3}
print(s)      # s 仍然是 {1, 2, 3}，没变
```

对比会修改原集合的写法：

python

```python
s.remove(2)   # 就地修改，s 变成 {1, 3}，原来的没了
```

这就是这段代码不需要"恢复现场"的原因——**每一层拿到的是自己的一份副本，从来没动过上一层的东西**。上一层的 `s` 完好无损，for 循环下一轮自然还是完整的候选池。

> 类比：不用 `remove/add` 的"借了要还"，而是每次**复印一份名单，在复印件上划掉一个名字**再交给下一层。原件永远干净。

### 那 path 为什么也不用恢复？

`path` 是真正共享的可变对象，从头到尾只有一个。它没有 pop，却依然正确——原因和上面不同：

**第 i 层只写 `path[i]` 这一格，而且一定先写后递归。**

所以当 `i == n` 时，`path[0..n-1]` 全都被本条路径上的第 0 层到第 n-1 层刚刚写过了。上一条路径留下的旧值不可能残留——**任何一格在被读到之前，必然已经被当前路径覆盖**。这就是这个写法的不变量。

而 append/pop 版本的 `path` 长度是变化的，pop 才能让长度回到正确状态；这里长度恒为 `n`，靠"下标定位 + 无条件覆盖"就够了。两种写法的不变量不同，但目的一样：**保证每层看到的状态是干净的**。

### 一个小推演

`nums = [1, 2, 3]`：

```
dfs(0, {1,2,3})
 └ x=1: path=[1,_,_]  dfs(1, {2,3})
    ├ x=2: path=[1,2,_]  dfs(2, {3})
    │   └ x=3: path=[1,2,3]  dfs(3,{}) -> 收 [1,2,3]
    └ x=3: path=[1,3,_]  dfs(2, {2})
        └ x=2: path=[1,3,2]  -> 收 [1,3,2]
```

注意回到 `dfs(1,·)` 的第二轮时，它手上的 `s` 依然是 `{2,3}`——因为从没被改过。

### set() 是什么

`set` 是 Python 的**集合**类型，两个核心特性：**元素不重复**、**查找是 O(1)O(1) O(1)**。

python

```python
s = set()          # 空集合（注意：{} 是空字典，不是空集合）
s.add(3)           # 加入元素
s.add(3)           # 重复加入，集合不变
3 in s             # True，O(1) 判断存在性
s.remove(3)        # 删除（元素不存在会报错）
s.discard(3)       # 删除（元素不存在也不报错）
len(s)             # 元素个数

set([1, 2, 2, 3])  # 从 list 建集合 => {1, 2, 3}，顺便去重
```

### 为什么快：底层是 Hash

`set` 和 `dict` 底层都是哈希表。判断 `x in s` 时，不是逐个遍历比较，而是对 `x` 算一次 hash 直接定位。对比：

python

```python
x in my_list   # O(n)，逐个扫
x in my_set    # O(1)，hash 定位
```

这就是为什么算法题里"记录见过的元素"几乎总用 `set` 而不用 `list`。

### 在你熟悉的题里的位置

- **环形链表**（哈希解法）：用 `visited = set()` 记录走过的节点，再次遇到说明有环——对应你笔记里快慢指针的替代方案，代价是 O(n)O(n) O(n) 空间。
- **滑动窗口**：维护"窗口内是否存在某元素"，比如无重复字符最长子串。
- **去重**：`set(nums)` 一步去重，但注意会**丢失顺序**。

一个常见坑：`set` 里只能放**可哈希（不可变）**的东西——数字、字符串、tuple 可以，`list` 不行：

python

```python
s.add([1, 2])        # TypeError: unhashable type
s.add((1, 2))        # OK，用 tuple 代替
```

也可以考虑使用布尔数组：

```python
class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        ans = []
        path = [0] * n
        on_path = [False] * n
        def dfs(i):
            if i == n:
                ans.append(path.copy())
                return
            for j in range(n):
                if not on_path[j]:
                    path[i] = nums[j]
                    on_path[j] = True
                    dfs(i+1)
                    on_path[j] = False
        dfs(0)
        return ans
```
这是全排列的**经典写法**，也是面试里更常见的一版。它和 set 版是同一棵递归树，只是"记录谁被用过"的方式换了。
### 两版的对应关系

```
set 版：  s          = 还没用的数字（值的集合）
布尔版：  on_path[j] = 下标 j 的数字是否已被用
```

for 循环的方向也随之翻转：

python

```python
for x in s:                   # set 版：直接遍历候选池
for j in range(n):            # 布尔版：遍历所有下标，用 if 过滤掉不可用的
    if not on_path[j]:
```

set 版是"池子里只剩合法的"，布尔版是"全都看一遍，跳过非法的"。结果等价，但布尔版**没有新建集合的开销**——这是它的主要优势。

### 关键：为什么 on_path 必须恢复，path 却不用

这是这段代码最值得琢磨的一点，两个数组待遇完全不同：

python

```python
path[i] = nums[j]
on_path[j] = True
dfs(i+1)
on_path[j] = False    # 只还这一个
```

区别在于**下标的含义**：

||下标是什么|会不会撞车|
|---|---|---|
|`path[i]`|`i` = 递归深度|不会。每层独占一格|
|`on_path[j]`|`j` = 数字在 nums 中的位置|会。所有层共用同一张表|

`path[i]` 的 `i` 就是当前层号，第 3 层永远只碰 `path[3]`，兄弟分支之间不会互相污染，而且下次进来一定会先覆盖再用——所以不需要还。

`on_path` 则是**整棵树共享的一张占用表**。第 1 层把 `on_path[0]` 设成 True，是在告诉底下所有子孙"0 号被我占了"。子树探索完毕，这个占用必须撤销，否则 for 循环的下一轮兄弟分支会误以为 0 号仍被占用——它就永远用不到那个数字了。

> 你之前总结过的"借了要还"在这里依然成立，只是**还的对象是 `on_path`，不是 `path`**。判断标准不是"哪个变量是共享的"，而是"哪个变量的状态会被兄弟分支读到"。

### 易错点

**1. 忘记 `on_path[j] = False`**

最高频错误。后果不是崩溃，而是**答案严重变少**——每个数字全局只会被用一次，最后只能得到 1 个排列（甚至 0 个）。

**2. 恢复写在 `if` 外面**

python

```python
for j in range(n):
    if not on_path[j]:
        ...
        dfs(i+1)
    on_path[j] = False    # 错：把别人占的位也给清了
```

必须严格包在 if 内部，跟 `= True` 配对。**谁占的谁还**。

**3. `path[i] = j` 写成下标而不是值**

要填的是 `nums[j]`。`on_path` 记的是下标，`path` 存的是值，两者别混。

**4. `ans.append(path)` 忘记 copy**

老朋友了，同 set 版。

**5. 循环变量写成 `for j in range(i, n)`**

排列不是组合，每层都要从 0 开始扫全部下标——后面的数可以排在前面。写成 `range(i, n)` 就变成子集/组合了。

### 复杂度对比

||时间|空间（不含答案）|
|---|---|---|
|set 版|O(n2⋅n!)O(n^2 \cdot n!) O(n2⋅n!)|O(n2)O(n^2) O(n2)|
|布尔版|O(n⋅n!)O(n \cdot n!) O(n⋅n!)|O(n)O(n) O(n)|

布尔版每层是 O(n)O(n) O(n) 的扫描但**不复制任何东西**，栈上只有 nn n 个整数帧；set 版每层要新建一个 O(n)O(n) O(n) 集合，深度 nn n 层就挂了 O(n2)O(n^2) O(n2) 的集合。

面试建议：**写布尔版，提一句 set 版更直观**。

排列 = 逐位填坑 + 一张全局占用表；`path` 靠"深度定位、无条件覆盖"自动保持干净，`on_path` 靠"谁占谁还"手动维持不变量。

```python
class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        ans = []
        col = [0] * n

        def valid(r, c):
            for R in range(r):
                C = col[R]
                if r + c == R + C or r - c == R - C:
                    return False
            return True

        def dfs(r, s):
            if r == n:
                ans.append(['.' * c + 'Q' + '.' * (n - 1 - c) for c in col])
                return
            for c in s:
                if valid(r, c):
                    col[r] = c
                    dfs(r + 1, s - {c})

        dfs(0, set(range(n)))
        return ans

```

### 第一步：先别想算法，先想"怎么表示一个棋盘"

最朴素的表示是一个 n×nn \times n n×n 的二维数组，`board[r][c]` 表示这格有没有皇后。

但你一旦这么写，就得自己维护"每行只能有一个皇后"这件事——因为这个数据结构**允许**你在一行里塞三个皇后，它不阻止你。所有非法状态它都能表示出来。

现在换个表示：

python

```python
col = [0] * n     # col[r] = 第 r 行的皇后放在第几列
```

这个数组**根本没有能力**表示"第 2 行有两个皇后"——因为 `col[2]` 只能存一个数。

> 这是设计上最重要的一步：**把约束编码进数据结构，而不是编码进检查逻辑**。
> 
> 类比：你想保证"每人只有一个座位号"。二维表示法是发一张大表格，然后写规则说"每人只能勾一格"，还得派人巡查。一维表示法是直接给每人发一张卡，卡上只能填一个数字——违规在物理上就不可能发生。

代价是每行必须**恰好**有一个皇后（不能是零个）。但 n 皇后要放 n 个、共 n 行，鸽笼原理告诉你每行必然正好一个。所以这个表示法没有丢掉任何合法解——**它排除的全是非法状态**。

**第一个约束，用完了，不需要任何代码。**

---

### 第二步：列约束一进来，问题就变成了排列

`col` 是长度 n 的数组，每个元素取值 0…n−10 \ldots n-1 0…n−1。加上"每列也只能有一个皇后"：

col[r1]≠col[r2]当r1≠r2col[r_1] \ne col[r_2] \quad \text{当} \quad r_1 \ne r_2col[r1​]=col[r2​]当r1​=r2​

n 个位置、n 个取值、两两不同 —— 这就是 `col` 是 0…n−10 \ldots n-1 0…n−1 的一个**排列**。

所以：

```
n 皇后的解  ⊂  0..n-1 的全排列
```

搜索空间从 nnn^{n} nn（每行独立选列）掉到 n!n! n!，而且**你已经会枚举全排列了**。这就是为什么你的代码看起来跟 permute 一模一样：

python

```python
dfs(r, s)          # permute 是 dfs(i, s)
col[r] = c         # permute 是 path[i] = x
dfs(r+1, s - {c})  # permute 是 dfs(i+1, s - {x})
```

**它就是 permute，只是在中间插了一道过滤。**

> 类比：n 皇后不是"在棋盘上摆棋子"，而是"给 n 个人排座位，每人一个不同的号码"——摆棋子的画面是误导性的，排列才是它的真身。

第二个约束交给 `s - {c}`：候选池里删掉用过的列。

---

### 第三步：对角线为什么是加减法

前两个约束是"免费"的，只有对角线需要真的检查。但怎么检查？

笨办法是从 `(r, c)` 沿四个斜方向一格格走出去看有没有皇后。能work，但太慢也太啰嗦。

关键观察：**同一条对角线上的格子，坐标满足一个恒等式**。

沿 ↘ 方向走一步，行 +1、列 +1，所以 `r - c` 不变：

```
        c=0   c=1   c=2   c=3
r=0      0    -1    -2    -3
r=1      1     0    -1    -2
r=2      2     1     0    -1
r=3      3     2     1     0
```

表里每一条 ↘ 斜线上的数字都相同。`r - c` 就是这条对角线的**身份证号**。

沿 ↙ 方向走一步，行 +1、列 -1，所以 `r + c` 不变：

```
        c=0   c=1   c=2   c=3
r=0      0     1     2     3
r=1      1     2     3     4
r=2      2     3     4     5
r=3      3     4     5     6
```

同理，`r + c` 是 ↙ 对角线的身份证号。

于是"两个皇后在同一对角线上"这个**几何**问题，变成了两个数字相等这个**代数**问题：

python

```python
if r + c == R + C or r - c == R - C:
    return False
```

> 类比：判断两个人是不是住同一栋楼，不用挨家挨户敲门找路，直接比对门牌号的前缀。`r+c` 和 `r-c` 就是格子的两个"楼号"。

顺带一提：你写的 `r-c == R-C` 移项后是 `r-R == c-C`，`r+c == R+C` 移项后是 `r-R == C-c`，合起来就是常见的另一种写法 `abs(r-R) == abs(c-C)`（行差等于列差）。两者完全等价，你的写法更直接。

---

### 第四步：为什么按行推进，而不是"随便找个空位放"

`dfs(r)` 一层管一行，r 从 0 到 n-1。为什么不能想放哪放哪？

因为**决策顺序如果不固定，同一个解会被数出很多遍**。先放 (0,1) 再放 (1,3)，和先放 (1,3) 再放 (0,1)，得到的是同一个棋盘。

固定"第 r 层只决定第 r 行"，就强制了一个**规范顺序**：每个解在递归树里对应唯一一条路径。去重不是靠事后过滤，而是靠**决策顺序的规范化**从源头杜绝。

这跟你之前 subsets 里"第 i 层只决定第 i 个元素选不选"是同一个道理。

---

### 第五步：三个约束的分工

现在回头看，整个设计的骨架是：

|约束|由谁保证|代价|
|---|---|---|
|每行一个|数据结构 `col` 的形状|零代码|
|每列一个|候选池 `s - {c}`|零额外检查|
|对角线|`valid()` 显式检查|O(r)O(r) O(r)|

三个约束，两个被"设计掉"了，只剩一个需要真检查。**好的搜索算法，一大半功夫花在让约束自动满足上，而不是花在检查上。**

---

### 第六步：`valid` 的不变量

现在再看那个缩进 bug，就清楚它错在哪个层面了。

`valid(r, c)` 想回答的问题是：

> 我准备把皇后放在 `(r, c)`。**已经放好的第 0 到 r-1 行**里，有没有谁跟它同对角线？

注意 `col[0..r-1]` 此刻是有效数据，`col[r..n-1]` 是上一条路径的残留垃圾——但我们只循环 `range(r)`，**永远不会读到垃圾区**。这就是这个函数能成立的不变量，和 permute 里 `path` 不用清理是同一件事。

而结论的结构是：

```
只要找到一个冲突         → 立刻否决      (return False 可以在循环内)
只有全部检查完都没冲突   → 才能通过      (return True 必须在循环外)
```

`return True` 是一个**关于全体的断言**。断言全体，就必须等全体都看完。你把它放进循环里，等于看了第一个人就宣布"全场没人反对"。

而 `r = 0` 那次调用把这个错误暴露得最彻底：一个人都没看，循环体一次没进，函数走到底返回 `None`。逻辑上第 0 行放哪都合法（前面根本没皇后），正确答案必须是 `True`——这个"空集上默认成立"的兜底值，恰恰只有循环外的 `return True` 能提供。

> 类比：`return False` 是"我看到一票反对，散会"；`return True` 是"点完名，全票通过"。没点名就宣布全票通过，是荒谬的；而一个人都没有的会议，按规则确实算全票通过。

---

### 串起来

```
表示法（col 数组）      → 行约束自动满足
候选池（s - {c}）       → 列约束自动满足  →  问题 = 全排列
代数化（r±c）           → 对角线 O(1) 判断
按行推进                → 每个解唯一路径，无需去重
valid 的全称断言        → 循环外 return True
```

一句话：**n 皇后不是"摆棋子"，是"枚举列的排列 + 用 r±c 过滤对角线冲突"。**

```python
                ans.append(['.' * c + 'Q' + '.' * (n - 1 - c) for c in col])

                return

            for c in range(n):

                if not on_path[c] and not diag1[r+c] and not diag2[r-c]:

                    col[r] = c

                    on_path[c] = diag1[r+c] = diag2[r-c] = True

                    dfs(r + 1)

                    on_path[c] = diag1[r+c] = diag2[r-c] = False

  

        dfs(0)

        return ans
```

### 顺带说一个你可能没意识到的地方：`diag2[r-c]` 为什么没越界

`r - c` 的取值范围是 −(n−1)…n−1-(n-1) \ldots n-1 −(n−1)…n−1，是**带负数**的。按理说应该写 `diag2[r - c + n - 1]` 把它平移到 0…2n−20 \ldots 2n-2 0…2n−2。

但你直接写 `diag2[r-c]`——**它居然是对的**，因为 Python 的负数下标会从尾部回绕：

```
r - c =  0        →  下标 0
r - c =  n-1      →  下标 n-1          正数占据 [0, n-1]
r - c = -1        →  下标 2n-2
r - c = -(n-1)    →  下标 n            负数占据 [n, 2n-2]
```

两段区间**恰好互不重叠、正好铺满** `m = 2n-1` 个格子。所以每条 ↘ 对角线仍然对应唯一一个槽位，没有串号。

不过这属于"碰巧成立"——它依赖 `m` 精确等于 2n−12n-1 2n−1，多一个少一个就会撞车。写显式偏移更稳妥，也更容易一眼看懂：

python

```python
diag2[r - c + n - 1]
```

### 这一版相比 `valid()` 版好在哪

||判断冲突|代价|
|---|---|---|
|`valid()` 扫描|O(r)O(r) O(r)，逐行比对|无额外空间|
|布尔数组|O(1)O(1) O(1)，查表|O(n)O(n) O(n) 空间 + 需要回溯恢复|

代价是三个数组**都是全局共享的占用表**，所以三个都必须"谁占谁还"——这和 permute 布尔版里 `on_path` 的道理完全一样。`col[r]` 依然不用还，因为它是**按深度定位、无条件覆盖**的。

你这行写得很漂亮：

python

```python
on_path[c] = diag1[r+c] = diag2[r-c] = True
...
on_path[c] = diag1[r+c] = diag2[r-c] = False
```

上下严格对称，一眼就能看出配对关系——**回溯代码最怕的就是占用和恢复不成对**，这种写法从形式上就防住了。
