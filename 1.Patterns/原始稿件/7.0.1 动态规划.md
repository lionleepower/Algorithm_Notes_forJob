```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        def dfs(i):
            if i < 0:
                return 0
            res = max(dfs(i-1), dfs(i-2)+nums[i])
            return res
        return dfs(n-1)
```
### 第一步：`dfs(i)` 的"合同"是什么

递归函数不是"一段会跑的代码"，而是一份**语义合同（contract）**：

dfs(i)=只考虑前 i+1 间房（下标 0∼i），能偷到的最大金额dfs(i) = \text{只考虑前 } i+1 \text{ 间房（下标 } 0 \sim i\text{），能偷到的最大金额}dfs(i)=只考虑前 i+1 间房（下标 0∼i），能偷到的最大金额

注意合同里写的就是"**最大**"。我们要证明的是：只要这份合同对 `i-1` 和 `i-2` 成立，它就自动对 `i` 成立——这和你在树里"信任左右子树返回正确结果"完全一样。

### 第二步：为什么 max 能兜住所有方案

想一个分堆的类比：**要找全班最高的人，可以把全班分成两组，然后取 max(第一组最高, 第二组最高)。这个结论成立的唯一前提是：每个人都被分进了某一组，没有人漏掉。**

现在看第 `i` 间房。任何一个合法的偷窃方案，对这间房**只有两种态度**，非此即彼：

- **不偷第 `i` 间** → 这个方案的收益完全来自前 `i-1` 间 → 这类方案里最好的就是 `dfs(i-1)`
- **偷第 `i` 间** → 那第 `i-1` 间必须放弃，剩余收益来自前 `i-2` 间 → 这类方案里最好的就是 `dfs(i-2) + nums[i]`

**所有可能的方案，恰好被这两类瓜分干净了**——不存在第三种态度，也没有哪个方案两类都不属于。既然分类完备，那么：

全体方案的最大值=max⁡(第一类的最大值, 第二类的最大值)\text{全体方案的最大值} = \max(\text{第一类的最大值},\ \text{第二类的最大值})全体方案的最大值=max(第一类的最大值, 第二类的最大值)

这就是那行 `max` 的全部含义。它不是"碰巧选了个大的"，而是**对一个完备分类的两个类别，各取其冠军，再决出总冠军**。

### 第三步：归纳闭环

- base case：`i < 0` 时没有房，最大收益是 0 ✓
- 归纳步：假设 `dfs(i-1)`、`dfs(i-2)` 都履行了合同（返回真最大值），由分类完备性，`dfs(i)` 也履行合同 ✓

多米诺骨牌从 base case 一路推倒上去，`dfs(n-1)` 自然是正确的最大值。你**不需要**在脑子里展开递归树验证——就像你不会展开整棵二叉树去验证 `maxDepth` 一样。

### 和你已有知识的连接

其实这行代码你早就见过它的"亲戚"：

- 它就是回溯里的"**选 or 不选**"分支——只不过回溯是把所有分支都枚举出来收集答案，DP 是每个分支只要一个数字（该类的最优值）就够了。
- 它也符合你树递归的模板：f(i)=combine(f(i−1),f(i−2))f(i) = combine(f(i-1), f(i-2)) f(i)=combine(f(i−1),f(i−2))，这里的 combine 就是 `max`。区别只是子问题从"左右子树"变成了"前缀更短的数组"。

一句话总结：**max 之所以保证最大，不是 max 本身有魔力，而是"选/不选"这个分类不重不漏地覆盖了所有方案——漏了才会错，max 只是在完备分类上取冠军。**

### 先看清楚"慢在哪"

朴素递归的问题不是"递归慢"，而是**同一个子问题被反复从头算**。

text

```text
        dfs(5)
       /      \
   dfs(4)     dfs(3)
   /    \     /    \
dfs(3) dfs(2) dfs(2) dfs(1)   ← dfs(3)、dfs(2) 重复出现
```

而且每次重复不是重复一次计算，是**重新展开整棵子树**。调用次数呈 Fibonacci 式增长，O(1.618n)O(1.618^n) O(1.618n)，指数级。

这类问题的特征叫 **overlapping subproblems（重叠子问题）**——它正是"可以用 DP"的两大信号之一。

### 为什么"缓存"是合法的

这一步是概念关键，不要跳过。

`dfs(i)` 之所以能被缓存，是因为它是一个**纯函数**：返回值**只由 `i` 决定**，与"我是从 `dfs(6)` 来的还是从 `dfs(7)` 来的"、"我前面偷了哪几间"统统无关。

这个性质有个正式名字：**无后效性**。它意味着 `i` 这个编号已经把"当前局面"完整概括了——它就是**状态（state）**。

> 便利贴类比：门牌号 `i` 上贴一张便利贴，写着"从这里往前最多能偷多少"。这张纸第一次写完就永远有效，因为它的内容和"谁来问的"无关。

这里正好能划出 **DP 与回溯的分水岭**：

||递归函数签名|答案由什么决定|能否按 `i` 缓存|
|---|---|---|---|
|回溯（子集/组合）|`dfs(i, path)`|`i` **和** `path`|不能|
|打家劫舍|`dfs(i)`|只有 `i`|能|

所以"能不能记忆化"这个问题，等价于问：**我的递归函数参数，是否已经完整刻画了状态？**

### 代码
```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        cache = [-1] * n
        def dfs(i):
            if i < 0:
                return 0
            if cache[i] != -1:
                return cache[i][]
            res = max(dfs(i-1), dfs(i-2)+nums[i])
            cache[i] = res
            return res
        return dfs(n-1)
```

当然我们平时真正使用时也可以考虑使用@cache:
```python
from functools import cache

class Solution:
    def rob(self, nums: List[int]) -> int:
        @cache                       # 自动记忆化
        def dfs(i: int) -> int:
            if i < 0:
                return 0
            return max(dfs(i - 1), dfs(i - 2) + nums[i])
        return dfs(len(nums) - 1)
```
### 顺序不能换：base case 必须在查表之前

如果写成这样：

python

```python
def dfs(i):
    if cache[i] != -1:      # ← 危险
        return cache[i]
    if i < 0:
        return 0
    ...
```

Python 里 `cache[-1]` **不会报错**，它会安静地返回列表最后一个元素。于是 `dfs(-1)` 可能返回一个已缓存的真实金额而不是 0，答案直接错，而且不抛异常、极难查。

一般原则：**base case 是"合同的边界定义"，永远排在最前；查表是"性能优化"，排在合法性检查之后。** 优化不该影响正确性。

### `-1` 作为哨兵是有前提的

它的含义是"尚未计算"，成立的唯一理由是：**真实答案永远不可能是 -1**（本题金额非负）。

如果换一道答案可能为负的题（比如某些带惩罚的路径 DP），`-1` 就会把一个合法结果误判成"没算过"，导致重复计算——甚至如果哨兵值恰好是常见答案，逻辑仍对但退化回指数级。稳妥做法是用 `None`，或另开一个 `visited` 数组。

### 一个命名上的小地雷

变量名 `cache` 和 `functools.cache` 同名。这题里没导入所以无害，但如果哪天你在同一文件里写了 `from functools import cache`，局部变量会把它遮住（shadow），后面再想用装饰器就炸了。习惯上叫 `memo` 更安全。

### 你现在拥有的两把钥匙

对照一下 `@cache` 版本，你会发现装饰器做的事和你手写的**逐字对应**：

|你写的|`@cache` 帮你做的|
|---|---|
|`cache = [-1] * n`|内部建一个 dict|
|`if cache[i] != -1: return`|以参数元组为 key 查 dict|
|`cache[i] = res`|算完写回 dict|

区别只有两点：`@cache` 用 dict 所以**不需要哨兵值**（key 在不在本身就是标记），而且参数是几维都自动支持——写 `dfs(i, j, k)` 也无需改动。代价是常数开销略大，且不能像数组那样 O(1)O(1) O(1) 随机访问。

面试里 `@cache` 写起来快，但手写这版更能证明你懂机制；C++ 里没得选，必须手写。两边你现在都通了。


### 复杂度：记住这个通用公式

时间=状态个数×单个状态的转移时间\text{时间} = \text{状态个数} \times \text{单个状态的转移时间}时间=状态个数×单个状态的转移时间

这里：状态是 `i`，共 nn n 个；每个状态内部只做一次 `max`，O(1)O(1) O(1)。

- 时间：O(n)O(n) O(n) ← 从 O(1.618n)O(1.618^n) O(1.618n) 塌缩下来
- 空间：O(n)O(n) O(n) memo + O(n)O(n) O(n) 递归栈

**为什么能塌缩**：加了 memo 之后，每个状态的"真正计算"只发生一次，第二次以后全是 O(1)O(1) O(1) 查表。递归树被剪成了一条链。

这个公式对所有 DP 都适用，以后遇到二维 DP（如 `dfs(i, j)`）直接套：状态数 O(nm)O(nm) O(nm) × 转移 O(1)O(1) O(1) = O(nm)O(nm) O(nm)。

```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        f = [0] * (n+2) # f[i+2] 对应 dfs(i)，+2 是为了省掉负下标判断
        for i,x in enumerate(nums):
            f[i+2] = max(f[i+1] , f[i] + x)
        return f[n+1]
```

注意这里的n+1是因为 n + 1 = n-1 + 2

            new_f = max(f1, f0 + x)
