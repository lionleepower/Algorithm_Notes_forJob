这里是恰好的情况，如果改成至多或是至少，又是什么情况呢，算法要怎么改：，这正是 0-1 背包计数的三兄弟：**恰好 / 至多 / 至少**。它们的递推式几乎一样，真正变化的是两个地方：**边界条件（i < 0 时返回什么）** 和 **容量越界（c 变负）怎么处理**。理解的关键是先想清楚状态 `c` 的语义。

## 概念上怎么区分

把 `c` 想成「剩余额度」：

**恰好装满**（你现在的代码）：`c` 是必须**精确归零**的额度。走完所有物品时 `c == 0` 才算一种方案；`c` 变负是非法的，所以 `c < nums[i]` 时禁止选。

**至多为 c**：`c` 是**不能超支**的额度。走完时 `c` 停在任何非负值都行——空选也是合法方案。所以约束和恰好一样严（不许变负），但验收标准放宽了。

**至少为 c**：`c` 是**必须还清的欠款**。选多了（`c` 变负）不但合法，还是「超额完成」。所以递归里允许透支，验收标准是走完时 `c <= 0`。

## 代码怎么改

**至多**：只改边界，`i < 0` 时无条件返回 1。

```python
@cache
def dfs(i, c):
    if i < 0:
        return 1              # 走到头时 c >= 0 恒成立，空选也算一种
    if c < nums[i]:
        return dfs(i - 1, c)  # 仍然不许超支
    return dfs(i - 1, c) + dfs(i - 1, c - nums[i])
```

**至少**：允许 `c` 透支，但为了让 `@cache` 的状态空间有限，把所有负数状态**折叠到 0**——因为「欠款已还清」之后再怎么选都一样，这些状态互相等价。

```python
@cache
def dfs(i, c):
    if i < 0:
        return 1 if c == 0 else 0   # clamp 后 c == 0 就代表"已达标"
    # 注意：没有 c < nums[i] 的剪枝分支了，选是永远合法的
    return dfs(i - 1, c) + dfs(i - 1, max(c - nums[i], 0))
```

这里最容易看漏的一点：至少版的边界写法**长得和恰好一模一样**，但含义完全不同——因为有了 `max(..., 0)`，`c == 0` 不再表示「刚好用完」，而是表示「需求已被满足（含超额）」。

## 对照表

|变体|c 的语义|c 变负|边界 i < 0|
|---|---|---|---|
|恰好|必须精确归零的容量|非法，剪掉|`c == 0` 返回 1|
|至多|不能超支的容量|非法，剪掉|恒返回 1|
|至少|必须还清的欠款|合法，clamp 到 0|`c == 0` 返回 1|

## 两个自检恒等式

写完可以用这两条关系验证正确性（也是面试口头推理的好素材）：

$$至多(c) = \sum_{k=0}^{c} 恰好(k)$$

$$至少(c) = 2^n - 至多(c-1)$$

第二条的直觉：总共 $2^n$ 种选法，减去「和 ≤ c-1」的就是「和 ≥ c」的。

## 回到 Target Sum 本身

如果原题改成「表达式结果**至少**为 target」，前面的 ± 转化依然成立：正数部分 $p$ 满足 $2p = target + sum$，但「至少」不再需要整除性检查——要求变成 $p \ge \lceil (target + sum) / 2 \rceil$，奇偶不整除时向上取整即可（恰好版遇到奇数直接返回 0，这个 pattern 在至少版里要删掉）。这也说明你代码开头那两行 `if target < 0 or target % 2` 是**恰好语义专属**的预检查，换语义时它们是第一个要重新审视的地方。

# 为什么要target += sum(nums)？

### 核心转化：把"加减号"变成"分两堆"

原题是：给每个数分配 `+` 或 `-`，使总和等于 `target`。

换个视角：分配符号，本质上是把 `nums` **分成两堆**——

- 堆  P：所有拿到 `+` 号的数
- 堆  N：所有拿到 `-` 号的数

于是原条件可以写成两条恒等式：

sum(P)−sum(N)=targetsum(P) - sum(N) = targetsum(P)−sum(N)=target sum(P)+sum(N)=sum(nums)sum(P) + sum(N) = sum(nums)sum(P)+sum(N)=sum(nums)

第二条永远成立，因为每个数必属于其中一堆。两式相加，sum(N)sum(N) sum(N) 被消掉：

2⋅sum(P)=target+sum(nums)2 \cdot sum(P) = target + sum(nums)2⋅sum(P)=target+sum(nums) sum(P)=target+sum(nums)2sum(P) = \frac{target + sum(nums)}{2}sum(P)=2target+sum(nums)​

这就是 `target += sum(nums)` 和 `target //= 2` 在做的事：**它不再关心符号，只问一个新问题——"从 nums 中选出一个子集，使其和恰好等于这个新 target，有几种选法？"**

一旦确定了哪些数进 PP P 堆，剩下的自动全进 NN N 堆，符号方案就唯一确定了。所以"符号方案数" = "子集选法数"，一一对应，计数不多不少。

### 为什么要做这个转化？

原问题里每个数可正可负，"当前和"的取值范围横跨负数到正数，很难直接套背包框架。转化之后：

- 只有"选 / 不选"两种决策（这个数进不进 PP P 堆）
- 目标是一个非负整数
- 这正是你熟悉的 subsets 那套「选或不选」分支结构，只是从"枚举所有子集"升级为"计数满足条件的子集"

### 两个提前剪枝的 return 0

转化也解释了这两行检查：

- `target < 0`：sum(P)sum(P) sum(P) 是若干非负数之和，不可能为负 → 无解
- `target % 2`：target+sum(nums)target + sum(nums) target+sum(nums) 必须是偶数才能被 2 整除。直觉上，sum(P)sum(P) sum(P) 和 sum(N)sum(N) sum(N) 的和与差**奇偶性相同**（同加同减一个数不改变奇偶），所以如果 `target` 和 `sum(nums)` 奇偶性不一致，无论怎么分堆都凑不出来 → 无解

### 奇偶性：一个更好用的不变量视角

与其算 sum(P)sum(P) sum(P)、sum(N)sum(N) sum(N)，有个更直接的角度：

**从"全都取正号"出发。** 此时总和是 S=sum(nums)S = sum(nums) S=sum(nums)。现在你想调整到 tt t，唯一的操作是**把某个数 xx x 的符号翻转**，而翻转一次，总和的变化是：

+x→−x⟹总和减少 2x+x \rightarrow -x \quad\Longrightarrow\quad \text{总和减少 } 2x+x→−x⟹总和减少 2x

变化量永远是 2x2x 2x，**永远是偶数**。

所以这是一个不变量：**无论怎么翻转符号，总和的奇偶性永远和 SS S 一样，改不了。** 你能到达的所有总和，都被锁死在 SS S 的那一半（要么全是奇数，要么全是偶数）。

于是：如果 tt t 和 SS S 奇偶性不同，tt t 根本不在可达集合里 → 直接 0。

而"tt t 与 SS S 奇偶性相同"这句话，等价于"t+St + S t+S 是偶数"（同奇同偶相加必为偶）。代码里 `target += sum(nums)` 已经把 `target` 变成了 t+St + S t+S，所以 `target % 2` 检查的就是这件事。

> 你原来困惑的那句"和与差奇偶性相同"，说的是 (a+b)(a+b) (a+b) 与 (a−b)(a-b) (a−b) 相差 2b2b 2b，所以奇偶必然一致——和上面的"翻转改变 2x2x 2x"其实是同一件事，后者更好记。
