你的困惑来自「选/不选」这个词在 LCS 里被用歪了。先把语义钉死，答案就自然掉出来。

## 先修正语义

`dfs(i, j)` 的定义是：**`text1[0..i]` 和 `text2[0..j]` 这两个前缀的 LCS 长度**。

那么 `dfs(i-1, j)` 的含义不是「不选 `s[i]`」，而是「**`s[i]` 退场，`t[j]` 还留在场上**」。关键就在后半句——`t[j]` 还在，它在子问题内部**仍然可以被配对，也仍然可以被抛弃**，这个选择权没有被剥夺。

## 于是「都退场」被包含了

用集合语言最清楚。记 $F(i,j)$ = 前缀 `s[0..i]` 与 `t[0..j]` 的**所有公共子序列构成的集合**。

$$F(i-1,,j-1) \subseteq F(i-1,,j)$$

为什么？任何一个「`s[0..i-1]` 与 `t[0..j-1]` 的公共子序列」，**它本身就已经是「`s[0..i-1]` 与 `t[0..j]` 的公共子序列」**——只不过恰好没用到 `t[j]` 而已。多给一个字符，老方案一个都不会失效。

所以 `dfs(i-1, j-1)` 这个候选，在 `dfs(i-1, j)` 的搜索空间里**已经被完整枚举过一遍了**。它不是一个新分支，而是旧分支的一个子集。`max` 里加它不会错，但纯属冗余。

> [!example]- 一个能看出差距的例子 `s = "ax"`, `t = "ba"`，考虑 `i=1` (`'x'`), `j=1` (`'a'`)，两字符不等：
> 
> ```
> dfs(0, 1)   s="a",  t="ba"  → 1    ← 'a' 和 t[1]='a' 配上了
> dfs(1, 0)   s="ax", t="b"   → 0
> dfs(0, 0)   s="a",  t="b"   → 0    ← 「都退场」
> ```
> 
> `dfs(0,0)` 严格更差。因为它把 `t[1]='a'` 也一起扔了，而这个字符**本来还有用**。「都退场」永远只是「让一个退场」的一个更保守的子情况，不可能反超。

## 那为什么相等时能只留一个分支

对称的道理，方向相反：`s[i] == t[j]` 时，**一定存在一个最优解把这两个字符配成对**（交换论证：若某最优解没配它俩，总能把它俩换进来而不变短）。所以此时 `dfs(i-1,j-1) + 1` 反过来支配了另外两个候选，那两个才是可以剪掉的冗余项。

两种情况合起来看：

|情况|支配者|被支配（可剪）|
|---|---|---|
|`s[i] == t[j]`|`dfs(i-1,j-1) + 1`|`dfs(i-1,j)`、`dfs(i,j-1)`|
|`s[i] != t[j]`|`dfs(i-1,j)`、`dfs(i,j-1)`|`dfs(i-1,j-1)`|

上一条消息里的「统一写法」就是**两边都不剪**，全塞进 `max`，让它自己挑。

## 一句话本质

`max` 的候选**允许重、不允许漏**。`dfs(i-1,j-1)` 属于「重」——它的方案集合被 `dfs(i-1,j)` 完整包含，所以写不写都不影响正确性，只影响常数。



还有，我们为什么可以把dfs(i-1, j-1)+1给换成dfs(i-1, j-1) + (s[i] == t[j])?

我只是在想$==$返回的不应该是一个布尔值吗，比如说TRUE 或是False,为什么有时候就是1，0，有时候就是true or false:

$==$ **永远**返回布尔值，从来没变过。变的是**谁在消费这个值**。

关键事实：**在 Python 里，`bool` 是 `int` 的子类**。`True` 和 `False` 不是「另一个世界的类型」，它们就是 `1` 和 `0`，只是印出来的时候换了个名字。

```python
>>> isinstance(True, int)
True
>>> True == 1
True
>>> True + True
2
>>> 5 + False
5
>>> sum([True, False, True])
2
```

所以 `dfs(i-1,j-1) + (s[i] == t[j])`：$==$ 返回的确实是 `True`，但 `+` 只认识数字，它调用 `int.__add__`，于是 `True` 就以本来面目（1）参与运算。**不是「有时候返回 1，有时候返回 True」，而是同一个东西在不同上下文里换了张脸**：

|上下文|表现|
|---|---|
|`print(x == y)`|`True` — 走 `__repr__`，显示成人类可读的名字|
|`if x == y:`|当真假用|
|`a + (x == y)`|当 1/0 用 —— 算术上下文|

## C++ 里是另一套机制，结论一样

C++ 的 `==` 返回 `bool`，但 `bool` 在算术表达式里会发生**整型提升（integral promotion）**，自动变成 `int` 的 `1` / `0`：

```cpp
return dfs(i-1, j-1) + (s[i] == t[j]);   // 合法，bool → int
```

Python 是「bool 本来就是 int」，C++ 是「bool 会被隐式转成 int」，路径不同但用起来一样。

> [!warning]- 两个坑
> 
> - **`True is 1` 是 `False`**。`is` 比的是对象身份，`True` 和 `1` 是两个不同对象，只是数值相等。判断相等永远用 $==$，别用 `is`（除了 `is None`）。
> - **这招不是所有语言都有**。Java、Go 里 `bool` 和 `int` 是完全隔离的，必须显式写 `(s[i]==t[j] ? 1 : 0)`。所以这个写法只是 Python/C++ 的便利，不是通用真理。

## 顺带一个高频用法

既然布尔能当 1/0 用，计数就可以不写 if：

```python
cnt = sum(c == 'a' for c in s)          # 统计字符出现次数
diff = sum(a != b for a, b in zip(s, t)) # 汉明距离
```

面试里这类写法既短又不容易写错，值得记住。

## 一句话本质

`== 只负责产出布尔；**是加法把布尔当成了数字**。在 Python 里这不是「转换」，而是布尔本来就是整数的一种。

```python
class Solution:

    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        n = len(text1)
        m = len(text2)
        @cache
        def dfs(i, j):
            if i < 0 or j <0:
                return 0
            if text1[i]== text2[j]:
                return dfs(i-1, j-1) + 1
            return max(dfs(i-1, j), dfs(i, j-1))
        return dfs(n-1, m-1)
```

回到正题。看不懂「插入/删除/替换」，通常卡在两个点：**只对 s 动手为什么够**，以及**插入为什么是 `dfs(i, j-1)`**。

### 先钉死语义合约

dfs(i,j)=把 s[0..i] 变成 t[0..j] 的最少操作数dfs(i,j) = \text{把 } s[0..i] \text{ 变成 } t[0..j] \text{ 的最少操作数}dfs(i,j)=把 s[0..i] 变成 t[0..j] 的最少操作数

两个下标各自代表「**这一侧还剩多少字符没处理**」。所有转移都在回答同一个问题：**最右边的 `s[i]` 和 `t[j]`，这一步怎么消化掉？**

### 换个视角：这题本质是「对齐」

别想「怎么编辑」，想「**怎么把两个串并排对齐**」。把 s 写在上排、t 写在下排，允许在任一排插空格，每一列只可能是三种形态：

|这一列|含义|代价|
|---|---|---|
|`s[i]` 对 `t[j]`|字符相同 = 匹配；不同 = **替换**|0 或 1|
|`s[i]` 对 空|s 有、t 没有 → **删除**|1|
|空 对 `t[j]`|t 有、s 没有 → **插入**|1|

编辑距离 = 最优对齐的总代价。而三个递归分支，就是在穷举「**最右边那一列长什么样**」——三种形态不重不漏，`min` 挑最便宜的。

指针怎么动，只看这一列**各自消耗了谁**：

- **替换**：这一列同时用掉 `s[i]` 和 `t[j]` → `dfs(i-1, j-1) + 1`
- **删除**：这一列只用掉 `s[i]`（下排是空格，`t[j]` 没被消耗，还留着） → `dfs(i-1, j) + 1`
- **插入**：这一列只用掉 `t[j]`（上排是空格，`s[i]` 一个字符都没用掉，还留着） → `dfs(i, j-1) + 1`

**插入之所以是 `j` 退、`i` 不动**，就是因为插进去的那个字符是凭空造的，它立刻和 `t[j]` 配对然后双双出场，而你手里原有的 `s[0..i]` 还**一个都没花掉**。

> [!tip]- 为什么只操作 s 就够了，不用考虑动 t  
> 「在 t 里删一个字符」和「在 s 里插一个字符」是同一个对齐结果，只是叙述方向相反。既然目标是让两串重合，双向操作能达到的对齐，单向操作也能达到，代价相同。所以约定只改 s，搜索空间不损失。

### base case 也是同一套语义

- `i < 0`：s 已经空了，t 还剩 `j+1` 个字符没对上 → 只能一个个**插入** → 返回 `j+1`
- `j < 0`：t 已经空了，s 还剩 `i+1` 个多余字符 → 只能一个个**删除** → 返回 `i+1`

不是「凭感觉写个 +1」，而是合约推出来的：剩下的字符必须全部处理，每个恰好 1 次操作。

### 相等时为什么能直接 `dfs(i-1, j-1)`

字符相同，这一列就是「免费匹配」，代价 0。它支配了另外两个候选，因为（和 LCS 那次同样的单调性论证）：

dfs(i−1,j−1)≤dfs(i−1,j)+1,dfs(i−1,j−1)≤dfs(i,j−1)+1dfs(i-1,j-1) \le dfs(i-1,j) + 1, \qquad dfs(i-1,j-1) \le dfs(i,j-1) + 1dfs(i−1,j−1)≤dfs(i−1,j)+1,dfs(i−1,j−1)≤dfs(i,j−1)+1

既然免费方案不可能比「花 1 块钱的方案」更贵，剪掉那两支是安全的。这正好对应上一条消息里的统一写法：

python

```python
return min(dfs(i-1, j) + 1,
           dfs(i, j-1) + 1,
           dfs(i-1, j-1) + (s[i] != t[j]))
```

`(s[i] != t[j])` 就是「这一列要不要付替换费」的指示器——相等免费，不等付 1。

> [!example]- `s = "horse"` → `t = "ros"`（答案 3）  
> 最优对齐（从左往右读列）：
> 
> ```
> s:  h   o   r   s   e
> t:  r   o   _   s   _
>    替换 匹配 删除 匹配 删除
>     1   0   1   0   1     = 3
> ```
> 
> 递归是从右往左建这张表的：先决定最后一列（`e` 对空格 = 删除），退到 `dfs(3, 2)`，再决定它的最后一列……每一步都只在三种列形态里挑。

### 一句话本质

编辑距离不是在「模拟编辑操作」，而是在**枚举两串的最优对齐方式**；三个递归分支 = 最右一列的三种可能，指针退不退，只取决于这一列有没有吃掉那一侧的字符。

```python
class Solution:

    def minDistance(self, s: str, t: str) -> int:

        n = len(s)

        m = len(t)

  

        f = [[0]*(m+1) for _ in range(n+1)]

        f[0] = list(range(m+1))

        for i, x in enumerate(s):

            f[i+1][0] = i + 1

            for j, y in enumerate(t):

                if x == y:

                    f[i+1][j+1] = f[i][j]

                else:

                    f[i+1][j+1] = min(f[i+1][j], f[i][j+1], f[i][j])+1

  

        return f[n][m]

```
