## 先说结论：份代码的全部信息量，都在 `dfs` 的定义里

$$dfs(i) = \text{以 } nums[i] \textbf{ 结尾} \text{ 的最长严格递增子序列长度}$$

这个"以 i 结尾"不是随手加的修饰，它是这道题唯一能走通的状态设计。下面每一件事——转移怎么写、base case 在哪、入口为什么是 `max`——都是从这句定义里推出来的。

---

## 一、为什么必须"以 i 结尾"？

先试试更自然的前缀定义：

$$dfs(i) = nums[0..i] \text{ 范围内的 LIS 长度}$$

这个定义推不下去。假设 `dfs(i-1) = 3`，现在要决定 `nums[i]` 能不能接上去——你会发现**信息不够**：这个 3 只告诉你长度，不告诉你那条子序列的结尾是几。而"能不能接"恰恰只取决于结尾值。

这就是**有后效性**：子问题的返回值不足以支撑父问题做决策。

修复办法只有一个——**把缺失的信息塞进状态**。缺的是"上一个选的数是谁"，那就规定 `nums[i]` 必须被选中且作为结尾。状态一锁定结尾，转移条件 `nums[j] < nums[i]` 就是纯粹的局部判断，后效性消失。

> 通用原则：**当"能否转移"依赖于上一步选了什么具体的值，就把那个值锁进状态。** 这是 LIS 和打家劫舍的根本分水岭——打家劫舍的"能否选"只依赖下标相邻关系，不依赖值，所以前缀语义够用。

代价是：定义变强了，答案就不再是单个状态。这是后面第三节的伏笔。

---

## 二、转移：为什么"枚举上一个选谁"不重不漏

```python
for j in range(i):
    if nums[j] < nums[i]:
        res = max(res, dfs(j))
return res + 1
```

按你熟悉的框架说：这里用的不是"选/不选"二元分支，而是**枚举上一个元素是谁**。

它为什么是一个完美划分？考虑任意一条以 `nums[i]` 结尾的递增子序列，把最后一个元素 `nums[i]` 摘掉：

- 要么变成空 → 对应 `res = 0` 那一支
- 要么剩下的部分**必然是以某个 `nums[j]` 结尾的递增子序列**，而这个 `j` 是唯一确定的（就是倒数第二个元素的下标）

所以「按倒数第二个元素的下标 j 分类」+「空」构成了对所有情况的**互斥且完备**的划分。`max` 在这里没有任何魔法，就是在这个完整分类上取最优——和你之前理解的一样。

---

## 三、base case 去哪了？它是**隐式**的

你没写 `if i == 0: return 1`，代码却是对的。为什么？

```python
res = 0                    # ← 这就是 base case
for j in range(i): ...     # i == 0 时循环体一次都不执行
return res + 1             # → 返回 1
```

值得注意的是：**`res = 0` 承担的不是"下标越界"，而是"前驱为空"这个分类分支。**

`i == 0` 只是触发它的场景之一。像 `nums = [5, 1]` 里的 `i = 1`，前面明明有元素，但没有比 1 小的，for 循环一个都没命中，同样走 `res = 0` 返回 1。

这正好印证你之前那条原则：**base case 由语义决定，不由下标决定**。这里的语义是"只有 `nums[i]` 自己一个元素的子序列，长度为 1"，它天然被初始值兜住了，所以不需要显式的边界判断。

---

## 四、入口为什么是 `max(dfs(i) for i in range(n))` 而不是 `dfs(n-1)`

这一点直接对应你最近纠结的"入口语义"问题，两题放一起对比最清楚：

||打家劫舍 198|LIS 300|
|---|---|---|
|`dfs(i)` 语义|前 `i+1` 间房的最优解（**前缀**）|以 `nums[i]` **结尾**的最优解（**必选 i**）|
|`nums[i]` 是否一定被使用|否，可选可不选|**是，强制选**|
|状态间是否有包含关系|有，`dfs(i)` 已涵盖 `dfs(i-1)` 的情况|无，各管各的结尾|
|答案|`dfs(n-1)`|`max(dfs(i))`|

关键判据：**`dfs(n-1)` 能当答案，当且仅当定义本身具有"前缀最优"语义（即它已经包含了不选 `nums[n-1]` 的情况）。**

LIS 的定义强制选中 `nums[i]`，那 `dfs(n-1)` 就只是"必须以最后一个元素结尾"的答案，显然漏掉了 LIS 不以 `nums[n-1]` 收尾的所有情况。所以必须在 n 个互斥的结尾上取 max。

> 一句话记法：**定义里带"必须包含 i"的，答案就是 max；带"前 i 个"的，答案就是最后一个状态。**

## 五、翻译成递推

记忆化 → 递推是机械的：`dfs` 改名 `f`，递归改循环，递归边界改初始值。

```python
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        f = [0] * n
        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    f[i] = max(f[i], f[j])
            f[i] += 1          # 注意 +1 在内层循环之外
        return max(f)
```

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> f(n, 0);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++)
                if (nums[j] < nums[i])
                    f[i] = max(f[i], f[j]);
            f[i]++;
        }
        return *max_element(f.begin(), f.end());
    }
}; 
```

`f[i] += 1` 必须放在内层 for 之后——写进循环里就变成每命中一个 j 就加一次，直接错。等价的写法是初始化 `f = [1]*n` 然后 `f[i] = max(f[i], f[j]+1)`，二选一，别混着写。

这里**没有滚动数组优化**：`f[i]` 依赖前面**所有**的 `f[j]`，不是固定的常数个，所以整个数组都得留着。这是 LIS 和爬楼梯/打家劫舍的又一个区别。

```python
class Solution:

    def lengthOfLIS(self, nums: List[int]) -> int:

        g = []

        for x in nums:

            j = bisect_left(g,x)

            if j == len(g):

                g.append(x)

            else:

                g[j] = x

        return len(g)


```


快速验证一下 `nums = [10,9,2,5,3,7,101,18]`：

```
x=10  bisect_left([], 10)      = 0 = len(g) → append   g=[10]
x=9   bisect_left([10], 9)     = 0 < len    → g[0]=9   g=[9]
x=2   bisect_left([9], 2)      = 0 < len    → g[0]=2   g=[2]
x=5   bisect_left([2], 5)      = 1 = len(g) → append   g=[2,5]
x=3   bisect_left([2,5], 3)    = 1 < len    → g[1]=3   g=[2,3]
x=7   bisect_left([2,3], 7)    = 2 = len(g) → append   g=[2,3,7]
x=101 bisect_left(...,101)     = 3 = len(g) → append   g=[2,3,7,101]
x=18  bisect_left(...,18)      = 3 < len    → g[3]=18  g=[2,3,7,18]
→ len(g) = 4  ✓
```

注意最后两步：`101` 进来时长度就已经涨到 4 了，`18` 只是把结尾从 101 压到 18。**长度不变、结尾变小** —— 这正是替换操作的全部意义，它在为后面可能出现的数留路。

几个补充：

**1. 可以更紧凑地写**（`bisect_left` 的返回值天然是"插入位置"）：

```python
j = bisect_left(g, x)
if j == len(g):
    g.append(x)
g[j] = x          # append 后 g[j] = x 是自我赋值，无害
```

两行合一，但可读性下降，面试建议还是写你现在这版 if/else，意图更清楚。

**2. 严格 / 非严格只差一个字母**：

|题目要求|用哪个|
|---|---|
|严格递增（本题）|`bisect_left` / `lower_bound`|
|非降（允许相等）|`bisect_right` / `upper_bound`|

想清楚为什么：`nums = [1,1]` 求严格递增答案是 1。`bisect_left(g=[1], 1) = 0 < len` → 替换，长度不变 ✓。若换成 `bisect_right` 返回 1 = len → append，长度变 2，那正是非降的答案。**`left` 会撞上相等元素并替换掉它，`right` 会跳过相等元素去追加** —— 这一条就是全部差别。





## 六、$O(n\log n)$ 的贪心 + 二分（面试重点）

$O(n^2)$ 是及格线，这个是加分项，而且思路完全不同——它不再是 DP，是贪心。

**核心状态定义（同样是定义先行）：**

$$g[k] = \text{当前扫描到的所有长度为 } k+1 \text{ 的递增子序列中，最小的那个结尾元素}$$

两条性质：

1. **`g` 严格递增。** 反证：若 `g[k] >= g[k+1]`，把那条长度 `k+2` 的子序列砍掉最后一个，就得到一条长度 `k+1`、结尾小于 `g[k]` 的子序列，与 `g[k]` 是最小矛盾。→ 所以可以二分。
2. **`len(g)` 就是答案。**

**处理每个 `x` 的规则：** 在 `g` 中二分找第一个 $\ge x$ 的位置 `k`

- 找到了 → `g[k] = x`（长度不变，但结尾变小）
- 没找到（x 比 g 中所有数都大）→ `g.append(x)`（长度 +1）

```python
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        g = []
        for x in nums:
            k = bisect_left(g, x)
            if k == len(g):
                g.append(x)
            else:
                g[k] = x
        return len(g)
```

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> g;
        for (int x : nums) {
            auto it = lower_bound(g.begin(), g.end(), x);
            if (it == g.end()) g.push_back(x);
            else *it = x;
        }
        return g.size();
    }
};
```

**为什么替换不会丢解？**

因为 `g[k]` 的语义是"**长度 k+1 可达的最小结尾**"，替换正是在维护这个最小值。而结尾越小，未来越多的数能接在它后面——这个"更小总是不劣"的单调性，就是贪心成立的依据。

同时，被替换掉的那个较大的值所证明的事实（"长度 k+1 是可达的"）已经被 `len(g)` 记住了，不会因为替换而丢失。

**一个很漂亮的联系：** `bisect_left` 返回的 `k`，加 1 之后正好就是 $O(n^2)$ 解法里的 `f[i]`。也就是说 **`g` 是把 `f` 按值分组后取的最小值**——两种解法算的是同一个东西，只是二分版用有序性把"扫一遍找最大 f[j]"压成了 $O(\log n)$。

> [!warning] `g` 数组本身**不是**一个合法的 LIS `nums = [3,4,1,2]` 跑完 `g = [1,2]`，但 `[1,2]` 虽然碰巧合法，很多情况下 `g` 里的元素在原数组中的下标顺序是乱的。**只有长度是对的。** 要还原具体序列得另存前驱指针。

## 七、易错点清单

|坑|说明|
|---|---|
|**严格 vs 非严格**|严格递增用 `nums[j] < nums[i]` / `bisect_left`；非降（允许相等）用 `<=` / `bisect_right`。二分版只差一个函数名，考试最爱在这里下刀|
|**答案写成 `dfs(n-1)`**|定义强制选 i，必须 max。见第四节|
|**`f[i] += 1` 写进内层循环**|变成累加，错得很隐蔽|
|**想优化成滚动变量**|依赖前面所有状态，不可滚动|
|**`@cache` 在类方法上**|LeetCode 上没问题，但工程里 `lru_cache` 装饰实例方法会持有 `self` 引用导致内存泄漏，面试被追问可以提一嘴|
|**忘记 `n == 0`**|本题约束 $n \ge 1$，但 `max()` 对空序列会抛异常，改题时注意|

## 八、复杂度

- **DP 版**：时间 $O(n^2)$（每个 i 扫一遍前缀），空间 $O(n)$
- **二分版**：时间 $O(n\log n)$（n 次二分），空间 $O(n)$（最坏 g 存满）
