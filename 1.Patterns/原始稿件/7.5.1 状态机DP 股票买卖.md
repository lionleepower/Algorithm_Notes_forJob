```python
class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        n = len(prices)
        @cache
        def dfs(i,hold):
            if i < 0:
                return -inf if hold else 0
            if hold:
            # 注意这里考虑的是昨天的量，在已持有的情况下，昨天可能直接买入，也可能是前天的持有
                return max(dfs(i-1, True), dfs(i-1, False) - prices[i])
            return max(dfs(i-1, False), dfs(i-1, True) + prices[i])
        return dfs(n-1, False)
```
## 先钉死语义契约

```
dfs(i, hold) = 只考虑前 i 天（0..i），
               且【第 i 天结束时】持股状态为 hold 时，
               能获得的最大利润
```

`hold` 不是"今天要不要买"，而是**今天收盘那一刻手里有没有股票**。这一句定死之后，入口、base case、转移全部被唯一确定。

## 转移：站在今天的状态，反推昨天

因为 `dfs(i-1, ·)` 已经把"第 i 天之前的所有事"结算完了，所以**第 i 天的买卖动作，发生在从 `i-1` 状态跳到 `i` 状态的那条边上**。

`dfs(i, True)`：今天收盘手上有货，只有两种来源（穷举分类，无重叠无遗漏）：

- 昨天收盘就有货 → 今天什么都不做：`dfs(i-1, True)`
- ==昨天收盘没货 → 今天买入，花掉 `prices[i]`：`dfs(i-1, False) - prices[i]`==

`dfs(i, False)`：今天收盘手上没货，同样两种来源：

- 昨天就没货 → 今天不动：`dfs(i-1, False)`
- 昨天有货 → 今天卖出，收入 `prices[i]`：`dfs(i-1, True) + prices[i]`

所以 `-prices[i]` 出现在 `hold=True` 分支里并不矛盾：**减号 = 买入动作，而买入的结果正是"变成持股"**。

## True/False 的两个记号

|位置|含义|
|---|---|
|`dfs(i, True)` 的 `True`|第 i 天**结束后**持股|
|递归里的 `dfs(i-1, False)`|第 i-1 天结束后不持股（今天才买）|

## base case：`-inf if hold else 0`

`i < 0` 表示"第 0 天还没开始"。这时候：

- 不持股是合法的，利润 `0`
- **持股是不可能的**——你还没开过市，凭空多一支股票

这里用 `-inf` 而不是 `0` 或 `-1`，是因为它要在 `max` 里**永远输**，等价于"这条路不存在"。验证一下：

```
dfs(0, True) = max(dfs(-1, True), dfs(-1, False) - prices[0])
             = max(-inf, 0 - prices[0]) = -prices[0]   ✅ 第 0 天买入
```

如果写成 `0`，就变成 `max(0, -prices[0]) = 0`，相当于宣称"你可以免费持有一支股票"，整个答案会被污染。

## 入口：`dfs(n-1, False)`

最后一天结束时手里还攥着股票，一定不优于把它卖掉（或者当初就别买）。所以答案取 `hold=False`。

**一句话**：`hold` 是"收盘时的持仓状态"，`±prices[i]` 是"从昨天状态跳到今天状态时付出/收到的代价"，`-inf` 是"非法状态"的编码方式。



同样，接下来我们来考虑递推：

```python
class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        n = len(prices)
        f = [[0] * 2 for _ in range(n+1)]
        f[0][1] = -inf
        for i,p in enumerate(prices):
            f[i+1][0] = max(f[i][0], f[i][1] + p)
            f[i+1][1] = max(f[i][1], f[i][0] - p)
        return f[n][0]
```

![](../../attachments/Pasted%20image%2020260730110854.png)

有三种题型，至少，恰好，以及至多；我们先来看至多：

多增加一个参数j去表示至多完成多少笔交易次数：

![](../../attachments/Pasted%20image%2020260730111049.png)

```python
class Solution:

    def maxProfit(self, k: int, prices: List[int]) -> int:

        n = len(prices)

        @cache

        def dfs(i, j, hold):

            if j < 0:

                return -inf

            if i < 0:

                return -inf if hold else 0

            if hold:

                return max(dfs(i-1, j, True), dfs(i-1, j, False) - prices[i])

            return max(dfs(i-1, j, False), dfs(i-1, j-1, True) + prices[i])

        return dfs(n-1, k, False)

```
这是 [[188. 买卖股票的最佳时机 IV]]。相比上一题只多了一个维度 `j`，但**难点全在"j 在哪一步减 1"和"两个 base case 的先后顺序"**上。

## 语义契约

```
dfs(i, j, hold) = 只考虑前 i 天（0..i），
                  这段区间内【至多】还能完成 j 笔交易，
                  第 i 天收盘时持股状态为 hold，
                  的最大利润
```

关键在于：`j` 是**"前 i 天这个子问题的交易预算"**，不是全局计数器。这个定义一钉死，下面全部推得出来。

## 为什么 `j-1` 出现在卖出分支

一笔交易 = 买 + 卖 的**一对**。只要不重复计数，在哪一端扣预算都行，这份代码选择**在卖出时扣**：

- 买入：`dfs(i-1, j, False) - prices[i]` —— 交易还没完成，预算不动
- 卖出：`dfs(i-1, j-1, True) + prices[i]` —— 今天用掉了一笔，前缀只剩 `j-1` 笔可用

如果你在买入时也减，就变成一次交易扣两次预算，答案会偏小。**"j 只在一个端点减"是这道题的核心不变量。**

## 两个 base case 的顺序是有讲究的

```python
if j < 0:  return -inf        # 必须在前
if i < 0:  return -inf if hold else 0
```

`j < 0` 表示"预算透支"，这是**非法状态**，用 `-inf` 编码，让它在 `max` 里永远输。

而顺序不能交换。反例：`k = 0, prices = [1, 5]`，正确答案是 `0`。

假如先判 `i < 0`：

```
dfs(0, -1, True) = max(dfs(-1,-1,True), dfs(-1,-1,False) - 1)
                 = max(-inf,            0 - 1)              = -1   ← 泄漏！
dfs(1, 0, False) = max(dfs(0,0,False), dfs(0,-1,True) + 5) = 4     ✗
```

`dfs(-1, -1, False)` 被 `i<0` 分支拦下来返回了 `0`，**"预算已经透支"这个信息被吞掉了**，于是白送一笔交易。先判 `j < 0` 就能堵死：任何 `j` 为负的状态，无论 `i` 多少、无论 hold 与否，一律 `-inf`。

**原则：非法性判断优先于终止性判断。**

## 验证一遍

`k = 1, prices = [1, 5]`：

```
dfs(1,1,False) = max( dfs(0,1,False),  dfs(0,0,True) + 5 )
dfs(0,1,False) = max( dfs(-1,1,False), dfs(-1,0,True) + 1 ) = max(0, -inf) = 0
dfs(0,0,True)  = max( dfs(-1,0,True),  dfs(-1,0,False) - 1 ) = max(-inf, -1) = -1
             ⇒ max(0, -1 + 5) = 4   ✅
```

注意 `dfs(0,0,True) = -1`：第 0 天买入后预算仍是 `0`，因为**买入不扣**，直到第 1 天卖出时才用 `j-1` 把它扣掉。

## 入口 `dfs(n-1, k, False)`

最后一天必然空仓（持股不如不买或卖掉），预算给满 `k`。因为定义是"**至多**"，`j` 用不完也不惩罚，所以这里不需要额外处理。

## 和你正在做的背包三变体是同一套骨架





同样，我们来考虑递推：
![](../../attachments/Pasted%20image%2020260730111422.png)
```python
class Solution:
    def maxProfit(self, k: int, prices: List[int]) -> int:
        n = len(prices)
        f = [[[-inf] * 2 for _ in range(k+2)] for _ in range(n+1)]
        for j in range(1, k+2):
            f[0][j][0] = 0
        for i, p in enumerate(prices):
            for j in range(1, k+2):
                f[i+1][j][0] = max(f[i][j][0], f[i][j-1][1] + p)
                f[i+1][j][1] = max(f[i][j][1], f[i][j][0] - p)
        return f[n][k+1][0]
```

这里的 `k+2` 是**两次下标平移中的第二次**。递归版里 `i` 和 `j` 都能取到 `-1`，而 Python 数组下标不能为负，所以两个维度各自 `+1` 偏移。

## 下标映射表

|递归|数组|维度大小|
|---|---|---|
|`i ∈ [-1, n-1]`|`f[i+1]`，即 `[0, n]`|`n+1`|
|`j ∈ [-1, k]`|`f[·][j+1]`，即 `[0, k+1]`|**`k+2`**|

`j` 的取值有 `k+2` 个：`-1, 0, 1, ..., k`。那个多出来的 `-1` 不是浪费，它就是递归里 `if j < 0: return -inf` 那一行的位置。

## `j = 0` 这一行永远是 -inf，这正是它的作用

初始化循环 `for j in range(1, k+2)` **故意从 1 开始**，所以 `f[0][0][·]` 保持 `-inf` 不变；主循环也从 `j = 1` 开始，`f[·][0][·]` 从头到尾没被写过。

于是当 `j = 1`（真实预算 `0`）时：

```python
f[i+1][1][0] = max(f[i][1][0], f[i][0][1] + p)
                              #  ^^^^^^^^^ 恒为 -inf
```

卖出这条边被 `-inf` 彻底堵死 —— **"预算为 0 时不能再卖"这个约束，是靠一整行哨兵值自动实现的，不需要任何 if 判断**。这和递归里 `j < 0` 提前返回 `-inf` 是同一件事的两种写法。

## 顺带对上了「非法优先于边界」

上一题我们说过判断顺序不能换。在递推版里，这个顺序被编码进了初始化：

- `f[0][j][0] = 0`（`j ≥ 1`） ← 对应 `dfs(-1, j≥0, False) = 0`
- `f[0][0][0]` 留作 `-inf` ← 对应 `dfs(-1, -1, False) = -inf`

如果初始化写成 `for j in range(k+2)`，就等价于把递归里两个 base case 的顺序调换了，`k = 0` 时又会白送一笔交易。

## 为什么不能写 k+1

假如只开 `k+1` 列、循环从 `j = 0` 开始，那 `f[i][j-1][1]` 在 `j = 0` 时变成 `f[i][-1][1]` —— Python 负下标不报错，它会**静默地取到最后一列**，答案错得毫无征兆。这是这类"哨兵行"写法最典型的坑：**多开一格 + 循环从 1 开始，是为了让越界访问变成受控的 `-inf`，而不是变成 wraparound。**

## 两条转移的不对称

```python
f[i+1][j][0] = max(f[i][j][0], f[i][j-1][1] + p)   # 卖出：预算 j-1 → j
f[i+1][j][1] = max(f[i][j][1], f[i][j][0]   - p)   # 买入：预算不变
```

和递归完全一致：**只在卖出端扣预算**。`f[i][j-1][1]` 读的是"前 i 天用 `j-1` 笔预算且持股"的最优值，今天卖掉，这笔交易闭合，总预算记为 `j`。

答案 `f[n][k+1][0]` 就是 `dfs(n-1, k, False)`：全部 `n` 天、预算 `k`、空仓。

**一句话**：`k+2 = (k+1 个合法预算值) + (1 行 -inf 哨兵)`，哨兵行把"预算透支"这个非法状态物化成了数组的一行，从而免掉了循环体内的边界判断。

要我把递归 → 记忆化 → 递推（含哨兵偏移）→ 空间优化这条演化链，连同 122/188/309/714 的差异对照，整理成一篇 Obsidian 笔记吗？


空间优化：
```python
class Solution:

    def maxProfit(self, k: int, prices: List[int]) -> int:

        n = len(prices)

        f = [[-inf] * 2 for _ in range(k+2)]

        for j in range(1, k+2):

            f[j][0] = 0

        for i, p in enumerate(prices):

            for j in range(k+1, 0, -1):

                f[j][1] = max(f[j][1], f[j][0] - p)

                f[j][0] = max(f[j][0], f[j-1][1] + p)

        return f[k+1][0]
```



接下来我们来考虑恰好k次，和至多k次：
恰好/至多/至少的差别只落在 `i < 0` 那一行：

|变体|`i < 0` 时的返回|
|---|---|
|至多 k 笔（本题）|`0`（只要不 hold，剩多少 j 都行）|
|恰好 k 笔|`0 if j == 0 else -inf`|
|至少 k 笔|`0`，同时把递归里的 `j-1` 改成 `max(j-1, 0)` 做下限钳制|

**一句话**：`j` 是子问题的交易预算，只在卖出端扣减；`-inf` 编码"非法"，且非法判断必须排在边界判断之前。

时间空间都是 $O(nk)$（状态数 $n \times k \times 2$，转移 $O(1)$）。
