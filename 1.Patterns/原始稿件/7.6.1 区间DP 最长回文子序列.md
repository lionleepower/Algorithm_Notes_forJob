```python
class Solution:

    def longestPalindromeSubseq(self, s: str) -> int:

        n = len(s)

        @cache

        def dfs(i, j):

            if i > j:

                return 0

            if i == j:

                return 1

            if s[i] == s[j]:

                return dfs(i+1, j-1) + 2

            return max(dfs(i+1, j), dfs(i, j-1))

        return dfs(0, n-1)
```

## 一、`i` 和 `j` 是什么

先把合同写死：

$$dfs(i, j) = \text{子串 } s[i..j] \text{（闭区间）内部的最长回文子序列长度}$$

`i` 是**左端点**，`j` 是**右端点**。它俩不是「两个串各自的前缀」（那是 [[7.3 线性dp 最长公共子序列]] 的语义），而是**同一个串上一个窗口的两侧边界**。

这个区别决定了这题属于**区间 DP**，不是前缀 DP：

||状态含义|状态在缩小的方式|
|---|---|---|
|LCS `dfs(i,j)`|两个串各自的**前缀**|从右端单向砍|
|本题 `dfs(i,j)`|一个串的**区间**|从**两端**往中间夹|

**为什么必须是区间？** 因为「回文」的判定天然是「首尾配对、向中间递进」。每做一次决策，你同时在动左端和右端，所以状态必须能同时表达「左边砍到哪、右边砍到哪」——一个下标不够，必须一对下标。这是回文类题目一律用区间 DP 的根本原因，不是巧合。

入口 `dfs(0, n-1)`：把定义里的区间替换成「完整问题」= 整个串。

## 二、转移：只问一句话

> **端点 `s[i]` 和 `s[j]` 这两个字符，怎么处理？**

回文子序列有一条硬性质：**它在原串里的首尾两个字符必须相等**。整个分类就建立在这条性质上。

### 情况 A：`s[i] == s[j]` → 直接 `dfs(i+1, j-1) + 2`，不取 max

这里最容易犯嘀咕：万一不用这两个端点反而更长呢？不会。**交换论证**：

设 $T$ 是区间 $[i,j]$ 的某个最优回文子序列，首尾字符落在原串位置 $p < q$（$i \le p < q \le j$，且 $s[p] = s[q]$）。把 $T$ 的头尾这两个字符**替换成位置 $i$ 和 $j$ 的字符**：中间部分 $T'$ 原本落在 $(p, q)$ 内，必然也落在 $(i,j)$ 内；而 $s[i] = s[j]$，所以 $s[i] + T' + s[j]$ 仍是回文，**长度一模一样**。

结论：**总存在一个最优解恰好用上了两个端点**。所以对角支支配另外两支，不需要 max。（`|T| ≤ 1` 的退化情况更显然：`i < j` 时光凭 `s[i]s[j]` 就有长度 2。）

### 情况 B：`s[i] != s[j]` → `max(dfs(i+1, j), dfs(i, j-1))`

既然首尾字符必须相等，而这俩不等，那**它们不可能同时充当答案的首尾**——至少有一个端点是废的。于是「丢左端」「丢右端」两支就覆盖了全部可能。

两支有重叠（都丢的方案在两边各被数了一次），但你笔记里那句话在这里同样适用：**候选允许重，不允许漏**，`max` 会自己挑。

**为什么不用补第四支 `dfs(i+1, j-1)`？** 同样的支配关系：任何「两端都不用」的方案，本身已经是 `dfs(i+1, j)` 搜索空间里的一员（只不过恰好没用到 `s[j]`）。写了不错，只是白算。

## 三、Base case：两步法，而且第二个不能省

按你惯用的两步走：

**第一步（语义）**：合同在边界处该返回什么？

- `i > j`：空区间，没有字符 → `0`
- `i == j`：单个字符，它自己就是长度为 1 的回文 → `1`

**第二步（可达性）**：转移最多退到哪儿？

- 对角支从长度为 2 的区间 `dfs(i, i+1)` 出发，会走到 `dfs(i+1, i)`，即 `i > j` ✓ 可达
- 单侧支从长度为 2 的区间出发，会走到 `dfs(i+1, i+1)`，即 `i == j` ✓ 可达

两格都得盖住。

> [!warning] 这题最经典的坑：`i == j` 绝不能省 如果只写 `if i > j: return 0`，那么 `dfs(i, i)` 会落进 `s[i] == s[j]` 分支（同一个字符当然相等），返回 `dfs(i+1, i-1) + 2 = 0 + 2 = 2`。
> 
> **一个字符被当成两个用了。** 这个错误不会报错、不会越界，只会让答案默默偏大——是本题唯一的静默 bug 点。

## 四、一个交叉验证的视角

$$\text{LPS}(s) = \text{LCS}(s,\ \text{reverse}(s))$$

回文的定义就是「正着读等于反着读」，所以 `s` 里最长的回文子序列，等价于 `s` 和它的逆序串的最长公共子序列。这条等式能让你把这题直接套进 [[7.3 线性dp 最长公共子序列]] 的模板里，$O(n^2)$ 同阶。

但**区间 DP 的写法更本质**：它直接刻画了「两端向中间夹」这个动作，而 LCS 转化是一个绕道。面试里说出这条等式能加分，落笔还是写区间 DP。

---


---

**一句话总结**：区间 DP 的全部功夫在「**两个端点这一步怎么处理**」——相等就成对吃掉（交换论证保证不亏），不等就至少丢一个（`max` 兜底）；而 `i == j` 这个 base 是回文类题目的专属陷阱。

递推：

依赖关系是 `(i+1, j-1)`、`(i+1, j)`、`(i, j-1)`，即**下方、左下、左方**。所以：

```python
class Solution:
    def longestPalindromeSubseq(self, s: str) -> int:
        n = len(s)
        f = [[0] * n for _ in range(n)]
        for i in range(n - 1, -1, -1):     # i 倒序：先算大 i
            f[i][i] = 1                    # 单字符 base
            for j in range(i + 1, n):      # j 正序：先算小 j
                if s[i] == s[j]:
                    f[i][j] = f[i + 1][j - 1] + 2
                else:
                    f[i][j] = max(f[i + 1][j], f[i][j - 1])
        return f[0][n - 1]
```

**`i` 倒序、`j` 正序**不是背下来的，是从依赖方向读出来的：需要 `i+1`（更大的 i）先算好 → i 倒序；需要 `j-1`（更小的 j）先算好 → j 正序。另外 `j` 从 `i+1` 起步，因为 `j < i` 的格子（空区间）恒为 0，压根不用填。

复杂度：状态数 $O(n^2)$（严格说是上三角 $n^2/2$），单次转移 $O(1)$ ⇒ 时间 $O(n^2)$，空间 $O(n^2)$。

```python
class Solution:

    def minScoreTriangulation(self, values: List[int]) -> int:

        n = len(values)

        @cache

        def dfs(i ,j):

            if i + 1 == j:

                return 0

            res = inf

            for k in range(i+1, j):

                res = min(res, dfs(i,k) + dfs(k,j) + values[i]*values[j]*values[k])

            return res

        return dfs(0,n-1)


```

### 一、`i` 和 `j` 是什么

这题的 `i`、`j` 不再是「字符下标」，而是**多边形上的两个顶点编号**。合同：

dfs(i,j)=由顶点 i, i+1, …, j 依次相连，再用弦 (i,j) 封口所围成的子多边形，其三角剖分的最低得分dfs(i, j) = \text{由顶点 } i,\ i{+}1,\ \dots,\ j \text{ 依次相连，再用弦 } (i,j) \text{ 封口所围成的子多边形，其三角剖分的最低得分}dfs(i,j)=由顶点 i, i+1, …, j 依次相连，再用弦 (i,j) 封口所围成的子多边形，其三角剖分的最低得分

关键在「封口」两个字。区间 [i,j][i,j] [i,j] 描述的不是一段序列，而是**一块被切下来的子多边形**：它的边界由原多边形上的一串连续边 (i,i+1),…,(j−1,j)(i,i{+}1),\dots,(j{-}1,j) (i,i+1),…,(j−1,j) 加上一条封口边 (i,j)(i,j) (i,j) 组成。

入口 `dfs(0, n-1)`：顶点 00 0 到 n−1n{-}1 n−1 全都在内，封口边是 (0,n−1)(0, n{-}1) (0,n−1)——这本来就是原多边形的一条真实边，所以整个多边形被完整覆盖。

### 二、和上一题的分野：区间 DP 的两大子类

这是本题最该记住的一点。同为区间 DP，[[516. 最长回文子序列]] 和这题的**转移形态完全不同**：

||决策问的是什么|分支数|子问题|
|---|---|---|---|
|516 回文|**两个端点**怎么处理？|O(1)O(1) O(1) 支|边界缩一格|
|**1039 本题**|**在哪里切开**？|O(n)O(n) O(n) 支（枚举 kk k）|一分为二，两块都要算|

上一题是「**缩边界**」，这一题是「**选分割点**」。看到 `for k in range(i+1, j)` 里套 `dfs(i,k) + dfs(k,j)` 这个形状，就该条件反射：**枚举分割点型区间 DP**，时间会带一个额外的 O(n)O(n) O(n)。

### 三、转移：分类的依据是什么

`for k` 看起来像在盲目穷举，其实背后有一条很干净的性质：

> **封口边 (i,j)(i,j) (i,j) 在任何一个合法剖分里，都必然恰好属于一个三角形。**

因为 (i,j)(i,j) (i,j) 是这块子多边形的**边界边**，只有一侧有图形，所以贴着它的三角形有且仅有一个。那个三角形的第三个顶点 kk k 必然满足 i<k<ji < k < j i<k<j。

于是分类就出来了，而且天然**不重不漏**：

- **不漏**：kk k 取遍 (i,j)(i, j) (i,j) 之间所有顶点，穷尽了「贴着 (i,j)(i,j) (i,j) 的三角形长什么样」的全部可能。
- **不重**：kk k 不同 ⇒ 那个三角形不同 ⇒ 剖分方案必然不同，两两互斥。（注意这里和 LCS 的「候选允许重」不一样——本题的分类是严格划分。）

**为什么切完之后能干净地相加？** 三角形 (i,k,j)(i,k,j) (i,k,j) 一落定，剩下的部分被它劈成两块：

text

```text
左块：顶点 i..k，封口边 (i,k)   → dfs(i, k)
中间：三角形 (i,k,j)            → values[i]*values[k]*values[j]
右块：顶点 k..j，封口边 (k,j)   → dfs(k, j)
```

这两块只在顶点 kk k（和 ii i、jj j）处接触，**内部再无任何公共区域，也不能跨块连对角线**（连了就穿过中间那个三角形了）。所以两块互不干扰，各自最优即整体最优——这就是无后效性在几何上的体现。

### 四、Base case：两步法

**第一步（语义）**：`i + 1 == j` 时，「子多边形」只剩两个顶点，退化成一条线段，切不出任何三角形 → 得分 `0`。

**第二步（可达性）**：转移里 k∈(i,j)k \in (i,j) k∈(i,j)，所以子调用 `dfs(i,k)` 的 k≥i+1k \ge i+1 k≥i+1、`dfs(k,j)` 的 k≤j−1k \le j-1 k≤j−1，跨度永远 ≥1\ge 1 ≥1。**`j - i == 1` 是能到达的最小状态，`i == j` 不可达**，不用管。

> [!warning] 这个 base 不能省，省了不是「返回 0」而是「返回 inf」  
> 若删掉 `if i + 1 == j: return 0`，当 `j == i+1` 时 `range(i+1, j)` 是空的，循环一次都不进，`res` 保持初值 `inf` 被返回。整条链路会被 `inf` 污染，答案直接错成 `inf`。
> 
> 这是「**先赋 `inf` 再 `min`**」这种写法的通病：空循环会静默漏出哨兵值。凡是转移写成 `res = inf` + for + `min` 的题，都要专门检查「循环可能为空吗」。
### 示例验证

`values = [3, 7, 4, 5]`（四边形，只有两种剖分方式，正好能看清）：

text

```text
剖分 A：连对角线 (0,2)
  三角形 (0,1,2) = 3*7*4 = 84
  三角形 (0,2,3) = 3*4*5 = 60      合计 144   ← k=2

剖分 B：连对角线 (1,3)
  三角形 (0,1,3) = 3*7*5 = 105
  三角形 (1,2,3) = 7*4*5 = 140     合计 245   ← k=1

dfs(0,3) = min(245, 144) = 144
```

`k` 枚举的正是「**跟边 (0,3) 组队的第三个顶点是谁**」——k=1k=1 k=1 对应剖分 B，k=2k=2 k=2 对应剖分 A，两种情况恰好穷尽，没有第三种。

### 推写法与复杂度

依赖的都是**更短的区间**（`dfs(i,k)` 和 `dfs(k,j)` 跨度都小于 `j-i`），所以有两种等价的循环顺序：

python

```python
# 写法一：i 倒序、j 正序（和 516 同款）
class Solution:
    def minScoreTriangulation(self, values: List[int]) -> int:
        n = len(values)
        f = [[0] * n for _ in range(n)]
        for i in range(n - 3, -1, -1):
            for j in range(i + 2, n):
                f[i][j] = min(f[i][k] + f[k][j] + values[i] * values[j] * values[k]
                              for k in range(i + 1, j))
        return f[0][n - 1]
```

也可以**按区间长度 `L` 从小到大**外层遍历（`for L in range(2, n)` → `for i` → `j = i + L`），这在枚举分割点型区间 DP 里更通用、更不容易把方向搞反，推荐当默认写法。

复杂度：

- 状态数 O(n2)O(n^2) O(n2)，单次转移要枚举 kk k 是 O(n)O(n) O(n) ⇒ **时间 O(n3)O(n^3) O(n3)**
- 空间 O(n2)O(n^2) O(n2)（这类区间 DP **压不成一维**，因为依赖的是整个二维表的两条方向，不像背包只依赖同一行）
