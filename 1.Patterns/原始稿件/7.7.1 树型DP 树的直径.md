## 一、先把合同钉死

`+2` 从哪来，完全取决于 `dfs` 返回的是什么。这题的合同是：

$$dfs(node) = \text{以 } node \text{ 为起点向下走到叶子，最长的那条链的**边数**}$$

注意是**边数**，不是节点数。这是全部混乱的源头。

先验证叶子节点：`l_len = r_len = -1`，返回 `max(-1,-1) + 1 = 0`。叶子到它自己，0 条边 ✓。

**所以 `return -1` 不是拍脑袋定的**，它是被「叶子必须返回 0」反推出来的哨兵：空儿子返回 $-1$，加上那条本不存在的边 $+1$，恰好抵消成 $0$。

---

## 二、`+1` 和 `+2` 是同一个东西：**连接边**

把 `node` 和它的儿子连起来，需要**一条边**。所有的 `+1` 都是在数这条边。

### `return max(l_len, r_len) + 1`

向上传的是「从 `node` 出发的最长下行链」。这条链 = 儿子那边最长的链 + `node` 到那个儿子的**一条边** ⇒ `+1`。

### `ans = max(ans, l_len + r_len + 2)`

这一行算的是**以 `node` 为拐点**的路径：

```text
    左链最深处 ←…← 左儿子 ← node → 右儿子 →…→ 右链最深处
                    ↑边1          ↑边2
```

总边数 = 左链边数 + **左连接边** + 右链边数 + **右连接边** $$= l_len + 1 + r_len + 1 = l_len + r_len + 2$$

**`+2` 就是左右各一条连接边。** `return` 那行只往上接一个方向，所以 `+1`；`ans` 那行左右两个方向都要接上，所以 `+2`。

验证一下最小情形：单个叶子节点，`-1 + -1 + 2 = 0`。一个孤立节点的直径是 0 条边 ✓。再验证一个节点带一个左儿子：`l_len = 0, r_len = -1`，`0 + (-1) + 2 = 1`，一条边 ✓。

---

## 三、换个哨兵，`+2` 就消失了

这能反过来证明 `+2` 不是本质，而是「返回边数 + 空返回 -1」这套约定的副产品：

```python
def dfs(node):
    if node is None:
        return 0                      # 空子树有 0 个节点
    l, r = dfs(node.left), dfs(node.right)
    nonlocal ans
    ans = max(ans, l + r)             # ← 不用 +2 了
    return max(l, r) + 1
```

||你的写法|这个写法|
|---|---|---|
|返回值语义|最长下行链的**边数**|最长下行链的**节点数**（即深度）|
|空节点|`-1`|`0`|
|叶子返回|`0`|`1`|
|拐点路径|`l + r + 2`|`l + r`|

第二版为什么不用加？因为「左边有 `l` 个节点」就意味着「从 node 往左有 `l` 条边」——节点数天然自带了那条连接边。两版答案完全一致，都是边数。

> [!warning] 这两套约定绝不能混 最经典的 bug：写了 `return -1`（边数版）却写成 `ans = max(ans, l + r)`（节点数版的公式），答案**恒偏小 2**。反过来写 `return 0` 配 `l + r + 2`，恒偏大 2。
> 
> 记法：**空节点返回 -1 ⇔ 拐点要 +2；空节点返回 0 ⇔ 拐点不加。** 一改就得两处一起改。

## 四、顺带说透这题真正的难点

`+2` 只是算术，本题的结构性难点在于：**为什么答案要用 `nonlocal ans` 打擂台，而不是直接 `return`？**

因为两个量的语义不同：

- **要往上传的**：必须是一条**单链**（从 node 向下的一条路）。因为父节点还要在它上面接一条边，接完必须仍然是一条路径。
- **要收集的答案**：是一条**拐点路径**（左链 + node + 右链）。它在 node 处已经分叉了，**父节点没法再往上接**——接上去就成了「Y 字形」，不是路径。

所以拐点路径是「用完即弃」的，只能当场记进全局擂台；能向上传的只有单链。直径也确实不一定经过根节点，必须每个节点都当一次拐点试试。

这个「**向上传单链、向全局报拐点**」的双轨结构，是一整类树形 DP 的通用骨架：

```python
def dfs(node):
    if node is None:
        return BASE
    l, r = dfs(node.left), dfs(node.right)
    nonlocal ans
    ans = max(ans, 拐点值(l, r, node))     # 报答案：可以分叉
    return 单链值(l, r, node)              # 传上去：必须是链
```

---

**一句话总结**：`+1` 是「node 连到儿子的那条边」，`return` 只接一个方向所以 `+1`，拐点路径左右都要接所以 `+2`；而 `-1` 这个哨兵存在的唯一目的，就是让叶子的两条虚边被抵消成 0。

```python
# Definition for a binary tree node.

# class TreeNode:

#     def __init__(self, val=0, left=None, right=None):

#         self.val = val

#         self.left = left

class Solution:

    def maxPathSum(self, root: Optional[TreeNode]) -> int:

        def dfs(node):

            if node is None:

                return 0

            l_val = dfs(node.left)

            r_val = dfs(node.right)

            nonlocal ans

            ans = max(ans, l_val + r_val + node.val)

            return max(max(l_val, r_val) + node.val, 0)

        dfs(root)

        return ans

```
## 一、合同：这次返回的不是「链长」，是「贡献值」

$$dfs(node) = \text{从 } node \text{ 出发向下走的最大链和，若为负则记作 } 0$$

后半句是这题的全部精髓。注意 `max(..., 0)` 写在 **`return` 里**，不是写在 `ans` 那行——这意味着向上传的东西已经不是「真实的最大链和」，而是「**我这棵子树能给父节点做的最大贡献**」。

贡献可以是 0，含义是：**「我这边全是负的，你别接我，当我不存在。」**

于是 `if node is None: return 0` 就不再是哨兵技巧了，它和 `max(..., 0)` 是**同一个语义的两处体现**——空子树没东西可拿，贡献 0；负子树主动弃权，贡献也是 0。两者天然统一，这就是为什么这题的空节点返回 `0` 而不是 [[543. 二叉树的直径]] 里的 `-1`。

---

## 二、为什么 `ans` 那行只有一个式子就够了

```python
ans = max(ans, l_val + r_val + node.val)
```

拐点路径本该有**四种形态**：只有 node、node+左链、node+右链、左链+node+右链。这里却只写了一个式子，不需要分类讨论。

原因就在于 `l_val`、`r_val` 已经被 clamp 到 $\ge 0$ 了：

|想表达的形态|靠什么自动实现|
|---|---|
|左右都要|`l_val > 0` 且 `r_val > 0`，都加上|
|只要左|`r_val` 恰好是 0，加了等于没加|
|只要右|`l_val` 是 0|
|只要 node 自己|两个都是 0|

**clamp 把「要不要」的分类讨论，变成了「加一个可能为 0 的数」。** 四种情况被一个加法吃掉了——这是本题最漂亮的地方，也是它比 543 更值得琢磨的原因。

反过来说：如果去掉 `max(..., 0)`，你就必须在 `ans` 那行手写四路 `max`，还得给空节点找一个「不可达」的哨兵（`-inf`），代码立刻变丑。

---

## 三、`node.val` 为什么不参与 clamp

```python
return max(max(l_val, r_val) + node.val, 0)
#                            ↑ node.val 在里面，被一起 clamp
```

看起来 `node.val` 也被 clamp 了，但语义上要分清两层：

- **在 `return` 里**：clamp 的对象是「node 这条链整体」。如果 node 自己是 $-10$、儿子贡献 $3$，整条链是 $-7$，那父节点接上去只会亏，所以整体弃权返回 0 ✓
- **在 `ans` 里**：`node.val` **裸着加**，没有 clamp。因为路径**至少包含一个节点**，node 作为拐点是被钦定的，不能弃权。

这个区别就是「弃权只针对子树，不针对自己」。

## 四、两个初始化陷阱

### `ans = -inf` 不能写成 `ans = 0`

如果树全是负数，比如 `[-3]`，答案就是 $-3$（路径不能为空）。初始化成 0 会返回 0，错。

对照 543：那题初始化 `ans = 0` 是对的，因为边数天然非负。**这两题的初值不能互抄。**

### `if node is None: return 0` 不能配「不 clamp 的 return」

举个最小反例，树 = `[2, -1]`（根 2，左儿子 -1，右儿子空）：

```text
正确答案：2（只取根节点）

clamp 版：
  dfs(-1) → ans = max(-inf, 0+0-1) = -1，return max(-1, 0) = 0
  dfs(2)  → ans = max(-1, 0+0+2) = 2          ✓

不 clamp 但空节点仍返回 0：
  dfs(-1) → return 0 + (-1) = -1
  dfs(2)  → ans = max(..., -1 + 0 + 2) = 1    ✗ 被负儿子拖累
```

`max(..., 0)` 和 `return 0` 必须**成套出现**，拆开就错。

## 五、与 543 的对照

两题是**同一个双轨骨架**，只换了两个函数：

||543. 直径|124. 最大路径和|
|---|---|---|
|返回值语义|最长下行链的**边数**|最大下行链的**和**（负则记 0）|
|空节点|`-1`（哨兵，抵消虚边）|`0`（真实语义，空贡献）|
|报答案|`l + r + 2`|`l_val + r_val + node.val`|
|向上传|`max(l, r) + 1`|`max(max(l,r) + node.val, 0)`|
|`ans` 初值|`0`|`-inf`|
|有 clamp 吗|无（边数非负，不需要）|**有**（值可负，必须允许弃权）|

骨架完全一致：

```python
def dfs(node):
    if node is None:
        return BASE
    l, r = dfs(node.left), dfs(node.right)
    nonlocal ans
    ans = max(ans, 拐点值(l, r, node))    # 报答案：允许分叉，用完即弃
    return 单链值(l, r, node)             # 传上去：必须是一条链
```

**为什么必须双轨**（上一题讲过，这里再钉一遍）：拐点路径在 node 处已经分叉成 Y 字形，父节点没法再往上接，所以只能当场记进擂台；能向上传的只有单链。

复杂度：每个节点访问一次 ⇒ 时间 $O(n)$，空间 $O(h)$（递归栈，最坏 $O(n)$）。

---

**一句话总结**：`max(..., 0)` 把返回值的语义从「最大链和」升级成「最大贡献」，负子树可以弃权——于是拐点那行的四种情况被一个加法自动吞掉，这是本题唯一的技巧。

class Solution:

## 一、合同

$$dfs(x) = \text{从 } x \text{ 出发向下走、且相邻字符都不同的最长链的**边数**}$$

回到 [[543. 二叉树的直径]] 的「边数」约定。验证叶子：`g[x]` 为空，for 一次都不进，返回 `x_len = 0` ✓。

> [!warning] 这里没有显式 base case，靠的是「空循环兜底」 叶子不需要 `if not g[x]: return 0`，因为 `x_len` 的初值 `0` **恰好就是叶子的正确语义**。
> 
> 对照 [[1039. 多边形三角剖分的最低得分]]：那题初值是 `inf`，空循环会把哨兵漏出去，所以必须显式写 base。**判据是「初值是否等于边界的语义值」**，不是「有没有循环」。这两题正好是正反例。

## 二、核心技巧：边遍历边打擂台

二叉树只有左右两个儿子，拐点路径直接 `l + r` 就行。多叉树有 $k$ 个儿子，拐点路径要挑**最大的两条链**——这份代码用一次遍历同时完成了「找最大两个」和「打擂台」。

不变量是关键：

> 处理第 $k$ 个儿子时，`x_len` 恰好是**前 $k-1$ 个儿子中最长的那条链**。

于是 `x_len + y_len` 的含义是「**历史最优 + 当前这个**」。

**为什么遍历完就一定拿到了最大两个之和？** 设全局最长的两条链来自儿子 $p$ 和 $q$（$p < q$）。那么处理到 $q$ 时，$p$ 必然是前 $q-1$ 个里最长的（否则 $p$ 就不是全局第二了），即 `x_len` 此刻正好等于 $p$ 的链长。**那一轮算出的就是答案。** 其余轮次算的都是更小的组合，被 `max` 自然滤掉。

这个「维护前缀最大值 + 当场配对」的写法，是所有多叉树版拐点问题的标准手法，值得单独记住。

---

## 三、这题唯一的顺序陷阱

```python
ans = max(ans, x_len + y_len)     # ① 先配对
x_len = max(x_len, y_len)         # ② 后更新
```

**这两行绝对不能交换。** 如果写成：

```python
x_len = max(x_len, y_len)         # ✗ 先更新
ans = max(ans, x_len + y_len)     # ✗ 此时 x_len 可能已经 == y_len
```

当 `y_len` 是目前最大时，`x_len` 被更新成 `y_len`，下一行算出 `y_len + y_len`——**同一个儿子被当成两条链用了两次**，答案偏大。

不变量的语言：`x_len` 必须在「尚未包含当前 `y`」的状态下参与配对。**先用旧值配对，再让新值入库。**

（这和 [[7.3 线性dp 最长公共子序列]] 一维滚动里 `pre` 的三步顺序是同一类错误：都是「旧值必须在被覆盖前用掉」。）

## 四、`if s[y] != s[x]` 为什么只包住两行，不包住递归

```python
for y in g[x]:
    y_len = dfs(y) + 1            # ← 在 if 外面，无条件执行
    if s[y] != s[x]:
        ans = max(ans, x_len + y_len)
        x_len = max(x_len, y_len)
```

**递归必须无条件执行**，因为 `dfs(y)` 除了返回链长，还有一个副作用——它会把 **y 子树内部的最优拐点路径**记进 `ans`。那些路径压根不经过 `x`，跟 `s[x]` 是什么毫无关系。

如果把 `dfs(y)` 挪进 `if` 里，整棵子树就不会被访问，里面的答案全丢。

而 `if` 里那两行的含义是：字符相同时，**这条链既不能接到 x 上，也不能参与 x 的拐点**——`x_len` 不更新（不往上传），`ans` 不更新（不当拐点）。相当于这个儿子对 `x` 而言彻底作废，但它自己那棵子树的账已经算过了。

> **一句话**：递归是为了「跑遍全树」，`if` 是为了「决定这条链能不能用」，两者职责不同，不能混在一层。

## 五、`+1` 出现在两个地方，含义不同

|位置|含义|
|---|---|
|`y_len = dfs(y) + 1`|**连接边**：`x → y` 这一条边。等价于 543 里 `return ... + 1` 的那个 +1|
|`return ans + 1`|**单位换算**：`ans` 数的是边，题目要节点数，$k$ 条边对应 $k+1$ 个节点|

验证单节点树 `parent = [-1], s = "a"`：`dfs(0)` 循环为空，`ans = 0`，返回 `0 + 1 = 1` ✓

## 六、建图那两行的坑

```python
for i in range(1, n):             # ← 必须从 1 开始
    g[parent[i]].append(i)
```

`parent[0] == -1`。如果从 `i = 0` 开始，会执行 `g[-1].append(0)`——Python 的负下标不报错，会把节点 0 挂到 `g[n-1]` 底下，**凭空造出一条环**，`dfs` 立刻无限递归。

这和你笔记里 [[7.1 DP 打家劫舍]] 记的 `memo[-1]` 静默取值是同一个坑：**Python 的负下标不会报错，只会安静地给你错误答案。**

另外注意 `g` 只存 children、不存双向边，所以 `dfs` 里不需要传 `fa` 参数防回头。如果题目给的是无向边列表，就必须写成 `dfs(x, fa)` 并跳过 `y == fa`。

## 七、三题对照

||543. 直径|124. 最大路径和|**2246. 本题**|
|---|---|---|---|
|树形态|二叉|二叉|**多叉**|
|返回值|最长链边数|最大链和（负则 0）|最长合法链边数|
|空/叶子|`None → -1`|`None → 0`|空循环 → `0`|
|拐点|`l + r + 2`|`l_val + r_val + node.val`|**`x_len + y_len` 滚动配对**|
|过滤条件|无|`max(..., 0)` 弃权|`s[y] != s[x]`|
|最终换算|直接返回|直接返回|`ans + 1`（边→点）|

骨架完全一致：

```python
def dfs(x):
    nonlocal ans
    ans = max(ans, 拐点值)      # 报答案：允许分叉，用完即弃
    return 单链值               # 传上去：必须是一条链
```

多叉树相对二叉树的唯一变化，就是**拐点值从「一次相加」变成「滚动配对」**。

## 八、两个补充

**复杂度**：每条边恰好走一次，时间 $O(n)$，空间 $O(n)$（邻接表 + 递归栈）。

**不需要 `@cache`**：树上每个节点只被它唯一的父亲调用一次，**没有重叠子问题**。这不是 DP 的记忆化场景，而是纯粹的「一次 DFS 顺便聚合」。（呼应上次讨论：树形 DP 的「DP」在于状态转移，不在于缓存。）

**栈深度风险**：$n$ 可达 $10^5$，链状树会触发 Python 默认递归上限 1000。LeetCode 环境通常放宽了，但面试白板时值得主动提一句「必要时改迭代或 `sys.setrecursionlimit`」。

---

**一句话总结**：多叉树的拐点路径靠「**先配对、再更新**」的滚动擂台一次拿到最大两条链，而 `if` 只管「这条链能不能用」、`dfs` 必须无条件跑完全树——这两层职责分开，是本题唯一容易写反的地方。
