```python
# Definition for a binary tree node.

# class TreeNode:

#     def __init__(self, val=0, left=None, right=None):

#         self.val = val

#         self.left = left

#         self.right = right

class Solution:

    def rob(self, root: Optional[TreeNode]) -> int:

        def dfs(node):

            if node is None:

                return 0, 0

            l_rob, l_not_rob = dfs(node.left)

            r_rob, r_not_rob = dfs(node.right)

            rob = l_not_rob + r_not_rob +node.val

            not_rob = max(l_rob, l_not_rob) + max(r_rob, r_not_rob)

            return rob, not_rob

        return max(dfs(root))

```

## 先诊断：抽象感来自哪里

不是来自树，是来自**返回值突然从「一个数」变成「一个二元组」**。

198 里 `dfs(i)` 返回一个数就够了；这里返回一个数就必然错。搞清楚"为什么一个数不够"，这题就通了。

---

## 一、为什么 198 的写法搬不过来

198 的转移是 `max(dfs(i-1), dfs(i-2) + nums[i])`——它依赖一个隐含前提：**元素排成一条线，"跳过相邻"可以翻译成"下标减 2"**。

树上这个翻译立刻失效：

- `i-1` 对应"孩子们"，但有两个；
- `i-2` 对应"孙子们"，可能有四个；
- 更糟的是，一旦你写 `node.val + dfs(四个孙子)`，就得手动展开 `node.left.left`、`node.left.right`…… 还要处理空节点，代码又丑又容易漏。

根本问题是：**"跳两层"是对约束的一种间接编码，只在链状结构上好用。** 树上要换一种编码方式。

---

## 二、换编码：状态不再是"位置"，而是"这个点选没选"

原来的约束是「相邻两点不能同时选」。这条约束**只作用在一条边的两端**。所以父亲要做决策，唯一需要知道的是：

> 我的左孩子（右孩子）**自己有没有被选**？

而不是"左子树的最大值是多少"。这就是关键分岔口——

如果 `dfs(node)` 只返回一个 `max`，你拿到的是"左子树最好能偷多少"，但**你不知道这笔钱里有没有包含 `node.left` 本身**。有的话你就不能选 `node`，没有的话你可以选。信息被 `max` 抹掉了，父亲无法做决策。

所以合同必须写成**两份**：

$$dfs(node) = (\ \underbrace{rob}_{\text{强制选 node 时，该子树的最大值}},\ \underbrace{notRob}_{\text{强制不选 node 时，该子树的最大值}}\ )$$

这叫**状态机 DP**：把"抹掉就没法用"的那一位信息，提升成状态的一个维度。

---

## 三、两条转移，各自的理由

```python
rob     = node.val + l_not_rob + r_not_rob
not_rob = max(l_rob, l_not_rob) + max(r_rob, r_not_rob)
```

**第一行**：既然前提是"选了 node"，约束立刻生效——左右孩子**必须**不选，所以只能取 `l_not_rob` / `r_not_rob`，没有 `max` 可选。

注意：约束到此为止。孙子层完全自由，而这份自由**已经被打包在 `l_not_rob` 的定义里了**（"不选 left，left 的子树随便偷的最大值"）。这就是为什么不需要手动去够孙子。

**第二行**：前提是"不选 node"，那么左右孩子**没有任何限制**，选不选都合法，各取自己两种情况里更大的那个。

这里有两个容易被跳过的合法性依据：

- 为什么能写 `max(l_rob, l_not_rob)`？因为对左孩子而言，"选"和"不选"是**不重不漏的完备分类**，取冠军即全局冠军——和 198 里 `max` 的正确性来源是同一条。
- 为什么左右可以**分别**取 `max` 再相加？因为左右子树之间**没有任何一条边相连**，约束不耦合，两边的最优可以自由组合。（如果题目改成"整棵树最多偷 k 个"，这条就崩了，必须多加一维。）

---

## 四、和 198 对照着看，就一点都不抽象了

198 的滚动变量版你写过：

```python
f0, f1 = f1, max(f1, f0 + x)
```

其实 198 也能写成状态机形式，你会发现和本题**逐字对应**：

||198（链）|337（树）|
|---|---|---|
|前驱个数|1 个（`i-1`）|2 个（left、right）|
|选自己|`notRob[i-1] + x`|`l_not_rob + r_not_rob + val`|
|不选自己|`max(rob[i-1], notRob[i-1])`|`max(l_rob,l_not_rob) + max(r_rob,r_not_rob)`|
|入口|最后一个位置取 `max`|`max(dfs(root))`|

**唯一的区别是前驱从 1 个变成 2 个，于是"取一个"变成"两边各取一个再相加"。** 树形 DP 的全部改动就这么多。

最后 `max(dfs(root))`：根没有父亲，两种前提都合法，取大的。

---

## 五、为什么这里不需要 `@cache`

因为**根本没有重叠子问题**。198 里 `dfs(3)` 和 `dfs(4)` 都会调 `dfs(2)`，才需要 memo；树上每个 `node` 只有一个父亲，`dfs(node)` 天然只被调用一次。

递归本身就是自底向上的一遍**后序遍历**——依赖方向是"父依赖子"，所以必须先 `dfs(left)`、`dfs(right)`，再算自己。这也是为什么两行 `l_rob, l_not_rob = dfs(node.left)` 必须写在最前面。

DP 表在哪？就存在每次递归的返回值里，用完即弃。

---

## 六、易错点

```text
1. not_rob 写成 l_rob + r_rob
   → 错。"不选 node" ≠ "必须选孩子"，孩子仍可不选。漏了一整类方案。

2. rob 里给孩子加了 max
   → 错。选了 node 就锁死孩子必须不选，这里没有选择权。

3. 空节点返回 0（单值）而不是 (0, 0)
   → 类型不匹配，解包直接崩。空树两种前提下都是 0。

4. 最后写 dfs(root)[0] 或 dfs(root)[1]
   → 错。根不受约束，必须 max。

5. 想用一个 max 返回值糊过去
   → 这就是本题的核心陷阱，见第二节。
```

**复杂度**：时间 $O(n)$，每个节点访问一次、常数转移；空间 $O(h)$ 递归栈，最坏 $O(n)$。

---

## 一句话总结

当"最优值是否用到了自己"这一位信息会影响父节点的决策时，就不能只返回 `max`——把它提升为状态的一维，返回 `(选, 不选)` 二元组，树形 DP 就是这样从 198 长出来的。
