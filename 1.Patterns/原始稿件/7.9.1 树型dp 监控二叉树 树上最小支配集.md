```python
# Definition for a binary tree node.

# class TreeNode:

#     def __init__(self, val=0, left=None, right=None):

#         self.val = val

#         self.left = left

#         self.right = right

class Solution:

    def minCameraCover(self, root: Optional[TreeNode]) -> int:

        def dfs(node):

            if node is None:

                return inf, 0, 0

            l_choose, l_by_fa, l_by_chlidren = dfs(node.left)

            r_choose, r_by_fa, r_by_chlidren = dfs(node.right)

            choose = min(l_choose, l_by_fa, l_by_chlidren) + min(r_choose, r_by_fa, r_by_chlidren) + 1

            by_fa = min(l_choose, l_by_chlidren) + min(r_choose, r_by_chlidren)

            by_children = min(l_choose+r_by_chlidren, l_by_chlidren+r_choose, l_choose+r_choose)

            return choose, by_fa, by_children

  

        choose, _, by_children = dfs(root)

        return min(choose, by_children)
```

## 先诊断

337 里两个状态，是因为约束只有一条边的两端；这里状态变成三个，是因为**约束换了性质**：

||337 打家劫舍 III|968 监控二叉树|
|---|---|---|
|约束|相邻两点**不能同时选**|每个点**都必须被覆盖**|
|父亲需要知道|孩子选没选（1 bit）|孩子**被谁**覆盖了（3 种可能）|

「被覆盖」的来源恰好有三个方向：**自己装、父亲装、儿子装**。所以状态维度就是 3。看晕的原因通常是：把这三个当成了"选/不选"的变体，其实它们回答的是另一个问题——**谁负责覆盖我**。

---

## 一、三份合同（这是全篇的地基）

`dfs(node)` 返回三个数，共同前提是：**node 的整棵子树里，除了 node 自己以外的所有节点都已被覆盖**。三者的区别只在 node 自己的处境：

$$ \begin{aligned} choose &= \text{node 自己装摄像头时，该子树的最少摄像头数}\ byFa &= \text{node 不装、指望父亲来覆盖它时，该子树的最少摄像头数}\ byChildren &= \text{node 不装、由某个儿子覆盖它时，该子树的最少摄像头数} \end{aligned} $$

关键理解 `by_fa`：父亲的摄像头**不在这棵子树里**，所以在子树内部看，node 是"欠着一份覆盖"的状态。这份债由调用者（父亲）来还。

---

## 二、三条转移，逐条给理由

### `choose`：node 装了

```python
choose = min(l_choose, l_by_fa, l_by_children) + min(...) + 1
```

node 装了摄像头 → 两个儿子**已经被 node 覆盖了**，儿子怎么处理自己完全自由：自己装（`choose`）、指望父亲也就是 node（`by_fa`）、被自己的儿子覆盖（`by_children`），三种都合法，取最便宜的。`+1` 是 node 这台摄像头。

注意 `l_by_fa` 这一支在这里**才是合法的**——因为它欠的那笔债，正好由 node 这台摄像头还上了。

### `by_fa`：node 不装，等父亲来救

```python
by_fa = min(l_choose, l_by_children) + min(r_choose, r_by_children)
```

node 没有摄像头 → 儿子**得不到任何来自 node 的覆盖**，必须自力更生：要么自己装，要么被自己的儿子覆盖。

`l_by_fa` 在这里被排除，因为它的含义是"左儿子指望 node 覆盖它"，而 node 是空的。**这一条被排除，正是 `by_fa` 与 `choose` 的唯一差别。**

### `by_children`：node 不装，靠儿子

```python
by_children = min(l_choose + r_by_children,
                  l_by_children + r_choose,
                  l_choose + r_choose)
```

要求变成：**至少有一个儿子装了摄像头**。同时另一个儿子仍然必须被覆盖、且仍然不能指望 node。于是穷举"谁装"：

- 左装、右不装（右只能靠它自己的儿子）
- 右装、左不装
- 两个都装

---

## 三、为什么第三项「都装」不能省？

这是最容易被当成冗余删掉的地方。看一个具体反例——node 有两个**叶子**儿子：

```text
叶子的三元组：dfs(leaf) → (choose=1, by_fa=0, by_children=inf)
                                          ↑ 叶子没有儿子，这条路不存在

l_choose + r_by_children = 1 + inf = inf
l_by_children + r_choose = inf + 1 = inf
l_choose + r_choose      = 1 + 1   = 2   ← 只有这一项是有限的
```

现实含义：node 靠一个叶子来覆盖，那**另一个叶子**既没有摄像头、上面的 node 也没有、自己又没有儿子——只能自己再装一台。答案就是 2。删掉第三项，这种局面直接算成 `inf`，整题崩掉。

（其实前两项里的 `r_by_children` 本该写成 `min(r_choose, r_by_children)`，原代码把这个 `min` 展开成了第三项，等价。）

---

## 四、空节点为什么是 `(inf, 0, 0)`

```python
if node is None:
    return inf, 0, 0
```

一个个对：

- `choose = inf`：空节点**不可能装**摄像头 → 用 `inf` 表示"此路不通"，它会在外层的 `min` 里自动被淘汰。这是求最小值 DP 里表示不可达的标准手法。
- `by_fa = 0`：空节点**不需要被覆盖**，也不产生成本。
- `by_children = 0`：严格说空节点没有儿子，这一项语义上不成立；但因为空节点根本不需要覆盖，把它当成"这一侧零约束、零成本"是安全的，且能让父亲的转移式不用特判 `None`。

验证一下：node 的左儿子是空，`by_fa` 那一侧算 `min(inf, 0) = 0` ✓；`by_children` 里凡是"左儿子装摄像头"的分支都是 `inf` ✓，走不通。**`inf` 负责堵死非法路径，`0` 负责让合法路径不受干扰**，一个哨兵干两件事。

---

## 五、最后为什么是 `min(choose, by_children)`

先记一个事实：

$$byFa \le byChildren \quad \text{恒成立}$$

因为 `by_fa` 的约束**更松**（node 自己不用在子树内被覆盖），任何 `by_children` 的合法方案自动也是 `by_fa` 的合法方案。所以 `by_fa` 永远不会更贵。

正因为如此，根节点必须**主动排除** `by_fa`——root 没有父亲，那笔"欠债"永远还不上，留着它一定会返回一个 root 未被覆盖的错误答案（而且因为它恒更小，一定会被 `min` 选中）。

这也是三个状态里 `by_fa` 存在的全部意义：它是一个**只对父亲有意义的中间态**，到了顶层就得丢掉。

---

## 六、易错点

```text
1. by_fa 里误用了 l_by_fa
   → node 没摄像头，儿子指望它就是空头支票。这是三条转移里唯一的区别点。

2. by_children 漏掉「两个都装」
   → 两个叶子儿子的场景直接算成 inf。见第三节。

3. 空节点 choose 写成 0
   → 等于允许在空位置装摄像头，答案会偏小。必须 inf。

4. 最后写成 min(三个)
   → by_fa 恒最小，必被选中，root 漏覆盖。

5. 想套 337 的两状态
   → 覆盖来源有三个方向，二元组表达不下。
```

**复杂度**：时间 $O(n)$，每节点一次常数转移；空间 $O(h)$ 递归栈。

---

## 一句话总结

337 的父亲只需要知道孩子"选没选"，所以两个状态；968 的父亲需要知道孩子"被谁覆盖"，而来源有自己/父亲/儿子三种，所以三个状态——树形 DP 的状态个数，等于**父亲做决策时必须从孩子那里拿到的信息量**，多一位不嫌多，少一位就一定错。
