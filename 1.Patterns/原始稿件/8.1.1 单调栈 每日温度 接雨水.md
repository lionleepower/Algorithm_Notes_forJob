```python
class Solution:

    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:

        n = len(temperatures)

        ans = [0] * n

        st = []

        for i in range(n-1,-1,-1):

            t = temperatures[i]

            while st and t >= temperatures[st[-1]]:

                st.pop()

            if st:

                ans[i] = st[-1] -i

            st.append(i)

  

        return ans
```

你这份代码是**从右往左**的写法，和常见的「从左往右结算」是**两种不同的视角**。先把它的语义契约钉死，其他一切都是推论。

## 一、栈的语义契约

```
遍历到 i 时，栈里存的是：i 右边所有「还有可能成为某个左侧元素答案」的下标
```

由这个契约立刻推出两条不变量（每轮循环结束时都成立）：

- **下标**：从栈顶到栈底**递增**（因为从右往左走，越早入栈的下标越大）
- **温度**：从栈顶到栈底**严格递增**（栈顶最小）

这两条合在一起就是全部：栈顶是**离 i 最近**的候选，而且它是候选里**最小**的那个。

## 二、为什么敢 pop —— 永久淘汰论证

```python
while st and t >= temperatures[st[-1]]:
    st.pop()
```

设栈顶为下标 $j$（$j > i$），且 $temperatures[i] \ge temperatures[j]$。

对任意 $k < i$，问「$j$ 还可能是 $k$ 的答案吗？」——不可能。因为 $i$ 比 $j$ **更近**，且 $temperatures[i] \ge temperatures[j]$：只要 $j$ 能满足 $k$（$temperatures[j] > temperatures[k]$），$i$ 必然也满足，而且更早遇到。**$j$ 被 $i$ 永久遮蔽了**，此后再无翻身机会，所以可以安全丢弃。

这就是单调栈的全部秘密：**一个元素一旦被「更近且不更小」的元素遮蔽，就永远无用**。不是「暂时不用」，是「永远不用」，所以敢 pop 而不是 peek。

## 三、`>=` 里的等号为什么必须要

题目要「严格更高」的温度。若 $temperatures[i] = temperatures[j]$：

- $j$ 对 $i$ 本身无用（不严格大）
- $j$ 对 $i$ 左边任何人也无用（被 $i$ 遮蔽，理由同上）

所以等号情况必须 pop。**反过来记**：从左往右的写法用 `>`（只在严格大于时才结算），等号方向恰好相反——因为那边判断的是「谁来给栈里的人结算」，语义不同。这是两种写法最容易记串的一点。

## 四、pop 完为什么栈顶就是答案

pop 循环退出时有 `temperatures[st[-1]] > t`（严格大于）。而**被 pop 掉的都是 $i$ 与 $st[-1]$ 之间的全部候选**，它们无一严格大于 $t$。所以 $st[-1]$ 是 $i$ 右边第一个严格更大者：

```python
ans[i] = st[-1] - i     # 存下标才能算天数差；存温度值就废了
```

栈空则说明右边没有更大的，`ans[i]` 保持初始的 0。



## 六、复杂度

时间 $O(n)$：每个下标**最多入栈一次、出栈一次**，`while` 的总执行次数被这个摊还上界卡死，与外层循环无关。空间 $O(n)$（栈，最坏是严格递减数组）。

```python
class Solution:

    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:

        n = len(temperatures)

        ans = [0] * n

        st = []

        for i,t in enumerate(temperatures):

            while st and t > temperatures[st[-1]]:

                j = st.pop()

                ans[j] = i-j

            st.append(i)

  

        return ans

```

从左到右也更能体现单调栈的特点



两种视角的对照

||从右往左（你的写法）|从左往右（常见写法）|
|---|---|---|
|栈的含义|**候选答案池**|**还没拿到答案的欠债人**|
|当前元素干什么|清理无效候选，然后**查询**|给栈里的人**结算**，然后入队|
|比较符|`t >= temperatures[st[-1]]` 时 pop|`t > temperatures[st[-1]]` 时 pop 并结算|
|谁负责写 ans|`ans[i]`，自己写自己|`ans[st[-1]]`，写别人|

两者都是 $O(n)$，都对。从右往左更符合「我要找我的答案」的直觉，从左往右更符合「延迟结算」的直觉。**建议只精熟一种**，另一种能读懂即可，否则等号方向必串。

```python

class Solution(object):

    def trap(self, height):

        """

        :type height: List[int]

        :rtype: int

        """

        ans = 0

        st = []

        for i, h in enumerate(height):

            while st and h>= height[st[-1]]:

                bootom_h = height[st.pop()]

                if len(st) == 0:

                    break

                left = st[-1]

                dh = min(height[left], h) - bootom_h

                ans += dh * (i - left -1)

            st.append(i)

        return ans

```

最后总结一下，如果找到要计算的内容涉及到上一个或是下一个更大更小的元素，就可以优先考虑单调栈
