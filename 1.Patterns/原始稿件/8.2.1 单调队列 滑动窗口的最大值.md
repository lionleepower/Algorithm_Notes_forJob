```python
class Solution:

    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:

        ans = []

        q = deque()

        for i, x in enumerate(nums):

            #1.入

            while q and nums[q[-1]] <= x:

                q.pop()

            q.append(i)

            #2.出

            if i - q[0] >= k:

                q.popleft()

            #3.记录答案

            if i >= k-1:

                ans.append(nums[q[0]])

        return ans
```
## 一、单调队列的语义契约

```
q 里存的是：当前窗口内，还有可能成为「未来某个窗口」最大值的下标
```

两条不变量（每轮结束时成立）：

- **下标**：队头 → 队尾**递增**
- **值**：队头 → 队尾**严格递减**

所以 `nums[q[0]]` 就是窗口最大值。

## 二、和单调栈的唯一区别：多了一个「过期」维度

在 739 里，元素只会因为**被遮蔽**而出局。这里多了第二种出局方式——**太老**。这就是为什么要用 deque 而不是 stack：**两头都要删**。

|出队方式|在哪一端|淘汰理由|判断依据|
|---|---|---|---|
|`pop()`|队尾|被遮蔽：新来的又大又新，旧的双重劣势|看**值**|
|`popleft()`|队头|过期：滑出窗口了，再大也没用|看**下标**|

队尾的淘汰论证和单调栈完全一致：$x \ge nums[q[-1]]$ 且 $i > q[-1]$，新元素**更大 + 活得更久**，旧元素永无翻身之日，安全丢弃。

队头则是全新的东西：**它可能仍然是队列里最大的，但因为滑出窗口而被迫出局**。这是「窗口」这个约束独有的代价。

## 三、三步顺序为什么是「入 → 出 → 记录」

这是本题唯一的思维陷阱。

**为什么「入」必须在最前**：新入队的 `i` 永远在窗口内，所以入队本身不会制造越界。而它保证了**入队后 `q` 必然非空**——后面 `q[0]` 的两次访问都不用判空。若把「出」提前，`while` 可能把队列清空，`q[0]` 直接 `IndexError`。

**为什么「记录」必须在最后**：读答案的前提是队头已经完成两轮清理（该遮蔽的遮蔽了，该过期的过期了）。提前读会读到脏数据。

顺序是被**依赖关系**锁死的，不是习惯。

## 四、两个细节

**`<=` 里的等号**：等值时也弹队尾。用 `<` 也能 AC（队列变成非严格递减，队头依然是最大值），但等值的旧元素严格无用——新的更靠右、活得更久。弹掉是纯赚，队列更短。

**「出」用 `if` 而不是 `while`**：每轮 `i` 只前进一格，窗口只滑动一格，**至多一个下标过期**。由不变量「轮末所有下标 $\ge i-k+1$」推出：下一轮只有恰好等于 $i-k+1$ 的那一个需要踢，而这样的下标最多一个。写 `while` 也对，但暴露了没想清楚。

**`i >= k-1`**：第一个完整窗口在 $i = k-1$ 处凑齐，之前不产出答案。

## 五、复杂度

时间 $O(n)$：每个下标最多入队一次、出队一次（从哪头出无所谓），`while` 的总次数被摊还上界卡死。空间 $O(k)$：队列长度不超过窗口大小。

注意这里 $O(n)$ 是**摊还**的——单看某一轮，`while` 可能弹掉 $k-1$ 个元素，但全程总弹出次数不超过 $n$。

---

**一句话本质**：单调队列 = 单调栈 + 过期机制。栈只需回答「谁遮蔽了谁」，队列还要回答「谁已经不在场了」。

这题和你的 [[1.2 滑动窗口]] 是两类：那边是「窗口内的量可增可减、双指针同向推进」，这边是「窗口内求极值、极值不可逆地丢失信息」——**最大值出窗后无法从剩余元素恢复**，所以必须提前把候选序列维护好。这个「不可逆」就是需要单调队列的触发信号。
